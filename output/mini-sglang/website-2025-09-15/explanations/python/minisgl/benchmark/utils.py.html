python/minisgl/benchmark/utils.py

这份代码其实是一个针对大语言模型（LLM）服务的压力测试（Benchmark）工具库。

它的核心作用是：模拟很多用户向 LLM 发送请求，记录下每个请求的响应速度，最后算出一份详细的性能报告（比如首字延迟、吞吐量等）。

为了让你看懂，我把它拆解成一个 “开发这个压测工具的 To-Do List”，我们一步步来看每个任务在代码里是怎么实现的。

📝 任务清单 (To-Do List)

  1. 定义数据结构：规定好“测试题目”长什么样，“测试结果”存什么。
  2. 搭建监控台 (Console)：为了不瞎跑，得有个进度条显示当前测到哪了。
  3. 核心功能：测这一个请求 (Benchmark One)：实现发送一个请求并记录时间。
  4. 核心功能：批量轰炸 (Benchmark Batch/Trace)：并发发送一堆请求，或者按真实时间轴回放请求。
  5. 数据分析 (Process Results)：把记录的时间变成能看懂的指标（TTFT, TPOT, 吞吐量）。
  6. 辅助功能：生成假数据或读取真日志。

逐步讲解

1. 定义数据结构 (Data Structures)

在开始写逻辑前，先定义好数据包。 * BenchmarkTrace: 代表一条测试输入。包含时间戳（什么时候发）、Prompt内容、希望输出多长。 * BenchOneResult: 代表一条精简的测试结果。只存输入长度、输出长度和一串时间点。 * RawResult: 代表一条详细的原始结果。包含完整的输入消息、时间点列表 (tics)。 * 代码细节：get_input_len 方法用来检查实际输入的 Token 数量是否和预期一致。

2. 搭建监控台 (Console & Progress Bars)

压测时如果不看进度条会很慌。代码里的 Console 类和 make_console 函数就是做这个的。 它使用了 tqdm 库来画进度条，而且分得很细： * Input Pbar: 发送了多少请求。 * Output Pbar: 完成了多少请求。 * Prefill Pbar: 预填充（处理输入） 阶段处理了多少 Token。 * Decode Pbar: 解码（生成输出） 阶段生成了多少 Token。

  • 代码细节：Counter 类用来统计当前有多少请求正在天上飞（In-flight），方便监控并发量。

3. 核心功能：测这一个请求 (Benchmark One)

这是最关键的函数：benchmark_one。 * 动作：它使用 OpenAI 的异步客户端 (AsyncOpenAI) 发送一个请求。 * 关键点：stream=True。为什么要流式？因为我们要测 “首字延迟”。 * 计时逻辑： 1. 发请求前记录时间 t0。 2. 收到第一个 Token (chunk) 时，记录时间 t1。t1 - t0 就是 TTFT (Time To First Token)。 3. 之后每收到一个 Token 都记录时间。 4. 根据收到 Token 的次数，更新 console 里的进度条（是正在 Prefill 还是在 Decode）。

4. 核心功能：批量轰炸 (Batch & Trace)

有了测单个请求的能力，现在要测并发能力。 * benchmark_batch: 简单粗暴。给你一堆消息，用 asyncio.gather 同时也 发出去。这是为了测系统在极高并发下的极限。 * benchmark_trace: 模拟真实场景。 * 比如真实日志里，用户A在 10:00 发请求，用户B在 10:05 发。 * 这个函数会读取 BenchmarkTrace 里的 timestamp，计算出需要 asyncio.sleep 等待多久再发送。 * 这就叫 “流量回放” (Replay)。

5. 数据分析 (Process Results)

测试跑完了，得到了一堆 tics (时间点列表)，老板要看报表。process_benchmark_results 负责算数： * TTFT (首字延迟): 第一个 Token 出来花的时间。越低越好，代表用户感觉“响应很快”。 * TPOT (Time Per Output Token): 生成后续每个 Token 的平均耗时。代表生成速度。 * E2E (End-to-End): 从发出请求到整个回答结束的总时间。 * Throughput (吞吐量): 每秒处理多少 Token (token/s) 或每秒处理多少请求 (req/s)。 * P50/P90/P99: 统计学术语。比如 P99 TTFT 是 100ms，意思是 99% 的请求首字延迟都小于 100ms（排除掉极个别的慢请求）。

6. 辅助功能 (Utils)

  • generate_message: 如果没有真实数据，就用 Tokenizer 随机拼凑一些乱码生成指定长度的文本，用来做假数据压测。
  • read_qwen_trace / read_mooncake_trace: 如果有真实日志（JSON格式），就解析它们，转换成 BenchmarkTrace 对象，准备给 benchmark_trace 跑回放。
  • scale_traces: 可以压缩或拉长时间轴。比如把一天的流量压缩在1小时内回放，测试高压情况。

总结：这段代码讲了啥？

这段代码就是一个由 Python 编写的、基于 OpenAI 接口标准的 LLM 性能压测器。

它的工作流是： 1. 准备数据（读日志或随机生成）。 2. 建立连接（初始化 OpenAI Client）。 3. 发起攻击（按时间轴或并发发送请求，同时用 tqdm 显示进度）。 4. 搜集弹壳（记录每个 Token 的到达时间）。 5. 输出战报（计算 P99 延迟、吞吐量等核心指标并打印日志）。
