python/minisgl/distributed/info.py

这段代码看起来很抽象，是因为它在处理分布式系统（Distributed System）的基础设施。

简单来说，这段代码就是给当前的程序（通常是一个运行在某个 GPU 上的进程）发一张“身份证”，并把这张身份证存在一个全局都能拿到的地方。

为了让你彻底搞懂，我制定了一个 5步走的 Task List（任务清单）。我们一步步来完成这些任务，就能看懂这段代码了。

📋 Task 1: 理解背景——为什么要发“身份证”？

在深度学习（比如大模型推理/训练）中，一个模型太大，一张显卡装不下，我们需要用多张显卡（比如 8 张）一起跑。这就是所谓的“分布式”。

假设有 8 个人（8 个进程）一起干活，每个人都需要知道两件事： 1. 我是谁？（我的编号是几？是第 0 号，还是第 7 号？）-> 代码里叫 rank。 2. 我们要多少人？（总共有几个人在干活？）-> 代码里叫 size。

代码对应： 文件名叫 distributed/info.py，意思就是“分布式信息”。这里的 TP 通常指 Tensor Parallel（张量并行），是一种多卡并行的技术。

📋 Task 2: 制作“身份证”模板

我们需要一个数据结构来存上面提到的两个信息（我是谁，总共几人）。

代码对应：

@dataclass(frozen=True)
class DistributedInfo:
    rank: int  # 我的编号 (0, 1, 2...)
    size: int  # 总人数 (比如 8)

    def __post_init__(self):
        # 检查逻辑：编号必须大于等于0，且必须小于总人数
        assert 0 <= self.rank < self.size

    def is_primary(self) -> bool:
        # 谁是组长？通常规定编号为 0 的是组长（主进程）
        return self.rank == 0
  • 讲解：
    • @dataclass(frozen=True)：意思是这张身份证一旦打印出来（初始化），上面的字就不能改了（只读）。
    • is_primary：这是一个方便的方法，用来判断“我”是不是老大。有些活（比如打印日志、保存模型）只需要老大干，其他人看着就行。

📋 Task 3: 设立一个“公共公告栏”

身份证做好了，但如果我们在代码的几百个函数里传来传去太麻烦了。我们需要一个全局变量，就像公司大厅的公告栏一样，把身份证贴在那，谁需要谁就去看。

代码对应：

# 这是一个全局变量，刚开始是空的 (None)
_TP_INFO: DistributedInfo | None = None
  • 讲解：
    • _TP_INFO 就是那个公告栏。下划线开头表示这是一个内部变量，不建议外面直接乱改。

📋 Task 4: 把身份证贴上去（初始化）

程序刚启动时，需要把当前的身份信息填好，贴到公告栏上。

代码对应：

def set_tp_info(rank: int, size: int) -> None:
    global _TP_INFO
    # 如果公告栏上已经有东西了，报错！(防止重复初始化)
    if _TP_INFO is not None:
        raise RuntimeError("TP info has been set")

    # 创建身份证，并贴到全局变量上
    _TP_INFO = DistributedInfo(rank, size)
  • 讲解：
    • 这个函数通常在程序启动的最开始调用一次。
    • 它保证了全局只有一个 _TP_INFO。

📋 Task 5: 从公告栏读取信息（获取）

现在代码的其他角落（比如模型的某一层）需要知道“我是第几号显卡”，它就得去读公告栏。这里提供了两种读取方式：

方式 A：强制读取（必须有，没有就报错） 代码对应：

def get_tp_info() -> DistributedInfo:
    # 如果公告栏是空的，说明程序还没初始化好，直接报错
    if _TP_INFO is None:
        raise RuntimeError("TP info has not been set")
    return _TP_INFO
  • 场景： 核心计算代码里用这个。因为如果不知道自己是谁，计算就没法进行了，必须报错停止。

方式 B：尝试读取（有没有都行） 代码对应：

def try_get_tp_info() -> DistributedInfo | None:
    # 直接返回，可能是身份证，也可能是 None
    return _TP_INFO
  • 场景： 辅助代码里用。比如打印调试信息，如果有分布式信息就打印 rank，没有就算了，不强求。

总结

把这个 List 串起来，这段代码讲的就是：

  1. 定义了一个不可修改的身份证类 (DistributedInfo)，存着 rank 和 size。
  2. 弄了个全局变量 (_TP_INFO) 当容器。
  3. 提供了 set 函数来存。
  4. 提供了 get 函数来取。

这就是一种典型的单例模式（Singleton Pattern）或者叫全局状态管理，目的是为了让程序里的任何地方都能方便地知道：“我在哪？我有多少队友？”
