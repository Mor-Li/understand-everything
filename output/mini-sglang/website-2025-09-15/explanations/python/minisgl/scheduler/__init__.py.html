学习任务清单 (To-Do List)

✅ Task 1: 理解“指引牌”的作用 (当前文件)

目标：明白为什么会有 __init__.py 这个文件，以及它里面那两行代码在干嘛。

  • 讲解：
    • Python 的规矩：在 Python 语言里，如果一个文件夹里包含了 __init__.py，Python 就会把这个文件夹当作一个“包” (Package)。
    • 便捷性：文件里的代码 from .scheduler import Scheduler 是为了简化引用。
      • 如果没有这个文件：外部想用调度器，得写很长：from minisgl.scheduler.scheduler import Scheduler。
      • 有了这个文件：外部只需要写：from minisgl.scheduler import Scheduler。
    • 结论：这个文件只是一个“接待员”，它把在这个文件夹深处的 Scheduler 类和 SchedulerConfig 类“请”到了门口，方便别人调用。

⬜ Task 2: 理解“规则手册” (SchedulerConfig)

目标：虽然你还没发给我看，但代码里提到了 SchedulerConfig。我们需要先搞懂它。

  • 概念预习：
    • 任何复杂的系统都需要配置。比如你要开一家餐厅（Scheduler），你需要先定好规则：有多少张桌子？每桌能坐几个人？营业时间是几点？
    • Config (配置) 就是在这个类里定义的。
    • 通常包含：最大并发数量（能同时处理几个请求）、显存限制（GPU有多大）、超时时间等。
    • 下一步行动：你需要去读同目录下的 config.py 文件。

⬜ Task 3: 理解“调度员”的核心工作 (Scheduler)

目标：理解 Scheduler 类（核心逻辑）是做什么的。这是 minisgl (Mini SGLang) 的心脏。

  • 核心概念讲解 (由浅入深)：
    • 背景：minisgl 是一个大模型（LLM）推理引擎。大模型就像一个超级昂贵、超级忙碌的大厨。
    • 问题：如果同时来了 100 个客人（用户的提问），大厨（GPU）一次只能炒 5 个菜，剩下的 95 个怎么办？谁先吃？谁后吃？如果有人点菜太长怎么办？
    • Scheduler (调度器) 的作用：
      1. 排队 (Queuing)：把进来的请求先存起来排队。
      2. 批处理 (Batching)：大厨炒菜喜欢“一锅出”。调度器会把几个类似的、短的请求凑成一波，一起发给 GPU 计算，这样效率最高。
      3. 内存管理 (Memory Management)：计算大模型需要很多显存（KV Cache）。调度器要计算“现在的显存够不够塞进下一个人的请求？”，如果不够，就让那个人等着。
    • 下一步行动：你需要去读同目录下的 scheduler.py 文件。

⬜ Task 4: 串联全流程 (The Big Picture)

目标：脑补整个数据流向。

  • 流程模拟：
    1. 用户发来一个请求：“你好”。
    2. Scheduler 接到请求，看了一眼 SchedulerConfig（规则手册），确认没超过最大限制。
    3. Scheduler 把请求放入等待队列。
    4. Scheduler 检查 GPU 显存，发现有空位。
    5. Scheduler 把这个请求和其他请求打包（Batch），送进模型去推理。
    6. 模型生成了字，Scheduler 把结果返回给用户。
