python/minisgl/utils/logger.py

这份代码确实包含了很多 Python 的高级特性（比如闭包、内部类、类型提示技巧），一下子看懵是很正常的。

简单来说，这个文件的作用是 “创建一个更好看、更智能的打印机（Logger）”。它不仅仅是简单的 print，而是给日志加上了颜色、时间戳、进程ID，甚至还能处理多显卡并行时的打印逻辑。

为了让你彻底看懂，我为你列了一个 学习 Task Todo List，我们将代码拆解成 6 个小任务，一步步攻克：

📝 学习 Task Todo List

  1. 基础任务：搞懂如何决定“该打印什么” (Log Level)。
  2. 身份任务：搞懂如何标记“谁在说话” (Suffix & PID)。
  3. 美化任务：搞懂如何给文字“上色和排版” (ColorFormatter)。
  4. 组装任务：搞懂如何把组件装进 Logger (Handler)。
  5. 进阶任务：搞懂多显卡环境下的“老大说话”机制 (Rank 0)。
  6. 收尾任务：搞懂怎么骗过代码编辑器 (Type Checking)。

🚀 逐步讲解

Task 1: 基础任务 - 决定“该打印什么”

代码位置：init_logger 函数开头部分，涉及 _LOG_LEVEL 和 LEVEL_MAP。

  • 观点：程序运行时废话可能很多，我们需要一个开关来控制。
  • 解释：
    • 代码里定义了一个字典 LEVEL_MAP，把字符串（如 "INFO", "ERROR"）映射到 Python 标准库的数字级别。
    • 它会优先看你传进来的 level 参数。如果没有传，就去读环境变量 os.getenv("LOG_LEVEL")。
    • 目的：比如开发时设为 DEBUG（啥都打印），上线后设为 WARNING（只打印报错），避免日志刷屏。

Task 2: 身份任务 - 标记“谁在说话”

代码位置：init_logger 中处理 suffix, strip_file, use_pid 的部分。

  • 观点：当日志很多时，你需要知道这条消息是哪个文件、哪个进程打印的。
  • 解释：
    • strip_file: 如果为 True，就把文件路径去掉，只留文件名（比如 utils/logger.py 变成 logger.py）。
    • use_pid: PID 是进程 ID。如果是多进程运行（比如数据加载），加上 PID (|pid=1234) 才能分清是哪个进程在跑。
    • 结果：这些信息被拼凑成一个字符串 suffix，准备贴在每条日志后面。

Task 3: 美化任务 - 给文字“上色和排版” (核心)

代码位置：class ColorFormatter(logging.Formatter) 内部类。

  • 观点：默认的黑底白字太难看，我要高亮不同级别的日志，还要统一时间格式。
  • 解释：
    • 颜色代码：COLORS 字典里那些 \033[36m 是 ANSI 转义码，终端看到这个就会变色（比如 ERROR 变红色，INFO 变绿色）。
    • format 方法：这是最关键的函数。每当要打印一条日志，都会经过这里：
      1. 时间戳：把时间格式化为 [2023-10-01|12:00:00|...] 的样子。
      2. TP Rank (分布式)：代码里尝试获取 tp_info（Tensor Parallel info）。如果是多卡运行，它会把显卡编号（Rank）加进去。这样你就知道是“0号显卡”还是“7号显卡”在报错。
      3. 拼接：最后把 时间 + 颜色 + 日志级别 + 消息内容 拼成一句话返回。

Task 4: 组装任务 - 把组件装进 Logger

代码位置：init_logger 后半部分，涉及 logging.StreamHandler。

  • 观点：有了格式化器（Formatter），还得有个“管道”把字输出到屏幕上。
  • 解释：
    • logger = logging.getLogger(name)：拿到一个记录器对象。
    • logger.handlers.clear()：先清空旧的，防止重复打印。
    • StreamHandler(sys.stdout)：创建一个向“标准输出”（屏幕）打印的管道。
    • handler.setFormatter(formatter)：告诉管道：“用刚才那个带颜色的格式器来处理文字”。
    • logger.propagate = False：这句话很重要。意思是“我自己处理完了就行，别传给上级 Logger”，防止一条日志打印两遍。

Task 5: 进阶任务 - 多显卡环境下的“老大说话”

代码位置：_call_rank0 函数和 logger.info_rank0 等赋值。

  • 观点：如果你有 8 张显卡在训练，你肯定不希望看到 8 行一模一样的 "Training Started"。你只希望主显卡（Rank 0）打印一次。
  • 解释：
    • 定义了一个辅助函数 _call_rank0。它会检查 tp_info.is_primary()（我是不是主卡？）。
    • 只有是主卡时，才真正调用 logger.info 或 logger.debug。
    • partial(...)：这是一个偏函数工具。它把 _call_rank0 包装了一下，生成了 info_rank0，debug_rank0 等新方法，并“绑”在了 logger 对象上。
    • 用法：以后你在代码里写 logger.info_rank0("Hello")，就只有 0 号卡会打印，其他卡保持沉默。

Task 6: 收尾任务 - 骗过代码编辑器

代码位置：if TYPE_CHECKING: 块。

  • 观点：因为 info_rank0 是我们动态绑上去的，VS Code 或 PyCharm 默认是不认识的，写代码时会报错说“Logger 没有 info_rank0 这个方法”。
  • 解释：
    • if TYPE_CHECKING: 里的代码只有在静态类型检查时才生效，运行时不执行。
    • 这里定义了一个假的 WrapperLogger 类，显式声明了 info_rank0 等方法。
    • 目的：纯粹是为了让代码编辑器有智能提示，且不报错，让开发体验更好。

总结

这个文件就是做了一个高级定制版的 Logger。

当你调用 init_logger("my_module") 时，它返回给你的 logger 对象： 1. 会自动带颜色。 2. 会自动带时间戳和进程ID。 3. 拥有特殊技能 info_rank0，专门用于多卡训练时只让主卡说话。
