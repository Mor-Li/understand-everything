.pre-commit-config.yaml

这份文件（.pre-commit-config.yaml）其实就是一份给代码仓库设定的“安检规则清单”。

想象一下：每次你写完代码想要提交（git commit）的时候，有一个机器人会自动跳出来，按照这份清单里的规则，一项一项地检查你的代码。如果检查不通过，它就不让你提交，直到你改好为止。

为了让你更容易理解，我为你列了一个 “学习任务清单 (To-Do List)”，我们一步一步拆解这份文件。

📋 你的学习任务清单 (To-Do List)

  1. Task 1：理解“什么时候”会触发安检 (看 default_stages)
  2. Task 2：认识“基础卫生管理员” (看 pre-commit-hooks)
  3. Task 3：认识“Python 装修工” (看 black)
  4. Task 4：认识“Python 纠错老师” (看 ruff)
  5. Task 5：认识“C++ 整理专员” (看 clang-format)
  6. Task 6：实际操作（怎么用起来）

详细步骤讲解

✅ Task 1：理解“什么时候”会触发安检

看文件的第一行：

default_stages: [pre-commit, pre-push, manual]

解读： 这告诉机器人，在以下三个时刻必须干活： * pre-commit: 当你在终端输入 git commit 时（最常用，代码存入本地仓库前）。 * pre-push: 当你输入 git push 时（代码推送到远程服务器前）。 * manual: 当你手动运行命令让它检查时。

✅ Task 2：认识“基础卫生管理员”

看 repos 下的第一个大块（pre-commit-hooks）：

  - repo: https://github.com/pre-commit/pre-commit-hooks
    hooks:
      - id: trailing-whitespace      # 帮你删掉每一行代码末尾多余的空格（强迫症福音）
      - id: end-of-file-fixer        # 确保文件最后一行是空行（Linux系统标准）
      - id: check-yaml               # 检查 YAML 文件格式有没有写错
      - id: check-toml               # 检查 TOML 文件格式有没有写错
      - id: check-ast                # 检查 Python 代码有没有严重的语法错误（比如少个括号）
      - id: check-added-large-files  # 阻止你误把几百兆的大文件提交上去
      - id: check-merge-conflict     # 防止你把解决冲突时的 `<<<<<<<` 标记误提交上去
      - id: detect-private-key       # 【重要】防止你把私钥/密码误提交泄露
      - id: debug-statements         # 防止你把调试用的 `pdb` 断点代码留在里面

观点： 这是一组“低级错误拦截器”。它不管你的代码逻辑对不对，只管你的代码干不干净、安不安全。

✅ Task 3：认识“Python 装修工”

看第二个大块（black）：

  - repo: https://github.com/psf/black
    hooks:
      - id: black
        language_version: python3

解读： * Black 是 Python 界最有名的“代码格式化工具”。 * 不管你写代码喜欢用单引号还是双引号，喜欢空格多一点还是少一点，Black 会强制把所有 Python 代码变成统一的风格。

观点： 这是为了消除团队争议。用了它，团队成员再也不用争论代码怎么排版好看了，机器人说了算。

✅ Task 4：认识“Python 纠错老师”

看第三个大块（ruff）：

  - repo: https://github.com/astral-sh/ruff-pre-commit
    hooks:
      - id: ruff
        args: [--fix]   # 注意这里：它不仅检查，还会尝试自动修复错误
        exclude: ^(tests/|\.venv/|build/|dist/) # 这些文件夹里的代码它不管

解读： * Ruff 是一个速度极快的 Python 代码检查器（Linter）。 * 它会检查你有没有导入了包但没用、变量名是不是写错了等等。 * args: [--fix] 表示：如果它发现能自动改好的小毛病，它就直接帮你改了，不用你动手。

观点： 这是“质量守门员”。它比 Black 更严格，Black 管排版，Ruff 管代码写得规不规范。

✅ Task 5：认识“C++ 整理专员”

看最后一个大块（clang-format）：

  - repo: https://github.com/pre-commit/mirrors-clang-format
    hooks:
      - id: clang-format
        types_or: [c++, cuda]       # 专门针对 C++ 和 CUDA 代码
        args: [--style=file, --verbose]
        exclude: |                  # 排除下面这个特定的文件，不检查它
          (?x)^(
            python/minisgl/kernel_v2/csrc/include/minisgl/nccl227.h
          )

解读： * 你的项目中不仅有 Python，还有 C++ 或 CUDA 代码。 * Clang-format 负责把这些 C++ 代码格式化整齐。 * exclude 部分列出的那个 .h 头文件可能是第三方库或者特殊文件，故意告诉机器人：“这个文件你别动，保持原样”。

观点： 这是一个混合语言项目（Python + C++），所以需要不同的工具来分别维护不同语言的代码整洁。

✅ Task 6：实际上手（怎么让它跑起来？）

既然看懂了，你需要在你的电脑上做这几步，这个文件才会生效：

  1. 安装工具：在终端运行 pip install pre-commit。
  2. 安装钩子：在项目根目录下运行 pre-commit install。
    • 这一步很重要，它会把这个配置文件“挂载”到你的 .git 目录里。
  3. 试运行：运行 pre-commit run --all-files。
    • 这会手动触发一次所有检查，你会看到一排 Pass（通过）或者 Fail（失败）。如果 Fail 了，工具通常会自动帮你改好文件，你只需要重新 git add 一下即可。

总结

这个文件就是雇了 4 个机器人： 1. 杂工（pre-commit-hooks）：扫地、倒垃圾、查违禁品。 2. Python 造型师（black）：把 Python 代码梳妆打扮整齐。 3. Python 质检员（ruff）：挑 Python 代码的毛病并尝试修复。 4. C++ 造型师（clang-format）：把 C++ 代码梳妆打扮整齐。
