python/minisgl/distributed/info.py

这份代码其实是在做一个非常基础但重要的事情：在一个多显卡（多GPU）并行的系统中，给每一个进程发一张“身份证”。

在深度学习框架（比如这里的 minisgl）中，通常会用到“张量并行”（Tensor Parallelism，简称 TP）。这意味着把一个大模型切开，分给好几张显卡一起算。每张显卡（或者说控制显卡的进程）都需要知道：“我是谁？”以及“我们要几个人一起干活？”。

为了让你彻底理解，我为你制定了一个 5步学习任务清单 (To-Do List)。我们一步步把这个文件拆解开。

📋 学习任务清单

  2. Task 2: 看懂核心数据结构（身份证 DistributedInfo）
  3. Task 3: 理解全局变量的作用（公告栏 _TP_INFO）

🚀 逐步讲解

✅ Task 1: 理解背景概念（Rank 和 Size）

想象有一个 4 人的搬家团队在搬钢琴。 * Size (总人数/规模): 团队一共有 4 个人。 * Rank (编号/排位): 为了分工明确，每个人都有个编号：0号、1号、2号、3号。

在代码里： * size: 代表总共有多少个 GPU 参与计算。 * rank: 代表当前这个程序跑在第几个 GPU 上（从0开始数）。

✅ Task 2: 看懂核心数据结构（身份证 DistributedInfo）

代码的第一部分定义了一个类 DistributedInfo：

@dataclass(frozen=True)
class DistributedInfo:
    rank: int
    size: int

    def __post_init__(self):
        assert 0 <= self.rank < self.size  # 检查编号是否合法

    def is_primary(self) -> bool:
        return self.rank == 0  # 0号通常是队长
  • 这是什么？ 这就是一张“身份证”。
  • frozen=True 是什么意思？ 意思是这张身份证一旦打印出来（初始化），上面的字就不能改了。你不能变着变着从 1号 变成了 2号。
  • is_primary 是干嘛的？ 在并行计算中，有些活（比如打印日志、保存模型）只需要一个人干，通常由 0号（队长）来干。这个函数就是用来判断“我是不是队长”。

✅ Task 3: 理解全局变量的作用（公告栏 _TP_INFO）

_TP_INFO: DistributedInfo | None = None
  • 这是什么？ 这是一个全局变量，你可以把它想象成公司大厅的 “公告栏”。
  • 初始状态：None。也就是一开始公告栏是空的，大家还不知道自己的身份。
  • 目的：因为程序里的任何地方（模型的哪一层、数据加载器等）可能随时都需要知道“我是谁”，我们不能把 rank 和 size 作为参数一层一层往下传（太麻烦了），所以直接贴在全局变量里，谁想看就来看。

✅ Task 4: 掌握读写规则（三个核心函数）

为了安全地使用这个“公告栏”，作者写了三个函数来管理它：

1. 贴公告 (set_tp_info)

def set_tp_info(rank: int, size: int) -> None:
    global _TP_INFO
    if _TP_INFO is not None:
        raise RuntimeError("TP info has been set") # 报错：已经贴过了！
    _TP_INFO = DistributedInfo(rank, size)
  • 逻辑：程序启动时调用。如果公告栏是空的，就把身份证贴上去。如果已经贴过了，就报错（防止有人篡改身份）。

2. 强制看公告 (get_tp_info)

def get_tp_info() -> DistributedInfo:
    if _TP_INFO is None:
        raise RuntimeError("TP info has not been set") # 报错：还没贴呢！
    return _TP_INFO
  • 逻辑：当你必须知道自己身份才能干活时调用。如果公告栏是空的，说明程序初始化出问题了，直接报错崩溃。

3. 尝试看公告 (try_get_tp_info)

def try_get_tp_info() -> DistributedInfo | None:
    return _TP_INFO
  • 逻辑：也就是“随便看看”。如果有信息就返回，没有就返回 None，不会报错。这用于那些“如果有并行环境我就并行，没有我就单机跑”的灵活代码。

✅ Task 5: 总结——为什么要写这个文件？

这个文件的作用就是 “全局身份管理”。

如果不写这个文件，你的代码里可能到处都要传递 rank 和 size 这两个参数，代码会变得非常乱。

一句话总结文中观点： 这是一个单例模式的实现，用来在程序的任何地方安全地存储和获取当前进程的分布式身份信息（我是几号，共有几人）。
