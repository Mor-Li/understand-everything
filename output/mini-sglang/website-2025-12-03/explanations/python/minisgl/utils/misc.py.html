[Task 1] 搞定数学小工具

这三个函数都是做整数除法的，但在深度学习（比如计算Tensor维度）时，我们对“除不尽”的情况有不同的处理需求。

  1. divide_down(a, b)

    • 意思：向下取整除法。
    • 代码：a // b
    • 人话：这就是 Python 默认的整数除法。
    • 例子：10 / 3 = 3.33... -> 结果是 3。

  2. divide_up(a, b)

    • 意思：向上取整除法（Ceiling Division）。
    • 代码：(a + b - 1) // b
    • 人话：只要有余数，结果就 +1。这是一个经典的数学技巧，用来避免使用浮点数函数 math.ceil。
    • 例子：
      • 10 / 3 = 3.33... -> 结果是 4。
      • 9 / 3 = 3 -> 结果是 3。

  3. divide_even(a, b)

    • 意思：整除检查。
    • 代码：assert a % b == 0 ... return a // b
    • 人话：如果除不尽，直接报错（Assert Error）。如果能除尽，才返回结果。
    • 场景：比如把一个 1024 维的向量分成 4 个头，必须能整除，否则程序就有 Bug，需要立刻报错停止。

[Task 2] 搞定神秘占位符

代码片段：

class Unset:
    pass
UNSET = Unset()
  • 这是什么？ 这叫 Sentinel Object（哨兵对象）。
  • 为什么不用 None？
    • 在 Python 里，有时候 None 是一个有效的输入值。
    • 比如函数 def func(value=None):，你无法区分用户是没传参数（使用了默认值 None），还是用户故意传了一个 None。
  • 怎么用？
    • 你可以写 def func(value=UNSET):。
    • 如果 value is UNSET，说明用户啥都没传。
    • 如果 value is None，说明用户故意传了 None。
    • 这在配置系统里非常常见。

[Task 3] 搞定最难的装饰器 (call_if_main)

这是全篇最难懂的部分。它的作用是：控制一个函数是否在脚本运行时立即执行。

通常我们写 Python 脚本会有这种写法：

if __name__ == "__main__":
    main()

这个装饰器就是为了简化这种写法，或者做更复杂的控制。

让我们拆解它的逻辑：

参数解释： * name: 传入当前模块的名字（通常是自动传入 __name__）。 * discard: 决定执行完后，这个函数名是否还保留（还是变成 None）。

逻辑流程（一步步看）：

情况 A：文件被当作模块导入 (Imported) * 此时 name 不等于 "__main__"。 * 通常我们不希望函数自动运行。 * 代码逻辑： * 如果不 discard（默认）：返回 lambda f: f。意思是：啥也不干，函数定义了就定义了，静静地待在那里。 * 如果 discard：返回 lambda _: None。意思是：把这个函数定义直接扔掉，外界看不见这个函数。

情况 B：文件作为主程序运行 (Run as script) * 此时 name 等于 "__main__"。 * 我们希望函数立即运行。 * 代码逻辑： * return lambda f: (f() and None) or f (如果不丢弃) * 人话：这行代码利用了短路逻辑。它会立即执行 f()。然后保留函数 f 以便后续可能还要用。 * return lambda f: (f() or True) and None (如果丢弃) * 人话：立即执行 f()，然后返回 None。这意味着函数执行完后，在这个脚本里 f 这个名字就变成 None 了（用完即焚）。

总结这个装饰器的用途： 它允许作者写这样的代码：

@call_if_main(__name__)
def my_script():
    print("程序开始运行了！")
    # ... 做一些测试 ...

当你运行 python misc.py 时，my_script 会自动跑起来。 当你 import misc 时，my_script 不会跑，只是作为一个普通函数待命。
