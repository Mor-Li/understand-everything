pyproject.toml

这份文件 pyproject.toml 是现代 Python 项目的核心配置文件。你可以把它想象成这个软件项目的“身份证” + “说明书” + “家规”。

为了让你看懂，我们假设你现在是这个项目（叫 minisgl）的经理，你需要给电脑（或者新来的程序员）下达一系列任务。

我们将这些内容拆解成一个 5步走的 To-Do List：

✅ Task 1: 填写“身份证” (基本信息)

目标：告诉大家我是谁，我几岁了，我主要干嘛的。

对应文件中的 [project] 部分： * Name: 我叫 "minisgl"。 * Version: 我现在的版本是 0.1.0 (还在早期开发阶段)。 * Requires-python: 想运行我？你的 Python 版本必须大于等于 3.10。 * Classifiers: 这里贴了一些标签，告诉别人： * 我是给开发者和科学家用的 (Intended Audience)。 * 我是搞人工智能的 (Artificial Intelligence)。 * 我是个 Alpha 测试版 (Development Status :: 3 - Alpha)。

✅ Task 2: 列出“配料表” (依赖库)

目标：告诉电脑，想运行我，必须先安装哪些第三方库。

对应文件中的 dependencies 部分。通过这些库，我们可以推测出这个项目是搞 AI 大模型推理的： * 核心动力: torch (PyTorch, 深度学习框架), transformers (Hugging Face 模型库)。 * 高性能加速: sgl_kernel, flashinfer-python (这俩通常用于加速大模型计算), accelerate。 * 对外服务: fastapi, uvicorn (说明这个项目可以启动一个 Web 服务 API)。 * 其他: openai (可能兼容 OpenAI 的接口格式)。

✅ Task 3: 告诉安装工“我在哪” (构建与打包)

目标：当别人执行 pip install . 时，告诉工具去哪里找代码。

对应文件中的 [build-system] 和 [tool.setuptools] 部分： * Build-system: 告诉电脑用 setuptools 这个工具来打包我。 * Where: 这一点很关键 -> package-dir = {"" = "python"} 和 where = ["python"]。 * 这意思是：我的源代码并没有直接放在根目录下，而是藏在了一个叫 python 的文件夹里。 * Package-data: 即使是 C++ 写的文件 (.csrc 目录下的)，也要一起打包带走。

✅ Task 4: 立下“开发家规” (代码规范)

目标：为了防止代码写得乱七八糟，强制规定代码风格。如果程序员不遵守，代码检查就会报错。

这里配置了三个严厉的“管家”：

  1. 排版管家 ([tool.black]):

    • 规矩: 一行代码最多 100 个字符 (line-length)。
    • 任务: 自动把代码格式化成漂亮的模样，不用程序员操心空格和换行。

  2. 纠错管家 ([tool.ruff]):

    • 规矩: 这是一个很新的、速度很快的代码检查工具。
    • 任务: 检查有没有未使用的变量、有没有写错的语法 (lint.select)。它被配置为忽略一些太长的行 (E501)，因为上面的 Black 管家会处理。

  3. 类型管家 ([tool.mypy]):

    • 规矩: Python 本来对变量类型不严格，但这个项目要求非常严格。
    • 任务: disallow_untyped_defs = true 意味着每个函数必须写清楚参数是什么类型（比如是整数还是字符串），否则报错。这通常是为了写出更健壮的工程代码。

✅ Task 5: 安排“期末考试” (测试配置)

目标：写完代码必须测试，这里规定了怎么测。

对应文件中的 [tool.pytest.ini_options]： * 考场: 测试题都在 tests 文件夹里。 * 监考规则: * --cov=minisgl: 必须统计“测试覆盖率”，看看有多少行代码被测试到了。 * test_*: 只要文件名或函数名是以 test_ 开头的，都被视为考题。

总结

读完这个文件，你其实已经对 minisgl 这个项目了如指掌了：

这是一个基于 Python 3.10+ 开发的 AI 推理/服务框架，核心代码在 python 文件夹下。它对代码质量要求很高（有严格的 Black/Ruff/Mypy 检查），并且依赖了 PyTorch 和 FlashInfer 等高性能计算库。
