python/minisgl/layers/embedding.py

这段代码涉及 大模型推理（LLM Inference） 中的核心概念：张量并行（Tensor Parallelism, TP）。

简单来说，当模型的词表（Vocabulary）非常大（比如 Llama 3 有 128k 个词），单个 GPU 显存放不下或者计算太慢时，我们需要把这个巨大的“词表矩阵”切成几份，分给不同的 GPU 去处理。

为了让你听懂，我们把这个过程拆解成一个 6步走的 Task List，每一步攻克一个知识点。

✅ Task 1: 理解背景——为什么要切分？

概念： 也就是代码里的 VocabParallelEmbedding。 想象一本超级厚的字典（词表），里面有 10 万个词。 * 单卡模式： 你一个人拿着整本字典查词。 * 多卡模式（TP）： 我们把字典撕成两半。GPU 0 拿前半本（词 ID 0~49999），GPU 1 拿后半本（词 ID 50000~99999）。这就是 Vocab Parallelism（词表并行）。

代码对应： * tp_info.size: 总共有几个人（几张卡）。 * tp_info.rank: 我是第几个人（第几张卡）。

✅ Task 2: 理解切分逻辑——我该管哪一部分？

位置： VocabParallelEmbedding 的 __init__ 方法。

逻辑： 既然大家分工了，每个人得知道自己负责的范围。 1. divide_up(num_embeddings, self.tp_size): 计算每个人分多少个词。 2. start_idx 和 finish_idx: 计算我的负责范围。 * 比如 GPU 0 负责 [0, 50)。 * 比如 GPU 1 负责 [50, 100)。 3. self.weight: 初始化属于我这一小块的权重矩阵。

✅ Task 3: 攻克输入层——如何查词？(Embedding Forward)

位置： VocabParallelEmbedding 的 forward 方法。

场景： 用户输入了一个词 ID，比如是 5。 * GPU 0 (负责 0-49): 它的范围包含 5。它能查到对应的向量（Vector）。 * GPU 1 (负责 50-99): 它的范围不包含 5。它查不到，结果通常是全 0 的向量。

关键操作 all_reduce： 既然 GPU 1 的结果是 0，GPU 0 的结果是正确向量。 代码最后一句 self._comm.all_reduce(y) 的作用是：把所有 GPU 的结果加起来。 * 向量 A (来自GPU0) + 0 (来自GPU1) = 向量 A。 * 这样每张卡最终都拿到了完整的、正确的词向量。

✅ Task 4: 攻克输出层——什么是 LM Head？

位置： ParallelLMHead 类。

概念： Embedding 是把“词 ID”变成“数学向量”。 LM Head (Language Model Head) 是反过来的，它把“数学向量”变回“下一个词的概率”。 它本质上也是一个巨大的矩阵乘法，所以它继承了 VocabParallelEmbedding。

难点：Weight Tying (权重绑定) * 代码里有 tie_word_embeddings。 * 原理： 为了省显存，很多模型（如 Llama, GPT）的输入层（Embedding）和输出层（LM Head）共用同一个大矩阵，只是用法不同。 * 代码逻辑： 如果 tied_embedding 不是空，我就不自己创建权重了，直接借用输入层的权重 (self.tied_embedding)。

✅ Task 5: 攻克输出层的计算——怎么算出概率？

位置： ParallelLMHead 的 forward 方法。

逻辑： 现在手里有一个隐藏层向量 x，想知道它是哪个词。 1. F.linear(x, module.weight, ...): 做矩阵乘法，算出每个词的打分（Logits）。 * GPU 0 算出词 0~49 的分数。 * GPU 1 算出词 50~99 的分数。

关键区别： 输入层我们要的是叠加（因为只有一个词是对的，其他是0），所以用 all_reduce。 输出层我们要的是拼接（因为我们需要知道所有 100 个词的分数，才能算出谁最高），所以代码里用了 all_gather。

✅ Task 6: 最后的拼接——All Gather 的魔法

位置： ParallelLMHead 的 forward 最后几行。

代码解析：

output_tensor = self._comm.all_gather(logits)
  • GPU 0 手里有 [分数0...分数49]。
  • GPU 1 手里有 [分数50...分数99]。
  • all_gather 之后，大家手里都有了 [分数0...分数49, 分数50...分数99]。

形状变换 (Reshape/View)： 代码最后那堆复杂的 view, movedim, reshape 是为了处理所有 GPU 把数据拼在一起后的形状问题，确保最后输出的形状是 [Batch Size, 完整的词表大小]。

📝 总结 Checklist

  1. 初始化：根据 GPU 数量，把大词表切成小块，每张卡只存自己那一块。
  2. Embedding (输入)：每张卡查自己的表，查不到就是 0。最后把大家的结果加起来 (all_reduce)。
  3. LM Head (输出)：每张卡算自己负责的那部分词的分数。最后把大家的分数拼起来 (all_gather)。
  4. Tying：为了省钱（显存），输入和输出经常共用同一套参数。
