python/minisgl/utils/logger.py

这份代码确实包含了很多 Python 的高级用法（比如内部类、闭包、动态属性赋值等），看起来会比较晕。

简单来说，这个文件的作用是 “给 Python 自带的日志系统（logging）穿上一件漂亮且实用的外衣”，专门用于一个叫 minisgl 的项目中。

我们可以把它拆解成一个 7步走的学习清单 (To-Do List)，每一步我们只关注代码中的一小部分功能。

📝 学习任务清单：从零读懂 logger.py

✅ Task 1: 理解核心目标 —— 为什么要写这个文件？

  • 目标：我们不想用简陋的 print()，而是想要一个带有时间戳、颜色、文件名，甚至能区分是哪个进程（PID）的高级打印工具。
  • 对应代码：整个 init_logger 函数就是为了制造出这样一个“高级喇叭”。

✅ Task 2: 设定“门槛” —— 决定什么该听，什么不该听

  • 概念：日志是有级别的（DEBUG < INFO < WARNING < ERROR）。如果设为 INFO，那么 DEBUG 的废话就不显示。
  • 对应代码： python # 如果没指定级别，就去环境变量里找 LOG_LEVEL，找不到就默认 INFO level = level or os.getenv("LOG_LEVEL", "").upper() _LOG_LEVEL = LEVEL_MAP.get(level, logging.INFO)
  • 人话：这是在设过滤网，只放行重要程度够高的消息。

✅ Task 3: 制作“身份证” —— 搞清楚是谁在说话

  • 概念：当程序在后台跑或者多开的时候，我们需要知道这行字是哪个文件、哪个进程打印的。
  • 对应代码： python # 处理文件名后缀 if strip_file: suffix = os.path.basename(suffix) # 处理进程ID (PID) if use_pid: pid = os.getpid() suffix = f"|pid={pid}{suffix}"
  • 人话：这段代码在拼凑字符串，准备把 |main.py|pid=1234 这种标签贴到每一句话后面。

✅ Task 4: 装修门面 —— 给文字上色 (核心难点 1)

  • 概念：黑底白字太难看，我们希望 ERROR 是红色的，INFO 是绿色的。
  • 对应代码：class ColorFormatter(logging.Formatter) 这一大块内部类。
    • COLORS = {...}: 定义了颜色的代码（比如 \033[31m 是红色）。
    • format 方法：这是核心。每当要打印一条日志，都会经过这里。它负责把时间戳、等级、消息内容拼在一起，并加上颜色代码。
  • 人话：这是一个“美工”部门。它拦截了原本朴素的文字，加上了颜色特效和精确的时间（年月日时分秒），然后再发出去。

✅ Task 5: 组装机器 —— 替换系统默认设置

  • 概念：有了“过滤网”（Level）和“美工”（Formatter），现在要把它装进 Python 的 logger 里。
  • 对应代码： python logger = logging.getLogger(name) logger.handlers.clear() # 先清空旧的，防止重复打印 handler = logging.StreamHandler(sys.stdout) # 准备输出到屏幕 handler.setFormatter(ColorFormatter()) #以此格式化 logger.addHandler(handler) # 装上去
  • 人话：这是在组装流水线。把刚才定义的规则应用到当前的 logger 对象上。

✅ Task 6: 并行计算的特殊需求 —— 只有“班长”能说话 (核心难点 2)

  • 概念：minisgl 看起来像是一个涉及多卡并行（TP - Tensor Parallel）的系统。如果有 8 张显卡同时跑，大家一起打印日志会刷屏且混乱。通常我们只希望第 0 号显卡（Rank 0，班长）说话。
  • 对应代码： python def _call_rank0(msg, *args, _which, **kwargs): # ... 获取并行信息 ... if tp_info.is_primary(): # 如果我是主节点（班长） getattr(logger, _which)(msg, *args, **kwargs) # 那我就打印
  • 人话：这是一个过滤器。如果我是普通小兵（Rank 1, 2, 3...），我就闭嘴；只有我是 Rank 0 时，才真正执行打印命令。

✅ Task 7: 动态黑魔法 —— 给对象强行加技能

  • 概念：Python 的 logger 原本只有 .info(), .error()。但作者想要 .info_rank0() 这种方法。
  • 对应代码： python # 这一段是在给 logger 对象动态添加新函数 logger.info_rank0 = partial(_call_rank0, _which="info") logger.warning_rank0 = partial(_call_rank0, _which="warning") # ...
    • if TYPE_CHECKING: 那一段代码其实不会运行，它只是写给代码编辑器（VS Code / PyCharm）看的，为了让编辑器能有自动补全提示。
  • 人话：这是给 logger 动了手术，强行给它植入了几个新技能（info_rank0 等），专门用于多卡训练时只让主卡打印。

总结

这篇代码讲了一个故事：

  1. 我要造一个日志工具。
  2. 它要能根据环境变量决定显示级别。
  3. 它要能显示PID和文件名。
  4. 它要很漂亮（带颜色、特定时间格式）。
  5. 最重要的是，它支持多卡模式，可以配置成“只有主显卡打印日志，其他显卡闭嘴”，防止刷屏。
