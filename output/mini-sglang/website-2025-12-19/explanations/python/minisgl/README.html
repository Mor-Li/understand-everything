python/minisgl

这是一个关于 python/minisgl 目录的高层级导读。

你可以把整个 minisgl 想象成一家精简版的高级餐厅（AI 推理引擎）。这个文件夹就是这家餐厅的总指挥部。

1. 🏠 当前文件夹 (python/minisgl) 主要负责什么？

这里是整个项目的心脏和入口。

  • 它不负责具体的炒菜动作（那是 kernel 和 models 做的事）。
  • 它负责定义规则、管理状态、启动服务以及协调各个部门的工作。
  • 它的核心目标是：让大模型（LLM）跑得起来，而且跑得快、不爆显存。

2. 📄 直接文件是干什么的？

这几个文件就像是指挥部里的几位核心人员：

🛠️ env.py —— 餐厅的“规章制度手册”

  • 角色：配置管理员。
  • 作用：它负责读取环境变量（比如“最大允许多少人同时吃饭”、“显存用多少”）。
  • 通俗理解：它是唯一的真理来源。不管谁想知道系统的设置，都得问它。它还能自动把能在系统里设定的 MINISGL_xxx 变量读进来变成代码能用的数字。

🧠 core.py —— 餐厅的“订单管理系统”

  • 角色：数据结构定义者。
  • 作用：它定义了在系统里流转的数据长什么样。
    • Req (Request)：一张具体的顾客点单（记录了顾客问了什么，已经生成了什么）。
    • Batch：一批订单（为了效率，厨师一次炒一锅，这就是那一锅）。
    • Context：当前的厨房环境（显存用在哪里，页表怎么查）。
  • 通俗理解：这是整个引擎的通用语言。调度员、厨师、服务员之间沟通，都用这里定义的数据格式。

🚪 __main__.py —— 餐厅的“正门”

  • 角色：标准启动入口。
  • 作用：当你运行 python -m minisgl 时，就是走的这个门。
  • 通俗理解：它会直接启动后台服务（Server），准备好接待网络请求，但不带聊天界面。

🖥️ shell.py —— 餐厅的“调试/体验窗口”

  • 角色：带交互界面的启动器。
  • 作用：它也会启动服务，但同时会打开一个命令行对话框。
  • 通俗理解：这是给开发者用的。既把机器开起来，又直接给你个麦克风，让你能立刻跟 AI 聊两句，测试一下好不好用。

3. 📁 子文件夹的作用（部门分工）

如果说上面的是指挥官，下面的文件夹就是具体的干活部门：

  • 🏗️ 模型构建部 (models/, layers/, llm/)：
    • 负责存放 Llama、Qwen 等模型的图纸，以及搭建神经网络的砖块（层）。告诉机器“大脑”长什么样。
  • ⚡ 核心动力部 (kernel/, attention/)：
    • 这是机房重地。里面写满了底层的加速代码（CUDA/Triton），负责最繁重的数学计算，确保算得飞快。
  • 👮 调度与后勤部 (scheduler/, kvcache/)：
    • Scheduler：像领位员，决定哪个请求先处理，哪个后处理。
    • KVCache：像仓库管理员，管理显存（内存），通过精细的显存分页技术（RadixCache），保证不浪费一点空间。
  • 📡 对外联络部 (server/, message/, tokenizer/, distributed/)：
    • 负责把人类的语言变成机器懂的数字（Tokenizer），处理网络请求（Server），以及多张显卡之间的通信（Distributed）。
  • 🧪 辅助工具部 (benchmark/, utils/)：
    • 用来测速、打日志、提供杂项支持。

🚀 4. 高层认知总结

MiniSGL 是什么？ 它是一个麻雀虽小五脏俱全的 LLM 推理系统。它模仿了 vLLM/SGLang 等业界顶尖引擎的架构，但代码更精简，适合学习和改写。

这个目录的逻辑流： 1. env.py 设定规则。 2. __main__.py 或 shell.py 启动机器。 3. 用户请求进来，被封装成 core.py 定义的 Req。 4. 调度器 (scheduler) 把 Req 打包成 Batch。 5. 模型 (models) 调用底层核心 (kernel) 进行计算。 6. 结果返回给用户。
