python/minisgl/distributed/info.py

没问题，这段代码看起来很抽象，但它的核心逻辑其实非常简单。它是在为多显卡（或多进程）并行计算做一个“身份登记”系统。

你可以把这段代码想象成是在管理一个施工队，每个工人都需要知道两个信息： 1. 我是几号工人？ (Rank) 2. 我们队一共几个人？ (Size)

为了帮你彻底理解，我制定了一个 5步走的 Task List，我们一步步来拆解：

✅ Task 1: 理解核心概念 —— "Rank" 和 "Size"

在分布式计算（比如用 4 张显卡跑大模型）中，每一张显卡（或进程）都需要有个编号。

  • rank (排名/编号): 当前显卡的 ID。从 0 开始。
    • 如果你有 4 张卡，编号就是 0, 1, 2, 3。
  • size (大小/总数): 一共有多少张卡。
    • 上面那个例子，size 就是 4。

代码对应部分：

@dataclass(frozen=True)
class DistributedInfo:
    rank: int  # 我是几号
    size: int  # 咱们一共几个人

注：@dataclass(frozen=True) 意思就是这个“工牌”一旦发给你，上面的字就不能改了（只读）。

✅ Task 2: 理解“自我检查”与“我是不是队长”

拿到工牌后，代码里做了两个小动作。

  1. 检查数据对不对 (__post_init__):
    • 逻辑：如果一共 4 个人，我的编号不可能是 5，也不能是 -1。
    • 代码：assert 0 <= self.rank < self.size (编号必须在 0 到 总数-1 之间)。
  2. 我是不是队长 (is_primary):
    • 逻辑：通常规定 0 号是队长，负责打印日志或者保存模型。
    • 代码：return self.rank == 0。

✅ Task 3: 理解“全局变量” —— 只有一块黑板

这个文件最关键的地方在于它定义了一个全局变量。

代码对应部分：

_TP_INFO: DistributedInfo | None = None
  • TP 通常指 Tensor Parallel (张量并行)。
  • 这行代码的意思是：我在办公室墙上挂了一块黑板（_TP_INFO）。
  • 刚开始，黑板是空的 (None)。

为什么要用全局变量？ 因为在这个项目中，任何一个角落的代码可能都需要随时知道“我是几号显卡”。如果不弄个全局变量，你就得把 rank 这个参数在几百个函数之间传以此来，非常麻烦。

✅ Task 4: 理解“写入”操作 —— 只能写一次

现在我们要往黑板上写字了。

代码对应部分：

def set_tp_info(rank: int, size: int) -> None:
    global _TP_INFO
    # 如果黑板上已经有字了，报错！不能重复登记！
    if _TP_INFO is not None:
        raise RuntimeError("TP info has been set")
    # 把 Rank 和 Size 写到黑板上
    _TP_INFO = DistributedInfo(rank, size)
  • 规则：这个函数在程序启动时只能调用一次。就好比你出生只有一次，不能重新出生。

✅ Task 5: 理解“读取”操作 —— 两种读法

其他代码想看黑板上的字，有两种方法：

方法 A：必须读到 (get_tp_info)

def get_tp_info() -> DistributedInfo:
    # 如果黑板是空的，说明程序还没初始化好，直接报错崩溃
    if _TP_INFO is None:
        raise RuntimeError("TP info has not been set")
    return _TP_INFO
  • 场景：正在进行核心计算时，必须知道我是谁。如果不知道，程序没法跑。

方法 B：尝试读一下 (try_get_tp_info)

def try_get_tp_info() -> DistributedInfo | None:
    # 直接把黑板给你，哪怕是空的也没关系
    return _TP_INFO
  • 场景：比如打印日志的时候，我想看看有没有设置并行信息。如果有就打印出来，没有就算了，不要报错。

📝 总结 (Summary)

把这 5 个 Task 串起来，这个文件的完整故事是：

  1. 定义了一张“工牌” (DistributedInfo)，上面写着编号和总人数。
  2. 准备了一个“全局存放处” (_TP_INFO)，一开始是空的。
  3. 提供了“发工牌”的函数 (set_tp_info)，程序启动时调用，且只能调用一次。
  4. 提供了“查工牌”的函数 (get_tp_info)，供程序的其他部分随时调用，以确定自己在分布式系统中的位置。

一句话概括： 这是一个全局单例（Global Singleton）模式的实现，用来存储和获取当前进程的分布式并行配置信息（我是几号，一共几个）。
