src/llamafactory/launcher.py

这段代码看起来很长，涉及很多环境变量和子进程操作，初看确实容易晕。

为了让你更容易理解，我们可以把这个 launcher.py 文件想象成一家大公司的 “前台接待处” (Receptionist)。它的核心工作不是“干活”（具体的训练或聊天），而是 “分流”。

我们可以把它的工作流程拆解为一个 Task To-Do List。当你在终端输入 llamafactory-cli xxx 时，这个脚本就会按顺序执行以下任务：

📋 任务清单：LlamaFactory 启动流程

Task 1: 准备工作 (Setup)

  • 动作：加载必要的工具包（日志、环境变量读取工具）。
  • 目的：确保前台有笔有纸，能记录东西。
  • 代码对应：launch() 函数开头的那几行 import。

Task 2: 接单——用户到底想干啥？ (Parse Command)

  • 动作：查看用户输入的第一个关键词。
  • 细节：
    • 如果你输入 llamafactory-cli train，它就记下指令是 train。
    • 如果你输入 llamafactory-cli webui，它就记下指令是 webui。
    • 如果你啥都没输，它默认指令是 help。
  • 代码对应：command = sys.argv.pop(1) ...

Task 3: 【关键分支】判断是否需要“多卡分布式训练” (Check Distributed Training)

  • 场景：这是代码里最长、最复杂的一段（第 60 行到 137 行）。
  • 逻辑：
    • 如果指令是 train 且 (被强制要求用 torchrun 或 你的电脑有多张显卡)：
      • 判定：这是个大工程，单靠一个普通进程搞不定，需要动用 torchrun（PyTorch 的分布式启动器）。
    • 执行步骤：
      1. 查户口：获取显卡数量、节点信息、主节点 IP 和端口。
      2. 设置环境：配置一些优化参数（如 PYTORCH_CUDA_ALLOC_CONF）。
      3. 摇人（启动子进程）：它会构建一个长长的命令字符串 torchrun --nnodes ... --nproc_per_node ...。
      4. 外包：使用 subprocess.run 执行这个 torchrun 命令。
      5. 注意：一旦进入这个分支，当前脚本就变成了“监工”，真正的训练任务交给了 torchrun 去跑。跑完后直接退出程序。
  • 代码对应：if command == "train" and ... 这一大块。

Task 4: 任务分发 (Dispatching)

  • 场景：如果不需要分布式训练（比如只是单卡训练，或者只是开个网页界面），代码就会往下走，进入一连串的 elif 判断。

  • 逻辑：根据 Task 2 拿到的指令，把任务指派给具体的部门（模块）。

    • Sub-task 4.1: API 服务

      • 指令：api
      • 动作：导入 api.app 模块，运行 run_api()。

    • Sub-task 4.2: 命令行聊天

      • 指令：chat
      • 动作：导入 chat.chat_model 模块，运行 run_chat()。

    • Sub-task 4.3: 模型导出

      • 指令：export
      • 动作：导入 train.tuner 模块，运行 export_model()。

    • Sub-task 4.4: 普通训练

      • 指令：train (但没触发 Task 3 的分布式条件，或者是被 torchrun 唤起的子进程)
      • 动作：导入 train.tuner 模块，运行 run_exp()。这是核心训练入口。

    • Sub-task 4.5: 网页界面

      • 指令：webui
      • 动作：导入 webui.interface 模块，运行 run_web_ui()。

Task 5: 兜底处理 (Fallback)

  • 动作：如果用户的指令看不懂（比如输了 llamafactory-cli blabla），或者输了 version/help。
  • 结果：打印版本号、欢迎语或者帮助文档（就是代码最上面的那个 USAGE 字符串）。

💡 总结一下

这个文件的作用就是 “路由” (Router)：

  1. 简单任务（WebUI、API、单卡训练）：直接 import 对应函数并运行。
  2. 复杂任务（多卡训练）：它会自动帮你拼凑出一长串 torchrun 命令并替你执行，省得你自己去手打那些复杂的参数（比如 master_addr, nproc_per_node 等）。

你只需要关注： 你在命令行敲下命令后，这个脚本会帮你决定是直接跑，还是帮你叫一群“显卡兄弟”（分布式）一起跑。
