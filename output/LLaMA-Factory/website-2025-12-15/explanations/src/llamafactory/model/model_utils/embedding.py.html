src/llamafactory/model/model_utils/embedding.py

这份代码的核心作用只有一个：给大模型“扩容”，并给新加入的词（Token）赋予一个合理的初始状态。

想象一下，你有一本字典（模型），现在你要往里面加几个新词（比如 <think> 这种特殊符号）。你不能只加个空白页，你得在页面上先随便写点什么，或者根据含义写点什么，这样模型在后续学习时上手更快。

下面我按照你的要求，分为 核心任务清单 (Todo List) 和 逐步讲解 两部分。

📋 核心任务清单 (Task Todo List)

如果要把“给模型加新词”这件事变成一个工作流，代码里的逻辑是这样的：

  1. 检查现状：看看分词器（Tokenizer）里的词是不是比模型（Model）里的词多？（如果多，说明需要扩容）。
  2. 准备环境：因为大模型可能跑在多张显卡上（DeepSpeed Zero3），先把分散的参数“聚拢”起来，方便修改。
  3. 物理扩容：把模型的“词向量表”（Embedding Matrix）的行数增加，腾出位置给新词。
  4. 决定策略：怎么填补这些新位置？
    • 策略 A（简单粗暴）：算一下老词的平均值，加点随机噪音填进去。
    • 策略 B（更有文化）：根据新词的“文字描述”来填。比如新词是 <think>，描述是 "reasoning"，那就拿 "reasoning" 的向量填进去。
  5. 执行填充：按照选定的策略，把数值填入新腾出的位置。
  6. 收尾：更新模型的配置参数，告诉它“你现在词表变大了”。

🧐 逐步讲解 (Step-by-Step)

我们把代码拆解开，对应上面的任务清单，一步步看它是怎么实现的。

第一步：总指挥 —— resize_embedding_layer

这是代码的入口函数（最下面那个）。

  • 它的任务：协调整个扩容过程。
  • 关键逻辑：
    1. 多卡同步：if is_deepspeed_zero3_enabled(): ...
      • 这部分是为了处理多显卡训练的复杂情况。简单理解就是：先把分散在各张卡上的权重拿回来，改成单机模式修改，改完再放回去。
    2. 判断是否需要扩容： python if len(tokenizer) > current_embedding_size:
      • 如果分词器里的词（比如 32005 个）比模型权重的行数（比如 32000 行）多，说明多了 5 个新词，需要干活了。
    3. 物理扩容： python model.resize_token_embeddings(len(tokenizer), pad_to_multiple_of=64)
      • 这是 PyTorch/Transformers 自带的方法，直接把矩阵拉长。
    4. 调用初始化逻辑：
      • 扩容后，新多出来的几行全是随机数（或者0）。这时候它调用了 _initialize_embeddings 去给这些新行填值。

第二步：分发员 —— _initialize_embeddings

这个函数是一个“路由”，它根据你配置的方法，决定用哪种方式填值。

  • 它的任务：看配置，选算法。
  • 逻辑：
    • 如果你选了 desc_init (描述初始化) 且提供了描述：调用 _description_based_initialization。
    • 否则（或者默认情况）：调用 _noisy_mean_initialization。

第三步：执行者 A (简单版) —— _noisy_mean_initialization

这是默认的初始化方法。

  • 理念：新来的词，我不知道它是啥意思。但我知道它大概率和“以前所有的词的平均水平”差不多。为了不让它太死板，我再加一点点随机波动（噪音）。
  • 代码解读：
    1. avg_weight = ...mean(...): 算出老词向量的平均值。
    2. noise_weight.normal_(...): 生成符合高斯分布的噪音。
    3. embed_weight[-num_new_tokens:] = avg_weight + noise_weight:
      • 新词向量 = 平均值 + 噪音。

第三步：执行者 B (进阶版) —— _description_based_initialization

这是一个更聪明的初始化方法。

  • 理念：如果新加的词是 <|image|>，与其瞎猜，不如告诉我它的含义是 "picture"。我就去模型里找 "picture" 的向量，拿来作为 <|image|> 的初始值。这样模型一开始就大概知道这个新词是干嘛的。
  • 代码解读：
    1. 拿到描述：比如 descriptions = {"<think>": "reasoning process"}。
    2. 理解描述：把 "reasoning process" 扔给分词器，变成 ID。
    3. 获取基准： python token_embeds = model.get_input_embeddings()(valid_token_ids) base_embedding = token_embeds.mean(dim=0)
      • 去模型现有的词表里，查出 "reasoning" 和 "process" 的向量，取平均值。
    4. 填入：把这个算出来的向量，填给新词 <think>。
    5. 可选：也可以像上面那样，加一点点噪音 (add_noise=True)。

总结

这个文件的作用就是：当你在微调模型想加入新 Token 时，它负责把模型的“脑容量”扩充一下，并且用一种科学的方法（而不是瞎填）给这些新 Token 赋初值，让模型训练起来更稳定、收敛更快。
