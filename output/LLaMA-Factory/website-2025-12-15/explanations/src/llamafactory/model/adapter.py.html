src/llamafactory/model/adapter.py

这份代码文件 src/llamafactory/model/adapter.py 的核心作用是：给大模型“穿装备”或“做手术”，以便让它准备好进行训练（微调）。

它就像一个总调度员，根据你设定的微调方式（全量微调、冻结微调、还是LoRA微调），来调整模型的参数状态。

为了让你看懂，我把它拆解成一个程序执行的 TODO List（任务清单）。想象一下，当程序运行到这个文件时，它实际上是在按顺序执行以下任务：

🟢 主任务清单：init_adapter (总入口)

当代码调用 init_adapter 函数时，它主要做三件事：

  1. [检查] 兼容性检查

    • Task: 检查模型是否被“量化”（压缩）过。
    • 逻辑: 如果模型是量化的（比如4bit/8bit），那你只能用 LoRA 或 OFT 微调。想做全量微调？直接报错，因为量化模型不支持全量训练。

  2. [决策] 决定精度（数据类型）

    • Task: 决定是否要把那些需要训练的参数强制转成 float32（高精度）。
    • 逻辑:
      • 如果是纯 bf16 训练或者是 BAdam 优化器 -> 不转（保持半精度，省显存）。
      • 如果用了 DeepSpeed ZeRO3 -> 不转（ZeRO3 会自己处理）。
      • 其他情况（比如 QLoRA） -> 转成 float32（为了保证数值稳定性，防止训练飞了）。

  3. [分发] 选择微调流派

    • Task: 根据你的配置 finetuning_type，把模型送到不同的“车间”去处理。
    • 分支:
      • 是 full (全量)？ -> 执行 任务 A (_setup_full_tuning)
      • 是 freeze (冻结)？ -> 执行 任务 B (_setup_freeze_tuning)
      • 是 lora 或 oft？ -> 执行 任务 C (_setup_lora_tuning) (最常用，代码最长)

🟠 支线任务 A：全量微调 (_setup_full_tuning)

如果选择了全量微调，程序做这些事：

  1. [设置] 打印日志：“Fine-tuning method: Full”。
  2. [筛选] 找出所有参数。
  3. [执行]
    • 如果是“被禁止”的模块（比如某些特殊的层）：锁住（不训练）。
    • 如果是普通参数：解锁（设为可训练），并根据主任务中的决定，可能将其转为 float32。

🟠 支线任务 B：冻结微调 (_setup_freeze_tuning)

如果选择了冻结微调（只练最后几层，或者特定层），程序做这些事：

  1. [计算] 算出模型一共有多少层。
  2. [筛选] 根据你的配置（比如 freeze_trainable_layers），计算出具体哪几层需要训练（例如：只练最后3层）。
  3. [处理] 处理一些特殊的模块（比如 Vision Transformer 的投影层），决定是否要加入训练列表。
  4. [执行] 遍历模型所有参数：
    • 如果在“训练名单”里 -> 解锁。
    • 不在名单里 -> 锁住（Freeze）。

🟠 支线任务 C：LoRA/OFT 微调 (_setup_lora_tuning)

这是最复杂的部分，也是代码最长的地方。它的逻辑如下：

  1. [加载] 处理旧的 Adapter (如果有)

    • Task: 检查你是不是想在已有的 LoRA 基础上继续练，或者合并多个 LoRA。
    • 逻辑: 如果有 adapter_name_or_path，就把这些旧的“外挂”加载进来。如果是为了合并，就用 merge_and_unload 把它们融合进主模型。

  2. [新建] 准备新的 Adapter (如果是训练模式)

    • Task 2.1: 找靶子 (Target Modules)

      • LoRA 需要挂载在具体的层上（比如 q_proj, v_proj）。程序会去寻找这些层。
      • 如果是 all，它会自动扫描所有线性层。
      • 如果用了 KTransformers（一种推理加速库），它会调整层名称以匹配。

    • Task 2.2: 扩充词表检查

      • 如果你扩充了词表（加了新词），程序会自动把 embed_tokens (词向量层) 和 lm_head (输出层) 加入训练目标，否则新词学不到东西。

    • Task 2.3: 配置参数

      • 设置 LoRA 的 rank (秩), alpha, dropout 等参数。
      • 如果是 DoRA 或 OFT，做相应的特殊配置。

    • Task 2.4: 挂载 (Get PEFT Model)

      • 核心动作: 调用 peft 库或者 unsloth / ktransformers 库，把 LoRA 模块“插”到模型里。
      • 特殊处理:
        • 如果是 Unsloth (加速训练库)：调用 get_unsloth_peft_model。
        • 如果是 KTransformers：调用 get_kt_peft_model。
        • 如果是 PiSSA (一种特殊的初始化)：使用 PiSSA 算法初始化权重。
        • 普通情况: 调用标准的 get_peft_model。

  3. [收尾] 再次确认精度

    • 最后再检查一遍，把所有需要训练的参数（LoRA A/B 矩阵等）确保转成了 float32（如果之前要求了的话）。

总结

这篇代码其实就是一个精细化的“开关管理器”：

  1. Full Tuning: 打开所有开关。
  2. Freeze Tuning: 关掉大部分开关，只开最后几个。
  3. LoRA Tuning:
    • 保持原模型开关全关。
    • 在旁边外接一个小电路（Adapter）。
    • 只打开这个小电路的开关。
    • 还要负责处理这个小电路的安装、旧电路的合并以及兼容各种加速插件（Unsloth/DeepSpeed）。
