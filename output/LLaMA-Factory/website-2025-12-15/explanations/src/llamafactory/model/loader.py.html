src/llamafactory/model/loader.py

这份代码文件 src/llamafactory/model/loader.py 是 LlamaFactory 框架中非常核心的一个“后勤总管”。

它的主要职责是：根据用户的配置，把模型（Model）、分词器（Tokenizer）和配置（Config）从硬盘或网络上加载到内存中，并组装成一个可以开始训练或推理的成品。

为了让你听懂，我把这个过程想象成“组装一台赛车”。我们列一个 Task To-Do List，然后一步步对应代码里的操作。

📋 组装模型的 To-Do List

  1. 准备通行证：准备下载模型所需的身份验证和路径信息。
  2. 招聘翻译官（Load Tokenizer）：加载分词器，负责把人类语言变成机器能懂的数字。
  3. 阅读图纸（Load Config）：读取模型的配置文件，看看我们要造什么车。
  4. 根据图纸修改设计：在造车前，根据需求微调图纸（比如扩大油箱/上下文长度）。
  5. 核心引擎组装（Load Model）：
    • 分支 A：如果是特殊引擎（Unsloth/KTransformers），走快速通道加载。
    • 分支 B：如果是普通引擎，去仓库搬运（HuggingFace AutoModel）。
    • 分支 C：如果是多模态（看图/听声音），加载对应的特殊组件。
  6. 引擎改装（Patch Model）：对加载好的引擎做针对性修复或调整。
  7. 加装外挂（Init Adapter）：这是微调的关键，给模型挂上 LoRA 适配器。
  8. 加装裁判（Value Head - 可选）：如果是做 RLHF（强化学习），需要加装一个打分器。
  9. 最终质检：冻结不需要训练的部件，打印参数量，准备由“训练师”接管。

逐步讲解代码逻辑

1. 准备通行证 (_get_init_kwargs)

在代码开头有个小函数 _get_init_kwargs。 * 动作：它把用户的 model_args（模型参数）转化成 HuggingFace 库能识别的字典。 * 目的：比如 trust_remote_code=True（允许运行远程代码），token（HuggingFace 的密码），cache_dir（模型下载存哪）。这相当于进仓库前的安检。

2. 招聘翻译官 (load_tokenizer)

  • 代码位置：def load_tokenizer(...)
  • 动作：
    • 尝试用 AutoTokenizer.from_pretrained 加载分词器。
    • 这里有个 try...except：它先试着加载“快速分词器”（Fast Tokenizer），如果失败了，就退而求其次加载“慢速分词器”。
    • patch_tokenizer：给分词器打补丁（比如有些模型没定义 padding token，这里会强制加上）。
    • 多模态支持：如果模型不仅读文字，还看图（如 LLaVA），它还会加载 AutoProcessor。

3. & 4. 阅读并修改图纸 (load_config)

  • 代码位置：def load_config(...) 和 load_model 的前几行。
  • 动作：
    • AutoConfig.from_pretrained：把模型的 config.json 读进来。
    • patch_config：关键步骤。比如你想把 Llama-3 的上下文窗口从 8k 扩展到 32k，或者改变 RoPE 的缩放比例，都是在这里修改配置对象的。
    • apply_liger_kernel：如果开启了 Liger Kernel（一种加速优化的内核），在这里修改配置以适配。

5. 核心引擎组装 (load_model 的核心部分)

这是最复杂的函数 def load_model(...)，它决定了模型怎么被加载进显存。

  • 特殊通道（加速库）：

    • if model_args.use_kt: 如果你用了 KTransformers，走这条路。
    • elif model_args.use_unsloth: 如果你用了 Unsloth（一个非常流行的微调加速库），走这条路。它会直接加载优化过的模型，省显存又快。

  • 标准通道（HuggingFace）：

    • 如果没用加速库，代码会根据配置判断模型类型：
      • AutoModelForCausalLM：最常见的文本生成模型（如 Llama, Qwen）。
      • AutoModelForVision2Seq：视觉语言模型。
      • AutoModelForSeq2SeqLM：翻译模型（如 T5）。
    • 从头训练 vs 预训练：
      • train_from_scratch: 如果是 True，只用配置创建一个空壳模型（随机初始化权重）。
      • 否则，从硬盘/网络加载真实的权重文件（.safetensors 或 .bin）。

6. 引擎改装 (patch_model)

  • 动作：模型加载完后，可能还不够完美。
  • patch_model(model, ...)：这里会处理一些特定模型的 bug 或者需求。比如：
    • 确保 Embedding 层的大小和分词器大小一致。
    • 设置正确的梯度检查点（Gradient Checkpointing）以节省显存。

7. 加装外挂 (init_adapter)

  • 这是微调的核心！
  • 动作：调用 init_adapter。
  • 解释：如果你做的是 LoRA 或 QLoRA 微调，原本的大模型会被冻结，代码会在这里往模型里插入小型的“适配器（Adapter）”模块。之后的训练只更新这些小模块。

8. 加装裁判 (add_valuehead)

  • 场景：如果你在做 RLHF（PPO 算法），模型不仅要生成文本，还需要一个“价值头（Value Head）”来给生成的文本打分。
  • 动作：
    • AutoModelForCausalLMWithValueHead.from_pretrained(model)：把刚才的模型包装一下，多加一个输出层用来打分。
    • 加载 Value Head 的权重（如果有的话）。

9. 最终质检 (函数末尾)

  • 冻结权重：
    • if not is_trainable: 如果你只是来做推理（聊天）的，把模型设为 eval() 模式，并把所有参数锁住不让更新。
    • 如果是训练模式，确保数据类型（dtype）正确（比如 float16 或 bfloat16）。
  • 打印报表：
    • count_parameters(model)：计算一下参数量。
    • logger.info(...)：并在屏幕上告诉你：“所有参数 xx 亿，其中可训练参数 xx 万”（让你确认 LoRA 只有很少的参数是可训练的）。

总结

这个文件的作用就是“承上启下”： * 上接用户的命令行参数（我要跑什么模型，用什么微调方法）。 * 下接 PyTorch 的训练循环（给训练器一个准备好的 model 对象）。

你看不懂是因为它把所有可能的加载情况（Unsloth, 多模态, RLHF, 全量微调, LoRA）都写在了一个函数里。但只要按着“加载配置 -> 加载底座 -> 加载适配器 -> 准备开跑”这个逻辑看，就清晰多了。
