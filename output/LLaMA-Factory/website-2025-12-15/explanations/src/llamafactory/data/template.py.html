src/llamafactory/data/template.py

这份代码文件 src/llamafactory/data/template.py 是 LlamaFactory 项目中非常核心的一个文件，它的作用可以概括为一句话：给大模型“立规矩”，告诉模型每一句话是谁说的，以及这句话哪里开始、哪里结束。

因为不同的模型（比如 Llama3、Qwen、DeepSeek）在训练时，要求的对话格式（Prompt Template）是不一样的。这个文件就是把这些乱七八糟的格式统一管理起来。

为了让你看懂，我列了一个 “学习任务清单 (To-Do List)”，我们一步步拆解：

✅ Task 1: 理解背景——为什么需要“模版” (Template)？

首先你要明白，大模型本质上是一个“文字接龙”机器。如果你直接把对话发给它，它分不清哪句是你说的，哪句是它说的。

  • 例子：
    • 人类：你好
    • AI：你好，有什么我可以帮你？
  • 给模型看的数据（Raw Text）：
    • 如果不加标记，模型看到的是 你好你好，有什么我可以帮你？（它晕了）。
    • 所以不同的厂商发明了不同的标记。
    • Llama 3 说： 我要这样 <|start_header_id|>user<|end_header_id|>你好<|eot_id|>
    • Qwen (通义千问) 说： 我要这样 <|im_start|>user\n你好<|im_end|>

结论： 这个文件的作用就是翻译官。它把标准的对话列表（[{role: user, content: "你好"}]）翻译成模型能听懂的特殊字符串。

✅ Task 2: 拆解核心类 Template (代码第 40-150 行)

代码里定义了一个叫 Template 的类（Class）。你可以把它看作是一个配置单。

请关注 Template 类里的这几个关键属性（字段）：

  1. format_user: 怎么包装“用户”说的话？（比如加前缀 User:）
  2. format_assistant: 怎么包装“AI”说的话？（比如加后缀 <|end_of_text|>）
  3. format_system: 怎么包装“系统提示词”？
  4. stop_words: AI 遇到哪些词必须闭嘴（停止生成）？
  5. encode_oneturn / encode_multiturn: 这是两个最重要的方法。
    • 它们负责把文本变成数字列表（Token IDs）。
    • 因为它会调用 tokenizer 把把你包装好的带特殊符号的文本切分、编码。

通俗理解： Template 类就是一个流水线工人，你给它原料（对话），它根据说明书（格式配置），把原料包装好，最后打包成箱（Token IDs）。

✅ Task 3: 理解特殊的“变种”模版

代码里还有几个继承自 Template 的子类，是为了处理特殊情况：

  1. Llama2Template:
    • 特点：Llama 2 模型比较怪，它喜欢把“系统提示词”合并到“用户的第一句话”里。这个类专门处理这种逻辑。
  2. ReasoningTemplate:
    • 特点：这是给最近很火的“推理模型”（如 DeepSeek-R1）用的。
    • 功能：它支持把模型的思维过程（Chain of Thought）用 <think> 和 </think> 包裹起来，并且可以选择在训练时是否要把这部分思维过程算入损失函数（Loss）。

✅ Task 4: 看看“注册表” (代码底部的 register_template)

从代码第 400 行左右开始，一直到文件结束，你会看到一大堆 register_template(...) 的调用。这部分其实最简单，它是“通讯录”。

它把市面上各种模型的格式都记录下来了。我们随便看一个例子，比如 Llama 3 (代码约 1070 行):

register_template(
    name="llama3",  # 模版名字
    # 用户的格式：<|start_header_id|>user...内容...<|eot_id|>...
    format_user=StringFormatter(
        slots=[
            (
                "<|start_header_id|>user<|end_header_id|>\n\n{{content}}<|eot_id|>"
                "<|start_header_id|>assistant<|end_header_id|>\n\n"
            )
        ]
    ),
    # 助手的格式：内容 + <|eot_id|>
    format_assistant=StringFormatter(slots=["{{content}}<|eot_id|>"]),
    # ... 其他配置
)

怎么看懂这部分： 你只要搜你想用的模型名字（比如 qwen），就能看到 LlamaFactory 是怎么处理它的格式的。如果你训练出来的模型说话总是不对劲（比如不停地重复），通常就是这里的格式配错了。

✅ Task 5: 高级功能扫盲 (Jinja & Ollama)

代码里还夹杂了一些看起来很复杂的函数，比如 _get_jinja_template 和 get_ollama_modelfile。

  1. Jinja Template:
    • HuggingFace 的 tokenizer 支持一种叫 chat_template 的标准（用 Jinja2 语言写的）。
    • 这个文件的代码可以自动生成那个 Jinja 字符串，并塞到 tokenizer 里。这样你训练完模型后，别人直接用 HuggingFace 的库就能推理，不用再手动拼格式了。
  2. Ollama Modelfile:
    • Ollama 是一个本地跑大模型的工具。这个功能是为了方便把你训练好的模型导出给 Ollama 使用，自动生成 Ollama 需要的配置文件。

总结：一步步阅读建议

  1. 不要试图一行行读逻辑，里面的字符串拼接逻辑很枯燥。
  2. 先看 Template 数据类，知道它存了哪些配置（前缀、后缀、停止词）。
  3. 重点看 _encode 方法（在第 130 行左右），这是核心逻辑：
    • 它遍历 messages 列表。
    • 判断是 User 还是 Assistant。
    • 根据角色加上对应的 format。
    • 转成 Token ID。
  4. 最后把它当字典查：当你需要微调某个特定模型（如 DeepSeek）时，去文件底下搜 name="deepseek"，看看它是怎么定义的，这就够了。
