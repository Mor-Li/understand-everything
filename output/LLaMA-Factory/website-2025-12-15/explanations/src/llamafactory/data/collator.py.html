src/llamafactory/data/collator.py

这份代码看起来很复杂，是因为它处理的是多模态大模型（Multimodal LLM）的训练数据，而且还要兼顾各种不同的模型架构（比如 Qwen-VL, Llama 等）和训练方式（SFT, DPO, KTO）。

简单来说，这个文件的作用就是“打包员”。

在训练开始前，你有一堆乱七八糟的数据（有的只有文字，有的有图片，有的长，有的短）。这个脚本的任务就是把这些数据整理成整齐划一的“包裹（Batch）”，塞给显卡（GPU）去计算。

为了让你听懂，我们把这个脚本的工作想象成一个流水线工人的“任务清单 (Todo List)”。

核心任务清单 (Todo List)

我们将代码逻辑拆解为以下 5 个步骤：

  1. 【分拣】：把混在一起的文字、图片、视频、音频分开拿出来。
  2. 【防崩坏（兜底）】：如果模型需要看图，但这一批数据里一张图都没有，为了防止机器报错，必须造一个“假图”塞进去。
  3. 【预处理】：把图片/视频转换成模型能看懂的数字（Tensor），并算出它们占了多少个 Token。
  4. 【对齐与填充】：因为每句话长度不一样，要把短的补齐（Padding），让大家长度一致，才能打包。
  5. 【计算位置信息（最难点）】：对于视觉模型（如 Qwen-VL），图片是二维/三维的，不是简单的线性文字，需要专门计算复杂的“3D 位置坐标”（RoPE index）。

逐步讲解（对应代码）

第一步：基础准备与分拣

代码位置：MultiModalDataCollatorForSeq2Seq 类的 __call__ 方法开头。

  • 工人独白：“老板给了我一堆数据 features，我得先把里面的图片、视频、音频单独拎出来，剩下的就是纯文本 ID。”
  • 代码行为： python # 循环遍历每一条数据 for feature in features: # 把 images, videos, audios 拔出来(pop)，如果没有就是空列表 images = feature.pop("images", None) or [] # ... 把它们存到 batch_images 等列表中 batch_input_ids.append(feature["input_ids"])

第二步：防崩坏（兜底机制）

代码位置：__call__ 方法中间的 fake_input_ids 相关逻辑。

  • 工人独白：“坏了！这一批数据全是纯文字，但我们训练的是多模态模型（比如 Qwen-VL），多卡训练时如果某张卡没收到图片数据，程序会卡死（Hanging）。我得赶紧造一个假数据混进去。”
  • 代码行为：
    • 检查 sum(batch_imglens) == 0（是不是一张图都没有？）。
    • 如果是，创建一个 fake_images（全白色的 64x64 像素小图）。
    • 创建一个 fake_messages（假对话）。
    • 把它加到第一条数据里，强行让这批数据“包含图片”，确保程序跑通。
    • 注：这部分代码看着很乱，其实就是为了修补分布式训练的一个 Bug。

第三步：打包文字与多模态输入

代码位置：super().__call__(features) 和 mm_inputs 部分。

  • 工人独白：“图片视频都拿出来了，现在我要调用工具（mm_plugin）把它们处理好。然后，把文字部分长短不一的句子，用 0 填充（Padding）到一样长。”
  • 代码行为：
    • self.template.mm_plugin.get_mm_inputs(...)：处理多模态输入。
    • super().__call__(features)：调用父类（HuggingFace 的标准功能）把文字 ID 补齐并转成 PyTorch Tensor。

第四步：计算复杂的 3D 位置 (RoPE)

代码位置：if self.get_rope_func is not None: 这一大块。

  • 工人独白：“这是最头疼的。普通的文字是一行写下去的（1D）。但现在的 Qwen2-VL 这种模型，它把图片看作一个立方体（时间 x 高 x 宽）。我必须告诉模型，每个 Token 在这个立方体的哪个坐标。”
  • 代码行为：
    • 判断模型是不是 qwen2_vl 或类似架构。
    • 准备参数 image_grid_thw（图片的时间、高、宽网格）。
    • 调用 self.get_rope_func 计算 position_ids（位置 ID）和 rope_deltas。
    • 目的：让模型理解“这张图的这个像素，是在左上角”这种空间关系。

不同的“工种” (子类解释)

代码后面定义了几个继承自 MultiModalDataCollatorForSeq2Seq 的子类，它们是针对不同任务的“特种工人”。

1. SFTDataCollatorWith4DAttentionMask

  • 任务：SFT（有监督微调）。
  • 特点：它多干了一件事——prepare_4d_attention_mask。
  • 解释：为了提高训练效率，有时会把多条短数据拼成一条长的（Packing）。这时候需要一个复杂的 4D 掩码（Mask），告诉模型：“虽然你们拼在一起了，但前一句话不能看后一句话，大家各论各的。”

2. PairwiseDataCollatorWithPadding

  • 任务：偏好对齐（DPO / RLHF）。
  • 特点：它处理的数据是成对的——“好的回答 (Chosen)” vs “坏的回答 (Rejected)”。
  • 解释：
    • 输入：一条数据里包含 chosen_input_ids 和 rejected_input_ids。
    • 操作：它把这两部分拆开，变成两条独立的数据，拼成一个 2倍大小的 Batch。
    • 目的：让模型学习“选这个，别选那个”。

3. KTODataCollatorWithPadding

  • 任务：KTO 对齐（另一种不需要成对数据的对齐算法）。
  • 特点：处理 target（目标数据）和 kl（参考数据）。
  • 解释：它会把数据整理成 KTO 算法需要的格式，包括一个布尔标签 kto_tags（告诉模型这句话是好是坏）。

总结

这个文件 collator.py 就是一个超级数据整理箱。

  1. 输入：一堆原始的、长短不一的、带图带字的 Python 字典。
  2. 处理：
    • 把图/视频转成数字。
    • 如果没有图，造假图防报错。
    • 把文字补齐长度。
    • 给 Qwen-VL 这种高级模型计算 3D 坐标。
    • 根据是 SFT 还是 DPO，把数据排成特殊的队列。
  3. 输出：整齐的 PyTorch Tensor，直接喂给 GPU 训练。

你看不懂是因为它把数据清洗、分布式训练的坑、特定模型的数学逻辑全部揉在一起了。只要记住它的核心目的是“把数据格式化成模型能吃的样子”即可。
