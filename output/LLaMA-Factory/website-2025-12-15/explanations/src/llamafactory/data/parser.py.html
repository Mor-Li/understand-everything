src/llamafactory/data/parser.py

这份代码 parser.py 的核心作用是“翻译”和“标准化”。

在训练大模型时，你可能会用到几十种不同的数据集。有的在 HuggingFace 上，有的在本地硬盘；有的列名叫 question/answer，有的叫 instruction/output。

LlamaFactory 不能直接读懂所有乱七八糟的格式，所以需要这个文件把它们统一成一种标准格式。

我们可以把这个过程想象成“给数据集办身份证”。下面是一个Task Todo List，带你一步步看懂代码在干什么：

Task 1: 定义“身份证”的模板 (Class DatasetAttr)

首先，我们需要规定一张“数据集身份证”上必须包含哪些信息。这就是代码开头 class DatasetAttr 做的事。

  • Todo: 创建一个数据结构，用来存储单个数据集的所有配置。
  • 代码对应: ```python @dataclass class DatasetAttr: # 1. 来源信息：是从网上下载(hf_hub)，还是读本地文件(file)？ load_from: Literal["hf_hub", "ms_hub", "om_hub", "script", "file"] dataset_name: str
    # 2. 格式信息：是 Alpaca 格式还是 ShareGPT 格式？
formatting: Literal["alpaca", "sharegpt", "openai"] = "alpaca"

# 3. 列名映射（关键）：
# 你的数据里哪一列是提示词(prompt)？哪一列是答案(response)？
# 这里定义了标准名称，比如 prompt, query, response, history 等。
prompt: Optional[str] = "instruction"
query: Optional[str] = "input"
response: Optional[str] = "output"
# ... 其他属性

    ``` * 白话解释: 这就是一个填空题模板。不管你原来的数据长什么样，最后都要填进这个模板里，告诉程序：“我的数据在硬盘的A位置，我的‘问题’列叫Q，‘答案’列叫A”。

Task 2: 找到“数据集花名册” (Function get_dataset_list 开头)

当你启动训练时，你会给程序一个名字（比如 wiki_demo），程序需要去查这个名字对应的具体信息。

  • Todo: 读取配置文件（通常叫 dataset_info.json），这就像一本电话簿，记录了所有可用数据集的详细信息。
  • 代码对应: python def get_dataset_list(...): # ... # 尝试打开 dataset_info.json 文件 with open(config_path) as f: dataset_info = json.load(f) # ...
  • 白话解释: 程序先要把记载了所有数据集信息的“字典”加载到内存里，准备随时查阅。

Task 3: 逐个核对“购物清单” (Loop for name in dataset_names)

你可能一次想训练三个数据集，程序需要一个一个处理。

  • Todo: 遍历用户输入的数据集名称列表。
  • 代码对应: python dataset_list: list[DatasetAttr] = [] for name in dataset_names: # 比如你输入了 ["data_A", "data_B"] if name not in dataset_info: raise ValueError(...) # 如果花名册里没这个名字，报错 # ...
  • 白话解释: 你在命令行里说了要用 dataset_A，程序现在开始在刚才加载的“花名册”里找 dataset_A 的详细条目。

Task 4: 确定“进货渠道” (Determine load_from)

找到条目后，程序要决定去哪里拿数据。

  • Todo: 判断这个数据集是存在 HuggingFace (国外源)，ModelScope (国内源)，还是本地的一个 JSON 文件。

  • 代码对应: ```python # 检查 json 里有没有 "hf_hub_url" 这种字段 has_hf_url = "hf_hub_url" in dataset_info[name] has_ms_url = "ms_hub_url" in dataset_info[name]

    if has_hf_url or ...: # 如果有 url，说明是网上的，设置 load_from="hf_hub" 或 "ms_hub" dataset_attr = DatasetAttr("hf_hub", dataset_name=...) elif "file_name" in dataset_info[name]: # 如果有 file_name，说明是本地文件，设置 load_from="file" dataset_attr = DatasetAttr("file", dataset_name=...) ``` * 白话解释: 程序在看地图。如果配置里写了网址，就准备下载；如果写了文件名，就准备读硬盘。

Task 5: 填写详细“映射规则” (Method .join())

这是最关键的一步。不同的数据集，列名千奇百怪。这一步把配置里的细节填入 Task 1 定义的“身份证”里。

  • Todo: 把 JSON 里的 columns (列名) 和 tags (标签) 信息，复制到 DatasetAttr 对象中。

  • 代码对应: ```python # 在 DatasetAttr 类里定义的 join 方法 def join(self, attr: dict[str, Any]) -> None: # ... if "columns" in attr: # 如果配置里说了 "prompt": "instruction_text" # 这里就把对象的 prompt 属性设为 "instruction_text" for column_name in column_names: self.set_attr(column_name, attr["columns"])

    在主函数里调用

    dataset_attr.join(dataset_info[name]) `` * **白话解释:** * LlamaFactory 默认认为问题列叫instruction。 * 但是你的数据里，问题列叫user_query。 * 这一步就是要把这个对应关系记录下来，以后程序读到user_query` 就知道这是问题。

总结：这个文件讲了什么？

这个文件就是 LlamaFactory 的“前台接待员”。

  1. 接待客人：你给它一堆数据集的名字。
  2. 查户口：它去 dataset_info.json 里查这些名字的底细。
  3. 发通行证：它把查到的信息（去哪下载、哪一列是问题、哪一列是答案）整理成一个个标准的 DatasetAttr 对象。
  4. 移交：最后把这些整理好的对象列表交给后续的代码，后续代码就不需要管数据格式乱不乱了，直接按标准读就行。
