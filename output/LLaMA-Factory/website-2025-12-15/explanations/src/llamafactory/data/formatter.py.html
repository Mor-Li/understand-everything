src/llamafactory/data/formatter.py

这段代码确实看起来有点抽象，因为它涉及到大模型（LLM）训练中最繁琐的环节——数据格式化（Data Formatting）。

简单来说，这个文件的作用就是把原始的对话数据，拼装成模型能看懂的特定格式字符串。就像是在做一个“填空题”生成器。

为了让你更容易理解，我把你当作这个项目的产品经理，我们把这个文件拆解成一个 Task Todo List（任务清单）。每一个类（Class）就是为了完成清单上的一个具体任务。

🚀 任务背景：我们要教 AI 说话

我们要训练一个 AI，不仅要让它会聊天，还要让它会使用工具（比如调用搜索、计算器）。但是 AI 只认识拼好的字符串，不认识复杂的 JSON 对象。所以我们需要写一组程序来处理这些文本。

以下是你的任务清单：

✅ Task 1: 定义基础规则 (Base Class)

负责对象： Formatter (抽象基类)

  • 场景：我们需要制定一个标准，不管后面怎么处理文本，大家都要遵守这个标准。
  • 要做的事：
    1. 定义一个叫 apply 的方法：不管输入什么，最后都要吐出一个列表（SLOTS），这个列表就是喂给模型的最终素材。
    2. 定义一个叫 extract 的方法：如果模型回复了内容，我们需要能从里面提取出它是不是想调用函数（Function Call）。
  • 代码解读：这是个“虚”的类，不干实事，只立规矩。

✅ Task 2: 处理“死板”的固定文本

负责对象： EmptyFormatter

  • 场景：有时候我们只是想把一段固定的系统提示词（System Prompt）塞给模型，比如“你是一个乐于助人的助手”。这里面没有任何变量，不需要填空。
  • 要做的事：
    1. 检查：如果你用了这个类，那文本里绝对不能有 {{name}} 这种占位符。如果有，就报错（因为你选错了工具）。
    2. 输出：直接把文本原样输出，不做任何修改。
  • 代码解读：
    • re.search(r"\{\{...\}\}"): 正在用正则抓有没有双大括号，如果有就报错 ValueError。

✅ Task 3: 处理“填空题” (普通对话)

负责对象： StringFormatter

  • 场景：这是最常用的。比如模板是“用户：{{instruction}}，回答：{{response}}”。我们需要把真实的数据填进去。
  • 要做的事：
    1. 检查：必须要有占位符 {{...}}，否则就没必要用我了。
    2. 填空：把输入字典里的内容（比如 instruction="你好"），替换掉模板里的 {{instruction}}。
  • 代码解读：
    • slot.replace("{{" + name + "}}", value): 这就是核心，把 {{变量名}} 替换成 真实值。

✅ Task 4: 处理“AI 想用工具”的情况 (高阶)

负责对象： FunctionFormatter (继承自 Task 3)

  • 场景：我们给 AI 看了工具，AI 决定要用。AI 吐出的原始数据通常是 JSON 格式（比如 {"name": "calculate", "args": "1+1"}），但我们要把它转换成一种特殊的字符串格式让模型继续学习，有时候还得包含 AI 的“思考过程”（Thought）。
  • 要做的事：
    1. 解析：把输入的 JSON 字符串变成 Python 对象。
    2. 分离思考：如果 AI 有思维链（Chain of Thought），要把“思考过程”和“函数调用”分开处理。
    3. 格式化：利用工具集（tool_utils）把函数调用变成模型特定的特殊字符（比如 <tool_call>...）。
  • 代码解读：
    • _parse_functions: 尝试解析 JSON，如果失败就报错。
    • tool_call_regex: 用正则去匹配 AI 的思考部分和工具调用部分。
    • 最后调用 super().apply() 把处理好的特殊字符串填进模板。

✅ Task 5: 告诉 AI “你有哪些工具”

负责对象： ToolFormatter

  • 场景：在对话开始前，我们要把一堆工具的定义（比如 Google 搜索的 API 文档）塞给 AI，告诉它：“嘿，你可以用这些工具哦”。
  • 要做的事：
    1. 输入：接收一个包含工具定义的列表（JSON）。
    2. 转换：把这个列表转换成一段人类和 AI 都能读懂的描述性文字（System Prompt）。
    3. 提取：(对应 extract 方法) 当模型输出一段话时，这个类负责识别出模型到底有没有调用工具，调用了哪个。
  • 代码解读：
    • self.tool_utils.tool_formatter(tools): 调用外部工具把 JSON 变成描述文本。
    • extract: 用来从模型的生成结果里把函数名和参数抠出来。

总结一下

这个文件的逻辑流是这样的：

  1. Formatter: 我是老大，定接口。
  2. EmptyFormatter: 处理纯文本（没变量）。
  3. StringFormatter: 处理普通对话（有变量，做字符串替换）。
  4. FunctionFormatter: 处理模型输出的函数调用（把 JSON 变成特殊格式字符串）。
  5. ToolFormatter: 处理系统提示里的工具定义（告诉模型有哪些工具可用）。

一句话概括： 这是 LlamaFactory 中负责把原始数据加工成模型训练所需的 Prompt 格式的流水线车间。
