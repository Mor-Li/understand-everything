src/llamafactory/data

欢迎来到 LlamaFactory 的 “中央厨房”（Data Central Kitchen）。

这里是整个模型训练流程中最繁忙、最基础的地方。不管你有什么样的原始食材（数据），都必须经过这里的清洗、切配、烹饪和打包，最后才能变成大模型（食客）愿意吃、能消化的大餐（Tensor/张量）。

以下是为你定制的通俗版认知地图：

1. 核心功能：这个文件夹是干嘛的？

一句话总结：它负责把“人类写的字”变成“机器能吃的数字”。

大模型不认识 Excel，也不认识 JSON，更不认识图片文件。这个文件夹的任务就是建立一条全自动流水线： 1. 进货：从硬盘或网上把数据拉进来。 2. 清洗：把乱七八糟的格式统一成标准格式。 3. 加工：按照不同模型（Llama3, Qwen 等）的特殊口味（Template），加上特殊的符号。 4. 打包：把长短不一的数据补齐，装进整齐的箱子（Batch），喂给 GPU。

2. 员工介绍：直接文件分别是干什么的？

我们要把原本杂乱的数据做成一道好菜，需要这几位“师傅”分工合作：

🛒 进货与初加工（读取与清洗）

  • loader.py（采购经理）：
    • 他是总指挥。当你下令“我要训练”时，他负责去协调下面的各个环节，把数据从原始文件变成最终的成品。
  • parser.py（分拣员/翻译员）：
    • 负责看懂食材的“标签”。你的数据列名是叫 question 还是 instruction？他负责把这些五花八门的列名，统一翻译成系统内部的标准名称。
  • converter.py（清洗工）：
    • 负责“去泥、削皮”。不管你是 Alpaca 格式、ShareGPT 格式还是 OpenAI 格式，他都负责把它们清洗、转换成一种统一的内部标准格式。

🎨 精细加工（格式化与模版）

  • template.py（摆盘设计师/模具）：
    • 这是最关键的文件之一。他手里拿着所有模型的“说明书”。Llama3 喜欢用 <|start_header_id|>，Qwen 喜欢用 <|im_start|>。他定义了每种模型说话的规矩。
  • formatter.py（拼盘师傅）：
    • 他是动手的。他拿着 template.py 给的设计图，把用户的输入和 AI 的回答，按照规矩拼接到一起，变成一段完整的对话字符串。
  • tool_utils.py（工具说明书撰写员）：
    • 如果模型需要用“计算器”或“搜索引擎”，这位师傅负责把这些工具的用法翻译成模型能听懂的“提示词方言”。

🖼️ 特殊食材处理（多模态）

  • mm_plugin.py（海鲜/野味专家）：
    • 专门处理图片、视频这些“特殊食材”。他负责把图片切片、转成数字，并把文本里的 <image> 标签替换成模型特定的占位符。

📦 打包出货

  • collator.py（打包员）：
    • 这是最后一步。因为每句话长短不一样，他负责把短的句子用 0 补齐（Padding），然后把几十条数据整整齐齐地码放在一个箱子（Batch）里，生成 PyTorch Tensor，直接发货给显卡。

🛠️ 后勤辅助

  • data_utils.py（杂工）：
    • 负责切分训练集/验证集，或者把多份数据混合在一起。
  • __init__.py（门童）：
    • 负责把里面好用的功能暴露给外面，方便调用。

3. 小房间：子文件夹是干嘛的？

  • 📁 processor/（特定菜系烹饪间）：
    • 虽然上面的文件处理了通用的流程，但不同的训练阶段（预训练、微调、DPO偏好对齐）对数据的处理逻辑有细微差别。
    • 这个文件夹里就是针对不同“菜系”（训练任务）的专用处理器。

4. 高层认知总结

当你看着 src/llamafactory/data 时，请在脑海中构建这样一幅画面：

这是一个高度自动化的食品加工厂。 1. loader 按下启动键。 2. parser 和 converter 把五花八门的原始数据变成了统一的净菜。 3. template 和 formatter 根据你要训练的模型（Llama/Qwen），给净菜加上了特制的酱料（特殊Token）。 4. 如果是图片数据，mm_plugin 会过来帮忙处理。 5. 最后，collator 把做好的菜装盒打包。

这一套流程保证了：无论你喂给它什么乱七八糟的数据，无论你要训练什么刁钻的模型，LlamaFactory 都能把它们变成标准统一的训练素材。
