src/llamafactory/data/processor/supervised.py

这份代码是 LlamaFactory 中用于 有监督微调（SFT, Supervised Fine-Tuning） 的数据处理核心逻辑。

简单来说，它的作用是：把人类能看懂的对话数据（文本/图片），转换成模型能看懂的数字（Token IDs），并告诉模型“哪些字你需要学习，哪些字你只需要读”。

为了让你听懂，我把这个脚本的工作流程拆解成一个 “老师准备考卷” 的 To-Do List。

核心任务清单：如何把聊天记录变成训练数据？

第一阶段：理解单个样本的处理 (_encode_data_example 方法)

这是最基础的“原子”操作。想象你拿到了一段对话（比如：用户问“你好”，AI答“我是助手”）。

  • [ ] Task 1.1：多模态内容预处理

    • 代码位置：messages = self.template.mm_plugin.process_messages(...)
    • 解释：如果输入里有图片、视频、音频，先把它们转换成模型能接受的占位符或格式。如果是纯文本，这步就是整理对话格式。

  • [ ] Task 1.2：数字化（Tokenization）

    • 代码位置：self.template.encode_multiturn(...)
    • 解释：把文字转换成数字 ID。
    • 例子："你好" -> [101, 204]。

  • [ ] Task 1.3：区分“题目”和“答案”（Masking / Labeling）

    • 关键点：这是 SFT 的精髓。
    • 逻辑：
      • 用户的提问（Prompt）是“题目”，模型不需要预测题目，只需要读懂。所以把这部分的 Label 设为 IGNORE_INDEX（通常是 -100，表示计算 Loss 时忽略）。
      • AI 的回答（Response）是“答案”，模型需要学习怎么写出这个答案。这部分的 Label 保留原本的 ID。
    • 代码位置： python if self.data_args.train_on_prompt: source_label = source_ids # 极其少见，通常不这么做 else: source_label = [IGNORE_INDEX] * source_len # 把提问部分“涂黑”，不计分

  • [ ] Task 1.4：长度裁剪（Truncation）

    • 代码位置：if total_length >= self.data_args.cutoff_len: break
    • 解释：模型有最大长度限制（比如 4096）。如果对话太长，必须切断。代码里有一个循环，会一段一段地拼凑对话，一旦超长就停止。

  • [ ] Task 1.5：添加特殊符号

    • 代码位置：添加 eos_token_id (End of Sentence)。
    • 解释：告诉模型“这句话说完了”。

第二阶段：批量处理普通数据集 (SupervisedDatasetProcessor 类)

现在你知道怎么处理一条数据了，接下来要处理整个文件。

  • [ ] Task 2.1：清洗数据

    • 代码位置：preprocess_dataset 中的 if len(...) % 2 != 1 判断。
    • 解释：检查对话是否完整。通常要求“一问一答”。如果格式不对（比如只有问题没回答），直接丢弃并在日志里报警。

  • [ ] Task 2.2：构建标准输入字典

    • 代码位置：model_inputs["input_ids"].append(...)
    • 解释：把处理好的一条条数据放入一个大列表里。
    • 产出：
      • input_ids: 喂给模型的数字序列。
      • labels: 告诉模型哪里要学习的序列（提问处是-100，回答处是数字）。
      • attention_mask: 告诉模型哪些是有效内容，哪些是填充的空白（全是1，因为这里还没做 Padding）。

第三阶段：进阶优化——数据打包 (PackedSupervisedDatasetProcessor 类)

这是代码下半部分 Packed... 类的功能。这是一个加速训练的技巧。

  • [ ] Task 3.1：发现“浪费”问题

    • 背景：假设模型支持长度 4096。如果你的一条数据只有 100 个字，剩下的 3996 个位置如果填 0 (Padding)，计算资源就浪费了。

  • [ ] Task 3.2：贪心背包算法（Knapsack Algorithm）

    • 代码位置：knapsacks = greedy_knapsack(lengths, self.data_args.cutoff_len)
    • 解释：这就像装箱子。
      • 箱子大小是 4096。
      • 你有各种长短不一的数据（100长，500长，3000长...）。
      • 算法会计算：怎么把这些短数据拼在一起，尽可能塞满一个 4096 的箱子，不留缝隙。

  • [ ] Task 3.3：拼接数据

    • 代码位置：packed_input_ids += batch_input_ids[index]
    • 解释：把好几段不相关的对话首尾相连，拼成一条很长的数据。
    • 注意：这里需要特殊的 attention_mask（代码里的 neat_packing），防止模型读串行了（比如把第一段对话的结尾当成了第二段对话的开头）。

  • [ ] Task 3.4：最终填充

    • 代码位置：pad_length = self.data_args.cutoff_len - len(...)
    • 解释：如果拼完之后还是没到 4096（比如拼到了 4090），剩下的 6 个位置再用 pad_token_id 填满。

总结

这段代码主要就干了两件事：

  1. 普通模式 (SupervisedDatasetProcessor)：

    • 把 用户:你好 + AI:在 变成 [用户ID, 你好ID, AI ID, 在ID]。
    • 把 Label 设为 [-100, -100, -100, 在ID] （只学 AI 说的字）。

  2. 打包模式 (PackedSupervisedDatasetProcessor)：

    • 把上面的短句子拼凑起来：[对话A] + [对话B] + [对话C] 塞满最大长度，为了省显存、跑得快。
