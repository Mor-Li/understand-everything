src/llamafactory/data/processor/feedback.py

这段代码确实比较抽象，因为它涉及到了大模型偏好对齐（Preference Alignment）中一种比较新的算法，叫做 KTO (Kahneman-Tversky Optimization)。

简单来说，以前我们教模型（比如 DPO 算法），是给它两个答案（A好，B坏），让它学“A比B好”。 而 KTO 不需要成对比较，它只需要你告诉模型：这个答案是“赞（Desirable）”还是“踩（Undesirable）”。

这个文件的作用就是：把原始数据处理成 KTO 算法能看懂的格式。

为了让你看懂，我把你（作为这个程序）需要完成的工作拆解成一个 To-Do List，我们一步步来划钩：

✅ Task 1: 准备“参照组”数据 (制造错位)

代码位置： preprocess_dataset 函数开头

kl_response = [examples["_response"][-1]] + examples["_response"][:-1]
  • 这是在干嘛？ KTO 算法需要计算一个“KL散度”，简单说就是需要一个“完全不相关的答案”作为背景板来对比。
  • 怎么做的？ 程序把所有数据的答案列表整体向后挪了一位（错位）。
    • 比如原本是：[问题1-答案1, 问题2-答案2, 问题3-答案3]
    • 挪位后变成：[问题1-答案3, 问题2-答案1, 问题3-答案2]
    • 这样 kl_response 里存的就是跟当前问题不匹配的答案。

✅ Task 2: 只有一问一答，判断是“赞”还是“踩”

代码位置： _encode_data_example 函数开头

if response[0]["content"]:  # desired example
    kto_tag = True
    messages = prompt + [response[0]]
else:  # undesired example
    kto_tag = False
    messages = prompt + [response[1]]
  • 这是在干嘛？ 程序在看原始数据，判断这条数据是正向反馈（好）还是负向反馈（坏）。
  • 怎么做的？
    • 数据里通常会有两个槽位。
    • 如果第一个槽位有内容，程序标记 kto_tag = True（这是个好回答，给个赞）。
    • 如果第一个没内容，取第二个槽位的内容，并标记 kto_tag = False（这是个坏回答，给个踩）。

✅ Task 3: 把文字变成数字 (Tokenization)

代码位置： self.template.encode_oneturn(...) * 这是在干嘛？ 计算机看不懂中文英文，只能看懂数字。 * 怎么做的？ * 程序把 prompt（问题）和 response（回答）拼接起来，用分词器（Tokenizer）转换成一串数字 ID。 * 同时，它也把 Task 1 里生成的那个“错位答案” (kl_messages) 也转成了数字。

✅ Task 4: 长度裁剪 (切掉太长的)

代码位置： infer_seqlen(...) 和 [:source_len] * 这是在干嘛？ 防止输入太长爆显存。 * 怎么做的？ 计算一下问题和答案加起来有多长，如果超过了设定的限制（cutoff_len），就把多余的部分切掉。

✅ Task 5: 制作考卷 (Labels 和 Masking)

代码位置：

labels = [IGNORE_INDEX] * source_len + response_ids
  • 这是在干嘛？ 告诉模型：“你只需要预测答案，不需要预测问题。”
  • 怎么做的？
    • Input IDs: [问题ID, 答案ID] (模型看到的完整内容)
    • Labels: [-100, -100, ..., 答案ID]
    • 这里 -100 (即 IGNORE_INDEX) 的意思是：计算误差时，忽略前面的问题部分，只算后面答案写得对不对。

✅ Task 6: 打包发货

代码位置： model_inputs["..."].append(...) * 这是在干嘛？ 把处理好的一条条数据装进大列表里，准备喂给 GPU 训练。 * 怎么做的？ 它打包了以下关键信息： 1. input_ids: 正常的问题+答案。 2. labels: 用来算分的标签（问题被遮住了）。 3. kl_input_ids: 问题+错位的答案（用来做数学对比）。 4. kto_tags: True 或 False（告诉模型这条数据是好是坏）。

总结一下

这个脚本 feedback.py 就像是一个流水线工人，专门为 KTO 训练做准备：

  1. 它把答案列表打乱，制造“不匹配的参考组”。
  2. 它给每一条数据贴上“好”或“坏”的标签。
  3. 它把文字转成数字，并把不需要模型学习的“提问部分”遮挡住。
  4. 最后打包输出，供模型学习“什么是好回答，什么是坏回答”。
