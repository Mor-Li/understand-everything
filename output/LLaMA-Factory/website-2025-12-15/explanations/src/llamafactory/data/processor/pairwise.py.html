src/llamafactory/data/processor/pairwise.py

这份代码文件 pairwise.py 的核心作用是：为“偏好学习”（如 DPO、Reward Modeling）准备数据。

在训练大模型时，我们有时不仅仅给它看“什么是对的”，还要给它看“哪个更好”。这需要成对的数据：一个提示词（Prompt），对应两个回答，一个是“胜出（Chosen）”的，一个是“落败（Rejected）”的。

为了让你更容易理解，我把你当作一个数据加工流水线的主管，这份代码就是你的操作手册。我们将任务拆解为一个 To-Do List，一步步带你看它是怎么工作的。

📋 任务清单：从原始文本到模型能吃的“成对数据”

Task 1: 检查原材料 (数据清洗)

对应代码位置： preprocess_dataset 方法中的 for 循环开头。

  • 要做什么： 也就是遍历你的原始数据集。
  • 代码逻辑：
    • 它会检查每一条数据。
    • if len(examples["_prompt"][i]) % 2 != 1: 检查对话历史是否符合逻辑（通常是一问一答）。
    • or len(examples["_response"][i]) < 2: 关键点！ 它检查是否有两个回答。因为是“成对（Pairwise）”训练，必须至少有一个“好的回答”和一个“坏的回答”。
    • 如果数据不合格，直接 continue（扔掉），并打印警告。

Task 2: 区分“好”与“坏” (分类)

对应代码位置： _encode_data_example 方法被调用时。

  • 要做什么： 把原始数据里的两个回答拆开处理。
  • 代码逻辑：
    • 代码默认 response[0] 是 Chosen（好的/胜出的）。
    • 代码默认 response[1] 是 Rejected（坏的/被拒绝的）。
    • 它会分别把 Prompt + Chosen 和 Prompt + Rejected 组合成两条独立的线去处理。

Task 3: 翻译成数字 (Tokenization)

对应代码位置： _encode_data_example 中的 self.template.encode_oneturn。

  • 要做什么： 计算机不认识中文或英文，只认识数字。我们需要把文本转成 Token IDs。
  • 代码逻辑：
    • 处理 Chosen 路径： 把 Prompt + Chosen Response 扔给分词器，得到 prompt_ids 和 chosen_ids。
    • 处理 Rejected 路径： 把 Prompt + Rejected Response 扔给分词器，得到 rejected_ids（这里不需要重新算 prompt_ids，因为是一样的）。
    • 注：如果有图片、视频等多模态内容，也会在这里被处理成占位符。

Task 4: 裁剪长度 (截断)

对应代码位置： _encode_data_example 中的 infer_seqlen 和切片操作 [:source_len]。

  • 要做什么： 模型输入的长度有限制（比如 4096 或 8192），太长了吃不下，必须切一刀。
  • 代码逻辑：
    • 它计算 Prompt 有多长，两个回答中最长的那个有多长。
    • 如果总长度超标，它会优先保留 Prompt，然后把回答（Chosen 和 Rejected）截断到最大允许长度。

Task 5: 制作“考卷”与“答案” (构建 Input 和 Label)

对应代码位置： _encode_data_example 的最后部分。

  • 要做什么： 这是最关键的一步。模型训练需要 input_ids（输入什么）和 labels（预测什么）。
  • 核心逻辑（非常重要）：
    • Input IDs (输入): 就是 Prompt + Response 的数字序列。
    • Labels (标签): 我们只希望模型学习“怎么回答”，而不希望它学习“怎么提问”。
    • IGNORE_INDEX: 这是一个特殊的数字（通常是 -100）。
    • 操作：
      • 把 Prompt 部分的 Label 全部设为 IGNORE_INDEX（意思是：这部分考试不计分，不用管）。
      • 把 Response 部分的 Label 设为真实的 Token ID（意思是：这部分要学会，算 Loss）。
    • 最终产出四样东西：
      1. chosen_input_ids: 提示词 + 好回答
      2. chosen_labels: (-100, -100...) + 好回答
      3. rejected_input_ids: 提示词 + 坏回答
      4. rejected_labels: (-100, -100...) + 坏回答

Task 6: 打包发货 (Batching)

对应代码位置： preprocess_dataset 的最后部分。

  • 要做什么： 把处理好的一条条数据放到一个大字典里，准备喂给 GPU。
  • 代码逻辑：
    • 将上面生成的 chosen_input_ids, rejected_input_ids 等等，分别 append 到 model_inputs 列表中。
    • 同时生成 attention_mask（告诉模型哪些是字，哪些是补全的空白）。

总结：这段代码在干嘛？

简单来说，这段代码就是一个“比较级数据厨师”：

  1. 拿来一堆素材（用户提问 + 两个回答）。
  2. 把素材切分成两盘菜：A套餐（好回答） 和 B套餐（坏回答）。
  3. 把菜切碎（Tokenization）。
  4. 把盘子边缘擦干净（Masking，把 Prompt 部分遮住不计算损失）。
  5. 最后打包送给模型，让模型学习：“A套餐比B套餐好吃，下次要学着做A套餐”。
