src/llamafactory/data/tool_utils.py

这份代码看起来很长，其实它只做了一件事：当“翻译官”。

它负责在 “人类定义的工具（代码）” 和 “大模型（LLM）” 之间进行翻译，让模型能够学会如何调用外部工具（比如搜索、计算器、API等）。

为了让你彻底读懂，我把阅读这份代码的任务拆解成一个 To-Do List，分为 5 个步骤，带你一步步通关。

✅ Task 1: 理解核心背景 —— 什么是“工具调用 (Function Calling)”？

在看代码前，先建立这个概念：大模型本身只是个聊天机器人，它无法直接运行 Python 代码或联网。 * 我们要做的： 告诉模型“我有这几个工具（函数），你想用哪个就告诉我”。 * 模型的反应： 模型会输出一段文本，比如 Action: search, Input: "天气"。 * 代码的职责： 这个文件就是用来处理“怎么告诉模型”以及“怎么解析模型的回答”的。

✅ Task 2: 拆解核心逻辑 —— 只有三个动作

不管代码里有多少个类（Class），它们都继承自 ToolUtils，并且必须实现三个核心方法。请在代码中找到 class ToolUtils(ABC):（第 92 行），这是“总纲”。

这三个方法对应了工具调用的三个阶段：

  1. tool_formatter (工具格式化器)

    • 场景： 在把问题扔给模型之前。
    • 作用： 你有一堆工具的定义（JSON格式），模型看不懂。这个函数负责把它变成一段提示词（Prompt），写在 System Message 里，告诉模型：“你有这些工具可用，请按照这个格式来调用……”。
    • 比喻： 给模型发一份“工具使用说明书”。

  2. function_formatter (函数调用格式化器)

    • 场景： 模型决定使用工具，或者我们训练模型时展示“正确答案”。
    • 作用： 把“我要调用 A 工具，参数是 B”这个意图，转换成模型该输出的特定文本格式。
    • 比喻： 教模型怎么填“申请单”。

  3. tool_extractor (工具提取器)

    • 场景： 模型输出了一段话之后。
    • 作用： 模型输出的是一串字符串（比如一段 XML 或 JSON 文本），Python 代码看不懂。这个函数用正则或 JSON 解析，把它还原成结构化的数据（函数名是什么？参数是什么？）。
    • 比喻： 审批员把模型填好的“申请单”读出来，录入系统。

✅ Task 3: 观察不同模型的“方言” (为什么要写这么多类？)

你会发现代码里有很多类：DefaultToolUtils, GLM4ToolUtils, Llama3ToolUtils, QwenToolUtils 等等。

原因： 不同的模型，对“工具调用”的格式要求不一样（就像方言）。

  • Llama 3 说： “我要看 JSON 格式的工具定义，并且我会输出 JSON 格式的调用。”
    • 看代码 Llama3ToolUtils (第 196 行)：它用 json.dumps 来处理。
  • Qwen (千问) 说： “我更喜欢 XML 标签，把工具包在 <tools> 里，调用时用 <tool_call>。”
    • 看代码 QwenToolUtils (第 267 行)：你会看到很多 <tool_call> 这种标签的处理。
  • Default (默认) 说： “用一种通用的文本格式：Action: xxx 和 Action Input: xxx。”
    • 看代码 DefaultToolUtils (第 119 行)：这是最经典的 ReAct 格式。

✅ Task 4: 实例演练 —— 读懂一个具体的类

我们以最复杂的 Qwen (千问) 为例，带你走一遍流程：

  1. 看 Prompt 定义 (第 64 行 QWEN_TOOL_PROMPT)：

    • 你会看到它定义了一个模板，里面写着 You are provided with function signatures within <tools></tools> XML tags。这就是在写“说明书”。

  2. 看 tool_formatter (第 271 行)：

    • 它遍历了你提供的工具列表，把它们转成 JSON，然后塞进上面的 <tools> 标签里。

  3. 看 function_formatter (第 281 行)：

    • 如果模型要调用函数，这个方法会生成类似 <tool_call>{"name": "...", "arguments": "..."}</tool_call> 的字符串。

  4. 看 tool_extractor (第 290 行)：

    • 它使用正则表达式 re.compile(r"<tool_call>(.+?)</tool_call>...)。
    • 它的任务就是从模型一大段废话中，精准地把 <tool_call> 中间的内容抠出来，变成 Python 能用的对象。

✅ Task 5: 总结与最后一步

这个文件的最终目的： 文件末尾有一个 TOOLS 字典（第 382 行）和一个 get_tool_utils 函数。

  • 作用： LlamaFactory 在训练或推理时，只需要知道你用的是什么模型（比如 "qwen"）。
  • 流程： 系统调用 get_tool_utils("qwen") -> 拿到 QwenToolUtils 类 -> 自动处理所有的格式转换。

一句话总结： 这是一个多语言适配器。它把统一的 Python 工具定义，翻译成不同模型（Llama, Qwen, GLM等）能听懂的“提示词方言”，并把模型说的“方言”翻译回 Python 能执行的指令。
