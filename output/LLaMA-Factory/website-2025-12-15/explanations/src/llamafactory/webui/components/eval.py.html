src/llamafactory/webui/components/eval.py

没问题。这段代码其实是在画一个网页界面。

你可以把这段代码想象成是在装修一个房子的控制室，这个控制室专门用来给 AI 模型做考试（Evaluation/评测）。

这段代码使用的是 Gradio 库（一个 Python 画图库），它的逻辑是从上到下依次摆放家具（按钮、输入框）。

为了让你看懂，我把它拆解成一个 “装修施工队”的任务清单 (TODO List)，每一步对应代码中的一段逻辑：

🏗️ 任务清单：构建“模型评测”控制台

✅ Task 1: 准备工作 (Setup)

  • 代码位置: 开头的 import 和 def create_eval_tab...
  • 在干什么: 施工队进场，确认工具（Gradio）都在。定义了一个主任务叫 create_eval_tab，意思是“创建评测标签页”。
  • 核心动作: 创建一个空的容器 elem_dict，用来最后装所有的组件。

✅ Task 2: 放置“试卷区” (Data Selection)

  • 代码位置: 第 1 个 with gr.Row():
  • 在干什么: 在界面最上面放一行控件，用来决定用什么数据来考 AI。
  • 具体组件:
    1. dataset_dir: 一个输入框，填“试卷仓库在哪里”（数据路径）。
    2. dataset: 一个下拉菜单，选“考哪几套卷子”（数据集名称）。
    3. preview_elems: 一个预览框，用来看看卷子长啥样。

✅ Task 3: 设定“考试规则” (Basic Config)

  • 代码位置: 第 2 个 with gr.Row():
  • 在干什么: 在下面再放一行，设定考试的具体流程。
  • 具体组件:
    1. cutoff_len: 滑动条。设定“题目最长多长”，太长了就截断。
    2. max_samples: 输入框。设定“最多考几道题”，比如只考 100 题试试水。
    3. batch_size: 滑动条。设定“一次批改几道题”（批处理大小）。
    4. predict: 复选框。勾上表示要把 AI 的答案保存下来。

✅ Task 4: 调整“考生状态” (Model Config)

  • 代码位置: 第 3 个 with gr.Row():
  • 在干什么: 设定 AI 回答问题时的性格参数。
  • 具体组件:
    1. max_new_tokens: 滑动条。限制 AI “最多能写多少字”。
    2. top_p 和 temperature: 滑动条。这两个是控制 AI 的创造力/随机性的。数值越高，AI 回答越天马行空；数值越低，回答越死板准确。
    3. output_dir: 输入框。设定“考完的成绩单存哪里”。

✅ Task 5: 安装“控制按钮” (Control Buttons)

  • 代码位置: 第 4 个 with gr.Row():
  • 在干什么: 放置真正的操作按钮。
  • 具体组件:
    1. cmd_preview_btn: “预览命令”按钮。按一下，看看后台实际执行的复杂代码长啥样。
    2. start_btn: “开始考试”按钮（设为主要颜色 primary，通常是显眼的颜色）。
    3. stop_btn: “停止”按钮（设为 stop 颜色，通常是红色）。

✅ Task 6: 安装“监控屏幕” (Monitor Area)

  • 代码位置: 第 5、6 个 with gr.Row():
  • 在干什么: 用来显示进度和日志。
  • 具体组件:
    1. progress_bar: 进度条（一开始是隐藏的）。
    2. output_box: 一个大屏幕（Markdown 格式），用来实时打印后台的日志信息（比如“正在处理第 10 题...”）。

✅ Task 7: 接通电路 (Event Wiring) 🔌 这是最关键的一步

  • 代码位置: 文件最后几行 (.click, .change, .focus)
  • 在干什么: 光画了按钮没用，得把按钮和后台机器连起来。
  • 具体连线:
    1. 预览按钮被点击 (cmd_preview_btn.click): -> 触发 preview_eval 函数（给你看命令）。
    2. 开始按钮被点击 (start_btn.click): -> 触发 run_eval 函数（真正开始跑评测），并把上面所有输入框里的数据传给后台。
    3. 停止按钮被点击 (stop_btn.click): -> 触发 set_abort 函数（强制中断）。
    4. 数据集菜单被点击 (dataset.focus): -> 触发 list_datasets，自动刷新一下有哪些数据集可选。

总结

这一个文件就是一个“前台接待员”。 它不负责具体的 AI 计算（那是后台 engine 做的事），它只负责： 1. 画出界面给用户看。 2. 收集用户填写的参数（用什么数据、随机度多少）。 3. 告诉后台：“老板，用户按了开始按钮，参数是这些，快干活！”
