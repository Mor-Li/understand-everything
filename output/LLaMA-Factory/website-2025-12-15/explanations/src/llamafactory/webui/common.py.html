src/llamafactory/webui/common.py

这份代码文件 src/llamafactory/webui/common.py 可以看作是 LlamaFactory 网页版界面（Web UI）的“后勤大管家”。

它不负责核心的“炼丹”（训练模型），而是负责处理各种杂活，比如读写配置文件、生成运行命令、查找文件路径等。

为了让你更容易理解，我把你（作为一个 Web UI 开发者）需要完成的Task Todo List列出来，并对应代码中的功能一步步讲解：

📋 任务清单：Web UI 后勤管理

✅ Task 1: 记住用户的个人偏好（存档/读档）

场景：用户上次选了中文界面，还填了一个模型路径。下次打开网页时，不能让用户重新填一遍。 * 代码对应： * load_config(): 读档。读取 user_config.yaml，看看用户上次设置了什么语言、用了什么模型。 * save_config(): 存档。当用户在网页上修改设置时，把当前的语言、模型路径保存下来。 * _get_config_path(): 告诉程序这个“存档文件”放在哪（通常在 llamaboard_cache 文件夹里）。

✅ Task 2: 搞清楚“东西”都在哪（路径管理）

场景：用户选了一个模型叫 "Llama-3"，程序得知道这个模型在硬盘的哪个文件夹里；训练好的模型又要存到哪去。 * 代码对应： * get_model_path(model_name): 找模型。根据模型名字，去查配置文件或者默认路径，返回具体的文件夹路径（还支持魔搭社区 ModelScope 等不同来源）。 * get_save_dir(*paths): 定终点。决定训练好的模型保存到 saves/ 目录下的哪个子文件夹里。 * load_dataset_info(): 找数据。读取 dataset_info.json，看看有哪些数据集可用。

✅ Task 3: 把网页上的“按钮”变成“命令”（翻译官）

场景：用户在网页上点选了“学习率 0.001”、“Batch Size 4”。程序需要把这些选项变成一行可以在终端运行的代码，或者保存成配置文件。 * 代码对应： * gen_cmd(args): 生成预览命令。把你选的所有参数拼成一行 llamafactory-cli train ... 的命令，展示在网页上让你复制或检查。 * save_cmd(args): 保存实际命令。把参数清洗一下（去掉空的），保存成文件，供后台真正运行训练时读取。 * load_args() / save_args(): 保存和读取训练参数预设（比如你保存了一个“由弱变强微调配置”）。 * get_template(model_name): 根据模型名字自动判断应该用哪种对话模板（比如 chatglm 用什么格式，llama 用什么格式）。

✅ Task 4: 控制后台进程（保安）

场景：用户点击了“开始训练”，但发现参数填错了，点击“取消”。程序必须立刻杀掉后台正在跑的训练进程。 * 代码对应： * abort_process(pid): 灭火器。给它一个进程 ID，它会顺藤摸瓜把这个进程以及它的所有子进程全部杀掉，强制停止训练。

✅ Task 5: 高级加速配置（DeepSpeed 助手）

场景：用户想用多张显卡训练，需要用 DeepSpeed 加速，但这玩意的配置文件（JSON）非常复杂，很难手写。 * 代码对应： * create_ds_config(): 自动填表。自动生成 DeepSpeed 的配置文件（比如 Zero2, Zero3 显存优化配置），保存在缓存目录里，这样用户就不用自己手写这些复杂的 JSON 文件了。

✅ Task 6: 其他小工具（瑞士军刀）

场景：一些零碎的辅助功能。 * 代码对应： * get_time(): 获取当前时间，用来给保存的文件命名（比如 2025-01-01-12-00-00）。 * is_multimodal(): 判断这个模型是不是多模态模型（能不能看图）。 * load_eval_results(): 读取训练后的评估分数，展示给用户看。

总结

这就好比你开了一家餐馆（Web UI）： 1. Task 1 是记账本，记熟客喜好。 2. Task 2 是仓库管理员，知道食材（模型/数据）在哪。 3. Task 3 是传菜员，把客人的点单（网页选项）写成菜单交给后厨（训练脚本）。 4. Task 4 是保安，客人退单了负责叫停后厨。 5. Task 5 是后厨自动化设备调试员。

这个文件就是把这些非核心但必须有的代码逻辑都封装在一起，让主程序代码更干净。
