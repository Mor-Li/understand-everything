src/llamafactory/webui/control.py

这个文件 src/llamafactory/webui/control.py 的作用，通俗点说，就是 Web 界面的“管家”或“控制器”。

它不负责真正的“炼丹”（训练模型），而是负责 处理你在网页上点的每一个按钮、选的每一个菜单，并根据你的选择更新界面上的其他选项。

为了让你更容易理解，我把它拆解成一个 学习任务清单 (Task List)，然后一步步给你讲。

📋 学习任务清单 (Task List)

你需要按照这个顺序来理解代码的功能：

  1. Task 1: 理解基础交互 —— 搞懂如何切换下载源（Hub）。
  2. Task 2: 理解模型配置逻辑 —— 搞懂为什么选了“全量微调”就不能选“量化”，以及量化位数的限制。
  3. Task 3: 理解数据与阶段的对应 —— 搞懂为什么选了“预训练”阶段，数据列表就变了。
  4. Task 4: 理解文件系统读取 —— 搞懂它是怎么自动找到你硬盘里的模型、存档和配置文件的。
  5. Task 5: 理解监控与反馈 —— 搞懂它是怎么把后台的训练进度条和 Loss 曲线画到网页上的。

🚀 逐步讲解 (Step-by-Step)

Task 1: 基础交互 (切换下载源)

代码对应： switch_hub

  • 场景：你在界面上想下载模型，但是 HuggingFace 连不上，你想切换到国内的 ModelScope（魔搭社区）。
  • 功能：这个函数接收你选的平台名字（hub_name），然后设置系统环境变量。
    • 如果选了 modelscope，它就设 USE_MODELSCOPE_HUB = 1。
    • 这样后台下载模型时就会走国内镜像。

Task 2: 模型配置逻辑 (量化与微调)

代码对应： can_quantize, can_quantize_to

  • 场景：你在界面上选择了微调方式（Finetuning Type）。
  • 功能 can_quantize：
    • 如果你选的是 Full (全量微调)，代码判断这不支持量化（Quantization），所以把量化选项的菜单锁死（interactive=False）。
    • 如果你选的是 LoRA 等 PEFT 方法，它就解锁菜单让你选。
  • 功能 can_quantize_to：
    • 当你选了具体的量化方法（比如 BitAndBytes (BNB)），它会告诉你有哪些位数可选（比如 8-bit, 4-bit）。
    • 如果是 HQQ 方法，选项就会变成 8, 6, 5, 4, 3, 2, 1 bit 等等。
    • 核心逻辑：这就是很多网页里“级联菜单”的后台逻辑（选了A，B菜单的内容会变）。

Task 3: 数据与阶段的对应

代码对应： change_stage, list_datasets, check_template

  • 场景：你把训练阶段从“指令监督微调 (SFT)”切到了“预训练 (Pre-Training)”。
  • 功能 change_stage：
    • 当你切换阶段时，它会清空当前选中的数据集，并判断是否需要“打包 (packing)”数据（预训练通常是纯文本，处理方式不同）。
  • 功能 list_datasets：
    • 它会去读取 dataset_info.json。
    • 如果你在做 SFT，它只给你列出带有“问答对”格式的数据集。
    • 如果你在做 DPO/RLHF（偏好排序），它只列出带有“排名 (ranking)”属性的数据集。
    • 目的：防止你用错误格式的数据去跑不兼容的训练阶段。
  • 功能 check_template：
    • 如果你用的是对话模型（Instruct Model），但模板却选了 default（默认文本补全），它会弹出一个警告框 (gr.Warning)，告诉你这样训练效果会很差。

Task 4: 文件系统读取 (自动扫描)

代码对应： get_model_info, list_checkpoints, list_config_paths, list_output_dirs

  • 场景：界面初始化，或者你想加载之前训练好的模型。
  • 功能：
    • get_model_info: 你选个模型名（比如 Llama-3-8B），它返回这个模型在硬盘上的绝对路径，以及它推荐使用的对话模板。
    • list_checkpoints: 你想加载之前的 LoRA 存档。这个函数会去扫描保存目录，看看有哪些文件夹里包含 adapter_model.bin 等文件，然后列在下拉框里给你选。
    • list_output_dirs: 假如训练断电了，你想“断点续训”。这个函数会扫描输出目录，看看哪个文件夹里有最新的存档点（checkpoint），列出来让你选。

Task 5: 监控与反馈 (进度条与图表)

代码对应： get_trainer_info

  • 场景：你点击了“开始训练”，现在想看训练进度。
  • 功能：这是一个定时刷新的函数。
    1. 读日志：它会去读后台生成的 running_log.txt 和 trainer_log.jsonl。
    2. 更新进度条：从日志里算出当前跑了多少步（current steps），总共多少步，计算百分比，更新界面上的进度条（Slider）。
    3. 画图：读取日志里的 Loss（损失值），调用绘图库生成一张 Loss 曲线图，展示在界面上。
    4. SwanLab：如果配置了 SwanLab（一个可视化的实验追踪工具），它还会把在线链接显示出来。

💡 总结

这个文件的核心逻辑就是：Mapping（映射）与 Filtering（过滤）。

  • 映射：把用户友好的名字（如 "Llama-3"）映射到硬盘路径。
  • 过滤：根据你上一步的选择（如 "全量微调"），过滤掉下一步不合法的选项（如 "4-bit量化"）。
  • 反馈：把硬盘里的死日志文件，转换成界面上活的进度条和图表。

看完这个 List，再回头看代码，你应该能把每一个函数和它在网页上起的作用对应起来了。
