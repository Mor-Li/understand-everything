src/llamafactory/train/kto/trainer.py

这份代码确实包含了很多细节，涉及到大模型训练中比较前沿的 KTO (Kahneman-Tversky Optimization) 算法。简单来说，KTO 是一种类似 DPO（直接偏好优化）的算法，但它不需要“成对”的数据（即不需要“A比B好”这种严格的对比），只需要告诉模型“这个回答是好的（Chosen）”或者“这个回答是坏的（Rejected）”。

为了让你看懂，我把你（作为一个开发者）如果要写出这个文件，需要完成的 5个核心 Task 列出来。我们将从“准备工作”一直讲到“计算分数”。

📋 Task List: 逐步构建 KTO 训练器

Task 1: 搞定“初始化” (Setup & Init)

目标：在开始训练前，把模型、参考模型（Ref Model）和超参数准备好。

  • 代码位置：__init__ 方法。
  • 你需要做什么：
    1. 加载模型：你需要一个正在训练的 model 和一个作为对照组的 ref_model（参考模型）。参考模型通常是训练前的原始模型，用来防止新模型“忘本”（跑偏太远）。
    2. 设置参数：KTO 算法有几个关键参数：
      • beta：控制模型偏离参考模型的程度。
      • desirable_weight / undesirable_weight：好样本和坏样本的权重（KTO 特有）。
    3. 禁用 Dropout：为了计算准确的概率，通常在对齐训练（Alignment）中会关掉 Dropout (disable_dropout_in_model)。
    4. 处理 DeepSpeed：如果用了 DeepSpeed 分布式训练，需要特殊处理参考模型的加载方式。

Task 2: 定义“模型如何看数据” (Forward Pass)

目标：告诉训练器，给一堆数据，怎么算出模型输出的概率（Log Probabilities）。

  • 代码位置：forward 和 concatenated_forward 方法。
  • 你需要做什么：
    1. 普通前向传播 (forward)：
      • 输入：input_ids (文本), pixel_values (如果是多模态/图片)。
      • 输出：logits (原始分数) -> logps (对数概率)。
      • 解释：这里就是让模型读题，然后算出它生成每个 token 的概率是多少。
    2. 区分好坏样本 (concatenated_forward)：
      • KTO 的数据比较特殊，一个 Batch 里混杂着“好数据”和“坏数据”。
      • 你需要用 batch["kto_tags"] 这个标签把它们分开。
      • True 的是 Chosen (好)，False 的是 Rejected (坏)。
      • 关键点：你需要分别算出好样本的概率 (chosen_logps) 和坏样本的概率 (rejected_logps)。

Task 3: 设立“参考基准” (Reference Log Probs)

目标：计算“如果我不训练，原始模型会怎么回答这个问题？”

  • 代码位置：compute_reference_log_probs 方法。
  • 你需要做什么：
    1. 把同样的数据喂给 self.ref_model（那个冻结的、不更新的参考模型）。
    2. 算出参考模型的 reference_chosen_logps 和 reference_rejected_logps。
    3. 为什么？ KTO/DPO 的核心思想是：奖励 = 现模型的概率 / 参考模型的概率。如果现模型对好答案的概率比参考模型高，奖励就高。

Task 4: 计算“损失函数” (Loss Calculation)

目标：这是核心！根据概率算出 Loss，告诉模型怎么改参数。

  • 代码位置：get_batch_loss_metrics 方法。
  • 你需要做什么：
    1. 收集所有概率：拿到 Task 2 算出的（当前模型概率）和 Task 3 算出的（参考模型概率）。
    2. 调用公式：self.kto_loss(...)（这是从父类 KTOTrainer 继承的数学公式）。
      • 它会计算：对于好样本，尽量提高概率；对于坏样本，尽量降低概率。
    3. 混合 SFT Loss (可选)：
      • 代码里有一段 if self.ftx_gamma > 1e-6:。
      • 这是为了防止模型为了讨好人类偏好而开始“胡言乱语”。加上一点 SFT（标准监督微调）的 Loss，让模型保持语言通顺。
    4. 计算指标 (Metrics)：顺便算一下 rewards/chosen（好样本得多少分）和 rewards/rejected（坏样本得多少分），方便画图看。

Task 5: 记账与汇报 (Logging)

目标：训练过程中，把分散在各个显卡上的指标收集起来，打印到日志里。

  • 代码位置：log 方法。
  • 你需要做什么：
    1. 分布式收集：因为训练通常是多卡并行的，每张卡只算了一部分数据。你需要用 self.accelerator.reduce 把所有卡上的指标（比如 Loss 和 Reward 的总和）加起来。
    2. 计算平均值：总和 / 样本数量 = 平均值。
    3. 计算 Margin：rewards/margins = chosen - rejected。这个值越大，说明模型越能区分好坏，训练效果越好。

总结：这段代码在干嘛？

这段代码就是 LlamaFactory 为了适配 KTO 算法 专门写的一个“教练”。

  1. 初始化时，它请来了“现任模型”和“前任模型（参考）”。
  2. 训练时，它把数据喂给两个模型，看它们对“好回答”和“坏回答”分别给多大的概率。
  3. 它通过 Loss 惩罚现任模型：如果现任模型给“坏回答”的概率太高，或者给“好回答”的概率比“前任”还低，就狠狠地罚它（更新参数）。
  4. 最后，它负责把训练过程中的分数（Reward）记录下来，让你看到模型是不是变聪明了。

你需要重点关注的只有 get_batch_loss_metrics 这个函数，它是整个流程的指挥中心。
