src/llamafactory/train/kto/workflow.py

这份代码是一个工作流脚本（Workflow Script）。

简单来说，它的作用就像是一个装修工长或者项目经理。它本身不负责“砌墙”（具体的数学计算）或“搬砖”（底层数据处理），它的任务是把所有的工具、材料、人员调度好，按照顺序执行任务，完成模型训练。

这个特定的脚本是用来跑 KTO (Kahneman-Tversky Optimization) 训练的。KTO 是一种类似 RLHF/DPO 的技术，用来让模型通过“好/坏”的反馈来对齐人类偏好。

为了让你更容易理解，我把它拆解成一个 Task Todo List（任务清单），就像我们在做一件事情的步骤一样。

📋 KTO 训练任务清单 (Task List)

这段代码的 run_kto 函数就是按照下面这个顺序一步步执行的：

✅ Task 1: 准备翻译工具 (Tokenizer)

  • 代码位置: tokenizer_module = load_tokenizer(model_args)
  • 通俗解释: 模型看不懂汉字或英文，它只懂数字。我们需要先加载一个“分词器（Tokenizer）”，把人类语言变成模型能读懂的数字代码。
  • 动作: 还要确定对话的模板（Template），比如是“用户：... AI：...”这种格式。

✅ Task 2: 准备教材 (Dataset)

  • 代码位置: dataset_module = get_dataset(...)
  • 通俗解释: 加载训练数据。KTO 的数据通常包含“输入提示词”、“模型回答”以及“这个回答是好是坏（Label）”。
  • 动作: 把数据下载下来，并用上面的分词器处理好。

✅ Task 3: 请出“学生” (Load Model)

  • 代码位置: model = load_model(...)
  • 通俗解释: 加载我们要训练的那个大模型。这就是我们要教的“学生”。

✅ Task 4: 整理试卷 (Data Collator)

  • 代码位置: data_collator = KTODataCollatorWithPadding(...)
  • 通俗解释: 这一步是把数据打包。因为模型一次要学很多条数据（Batch），有的句子长，有的句子短。这个工具负责把短的句子补齐（Padding），把它们弄得整整齐齐，方便喂给模型。

✅ Task 5: 请出“参照对象” (Reference Model)

  • 代码位置: ref_model = create_ref_model(...)
  • 通俗解释: 这是重点。 在 KTO/DPO 这类训练中，我们需要知道模型“改了多少”。所以我们需要一个原始模型作为参照物（Reference Model）。
    • 如果模型改得太离谱，虽然讨好了人类，但忘了初衷（语言能力崩坏），这是不行的。
    • 参照模型通常就是训练前的那个模型副本，用来时刻提醒学生“不要忘本”。

✅ Task 6: 聘请“教练” (Initialize Trainer)

  • 代码位置: trainer = CustomKTOTrainer(...)
  • 通俗解释: 初始化训练器。这是 LlamaFactory 里的核心控制器。
  • 动作: 把上面准备好的所有东西——学生（Model）、参照物（Ref Model）、教材（Dataset）、整理工具（Collator）——全部交给这个教练。

✅ Task 7: 开始特训 (Training)

  • 代码位置: python if training_args.do_train: train_result = trainer.train(...)
  • 通俗解释: 如果你命令里写了“要训练”，这里就开始跑进度条了。
  • 子任务:
    1. trainer.train(): 疯狂计算，更新参数。
    2. trainer.save_model(): 训练完了，把变聪明后的模型保存到硬盘。
    3. plot_loss(...): 画一张图（Loss曲线），看看训练过程中错误率是不是在下降。

✅ Task 8: 期末考试 (Evaluation)

  • 代码位置: python if training_args.do_eval: metrics = trainer.evaluate(...)
  • 通俗解释: 如果你命令里写了“要评估”，就用测试集考考它。
  • 动作: 计算分数。如果“学生”和“参照对象”是同一个（比如你没加载参照模型），就算不出奖励分（Reward），代码里有一段逻辑专门处理这种情况。

✅ Task 9: 发成绩单 (Model Card)

  • 代码位置: create_modelcard_and_push(...)
  • 通俗解释: 生成一个 README.md 文件，记录这次训练用了什么参数、跑了多久、效果如何。如果配置了 HuggingFace Hub，还会自动把模型上传到云端。

总结

这个文件其实没干什么“重活”，它只是把以下流程串联了起来：

  1. 拿工具 (Tokenizer)
  2. 拿数据 (Dataset)
  3. 拿模型 (Model)
  4. 拿参照模型 (Ref Model)
  5. 启动训练器 (Trainer) -> 这是最核心的一步
  6. 保存结果

你看懂这个流程，就看懂了这个文件。具体的 KTO 数学公式怎么算，其实藏在 CustomKTOTrainer 这个类里面，不在这个文件里。
