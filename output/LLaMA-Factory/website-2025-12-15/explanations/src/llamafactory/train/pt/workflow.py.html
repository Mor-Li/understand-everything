src/llamafactory/train/pt/workflow.py

这份代码其实是一个预训练（Pre-Training）的标准工作流程脚本。

你可以把它想象成“如何训练一个大模型从零开始（或基于基础模型）通过阅读大量文本来学习说话”的说明书。它不涉及具体的对话指令微调（Instruction Tuning），而是更基础的“完形填空”或“接龙”训练。

为了让你更容易理解，我把这段代码拆解成一个项目经理给机器下达的 Todo List（任务清单）。

📋 任务清单：LLM 预训练流水线

整个脚本 run_pt 就是在按顺序执行以下 7 个任务：

  1. 准备“翻译官” (Tokenizer)：加载分词器，决定怎么把文字变成数字。
  2. 准备“教材” (Dataset)：把原始文本处理成模型能读懂的格式。
  3. 请出“学生” (Model)：加载大模型本身。
  4. 组建“教务处” (Trainer)：配置训练管理器，准备好怎么喂数据。
  5. 开始“上课” (Training)：如果要求训练，就开始跑进度条，并记录学习曲线。
  6. 期末“考试” (Evaluation)：如果要求评估，就测试模型的困惑度（Perplexity）。
  7. 发“成绩单” (Model Card)：生成模型名片，保存结果。

🧐 逐步详解（对应代码）

现在我们把这个 List 展开，一段一段对应代码里的逻辑：

任务 1：准备“翻译官” (Tokenizer)

大模型看不懂中文英文，只看得懂数字。

tokenizer_module = load_tokenizer(model_args)
tokenizer = tokenizer_module["tokenizer"]
template = get_template_and_fix_tokenizer(tokenizer, data_args)
  • 解释：这里加载了分词器（Tokenizer）。它的作用是把“我爱吃苹果”切分成 ["我", "爱", "吃", "苹果"] 并转换成数字 ID。
  • 注意：get_template 这一步是为了确定对话模板，虽然预训练主要是跑纯文本，但有时候也需要处理特殊的格式。

任务 2：准备“教材” (Dataset)

dataset_module = get_dataset(template, model_args, data_args, training_args, stage="pt", **tokenizer_module)
  • 解释：get_dataset 负责读取你的 txt/json 文件。
  • 关键点：注意这里的 stage="pt"。这告诉系统：“我们要进行的是 Pre-Training (pt)，不是微调”。这意味着数据处理方式是“把文本连起来让模型预测下一个字”，而不是“一问一答”。

任务 3：请出“学生” (Model)

model = load_model(tokenizer, model_args, finetuning_args, training_args.do_train)
  • 解释：把神经网络模型（比如 Llama-3, Qwen 等）加载到显存里。这就是我们要训练的对象。

任务 4：组建“教务处” (Trainer)

在正式训练前，需要一个整理数据的工具（Collator）和一个统筹全局的管理者（Trainer）。

data_collator = DataCollatorForLanguageModeling(tokenizer=tokenizer, mlm=False)

trainer = CustomTrainer(
    model=model,
    args=training_args,
    ...
    data_collator=data_collator,
    ...
)
  • DataCollator：负责把数据打包成一个个 Batch（批次）喂给模型。
    • mlm=False 很关键！这代表我们做的是 Causal Language Modeling (因果语言建模)，也就是像 GPT 一样“根据上文预测下一个字”，而不是像 BERT 那样“填空”（Masked Language Modeling）。
  • CustomTrainer：这是 LLaMA-Factory 定制的训练器，它继承自 HuggingFace 的 Trainer，负责控制循环、保存存档、优化参数等脏活累活。

任务 5：开始“上课” (Training)

这是最核心、最耗时的部分。

if training_args.do_train:
    train_result = trainer.train(...) # 开始跑训练
    trainer.save_model()              # 保存训练好的模型
    trainer.log_metrics(...)          # 记录指标
    trainer.save_state()              # 保存训练状态
    if ... plot_loss:                 # 如果需要，画出 Loss 曲线图
        plot_loss(...)
  • 解释：
    1. 如果你的命令里写了 --do_train，这里就会开始疯狂运转 GPU。
    2. 跑完后，它会把模型权重保存到硬盘。
    3. plot_loss 会画一张图，告诉你随着时间推移，模型的错误率（Loss）是不是在下降。

任务 6：期末“考试” (Evaluation)

训练完了（或者只想测一下），看看模型有多聪明。

if training_args.do_eval:
    metrics = trainer.evaluate(...) # 跑测试集

    # 计算困惑度 (Perplexity)
    try:
        perplexity = math.exp(metrics["eval_loss"])
    except OverflowError:
        perplexity = float("inf")
    metrics["eval_perplexity"] = perplexity

    trainer.log_metrics("eval", metrics)
  • 解释：
    1. trainer.evaluate 会在验证集（模型没见过的数据）上跑一遍。
    2. Perplexity (困惑度)：这是代码中数学计算的部分。
      • 模型通过计算 Loss (损失) 来衡量好坏。
      • 但在语言模型中，我们更习惯看 Perplexity (PPL)。
      • 公式是 PPL = exp(Loss)。
      • 简单理解：困惑度越低，说明模型对下一个词的预测越有把握，模型越聪明。

任务 7：发“成绩单” (Model Card)

create_modelcard_and_push(trainer, ...)
  • 解释：最后一步，自动生成一个 README.md 文件（Model Card），记录你用了什么参数、什么数据、训练了多久。如果配置了 Hub Token，还会自动上传到 HuggingFace 网站。

总结

这段代码不需要你懂每一行具体的数学实现，你只需要知道它的逻辑流：

  1. 加载资源（分词器、数据、模型）。
  2. 配置管家（DataCollator 和 Trainer）。
  3. 如果训练 -> 跑循环，存模型，画图。
  4. 如果评估 -> 算 Loss，把 Loss 转换成困惑度 (PPL)。
  5. 收尾 -> 写文档。

这就是一个标准的 “喂书给模型读” 的过程。
