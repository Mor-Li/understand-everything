src/llamafactory/train/tuner.py

这个文件 src/llamafactory/train/tuner.py 可以被看作是整个 LlamaFactory 训练流程的 “总调度员” 或者 “控制中心”。

它的主要作用不是执行具体的数学计算（比如梯度下降），而是解析你的命令，然后把任务分发给具体的部门（具体的训练脚本）去执行。

为了让你更容易理解，我把这个文件做的事情拆解成一个 “任务清单 (Todo List)”，模拟一次训练任务从开始到结束的流程：

📋 LlamaFactory 训练任务清单 (由 tuner.py 执行)

1. 任务启动与环境检查 (Entry Point)

对应代码函数： run_exp * Todo: 接收用户输入的指令（命令行参数）。 * Todo: 检查是否需要使用 Ray（一个分布式计算框架）。 * 如果用 Ray，就启动 Ray 的训练器。 * 如果不用，直接在本地开始运行训练函数 _training_function。

2. 准备工具箱 (Preparation)

对应代码函数： _training_function (前半部分) * Todo: 解析参数。将用户的一长串命令拆解为： * model_args: 模型相关（比如用 Llama 3 还是 Qwen）。 * data_args: 数据相关（用什么数据集）。 * finetuning_args: 微调策略（比如是 LoRA 还是全量微调）。 * training_args: 训练参数（学习率、Batch size 等）。 * Todo: 准备 Callbacks（回调函数/观察员）。 * 安装 LogCallback：负责记录日志。 * 安装 EarlyStoppingCallback：如果训练效果不再提升，提前终止，省电省钱。 * 安装 SwanLab / ReporterCallback：负责把训练过程画成图表展示给你看。

3. 任务分发 (Routing - 最核心的部分)

对应代码函数： _training_function (中间巨大的 if/elif 判断块) * Todo: 根据用户指定的 stage (阶段)，决定运行哪种训练模式： * 情况 A (pt): 如果是 Pre-Training（预训练），调用 run_pt。这通常是让模型读海量文本。 * 情况 B (sft): 如果是 Supervised Fine-Tuning（有监督微调），调用 run_sft。这是最常用的，教模型回答问题。 * 情况 C (rm): 如果是 Reward Modeling（奖励模型训练），调用 run_rm。教模型打分。 * 情况 D (ppo / dpo / kto): 如果是强化学习或偏好对齐，调用对应的 run_ppo, run_dpo 等。 * Todo: 检查是否启用了 mca (M-Core Adapter) 等特殊加速或多模态适配，如果有，调用对应的特殊版本函数。

4. 任务收尾 (Cleanup)

对应代码函数： _training_function (最后部分) * Todo: 训练结束后，清理分布式进程（dist.destroy_process_group），释放 GPU 资源，防止显存泄露。

5. 产品打包与出货 (Export)

对应代码函数： export_model (这是一个独立的功能) * Todo: 当你训练完想把模型拿去用时，这个函数负责： 1. 加载原本的底座模型（Base Model）。 2. 加载你训练好的参数（Adapter/LoRA）。 3. 合并 (Merge)：把 LoRA 参数融合进底座模型里。 4. 量化 (Quantize)：如果需要，把模型压缩（比如转成 float16 或 int4）以减小体积。 5. 保存 (Save)：把最终的模型文件、Tokenizer（分词器）保存到指定目录。 6. 生成 Ollama配置: 顺便生成一个 Modelfile，方便你直接导入到 Ollama 里运行。

总结一下文中的核心观点

如果不看代码细节，这个文件其实就在表达一个观点：

“我是整个系统的路由（Router）。不管你想做什么（预训练、微调、RLHF 还是导出模型），都先来找我。我会帮你整理好配置，监控好过程，然后把你指派给专门负责那个任务的专家去干活。”

对于你的学习建议： 如果你想修改训练的具体逻辑（比如 Loss 怎么算，数据怎么喂），不要看这个文件，这个文件只是个“皮”。你应该去 src/llamafactory/train/sft/workflow.py 或者 trainer.py 这种具体目录下看。这个文件只是负责把流程串起来。
