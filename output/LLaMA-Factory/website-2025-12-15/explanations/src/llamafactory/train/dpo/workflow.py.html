src/llamafactory/train/dpo/workflow.py

这份代码文件 workflow.py 是 LlamaFactory 中用于执行 DPO (Direct Preference Optimization) 训练任务的“总指挥”或“流程脚本”。

简单来说，DPO 是一种让大模型“对齐”人类喜好的技术（类似于 RLHF，但更简单）。这个脚本的作用就是把所有需要的零件（模型、数据、分词器、训练器）组装起来，然后按顺序执行训练。

为了让你更容易理解，我们可以把这个过程想象成“教一个学生（模型）学会分辨好坏（DPO）”的过程。

下面是一个按顺序列出的 Task Todo List，对应代码中的执行步骤：

DPO 训练流程 Task List

✅ 第一步：准备教具（加载基础组件）

任务： 拿出课本（Tokenizer）、制定答题格式（Template）、准备练习题（Dataset）和叫出学生（Model）。 * 代码位置： 函数开头 tokenizer_module = ... 到 model = load_model(...)。 * 解读： 1. 加载分词器 (load_tokenizer)：机器看不懂汉字，需要分词器把字变成数字。 2. 获取模版 (get_template...)：不同的模型说话格式不同（比如 user/assistant 标签），这里要确定好格式。 3. 加载数据集 (get_dataset)：DPO 需要特殊的数据，必须是成对的（Pairwise），即“同一个问题，答案 A 是好的，答案 B 是坏的”。 4. 加载模型 (load_model)：把我们要训练的大模型加载到显存里。

✅ 第二步：整理试卷（数据整理器）

任务： 把练习题打包整理好，确保格式整齐，方便批改。 * 代码位置： data_collator = PairwiseDataCollatorWithPadding(...) * 解读： * 这里用了一个特殊的整理器 PairwiseDataCollator。 * 因为它不仅要处理输入的文本，还要把数据整理成“好答案”和“坏答案”的对比格式，并处理填充（Padding）以保证长度一致。

✅ 第三步：设立对照组（创建参考模型）

任务： 找一个“原来的自己”作为参照物，防止学生学得太偏激，连话都不会说了。 * 代码位置： if finetuning_args.use_ref_model: 这一块。 * 解读： * DPO 的核心原理需要一个 Reference Model (参考模型)。 * 通常参考模型就是训练前的模型副本。 * 训练时，我们会比较“当前模型”和“参考模型”的输出差异。如果当前模型改动太大（偏离初心），DPO 算法会进行惩罚。 * 代码逻辑：如果没指定特定的参考模型，就默认复制一份当前模型作为参考。

✅ 第三步半：聘请老师（初始化训练器）

任务： 组建一个班级，把学生、对照组、试卷、教具都交给老师。 * 代码位置： trainer = CustomDPOTrainer(...) * 解读： * 这里实例化了 CustomDPOTrainer。这是 LlamaFactory 定制的训练器，继承自 HuggingFace 的工具。 * 它把模型 (model)、参考模型 (ref_model)、数据 (data_collator) 等所有东西都装进去了，准备开跑。

✅ 第四步：开始上课（执行训练）

任务： 如果配置里说了要训练 (do_train)，那就开始刷题！ * 代码位置： if training_args.do_train: 内部。 * 解读： 1. trainer.train()：这是最核心的一行，开始漫长的训练循环（前向传播、算 Loss、反向传播、更新参数）。 2. trainer.save_model()：学完了，把训练好的模型参数保存到硬盘。 3. 记录指标：计算一下每秒处理多少个 token（看训练速度快不快）。 4. 画图 (plot_loss)：如果配置了画图，会生成 Loss 曲线图，让你直观看到学生是不是越学越好（Loss 应该下降，Reward 应该上升）。

✅ 第五步：期末考试（执行评估）

任务： 如果配置里说了要评估 (do_eval)，就做一套没见过的题，看看水平。 * 代码位置： if training_args.do_eval: 内部。 * 解读： * trainer.evaluate()：用验证集（Eval Dataset）跑一遍，不更新参数，只看分数。 * 特殊逻辑：代码里有一句 if id(model) == id(ref_model)。意思是，如果你是为了省显存，没加载额外的参考模型（用了同一个对象），那么就没法计算准确的 Reward（奖励分），所以要把奖励相关的指标删掉，免得误导。

✅ 第六步：发毕业证（生成模型卡片）

任务： 训练结束，写一份说明书，告诉大家这个模型是怎么练出来的，并上传到网盘（HuggingFace Hub）。 * 代码位置： 最后一行 create_modelcard_and_push(...) * 解读： * 自动生成 README.md，记录你的训练参数（比如学习率、Batch size），方便以后复现。

总结

这段代码其实就是一个标准的流水线（Workflow）：

  1. 进货（Load Model/Data）
  2. 加工前处理（Collate/Ref Model）
  3. 组装机器（Init Trainer）
  4. 开机生产（Train）
  5. 质检（Eval）
  6. 出货（Save/Push）

你看不懂可能是因为里面有很多 LlamaFactory 封装的函数（比如 get_dataset, load_model），但你只需要知道它们是负责“拿东西”的，核心逻辑就是上面这个清单。
