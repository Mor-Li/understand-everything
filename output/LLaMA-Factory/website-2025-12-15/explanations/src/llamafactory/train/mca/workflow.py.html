src/llamafactory/train/mca/workflow.py

这份代码文件 workflow.py 位于 src/llamafactory/train/mca/ 目录下，它的核心作用是作为一座“桥梁”。

它连接了 LLaMA-Factory（易用的微调框架）和 Megatron-Core (MCA)（NVIDIA 开发的高性能、大规模分布式训练框架）。

简单来说，这个文件的目的是：让 LLaMA-Factory 能够调用 Megatron-Core 的底层能力来进行预训练（PT）、指令微调（SFT）和偏好优化（DPO）。

为了让你看懂，我把它拆解成一个“任务清单 (To-Do List)”，然后逐个任务给你讲解代码在干什么。

📋 任务清单 (Task To-Do List)

想象你是一个负责训练大模型的项目经理，要运行这个脚本，你需要按顺序完成以下任务：

  1. [环境检查]：确认安装了高性能引擎（mcore_adapter）。
  2. [工具准备]：准备好分词器（Tokenizer）和数据处理模板。
  3. [数据预处理]：
    • 加载数据集。
    • 关键动作：对数据长度做特殊处理（错位切割）。
    • 关键动作：对输入数据做“左移/右移”操作（为了预测下一个token）。
  4. [模型加载]：检查模型是否支持，并加载 Megatron 版本的模型结构。
  5. [选择训练模式]：
    • 任务 A (run_pt)：跑预训练（Pre-Training）。
    • 任务 B (run_sft)：跑指令微调（Supervised Fine-Tuning），含多模态特殊处理。
    • 任务 C (run_dpo)：跑偏好优化（DPO），需要加载参考模型。
  6. [开始训练]：启动训练器，保存模型，画损失函数图。

🚀 逐步详细讲解

下面我按照上面的清单，结合代码给你讲讲它具体是怎么实现的。

1. 环境检查 (Check Environment)

代码开头有一段检查：

if not is_mcore_adapter_available():
    raise ImportError(...)
  • 含义：因为这是专门针对 Megatron-Core 的流程，如果你的环境里没装 mcore-adapter 这个包，程序直接报错退出。这是为了防止你用错误的配置跑代码。

2. 工具准备 (Prepare Tools)

在每个 run_xxx 函数的开头，都有类似的代码：

tokenizer_module = load_tokenizer(model_args)
tokenizer = tokenizer_module["tokenizer"]
template = get_template_and_fix_tokenizer(tokenizer, data_args)
  • 含义：加载分词器（把文字变成数字的工具）和对话模板（比如 User/Assistant 的格式）。这是所有训练的基础。

3. 数据预处理 (Data Pre-processing) - 核心难点

这里有两个非常细节的处理逻辑，是这段代码的精华：

A. 长度的小把戏 (cutoff_len)

data_args.cutoff_len += 1
dataset_module = get_dataset(...)
data_args.cutoff_len -= 1
  • 为什么？ 训练大模型是“预测下一个字”。如果你想要训练长度为 1024 的序列，你实际需要 1025 个 token。前 1024 个做输入，后 1024 个（从第2个开始到第1025个）做答案。
  • 操作：所以代码先偷偷把截断长度 +1，加载完数据后，再把参数改回来。

B. 数据的错位处理 (_data_collator_wrapper) 代码定义了一个 _data_collator_wrapper 函数：

feature["labels"] = feature["input_ids"][1:]  # 标签是输入的后一位
feature["input_ids"] = feature["input_ids"][:-1] # 输入去掉最后一位
  • 含义：这是标准的 Causal Language Modeling（因果语言模型）处理。
    • 输入：A B C D
    • 标签：B C D E
    • Megatron-Core 可能需要我们在送入模型前手动做好这个切分，而普通的 HuggingFace 模型有时是在模型内部做的。这里显式地处理了数据的“错位”。

4. 模型加载 (Load Model)

_check_model_support(model_args)
model = AutoModel.from_pretrained(..., training_args)
  • 含义：
    1. 先检查你的模型（比如 Llama3, Qwen2）是否在 MCA 的支持列表里。不支持就报错。
    2. 使用 mcore_adapter.models.AutoModel 加载模型。注意，这里用的不是 transformers 的 AutoModel，而是适配了 Megatron 分布式并行的版本。

5. 选择训练模式 (Training Modes)

文件里定义了三个主要函数，对应三种训练阶段：

任务 A: run_pt (预训练) * 特点：最简单。 * 流程：加载数据 -> 包装数据整理器（Collator） -> 启动 McaTrainer -> 训练并保存。

任务 B: run_sft (指令微调) * 特点：处理问答数据，且包含多模态（视觉）模型的特殊逻辑。 * 多模态冻结逻辑： python if getattr(model.config, "hf_model_type", None) in ["qwen2_vl", "qwen2_5_vl"]: # ... 冻结 vision_tower (看图的眼睛) # ... 冻结 projector (连接眼睛和大脑的神经) # ... 冻结 language_model (大脑) 这段代码专门针对 Qwen2-VL 系列模型。在微调时，用户可能只想训练其中的一部分（比如只练语言模型，不练视觉部分），这里根据参数把不需要训练的层锁住（requires_grad_(False)）。

任务 C: run_dpo (偏好优化) * 特点：需要两个模型（当前模型 + 参考模型）。 * 逻辑： python if finetuning_args.use_ref_model: # 复制一个模型作为 referee (裁判/参考) ref_model = AutoModel.from_config(ref_config) DPO 算法需要对比“新模型生成的概率”和“老模型生成的概率”，所以这里加载了一个 ref_model。 * 训练器：使用的是 McaDPOTrainer，专门用于处理 DPO 的损失函数。

6. 开始训练与收尾 (Train & Plot)

在每个函数的最后：

trainer.train(...)
trainer.save_model()
plot_loss(...)
  • 含义：
    1. Train：开始在这个高性能分布式框架上跑训练。
    2. Save：保存训练好的权重。
    3. Plot：如果是在主进程（process_zero），画出 Loss 曲线图，让你直观看到模型有没有变聪明。

总结

一句话概括： 这个文件是 LLaMA-Factory 的“Megatron-Core 插件”。它负责把数据切好（错位处理）、把模型加载好（适配分布式）、并根据你是要预训练、微调还是DPO，选择正确的流程启动高性能训练。
