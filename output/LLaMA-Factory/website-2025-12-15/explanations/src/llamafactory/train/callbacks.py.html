src/llamafactory/train/callbacks.py

这份代码文件 callbacks.py 定义了一系列 “回调函数”（Callbacks）。

为了让你听懂，我们可以把训练模型想象成在大厨（Trainer）在厨房里做一道极其复杂的菜（训练过程）。

而这个文件里的代码，就是大厨身边的几个专门的小助手。他们不负责炒菜（不涉及核心梯度下降算法），但负责在特定时间点打杂，比如“刚开火时”、“炒到一半时”、“关火时”做一些记录和整理工作。

我为你列一个 Task Todo List（任务清单），按照这些助手的功能，一步步带你过一遍：

任务清单：LlamaFactory 训练小助手的日常

✅ Task 1: 负责“记账”和“看表”的秘书 —— LogCallback

这是最长的一个类，也是最常用的。 * 场景：大厨在炒菜，每炒几下（Step），就需要有人记录现在的火候（Loss）、尝尝咸淡（Eval）、看看还要炒多久。 * Todo List: 1. 开始计时 (on_train_begin)：一开火，记录开始时间，初始化线程池。 2. 计算进度 (on_log)： * 算算现在炒了百分之几了？ * 估算一下 remaining_time（剩余时间）还要多久？ * 看看显存（VRAM）占用了多少？ 3. 写日记 (_write_log)：把上面的数据写到一个叫 trainer_log.jsonl 的文件里，方便以后复盘。 4. 监听老板指令：如果你在网页界面（WebUI）上点了“停止训练”，它会负责接收这个信号 (aborted)，告诉大厨赶紧停手。

✅ Task 2: 负责“保管工具”的保管员 —— SaveProcessorCallback

  • 场景：模型训练好（存盘）的时候，光存模型参数（大脑）是不够的，还得存“分词器”（Processor/Tokenizer，相当于嘴巴和耳朵）。否则模型有脑子但听不懂人话。
  • Todo List:
    1. 存盘时 (on_save)：每当大厨保存模型进度（Checkpoint）时，顺手把分词器（Processor）也存到同一个文件夹里。
    2. 结束时 (on_train_end)：做完菜了，最后再确认存一次分词器。

✅ Task 3: 负责“对外汇报”的通讯员 —— ReporterCallback

  • 场景：你需要用 WandB 或 SwanLab 这种可视化工具在网页上监控训练。
  • Todo List:
    1. 汇报配置 (on_train_begin)：刚开始训练时，把所有的参数（比如学习率多少、数据路径在哪、模型参数是啥）打包发送给 WandB 或 SwanLab 服务器。这样你在网页上就能看到这次实验的具体配置了。

✅ Task 4: 负责“特殊零件维修”的技工 —— FixValueHeadModelCallback

  • 场景：这涉及到 RLHF（人类反馈强化学习）。这种训练方式会给模型加一个额外的“评价头”（Value Head）。HuggingFace 的默认保存机制有时候存这种模型会乱（比如文件切分不对，或者用了 DeepSpeed 后参数没对齐）。
  • Todo List:
    1. 存盘后修复 (on_save -> fix_valuehead_checkpoint)：
      • 每当模型保存后，这个技工立刻冲进去。
      • 检查保存的文件里，模型本体和“评价头”是不是混在一起了？
      • 动作：把它们拆分开，整理好，重新保存成标准格式。确保下次加载时不会报错。

✅ Task 5: 负责“魔改转换”的专家 —— PissaConvertCallback

  • 场景：PiSSA 是一种比较新的微调技术（类似 LoRA，但初始化方式不同）。它在训练开始和结束时，需要对参数做特殊的数学转换，才能变成通用的格式。
  • Todo List:
    1. 开始前 (on_train_begin)：保存一份初始状态的 PiSSA 适配器，作为基准。
    2. 结束后 (on_train_end)：
      • 把训练好的 PiSSA 参数进行转换。
      • 把它变成标准的 LoRA 格式保存下来（这样你以后推理时，就可以像用普通 LoRA 一样用它了）。
      • 清理掉中间产生的临时文件。

总结

这个文件 callbacks.py 实际上就是在回答一个问题：

“在使用 Hugging Face Trainer 标准训练流程之外，LlamaFactory 还需要额外做哪些琐事？”

  • 琐事 1：我要更详细的日志和进度条 (LogCallback)。
  • 琐事 2：我要确保分词器不丢失 (SaveProcessorCallback)。
  • 琐事 3：我要把配置发给 WandB (ReporterCallback)。
  • 琐事 4：我要修补 RLHF 模型保存的 Bug (FixValueHeadModelCallback)。
  • 琐事 5：我要处理 PiSSA 这种特殊微调方法的格式转换 (PissaConvertCallback)。

你看懂了吗？其实就是给大厨配了 5 个不同功能的打杂小工。
