src/llamafactory/eval/template.py

这份代码看起来确实比较抽象，因为它主要处理的是数据格式化（String Formatting）的工作。

简单来说，这个文件的作用是：把一道道原始的考试题（比如 Excel 或 JSON 里的数据），变成大模型（LLM）能看懂的“对话格式”，用来测试这个模型聪不聪明。

为了让你彻底理解，我为你制定了一个 5步走的 Task List（待办清单）。我们一步一步来拆解这个文件。

📝 Task 1：理解“原材料”和“成品”

目标：搞清楚这个代码的输入（Input）和输出（Output）是什么。

  • 原材料（Input）： 通常是一道单项选择题的原始数据，长这样（字典格式）： python example = { "question": "天空是什么颜色的？", "A": "红色", "B": "蓝色", "C": "绿色", "D": "黄色", "answer": "B" }
  • 成品（Output）： 我们要把它变成模型能读懂的 prompt（提示词），长这样： text 天空是什么颜色的？ A. 红色 B. 蓝色 C. 绿色 D. 黄色 答案： 并且，还要把它包装成 [{"role": "user", ...}, {"role": "assistant", ...}] 这样的对话列表。

结论：这个文件的核心工作就是搬运工，把 Input 变成 Output。

🧱 Task 2：拆解模版类 EvalTemplate 的三个零件

目标：理解代码中 @dataclass class EvalTemplate: 定义了哪三个核心零件。

代码里定义了三个字符串变量，它们就像是“填空题”的模版：

  1. system (系统指令)：
    • 告诉模型它在干什么。
    • 代码例子："以下是中国关于{subject}考试的单项选择题..."
  2. choice (选项格式)：
    • 定义选项怎么排版。
    • 代码例子："\n{choice}. {content}" （意思就是：换行 + 选项字母 + 点 + 选项内容）。
  3. answer (回答引导词)：
    • 提示模型该开始回答了。
    • 代码例子："\n答案："

结论：这三个变量定义了考卷的“排版风格”。

⚙️ Task 3：解析单道题目 (_parse_example 方法)

目标：看懂 def _parse_example(...) 这个函数在干嘛。

这个函数是核心逻辑。它的工作流程如下：

  1. 找选项：代码里有一句 candidates = [...]。它会遍历 CHOICES（通常是 A, B, C, D）。如果题目里有 "A"，它就套用 Task 2 里的 choice 模版，变成 "A. 红色"。
  2. 拼凑问题：它把 question（题目） + candidates（处理好的选项） + self.answer（引导词“答案：”）全部拼成一个长字符串。
  3. 提取答案：它把正确答案（比如 "B"）单独拿出来。

代码对应逻辑：

输入：{"question": "...", "A": "...", ...} 输出元组：( "题目... A. xxx... 答案：", "B" )

📦 Task 4：组装整张考卷 (format_example 方法)

目标：理解 def format_example(...) 如何处理“少样本学习”（Few-shot）并生成最终消息列表。

在大模型评估中，我们通常会在问正式问题前，先给它看几个例题（这叫 Support Set / Few-shot）。

这个函数的逻辑是： 1. 创建消息列表：messages = []。 2. 处理例题（Support Set）： * 如果提供了例题（support_set），它会循环遍历。 * 把每个例题变成一轮对话：User 说题目，Assistant 说正确答案。 * 目的：让模型照猫画虎，学会答题格式。 3. 处理当前题目（Target Data）： * 把我们要考的那道题，处理成 User 的话，加入列表。 * 把正确答案放入 Assistant 的话（用于后续比对，或者训练时计算 loss）。 4. 注入系统提示词（System Prompt）： * 代码：messages[0]["content"] = self.system.format(...) + ... * 它把 Task 2 里的 system（比如“这是关于化学的考试...”）强行加到了第一条消息的最前面。

结论：这个函数输出了最终喂给模型的完整对话历史。

🗂️ Task 5：注册菜单 (_register_eval_template)

目标：理解文件底部的代码在做什么。

文件最后几行代码是在“注册”模版。你可以把它想象成餐厅的菜单：

  • en (英文套餐)：
    • System: "The following are multiple choice questions..."
    • Answer: "Answer:"
  • zh (中文套餐)：
    • System: "以下是中国关于{subject}考试的..."
    • Answer: "答案："

get_eval_template 函数就是服务员，你说我要 "zh" 模版，它就给你拿中文的那套格式配置。

总结 (Summary)

这段代码讲了什么？ 它定义了一个试卷排版机。

  1. 它不管题目内容是什么，只管排版。
  2. 它规定了中文考试怎么排版（用中文提示词），英文考试怎么排版（用英文提示词）。
  3. 它负责把 Excel/JSON 里的原始数据，拼接成 ChatGPT/LLM 能够理解的 User: 题目... Answer: ? 这种对话格式。
