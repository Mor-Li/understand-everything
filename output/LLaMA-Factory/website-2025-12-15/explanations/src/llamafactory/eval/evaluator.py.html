src/llamafactory/eval/evaluator.py

这份代码 evaluator.py 的核心作用是给大模型“监考”。

具体来说，它是用来自动化评估大语言模型在选择题任务（比如 MMLU、CMMLU 这种学术评测集）上的表现的。它不让模型生成一长串文字，而是让模型在 A、B、C、D 四个选项中选出概率最高的一个，然后算出准确率。

为了让你更容易理解，我们可以把这个 Evaluator 类想象成一个“监考老师”。下面是这位监考老师的工作清单（To-Do List）：

📋 监考老师的任务清单 (To-Do List)

Phase 1: 考前准备 (初始化阶段)

  • [ ] Task 1.1: 领卷子和文具 (__init__)
    • 加载需要被测试的模型（Model）和分词器（Tokenizer）。
    • 准备好“答题卡”的格式（Template），比如是英文考试还是中文考试。
    • 关键点：提前记下 "A", "B", "C", "D" 这四个字母在模型字典里对应的 ID。因为之后只看这四个选项的概率。

Phase 2: 了解考试范围 (Eval 主流程开始)

  • [ ] Task 2.1: 查看考纲 (eval 方法开头)
    • 确定要考哪个题库（比如 MMLU 或 CMMLU）。
    • 读取 mapping.json，弄清楚有哪些科目（比如“高等数学”、“中国历史”），以及这些科目属于什么大类（比如“理科”、“文科”）。

Phase 3: 逐科考试 (循环处理每个科目)

  • [ ] Task 3.1: 发卷子 (load_dataset)
    • 下载并加载当前科目（例如“高中物理”）的题目数据。
  • [ ] Task 3.2: 举例示范 (Few-shot) (format_example)
    • 为了让模型表现更好，通常不会直接问问题。
    • 监考老师会在考题前先给几个“例题”（Support Set）。
    • 格式变成：问题1: ... 答案: A\n\n 问题2: ... 答案: C\n\n (正式考题): ... 答案:，引导模型补全最后一个字。
  • [ ] Task 3.3: 把卷子塞进模型 (template.encode_oneturn)
    • 把上面的文本转换成模型能看懂的数字（Input IDs）。

Phase 4: 答题与阅卷 (核心推理)

  • [ ] Task 4.1: 批量答题 (batch_inference)
    • 这是最硬核的一步。模型不需要生成一整句话。
    • 模型读完题目后，计算下一个字是 A、B、C、D 的概率分别是多少。
    • 决策：谁的概率最大，就选谁。比如 B 的概率是 80%，那就选 B。
  • [ ] Task 4.2: 现场判分 (corrects = ...)
    • 拿模型的预测结果（比如 "B"）和标准答案（比如 "B"）对比。
    • 对了这个科目就加分。

Phase 5: 汇总成绩单 (收尾)

  • [ ] Task 5.1: 统计分数 (_save_results)
    • 计算每个大类（STEM、人文、社科等）的平均准确率。
    • 计算总平均分。
  • [ ] Task 5.2: 公布并存档
    • 在屏幕上打印分数。
    • 把具体的错题、对题记录保存成 JSON 文件，方便人类复查。

1. 为什么只看 A/B/C/D？

在 __init__ 里：

# 提前把 A,B,C,D 对应的数字编码找出来
self.choice_inputs = [self.tokenizer.encode(ch, ...)[-1] for ch in CHOICES]

在 batch_inference 里：

# 算出所有词的概率
logits = self.model(**batch_input).logits
# ...省略中间步骤...
# 只把 A,B,C,D 四个位置的概率拿出来比较，softmax 归一化
choice_probs = torch.nn.functional.softmax(word_probs[:, self.choice_inputs], dim=-1)
# 选概率最大的那个作为预测结果
return [chr(ord("A") + offset.item()) for offset in torch.argmax(choice_probs, dim=-1)]

解释：这比让模型生成文本（Generate）要快得多，也更准确，因为我们强行限制模型只能在选项里选。

2. 怎么做“几-shot” (Few-shot)？

在 eval 循环里：

# 从训练集中随机抽 n_shot 个样本作为例题
support_set = dataset["train"].shuffle().select(range(min(self.eval_args.n_shot, ...)))
# 把例题和正式考题拼在一起
messages = self.eval_template.format_example(..., support_set=support_set, ...)

解释：这就是所谓的“上下文学习”（In-Context Learning），给模型几个例子，它能模仿例子的格式来答题。

总结

这个脚本就是一个专门做选择题的流水线： 1. 加载模型。 2. 下载题库。 3. 拼凑提示词（包含几个例题）。 4. 看模型觉得 A/B/C/D 哪个概率大。 5. 算分并保存。
