src/llamafactory/api/common.py

没问题，这段代码乍一看确实有点枯燥，因为它全是后端 API 的“幕后工作”，主要是为了安全和数据格式转换服务的。

你可以把这个文件 common.py 想象成一个“办事大厅的安检员兼翻译官”。它的工作就是确保进来的请求是安全的，并且把数据翻译成通用的格式。

我们把它拆解成一份 “安检员的每日工作清单 (ToDo List)”，一步步来看它在干嘛：

📋 安检员的工作清单 (Task List)

✅ 任务 1：准备工作环境 (设置变量)

代码对应： 开头的 import 和 SAFE_MEDIA_PATH, ALLOW_LOCAL_FILES * 他在干嘛： * 安检员上班了，先确认一下：“我有 fastapi 这个工具吗？”（如果有，就拿出来用）。 * 划定安全区：他在环境里设了一个红线，叫 SAFE_MEDIA_PATH。意思是：“以后存取文件，只能在这个文件夹（保险箱）里，别的地方不许碰。” * 查看开关：看一眼 ALLOW_LOCAL_FILES 开关开了没。如果没开，谁也别想读取本地文件。

✅ 任务 2：当个好翻译 (数据格式化)

代码对应： dictify 和 jsonify 函数 * 他在干嘛： * 系统里有很多复杂的数据对象（叫 BaseModel，来自 Pydantic 库）。 * 外界（比如前端网页）看不懂这些对象，只看得懂 字典 (Dict) 或者 JSON 字符串。 * dictify：把复杂对象变成 Python 字典。 * jsonify：把复杂对象变成一串文本（JSON）。 * 特殊处理：你会看到 try...except，这是因为 Pydantic 这个库有两个版本（v1 和 v2），写法不一样。安检员很贴心：“不管你用旧版还是新版，我都能给你翻译对。”

✅ 任务 3：【重头戏】检查文件路径，防止家被偷 (LFI 防护)

代码对应： check_lfi_path(path) * 背景知识：黑客可能会发一个路径叫 ../../windows/system32 试图读取你服务器的系统文件，这叫 LFI (本地文件包含) 攻击。 * 安检流程： 1. 第一关：先看总开关 ALLOW_LOCAL_FILES。如果没开，直接拒绝：“对不起，禁止访问本地文件。” 2. 第二关：确定“保险箱”在哪 (SAFE_MEDIA_PATH)。 3. 第三关：拿到用户想看的文件路径，算出它的真实绝对路径 (realpath)。 4. 第四关 (核心)：比对一下。用户想看的文件，是不是乖乖呆在“保险箱”目录里？ * 如果是 safe_media/image.jpg -> 放行。 * 如果是 safe_media/../../etc/passwd (试图跳出目录) -> 报警 (报错 403)：“你越界了！只能访问安全目录里的文件。”

✅ 任务 4：【重头戏】检查网址，防止内鬼泄密 (SSRF 防护)

代码对应： check_ssrf_url(url) * 背景知识：假设你的服务器能访问外网，也能访问内网（比如公司内部数据库）。黑客可能会骗你的服务器去访问 http://192.168.1.1 (内网地址)，借你的手偷内网数据。这叫 SSRF (服务端请求伪造)。 * 安检流程： 1. 第一关：检查协议。是不是 http 或 https？如果是什么 ftp:// 或 file://，直接拒绝。 2. 第二关：提取域名（Hostname）。 3. 第三关 (照妖镜)：把域名解析成 IP 地址。 * 比如把 google.com 解析成 142.250.x.x。 4. 第四关 (核心)：检查这个 IP 是公网 (Global) 的还是私网 (Private) 的。 * 如果是公网 IP -> 放行。 * 如果是私网 IP (比如 127.0.0.1, 192.168.x.x, 10.x.x.x) -> 报警 (报错 403)：“禁止访问内部网络或私有地址！”

💡 总结一下

这个文件的核心观点只有两个：

  1. 兼容性 (Compatibility)：帮程序处理不同版本的数据格式转换，让数据能顺畅流通。
  2. 防御性编程 (Security)：
    • 不信任用户输入的文件路径（怕你偷看服务器系统文件）。
    • 不信任用户输入的网址（怕你利用服务器去扫描内网）。

它就像是一个极其谨慎的看门大爷，每当有数据要进出，他都要查证件、查包裹，确保没有危险品。
