Makefile

没问题，这个文件（Makefile）其实不是用来写代码逻辑的，而是给开发者用的“快捷指令菜单”。

在开发大型 Python 项目时，我们经常要重复敲很长的命令（比如测试、打包、格式化代码）。Makefile 的作用就是把这些长命令起一个短名字，你只需要敲 make <名字>，它就会自动执行后面的一串操作。

我们可以把学习这个文件当成一个入职新项目的 To-Do List。请按以下顺序一步步来理解：

任务 1：搞懂“操作范围” (Variables)

目标：知道这些命令会对哪些文件夹生效。

  • 代码行：check_dirs := scripts src tests tests_v1 setup.py
  • 解释：这里定义了一个变量叫 check_dirs。
  • 含义：后续所有的检查、格式化、测试命令，都只会针对这几个文件夹或文件进行操作（即：脚本目录、源码目录、测试目录、安装文件）。

任务 2：搞懂“代码美容” (Style & Quality)

目标：学会如何保持代码整洁。这里有两个命令，一个是“只看不改”，一个是“直接帮我改”。

步骤 A：检查质量 (quality) * 命令：make quality * 代码内容： * ruff check $(check_dirs): 用 ruff 工具检查代码有没有 bug 或不规范的地方。 * ruff format --check $(check_dirs): 检查代码排版（缩进、空格）是否漂亮。注意这里的 --check，意思是我只告诉你哪里乱了，但我不修改文件。 * 场景：通常在提交代码前运行，看看自己有没有写出“脏”代码。

步骤 B：一键美颜 (style) * 命令：make style * 代码内容： * ruff check $(check_dirs) --fix: 检查代码，并且自动修复能修的问题。 * ruff format $(check_dirs): 直接把代码排版自动格式化成标准样子。 * 场景：写完代码乱糟糟的，运行一下这个，代码瞬间变得整齐划一。

任务 3：搞懂“代码测试” (Test)

目标：学会如何验证代码是对的。

  • 命令：make test
  • 代码内容：
    • CUDA_VISIBLE_DEVICES= 和 ASCEND_RT_VISIBLE_DEVICES=0: 这些是环境变量。意思是屏蔽掉显卡/GPU（或者指定特定设备），强制用 CPU 跑测试，防止占用宝贵的训练资源。
    • WANDB_DISABLED=true: 关掉 WandB（一个记录训练数据的工具），因为跑测试不需要记录数据。
    • pytest -vv ...: 运行 Python 的测试工具 pytest，去跑 tests/ 文件夹里的测试用例。
  • 场景：改完代码后，必须跑这个，确保没把以前的功能改坏。

任务 4：搞懂“打包发布” (Build)

目标：学会如何把项目变成一个安装包。

  • 命令：make build
  • 代码内容：
    • pip3 install build: 先安装打包工具。
    • python3 -m build: 运行打包命令。
  • 场景：当你准备把这个项目发布到 PyPI 或者发给别人安装时使用。它会生成 .whl 或 .tar.gz 文件。

任务 5：搞懂“提交规范” (Commit & License)

目标：学会项目管理的杂项检查。

步骤 A：版权检查 (license) * 命令：make license * 代码内容：运行一个 Python 脚本 check_license.py，检查所有文件头部是不是都写了版权声明（比如 "Copyright 2024..."）。

步骤 B：提交钩子 (commit) * 命令：make commit * 代码内容： * pre-commit install: 安装 git 的钩子（hook）。 * pre-commit run --all-files: 立即对所有文件运行一遍检查。 * 场景：这是为了防止你把垃圾代码 git push 上去。安装后，每次你 git commit 时，它都会自动帮你检查代码格式。

总结：你应该怎么用？

如果你下载了这个项目，你在终端（Terminal）里只需要敲以下简短的命令：

  1. 写完代码想偷懒自动排版？ $\rightarrow$ 敲 make style
  2. 想看看代码有没有逻辑错误？ $\rightarrow$ 敲 make quality
  3. 准备提交代码前，确保功能正常？ $\rightarrow$ 敲 make test
  4. 准备发布给别人用？ $\rightarrow$ 敲 make build

这个文件就是为了让你省去记忆 ruff check src tests ... --fix 这么长一串命令的麻烦。
