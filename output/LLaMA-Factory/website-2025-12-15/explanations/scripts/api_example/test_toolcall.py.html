这份代码的核心概念叫做 Tool Calling（工具调用） 或 Function Calling（函数调用）。

简单来说，大模型（LLM）虽然能聊天，但它算数经常算错，或者无法获取外部信息。工具调用就是给大模型装上“外挂”，让它在遇到无法解决的问题时，知道去调用一个写好的编程函数来得到准确结果。

为了让你看懂，我把这段代码拆解成一个 6步走的任务清单 (Task List)。你可以把这段脚本想象成一个 “中介”，它在 用户 和 大模型 之间跑腿。

📋 任务清单：让 AI 学会使用计算器

✅ Task 1: 准备“外挂”工具 (定义本地函数)

大模型不擅长做复杂的加权平均分计算，所以我们先用 Python 写好一个绝对准确的函数。

  • 代码对应： python def calculate_gpa(grades: list[str], hours: list[int]) -> float: # ...这里是具体的算分逻辑... return round(total_score / total_hour, 2)
  • 解读： 这就是那个“工具”。它接收成绩（A/B/C）和学分（3/4），算出 GPA。这部分完全是传统的编程，跟 AI 没关系。

✅ Task 2: 告诉 AI 它有哪些工具可用 (定义工具描述)

大模型看不懂上面的 Python 代码，我们需要用一种它能看懂的格式（JSON Schema）告诉它：“我有一个工具叫 calculate_gpa，你需要给我提供 grades 和 hours 这两个参数。”

  • 代码对应： python tools = [ { "type": "function", "function": { "name": "calculate_gpa", # 工具名字 "description": "Calculate the Grade Point Average...", # 告诉AI这工具是干啥的 "parameters": { ... } # 告诉AI需要提取什么参数 }, } ] tool_map = {"calculate_gpa": calculate_gpa} # 建立名字到函数的映射，方便一会调用
  • 解读： 这就像给 AI 发了一份“工具说明书”。

✅ Task 3: 用户提问 (第一轮对话)

用户提出了一个需要计算的问题。

  • 代码对应： python messages = [] messages.append({"role": "user", "content": "My grades are A, A, B, and C. The credit hours are 3, 4, 3, and 2."})
  • 解读： 用户说：“我成绩是A,A,B,C，学分是...”。注意，用户并没有直接要求调用函数，他在用自然语言说话。

✅ Task 4: AI 思考并决定“摇人” (获取 AI 响应)

我们将用户的问题和工具说明书一起发给 AI。AI 读了问题，发现自己算不准，于是决定：“既然你给了我 calculate_gpa 这个工具，那我要用它！”

  • 代码对应： ```python # 发送请求，带上 tools result = client.chat.completions.create(messages=messages, model="test", tools=tools)

    AI 返回的信息里包含 tool_calls，说明它想调用工具

    tool_call = result.choices[0].message.tool_calls[0].function print(tool_call)

    输出示例: name='calculate_gpa', arguments='{"grades": ["A", "A"...], "hours": [3, 4...]}'

    `` * **关键点：** AI **并没有** 运行代码。它只是返回了一个“请求单”，上面写着：“请帮我运行calculate_gpa，参数是['A', 'A'...]`”。

✅ Task 5: 脚本代替 AI 执行任务 (本地运行函数)

脚本（中介）收到了 AI 的请求单，在本地运行 Task 1 里写的 Python 函数，算出结果。

  • 代码对应： python # 1. 解析 AI 给出的参数 name, arguments = tool_call.name, json.loads(tool_call.arguments) # 2. 真的去运行那个 Python 函数 tool_result = tool_map[name](**arguments) # 3. 把结果包装成一条消息 messages.append({"role": "tool", "content": json.dumps({"gpa": tool_result}, ensure_ascii=False)})
  • 解读： 这里算出了 3.42。脚本把这个结果伪装成一条消息，准备发回给 AI。现在的对话历史看起来是这样的：
    1. 用户：我成绩是...（User）
    2. AI：我要调用 calculate_gpa...（Assistant）
    3. 工具：结果是 3.42 （Tool）

✅ Task 6: AI 生成最终回复 (第二轮对话)

AI 拿到了工具算出来的准确结果 3.42，它现在可以自信地回答用户了。

  • 代码对应： python # 再次请求 AI，这次 AI 知道了工具的运行结果 result = client.chat.completions.create(messages=messages, model="test", tools=tools) print(result.choices[0].message.content)
  • 解读： AI 输出：“根据您的成绩和学分，您的 GPA 是 3.42。” —— 任务完成。

💡 总结一下

这个脚本演示了一个完整的闭环：

  1. 定义工具（Python 函数）。
  2. 描述工具（JSON Schema）。
  3. AI 决定调用（AI 返回函数名和参数）。
  4. 外部执行（脚本运行函数）。
  5. AI 整合结果（AI 看到结果后，用人话回答用户）。

这就是大模型应用开发中最核心的 Agent（智能体） 原理的基础。
