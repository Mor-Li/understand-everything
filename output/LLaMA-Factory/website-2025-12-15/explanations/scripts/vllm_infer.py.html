scripts/vllm_infer.py

这份代码是一个用于 使用 vLLM 引擎进行模型推理（Inference） 的脚本。

简单来说，它的作用是：加载一个大模型（可以是纯文本，也可以是看图/看视频的多模态模型），喂给它一批数据，让它快速生成回答，并将结果保存下来。

vLLM 是目前最流行、速度最快的大模型推理加速库之一。

为了让你更容易理解，我把这个脚本的工作流程拆解成一个 “任务清单 (Todo List)”。想象一下，如果这个脚本是一个打工人，他的工作日志是这样的：

📋 脚本执行的 Task Todo List

  1. 【准备阶段】接需求与核对参数：看看用户要用哪个模型？哪个数据集？生成参数（温度、长度）是多少？
  2. 【工具准备】加载分词器与模板：拿出翻译书（Tokenizer）和对话格式模板（Template），准备处理文本。
  3. 【启动引擎】初始化 vLLM：启动高性能推理引擎，配置好显卡加速策略。
  4. 【获取原料】加载数据：把需要测试的问题（Dataset）从硬盘里读出来。
  5. 【设定规则】配置采样参数：规定模型回答时的创造力（Temperature）、惩罚重复内容等规则。
  6. 【核心工作】批量推理 (Batch Inference)：
    • 子任务 6.1：把数据分成小批次（Batch）。
    • 子任务 6.2：处理多模态内容（如果有图片、视频、音频，把它们格式化）。
    • 子任务 6.3：让 vLLM 引擎开始生成回答。
    • 子任务 6.4：收集结果。
  7. 【收尾工作】保存结果：把所有的问题、标准答案、模型生成的回答写到一个文件里。

🧐 逐步详细讲解

下面我按照上面的清单，结合代码给你详细讲讲：

1. 【准备阶段】接需求与核对参数

代码位置：vllm_infer 函数的开头部分。 * 动作：脚本接收了一大堆参数，比如 model_name_or_path（模型在哪）、dataset（测什么题）、batch_size（一次做几道题）。 * 逻辑：它会检查你的 GPU 数量够不够分（pipeline_parallel_size），并把所有参数整理好。

2. 【工具准备】加载分词器与模板

代码位置：

tokenizer_module = load_tokenizer(model_args)
template_obj = get_template_and_fix_tokenizer(tokenizer, data_args)
template_obj.mm_plugin.expand_mm_tokens = False
  • 解释：
    • 加载 Tokenizer 是为了把人类文字变成数字（Token）。
    • 加载 Template 是为了给模型加 Prompt 格式（比如 <|im_start|>user...）。
    • expand_mm_tokens = False：这是一个小细节，告诉工具不要手动把 <image> 标签展开成一堆占位符，因为 vLLM 引擎自己会处理。

3. 【启动引擎】初始化 vLLM

代码位置：

engine_args = { ... }
llm = LLM(**engine_args)
  • 解释：这是脚本最关键的一步。它配置了 vLLM 引擎：
    • tensor_parallel_size：如果你有多张卡，决定用几张卡并行计算。
    • enable_lora：如果你挂载了微调后的 LoRA 适配器，这里要开启。
    • limit_mm_per_prompt：限制每个问题里最多能放几张图或几个视频。
    • 最后 llm = LLM(...) 真正启动了引擎，模型加载进显存。

4. 【获取原料】加载数据

代码位置：

dataset_module = get_dataset(...)
train_dataset = dataset_module["train_dataset"]
  • 解释：利用 LlamaFactory 的数据处理模块，把指定的数据集（如 alpaca_en_demo）读取进来，准备喂给模型。

5. 【设定规则】配置采样参数

代码位置：

sampling_params = SamplingParams(...)
  • 解释：告诉模型该怎么说话：
    • temperature：高了胡说八道（有创造力），低了死板。
    • stop_token_ids：告诉模型遇到哪些词就闭嘴（停止生成）。
    • max_tokens：最多能说多少字。

6. 【核心工作】批量推理 (Batch Inference)

这是代码里那个大的 for 循环： for i in tqdm(range(0, len(train_dataset), batch_size), ...):

为什么要分批？ 如果你有 10 万条数据，一次性全塞进去内存会爆，文件句柄也会不够用。所以要一小撮一小撮地做。

  • 子任务 6.1 & 6.2：多模态数据处理

    • 代码里有大量的 if batch["images"] / elif batch["videos"]。
    • 图片：如果有图，调整图片大小 (_regularize_images)。
    • 视频：如果有视频，这部分代码最复杂。
      • 它会读取视频文件 (av.open)。
      • 提取关键帧、计算 FPS（帧率）、总帧数。
      • 特别是针对 Qwen2-VL 或 GLM4V 这种模型，它们需要非常具体的视频参数（如 video_metadata_kwargs），代码在这里专门做了适配。
    • 音频：如果有声音，处理采样率。
    • 最终打包成 vllm_input_data。

  • 子任务 6.3：生成 python results = llm.generate(vllm_inputs, sampling_params, lora_request=lora_request)

    • 解释：这就是“魔法”发生的时刻。调用 vLLM 的 generate 接口，传入整理好的数据，模型开始计算并返回结果。

7. 【收尾工作】保存结果

代码位置：最后面的 with open(save_name, "w", ...)。 * 解释：循环结束后，把所有的： * prompt (原问题) * predict (模型生成的回答) * label (数据集里的标准答案，如果有的话) * 打包成 JSON 格式，一行一行写入到 generated_predictions.jsonl 文件中。

总结

这个脚本就是一个高性能的流水线工人。它负责把你的数据（无论是字、图还是视频）清洗整理好，利用 vLLM 这个强力机器进行加工（推理），最后把产出的结果整整齐齐地打包存好。
