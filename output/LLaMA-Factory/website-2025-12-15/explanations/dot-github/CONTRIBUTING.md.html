.github/CONTRIBUTING.md

这份文件叫 CONTRIBUTING.md，直译过来就是“贡献指南”。

简单来说，这是一份“如何加入我们一起开发”的说明书。如果你想给 LLaMA Factory 这个项目修 Bug、加功能，或者只是改改错别字，你就必须遵守这里的规则。

为了让你更容易理解，我把它拆解成三个阶段的任务清单 (Todo List)，从最简单的“举手之劳”到硬核的“写代码提交”。

第一阶段：我想帮忙，但我不想写代码 (入门任务)

文件中提到，贡献不仅仅是写代码。你可以做以下几件事：

  • [ ] 任务 1：当个热心肠
    • 在社区里回答别人的问题。
    • 帮忙改进文档（哪怕是修正一个错别字）。
  • [ ] 任务 2：帮忙宣传
    • 如果你用这个项目做出了很酷的东西，发博客或者推特的时候提一下它。
    • 最简单的： 去 GitHub 仓库点一个 ⭐️ (Star)，这就相当于给作者点个赞。
  • [ ] 任务 3：遵守家规
    • 无论做什么，都要遵守 [Code of Conduct] (行为准则)，简单说就是礼貌待人，不要攻击别人。

第二阶段：我要改代码，先搭建环境 (准备任务)

如果你决定要修改代码（比如修 Bug 或加新功能），你需要先在自己的电脑上把环境搭好。

  • [ ] 任务 1：把代码“搬”到你的账号下 (Fork)
    • 原文步骤 1： 在 GitHub 网页上点击 Fork 按钮。
    • 解释： 这相当于把官方的代码库完整“复印”了一份到你自己的 GitHub 账号下，这样你随便怎么改都不会影响原本的官方代码。
  • [ ] 任务 2：把代码下载到本地 (Clone)
    • 原文步骤 2： 使用 git clone 命令把你账号下的那份代码下载到你的电脑硬盘里。
    • 关键点： 还要运行 git remote add upstream ...。这是为了告诉你的电脑：“官方原本的仓库在哪里”，方便以后同步更新。
  • [ ] 任务 3：安装“开发者模式”
    • 原文步骤 4： 运行 pip install -e ".[dev]"。
    • 解释： 普通用户是用 pip install 安装来用的；你是开发者，加上 -e 意味着你改了本地的文件，程序运行效果会立刻改变，不用每次改完都重新安装。

第三阶段：开始干活并提交 (核心任务)

这是最硬核的部分，也是文件中代码最多的部分。假设你现在要开始修一个 Bug 了：

  • [ ] 任务 1：开辟新战场 (Create Branch)
    • 原文步骤 3： git checkout -b dev_your_branch
    • 解释： 不要直接在主干道（main）上改，新建一个分支（branch），专门用来放你这次要改的内容。
  • [ ] 任务 2：写代码 & 遵守规范 (Style Guide)
    • 原文 Style guide： 必须遵守 Google Python 风格指南。
    • 解释： 代码格式要漂亮、统一，不能乱写。
  • [ ] 任务 3：自我检查 (Check)
    • 原文步骤 5： 在提交前，必须运行以下命令：
      • make commit
      • make style && make quality (自动帮你整理代码格式，检查低级错误)
      • make test (运行测试，确保你没把原来的功能改坏)
  • [ ] 任务 4：上传代码 (Submit)
    • 原文步骤 6：
      • git add . 和 git commit (保存你的修改)。
      • git fetch upstream 和 git rebase upstream/main (这一步很重要：看看官方由于在你写代码期间有没有更新？如果有，把官方的更新同步过来，避免冲突)。
      • git push (把代码上传到你自己的 GitHub 仓库)。
  • [ ] 任务 5：交作业 (Pull Request)
    • 原文步骤 7： 去 GitHub 网页上，点击 Create Pull Request。
    • 解释： 这就是正式告诉官方：“我改好了，请你们检查一下，如果没问题，就合并到官方代码里去吧！”

总结

这篇文档其实就在讲一件事： “如果你想改我们的代码，请先 Fork 一份，在本地安装好环境，按我们的代码规范去改，改完记得跑测试，最后通过 Pull Request 提交给我们。”
