.github/workflows/docker.yml

这份文件是一个 GitHub Actions 的自动化脚本。你可以把它想象成给云端机器人下达的一份“流水线工作清单”。

这份清单的目标非常明确：每当代码更新时，自动把项目打包成 Docker 镜像（Image），并发布到网上供别人下载。

为了让你好理解，我把它拆解成三个阶段的 Todo List（待办事项清单） 来给你讲：

第一阶段：什么时候开始干活？（触发条件）

机器人时刻盯着你的仓库，一旦发生以下 任意一件 事，它就会拿出清单开始干活：

  1. 手动触发：你在网页上点了一个“运行”按钮 (workflow_dispatch)。
  2. 代码更新：有人往 main 分支提交了代码 (push)，且修改了 Python 文件、requirements.txt 或者 Docker 相关配置。
  3. 代码审查：有人提交了合并请求 (pull_request)，且修改了上述文件。
  4. 发布新版：你在 GitHub 上发布了一个正式版本 (release)。

第二阶段：怎么分工？（策略矩阵）

这个项目支持不同的硬件（比如 NVIDIA 显卡和华为昇腾 NPU）。机器人为了效率，会使用“影分身术”，同时启动 3 个平行的任务 (matrix)：

  • 分身 1：负责构建 CUDA 版本（给 NVIDIA 显卡用）。
  • 分身 2：负责构建 NPU A2 版本（给华为昇腾 910B 用）。
  • 分身 3：负责构建 NPU A3 版本（给华为昇腾 910 Pro B 用）。

(注意：下面列出的 Todo List，这 3 个分身都会各自跑一遍)

第三阶段：具体干活的步骤（Todo List）

这就是机器人拿到清单后，一步一步执行的动作：

✅ Task 1: 清理工作台

  • 动作：清理磁盘空间。
  • 目的：Docker 构建很占地盘，先把云端电脑里的垃圾删一删，腾出空间，防止硬盘爆满。

✅ Task 2: 拿原材料

  • 动作：Checkout 代码。
  • 目的：把 GitHub 仓库里的最新代码下载到云端电脑里。

✅ Task 3: 准备工具

  • 动作：安装 Python 3.10。
  • 目的：因为后面需要运行 Python 脚本来获取版本号。

✅ Task 4: 确定“产品标签” (Tag)

  • 动作：判断这次构建叫什么名字。
    • 如果是“发布新版”事件：名字就是版本号（比如 v1.0.0）。
    • 如果是“日常更新”事件：名字就叫 latest（最新版）。
  • 目的：给做出来的镜像贴上正确的标签。

✅ Task 5: 准备打包工具

  • 动作：设置 Docker Buildx。
  • 目的：这是一个高级打包工具，支持跨平台构建（比如在 Intel 电脑上打包 ARM 架构的镜像）。

✅ Task 6: 登录仓库 (打卡上班)

  • 动作：登录 Docker Hub 和 Quay.io。
  • 条件：只有在不是“别人提交 PR”的情况下才登录。
  • 目的：要发布镜像必须先登录账号。如果是别人提交的代码（PR），为了安全，不登录，只测试打包但不上传。

✅ Task 7: 开始打包并发货 (核心步骤)

这里机器人会根据它是哪个“分身”（CUDA 还是 NPU），选择性地执行下面的某一步：

  • 📦 情况 A：如果你是 CUDA 分身

    • 读取配方：使用 ./docker/docker-cuda/Dockerfile 这个文件。
    • 加点佐料：安装额外的 Python 库（metrics, deepspeed, liger-kernel）。
    • 执行：打包成镜像。
    • 发货：推送到 Docker Hub，标签打上 hiyouga/llamafactory:版本号。

  • 📦 情况 B：如果你是 NPU-A2 分身

    • 读取配方：使用 ./docker/docker-npu/Dockerfile 这个文件。
    • 多平台：同时打包 amd64 (电脑) 和 arm64 (手机/服务器) 两种架构。
    • 发货：推送到 Docker Hub 和 Quay.io，标签后缀加上 -npu-a2。

  • 📦 情况 C：如果你是 NPU-A3 分身

    • 换个底料：虽然配方文件一样，但基础镜像换成了 cann:8.3...-a3 版本。
    • 执行：打包。
    • 发货：推送到 Docker Hub 和 Quay.io，标签后缀加上 -npu-a3。

总结一下

这个文件的作用就是： “只要代码一变，就自动帮我打包出 NVIDIA、华为 A2、华为 A3 这三种环境下的 Docker 镜像，并自动上传到 Docker Hub 仓库里，省得我人工手动去打包了。”
