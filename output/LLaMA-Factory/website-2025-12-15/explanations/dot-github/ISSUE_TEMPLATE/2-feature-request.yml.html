.github/ISSUE_TEMPLATE/2-feature-request.yml

没问题，这份代码其实是一份“在线填表说明书”。

在 GitHub（程序员托管代码的网站）上，当有人想给作者提建议（想要新功能）时，作者不希望大家乱填，所以写了这个文件，生成一个固定格式的表单。

我们把它想象成你在设计一份“新功能申请表”。下面是一个循序渐进的学习任务清单（Task List），带你一步步看懂它：

📋 任务清单：从零读懂这份配置

✅ Task 1: 搞懂“我是谁” (文件头部)

首先看文件的最开头几行。这部分定义了这张表单在菜单里长什么样。

name: "\U0001F680 Feature request"
description: Submit a request for a new feature
labels: ["enhancement", "pending"]
  • name: 表单的名字。用户会看到一个叫 “🚀 Feature request” 的按钮。
  • description: 按钮下面的小字说明。告诉用户这里是用来“提交新功能请求”的。
  • labels: 自动打标签。一旦用户填完表提交，系统会自动给这个建议贴上“enhancement”（增强/改进）和“pending”（待处理）的标签，方便作者分类。

✅ Task 2: 设置“温馨提示” (Markdown 模块)

进入 body 部分，这是表单的具体内容。第一块是给用户看的提示语，不需要用户填写。

  - type: markdown
    attributes:
      value: |
        Please do not create issues that are not related to new features under this category.
        请勿在此分类下创建和新特性无关的 issues。
  • type: markdown: 意思就是“这只是一段纯文本”。
  • value: 具体显示的文字。作者在这里喊话：“别走错片场了！这里只收新功能建议，不要在这里报 Bug。”

✅ Task 3: 设置“必读确认” (Checkboxes 模块)

为了防止用户不看规则就乱提问，这里设计了一个必须勾选的框。

  - type: checkboxes
    id: reminder
    attributes:
      label: Reminder
...
      options:
        - label: I have read the above rules and searched the existing issues.
          required: true
  • type: checkboxes: 这是一个复选框。
  • label: 这一项的标题，叫“Reminder”（提醒）。
  • required: true: 这是重点。意思是“必填”。如果用户不把“我已阅读上述规则...”前面的勾打上，提交按钮是灰色的，按不下去。

✅ Task 4: 设置“核心内容框” (Textarea 模块)

这是整张表最重要的部分，给用户一个大框框写作文，描述他想要什么功能。

  - type: textarea
    id: description
    validations:
      required: true
    attributes:
      label: Description
      description: |
        A clear and concise description of the feature proposal.
        请详细描述您希望加入的新功能特性。
  • type: textarea: 多行文本输入框（大写字板）。
  • label: 框框上面的标题叫“Description”（描述）。
  • validations: required: true: 同样是必填项。用户不能交白卷。

✅ Task 5: 设置“附加信息框” (Textarea 模块)

最后，作者想问问用户：“你自己写代码了吗？”

  - type: textarea
    id: contribution
    validations:
      required: false
    attributes:
      label: Pull Request
      description: |
        Have you already created the relevant PR and submitted the code?
        您是否已经创建了相关 PR 并提交了代码？
  • type: textarea: 这里又是一个文本框。
  • label: 标题是 “Pull Request” (PR，意思是代码合并请求)。
  • validations: required: false: 注意这里。这是 false，意味着是“选填”。用户如果没写代码，这一栏空着也能提交。

总结：它最后变成了什么？

当你把这个文件放进 GitHub 后，用户点击“新建 Issue”时，看到的不是一片空白，而是一个漂亮的网页表单：

  1. 最上面有一行提示文字（Task 2）。
  2. 下面有一个必须勾选的框：“我已阅读规则”（Task 3）。
  3. 再下面是一个必填的大输入框，让用户写新功能想法（Task 4）。
  4. 最下面是一个选填的输入框，问用户有没有现成的代码（Task 5）。

一句话概括： 这就是一份“新功能建议收集表”的蓝图代码。
