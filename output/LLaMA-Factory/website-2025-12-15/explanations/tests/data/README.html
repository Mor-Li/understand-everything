tests/data

这是一个非常形象的 “数据流水线质检车间”。

在 LlamaFactory 训练大模型之前，数据需要经过一系列复杂的“清洗、切割、打包”过程。这个 tests/data 文件夹不是用来存放真实训练数据的，而是用来存放“考卷”的——用来测试负责处理数据的那些代码（Data Pipeline）有没有干坏事。

1. 🏭 当前文件夹 (tests/data) 的核心功能

你可以把它想象成 “数据预处理部门的质检中心”。

它的核心任务是：确保原材料（原始数据）在变成成品（模型能吃的 Tensor）的过程中，没有被切坏、包错或者调料放反。

如果这里面的测试跑不通，说明你的训练数据处理逻辑有 Bug，喂给模型的数据可能是乱码或者错位的，训练必崩。

2. 📄 各个直接文件的角色（通俗版）

这些 test_*.py 文件每一个都对应着数据处理流水线上的一个特定工种。我们可以把它们看作不同的 “质检员”：

📦 test_loader.py —— “仓库管理员的考核”

  • 负责测试：数据加载器（Loader）。
  • 通俗解释：检查能不能把数据从硬盘里完整地搬出来。
  • 考核内容：
    • 如果不给验证集，是不是真的只加载了训练集？
    • 如果我说“切10%做验证”，你是不是真的切准了？
    • 如果我指定了一份考题，你是不是加载了那份指定的考题？
    • 一句话：确保原材料进场没问题。

🔄 test_converter.py —— “翻译官的考核”

  • 负责测试：格式转换器（Converter）。
  • 通俗解释：市面上的数据格式五花八门（有的像 Alpaca，有的像 ShareGPT），这个测试检查能不能把它们统统翻译成 LlamaFactory 的“内部标准普通话”。
  • 考核内容：
    • 能不能把 Alpaca 的 instruction/output 变成标准的 user/assistant？
    • 能不能把 ShareGPT 的复杂对话列表拆解对？
    • 一句话：确保不管外地人说什么方言，进门后都得讲普通话。

🗣️ test_template.py —— “礼仪老师的考核”

  • 负责测试：对话模板（Chat Template）。
  • 通俗解释：不同的模型（Llama3, Qwen, Gemma）有不同的“社交礼仪”（特殊符号）。Llama3 喜欢用 <|start_header_id|>，Qwen 喜欢用 <|im_start|>。
  • 考核内容：
    • 检查翻译给 Llama3 的话，是不是带了它喜欢的标签？
    • 检查多轮对话（你一句我一句）有没有拼错？
    • 一句话：确保喂给模型的话，符合该模型的“语法规范”。

🛠️ test_formatter.py —— “工具箱管理员的考核”

  • 负责测试：工具/函数调用格式（Function Calling Formatter）。
  • 通俗解释：当我们要教 AI 使用工具（比如查天气、调 API）时，格式非常复杂（涉及 XML 标签或 JSON）。
  • 考核内容：
    • 能不能把 Python 的函数定义变成 AI 能看懂的 Prompt？
    • 如果 AI 吐出了一段乱码，能不能从中抠出函数名和参数？
    • 一句话：确保 AI 能看懂说明书，并且能正确拿起螺丝刀。

🧩 test_collator.py —— “打包员的考核”

  • 负责测试：数据整理器（Data Collator）。
  • 通俗解释：数据有长有短，但 GPU 喜欢整齐的方块。这个测试检查能不能把长短不一的数据凑成整齐的一批。
  • 考核内容：
    • 短的数据有没有补零（Padding）？
    • 如果不该看的地方（比如填充部分），有没有把眼睛蒙上（Mask）？
    • 如果是多模态，图片有没有占好位置？
    • 一句话：确保装进显卡的每一个“箱子”都是整齐划一的。

👁️ test_mm_plugin.py —— “视听专家的考核”

  • 负责测试：多模态插件（Multi-modal Plugin）。
  • 通俗解释：专门负责处理图片、视频、音频的测试。
  • 考核内容：
    • 给 LLaVA 模型喂图，是不是变成了 576 个 Token？
    • 给 Qwen-VL 喂图，是不是加了 <|vision_start|> 标签？
    • 一句话：确保瞎子（纯文本模型）能带上眼镜看懂图。

3. 📁 子文件夹的作用 (processor/)

  • tests/data/processor/：这是“精加工车间”。
  • 作用：上面的文件大多在测“格式”和“加载”，而这个子文件夹里的测试（如 test_supervised.py, test_feedback.py）是在测具体的训练逻辑预处理。比如：做 SFT（微调）时数据怎么处理？做 RLHF（强化学习）时数据怎么处理？它们比外层的测试更关注特定算法的数据细节。

4. 🧠 高层认知总结

要理解这部分代码，你只需要记住一条流水线：

  1. 进货 (test_loader): 把数据搬进来。
  2. 初加工 (test_converter): 把各种格式统一成标准格式。
  3. 精装修 (test_template & test_mm_plugin): 根据模型喜好，加上标签，塞进图片。
  4. 配工具 (test_formatter): 如果需要用工具，把说明书塞进去。
  5. 打包发货 (test_collator): 把处理好的数据拼成整齐的方块，准备喂给 GPU。

tests/data 就是为了保证这条流水线上的每一个环节，都不会掉链子。
