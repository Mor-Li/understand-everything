tests

你好！我是你的代码导游。欢迎来到 LlamaFactory 的 tests (测试) 目录。

如果把整个项目比作一家“超级工厂”，那么 tests/ 目录就是这家工厂的 “质检中心”。

这里不生产任何产品（不含核心代码），但这里拥有“生杀大权”。任何新写的代码、新改的功能，必须在这里通过层层考验，拿到“合格证”，才能被合并到主线里去。

下面我带你参观一下这个质检中心：

1. 🏢 当前文件夹 (tests) 主要负责什么？

它的核心职责是 “找茬” 和 “保平安”。

  • 找茬：通过自动化的脚本，模拟各种使用场景，试图把程序弄崩。如果程序崩了，说明有 Bug。
  • 保平安：确保程序员在修改 A 功能的时候，没有不小心把 B 功能搞坏（这叫回归测试）。

简单来说，它是 LlamaFactory 的安全网，防止半成品流向用户。

2. 📄 这里的直接文件是干什么的？

这一层的文件是质检中心的 “行政管理人员”，它们不负责具体的测试，而是负责立规矩和管环境。

  • 👮‍♂️ check_license.py (门口保安)

    • 作用：它不管代码逻辑，只管“查证件”。
    • 工作：它会把所有代码文件翻一遍，检查第一行有没有写上“Copyright ... LlamaFactory”的版权声明。如果没写，它就报警（报错），不让你提交代码。

  • 📢 conftest.py (考场广播/总指挥)

    • 作用：这是 Pytest（测试框架）的配置文件，负责在测试开始前“清点人数”和“宣读考场纪律”。
    • 工作：
      • 查硬件：看看现在的电脑是 CPU 还是 GPU？
      • 定规则：如果现在只有 CPU，那么所有贴了“必须用 GPU”标签的测试题，统统跳过不做。
      • 发补丁：如果有特殊的代码需要修补才能运行，它负责分发这些修补工具（Fixtures）。

  • 🏷️ utils.py (标签打印机)

    • 作用：这是一个工具箱，主要是为了方便给测试题“贴标签”。
    • 工作：它定义了一个快捷方式 runs_on。写测试的人可以用它给代码贴上 @runs_on('gpu') 的标签。这就像给箱子贴“易碎品”贴纸一样，方便上面的总指挥（conftest.py）进行分类处理。

  • 🔄 version.txt (强制刷新按钮)

    • 作用：这是测试系统的“缓存版本号”。
    • 工作：为了跑得快，测试系统会把一些旧数据存起来（缓存）。如果你发现测试莫名其妙跑不过，或者环境变了，就把这个文件里的数字改一下。系统看到数字变了，就会把旧缓存扔掉，强制从头开始跑一遍。

3. 📁 子文件夹的作用 (概括版)

这些子文件夹是具体的 “专项质检车间”，每个车间负责检查流水线上的不同环节：

  • 📦 data/ (原材料车间)：
    • 检查数据处理流程。确保原始数据被正确地加载、清洗、格式化，最后打包成模型能吃的样子。
  • 🚗 model/ (组装车间)：
    • 检查模型加载逻辑。确保当我们要求加载 LoRA、全量微调或量化模型时，系统真的把模型正确地组装到了内存里。
  • 🔥 train/ (演习车间)：
    • 检查训练逻辑。通过跑一些极小的假任务，验证训练过程中的开关（比如是否打乱数据）是否好使。
  • 📝 eval/ (阅卷车间)：
    • 检查评测工具。确保给 AI 出题的模板格式是正确的，防止因为题目印错导致 AI 考零分。
  • 🏎️ e2e/ (试驾车道)：
    • End-to-End (端到端) 测试。模拟用户真实操作，从头到尾跑通“训练 -> 对话”的全流程，确保车子能上路，不散架。

4. 🧠 高层认知：一句话理解这部分

不要被这些代码吓到，你就把 tests/ 目录看作是 LlamaFactory 的 “体检报告”。

  • 对于开发者：这是护身符。每次改完代码跑一遍，全绿（Pass）了才敢睡觉。
  • 对于用户：这是质量保证书。它证明了这个项目不是随便拼凑的草台班子，而是经过了严苛的自动化测试检验的工业级产品。
