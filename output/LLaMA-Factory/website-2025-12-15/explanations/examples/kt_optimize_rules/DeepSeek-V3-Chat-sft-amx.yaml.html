examples/kt_optimize_rules/DeepSeek-V3-Chat-sft-amx.yaml

这份文件其实是一份“改装指南”。

把它想象成你去修车店，跟师傅说：“把这辆原厂的 DeepSeek-V3 跑车改装一下，引擎换成更省油的，轮胎换成抓地力更好的，音响换成更响的。”

这个 YAML 文件就是告诉程序（ktransformers）：“在加载模型时，看到 A 部件，请把它拆掉，换成 B 部件，并且用 C 模式运行。”

为了让你彻底搞懂，我为你列了一个 4 步走的学习 Task List，我们一步步来拆解。

Task 1：理解核心逻辑 —— "Match & Replace"（查找与替换）

在看具体代码前，先懂它的语法结构。所有的代码块都遵循这个简单的逻辑：

  1. Match（查找）：用正则表达式或类名，在原版 PyTorch 模型里找到特定的零件（比如某个层、某个计算模块）。
  2. Replace（替换）：用 ktransformers 库里自己写的高性能、经过优化的零件（Kernel/Operator）替换掉原厂零件。
  3. Kwargs（参数）：给新零件下达指令，比如“你在 GPU 上跑”还是“你在 CPU 上跑”。

你的任务： 记住这个公式 -> 看到旧的，换成新的，指定运行设备。

Task 2：理解两个关键阶段 —— "Prefill" 与 "Generate"

你会反复看到这两个词，必须先懂它们：

  • Prefill（预填充/阅读阶段）：当你把一大段话发给 AI 时，AI 快速阅读并理解这段话的过程。这通常计算量大，但是一次性的。
  • Generate（生成/回答阶段）：AI 一个字一个字往外蹦的过程。

文件中的策略是： * Prefill 通常全在 GPU (cuda) 上做，因为要快。 * Generate 可能会用到 CPU，因为 DeepSeek-V3 模型太大了，显存装不下，需要把一部分计算挪到内存里用 CPU 算（利用 AMX 加速）。

Task 3：逐个击破 —— 拆解文件中的 6 大改装动作

现在我们按顺序看文件里的内容，我把它翻译成“人话”：

步骤 3.1：优化“位置感” (RoPE)

- match: ...DeepseekV3RotaryEmbedding  # 原厂的位置编码
  replace: ...YarnRotaryEmbeddingV3    # 改装后的 Yarn 版本
    kwargs: device: "cuda"             # 在显卡上跑
  • 解释：这是模型用来理解词语顺序的组件。
  • 动作：换成了支持更长上下文的 Yarn 版本，全在 GPU 上跑。

步骤 3.2：优化“普通神经连接” (Linear Layers)

- match: ...torch.nn.Linear            # 原厂的线性层
  replace: ...KTransformersLinear      # 改装后的量化线性层
  • 解释：这是模型里最常见的连接层。
  • 动作：换成了 KTransformersLinear。这是为了支持量化（把高精度的数变成低精度，省显存），让它跑得更快。全在 GPU 上跑。

步骤 3.3：处理“专家模型”的外壳 (MoE & Gate)

  • 代码段 4 & 5 (DeepseekV3MoE, MoEGate)。
  • 解释：DeepSeek-V3 是个 MoE 模型（混合专家模型）。这部分处理的是“总控室”和“门控（决定用哪个专家）”。
  • 动作：换成优化版，依然在 GPU 上跑。

步骤 3.4：【最关键的一步】改装“专家核心” (Experts)

这是整个文件最重要的部分！

- match:
    name: "^model\\.layers\\..*\\.mlp\\.experts$" # 找到所有的专家模块
  replace:
    class: ...KTransformersExperts     # 换成 ktransformers 的专家模块
    kwargs:
      prefill_device: "cuda"           # 阅读时：用显卡（追求速度）
      generate_device: "cpu"           # 生成时：用 CPU！！（为了省显存）
      generate_op: "KSFTExpertsCPU"    # 使用 CPU 专用的算子
      backend: "AMXInt8"               # 使用 Intel CPU 的 AMX 指令集加速
  • 解释：DeepSeek-V3 参数巨大，普通显卡根本装不下。
  • 策略：
    • 阅读提问时，硬挤在 GPU 上算一下（或者分层算）。
    • 回答时，把最占内存的“专家参数”放在系统内存里，用 CPU 来计算。
    • AMXInt8 意思是利用 Intel 第四代/五代至强处理器的 AMX 加速指令集，配合 Int8 量化，让 CPU 跑得飞快。
    • 这就是为什么文件名里有 amx。

步骤 3.5：优化“注意力机制” (Attention)

- match: ...self_attn
  replace: ...KDeepseekV2Attention
  • 解释：这是 AI 集中注意力看上下文的地方。
  • 动作：换成优化过的 MLA（DeepSeek 特有的注意力机制）实现，在 GPU 上跑。

步骤 3.6：收尾 (Embeddings)

- match: "^model.embed_tokens"
  replace: ... "cpu"
  • 解释：这是查字典的地方（把文字变成数字）。
  • 动作：扔到 CPU 上去。因为词表很大，放在显存里浪费，CPU 查表足够快了。

Task 4：总结 —— 这个文件到底实现了什么？

如果你执行了这个配置文件，你得到的是这样一个 DeepSeek-V3 模型：

  1. 省显存：它把最大的两块肉（MoE 专家参数 和 词表 Embedding）扔到了 CPU 内存里。
  2. 高性能 CPU 推理：它利用了 Intel CPU 的 AMX 指令集（AMXInt8），使得用 CPU 跑大模型也不会太慢。
  3. 混合动力：
    • GPU 负责：核心的注意力计算、复杂的逻辑门控（这时候显卡负载高）。
    • CPU 负责：吞吐量巨大的专家计算（这时候内存带宽压力大）。

一句话总结： 这是一个“显存不够，内存来凑”的配置方案，专门针对支持 AMX 指令集的 Intel CPU 进行了优化，让你能在显存有限的情况下，流畅运行 DeepSeek-V3。
