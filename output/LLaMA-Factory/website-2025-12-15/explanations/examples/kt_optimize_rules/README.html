examples/kt_optimize_rules

你好！这里是 examples/kt_optimize_rules 目录的说明书。

如果说 ktransformers 是一个超级改装车间，那么这个目录里存放的就是针对不同车型的“改装施工图纸”。

1. 🏎️ 这个文件夹主要负责什么？

核心功能：制定“资源分配”与“性能优化”的规则。

当你下载了一个巨大的 AI 模型（比如 DeepSeek-V3），直接运行可能会把你的显卡撑爆，或者跑得像蜗牛一样慢。 这个文件夹里的 .yaml 文件就是告诉程序： * 拆零件：把原厂慢吞吞的零件拆下来。 * 换零件：换上 ktransformers 特制的“涡轮增压”零件（高性能算子）。 * 分地盘：规定哪些零件放在 显卡 (GPU) 上跑（追求速度），哪些零件扔到 内存 (CPU) 上跑（为了省显存）。

2. 📄 这里的直接文件分别是干什么的？

这里的文件虽然多，但其实都是同一个逻辑的变种。你可以通过文件名来秒懂它们的作用。

文件名通常遵循这个公式：[模型名字] - [场景/版本] - [硬件策略].yaml

我们将它们分为几类来理解：

A. “AMX 战神”系列 (文件名含 amx)

  • 代表文件：DeepSeek-V3-Chat-sft-amx.yaml, Qwen3Moe-sft-amx.yaml 等。
  • 作用：专门为 Intel 高端 CPU 优化的配置。
  • 核心策略：利用 Intel CPU 的 AMX 加速指令。它会把模型里最大、最占地方的“专家模块 (MoE Experts)”强制放在 CPU 内存里跑，只把最核心的计算留在显卡上。
  • 适合谁：显存不够大，但有一颗支持 AMX 的强力 Intel CPU 的用户。

B. “多卡并联”系列 (文件名含 multi-gpu)

  • 代表文件：DeepSeek-V3-Chat-sft-amx-multi-gpu-4.yaml 等。
  • 作用：指挥多张显卡协同工作。
  • 核心策略：像接力赛一样，把模型切成几段，GPU 0 跑完传给 GPU 1，再传给 GPU 2... 同时配合 CPU 处理超大参数。
  • 适合谁：拥有多张显卡（如 2张、4张 4090）的用户。

C. “轻量级/标准”系列 (文件名含 Lite 或无特殊后缀)

  • 代表文件：DeepSeek-V2-Lite-Chat.yaml, DeepSeek-V2-Chat.yaml。
  • 作用：针对特定大小模型的标准优化方案。
  • 核心策略：通常是将线性层换成量化版本（Marlin），并根据模型大小决定是否需要把部分计算卸载到 CPU。

3. 🧠 给你一个高层的认知（秒懂核心）

你可以把这个文件夹看作是 “显存精算师”的账本。

如果不使用这些规则，运行大模型就像“把大象装进冰箱”——显卡显存（冰箱）根本塞不进去。

使用了这些规则后，程序会执行“显存不够，内存来凑”的战术： 1. 快但贵的显存（GPU），只留给最需要速度的“大脑”（Attention 注意力机制）。 2. 慢但大的内存（CPU），用来存放体积巨大的“身体”（MoE 专家参数）。 3. 特殊技能：利用优化的算子（如 AMX、Marlin），让 CPU 跑得也没那么慢，让 GPU 跑得飞快。

一句话总结： 这里存放的是让消费级硬件（普通显卡+大内存）也能跑得动企业级巨型模型的魔法配置单。
