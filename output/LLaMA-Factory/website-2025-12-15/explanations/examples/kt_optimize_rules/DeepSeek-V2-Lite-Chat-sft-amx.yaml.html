examples/kt_optimize_rules/DeepSeek-V2-Lite-Chat-sft-amx.yaml

这份文件其实是一份“装修/改装清单”。

想象一下，你刚买了一套名为“DeepSeek-V2”的精装房（原版模型），但你想让它住起来更舒服、更省电，或者你的某些家具（显卡显存）放不下这么大的房子。

于是，你写了这份 yaml 文件，告诉装修队（ktransformers 程序）：“看到原本的 A 部件，请把它拆掉，换成更高级的 B 部件，并且指定 B 部件是放在楼上（GPU）还是楼下（CPU）运行。”

这份配置的核心目的是：利用 CPU 的 AMX 指令集加速（Intel CPU 的一种加速功能）来运行模型中巨大的“混合专家（MoE）”部分，而把其他核心计算留在 GPU 上，实现“CPU+GPU”协同工作。

下面我为你列一个 Task To-Do List，一步步拆解这份文件在干什么：

🛠️ 任务清单：DeepSeek-V2 模型改装计划

Task 1: 升级“定位系统” (RoPE)

  • 原文对应： 第 1 段 (match: ...RotaryEmbedding)
  • 任务： 找到模型里的“旋转位置编码（RoPE）”模块。
  • 动作： 替换成 ktransformers 特制的优化版本。
  • 去哪儿运行？ 全部扔给显卡 (CUDA)。
  • 通俗解释： 这是模型用来理解文字顺序的零件，原版的太慢，换个专门优化过的，让显卡快速处理。

Task 2: 批量升级“普通运算单元” (Linear Layers)

  • 原文对应： 第 2 段 (match: ...torch.nn.Linear)
  • 任务： 找到模型里所有的普通线性层（Linear），但排除掉注意力机制里的一部分特殊层（正则 (?!.*self_attn...) 排除的那些）。
  • 动作： 替换成 KTransformersLinear（一种支持量化数据的内核）。
  • 去哪儿运行？ 无论是阅读提问（Prefill）还是生成回答（Generate），都用显卡 (CUDA)。
  • 通俗解释： 这是模型里最常见的“神经元”连接。把它们全部换成高性能版本，跑在显卡上。

Task 3: 升级“嘴巴” (LM Head)

  • 原文对应： 第 3 段 (match: ^lm_head)
  • 任务： 找到模型最后输出文字的那个层（LM Head）。
  • 动作： 替换成 KTransformersLinear。
  • 去哪儿运行？ 显卡 (CUDA)。
  • 通俗解释： 这是模型吐出下一个字的关口，同样换成高性能版，放在显卡上。

Task 4: 升级“专家调度员” (MoE Router)

  • 原文对应： 第 4 段 (match: ...DeepseekV2MoE)
  • 任务： 找到 DeepSeek 模型特殊的“混合专家（MoE）”模块的主体。
  • 动作： 替换成 KDeepseekV2MoE。
  • 去哪儿运行？ 显卡 (CUDA)。
  • 通俗解释： DeepSeek 是个 MoE 模型，意味着它有很多“专家”。这个模块是“调度员”，负责决定把问题交给哪个专家。调度员需要反应快，所以放在显卡上。

Task 5: 【核心任务】把“专家团”搬到 CPU (The Experts)

  • 原文对应： 第 5 段 (match: ...mlp.experts)
  • 任务： 找到那一大堆具体的“专家”层（Experts）。这是模型参数量最大、最占显存的部分。
  • 动作： 替换成 KTransformersExperts。
  • 去哪儿运行？
    • CPU! (看 prefill_device: "cpu", generate_device: "cpu")
    • 黑科技： backend: "AMXInt8"。这意味着使用 Intel CPU 的 AMX 加速指令，并且用 Int8（8位整数）格式来压缩计算。
  • 通俗解释： 显存不够放不下所有的专家，所以我们把最占地方的“专家团”全部赶到 CPU 上去跑。为了防止 CPU 太慢，我们开启了 AMX 加速和 Int8 量化。这是这个配置文件的灵魂所在。

Task 6: 升级“注意力机制” (Attention/MLA)

  • 原文对应： 第 6 段 (match: ...self_attn)
  • 任务： 找到模型的注意力层（Self Attention）。
  • 动作： 替换成 KDeepseekV2Attention。
  • 去哪儿运行？ 显卡 (CUDA)。
  • 通俗解释： DeepSeek V2 使用了一种叫 MLA 的特殊注意力机制。这里用专门优化的代码来替换原版，让它在显卡上跑得飞快。

Task 7: 调整“整体架构”与“门面” (Model & Embeddings)

  • 原文对应： 最后两段 (match: ^model$, match: ...embed_tokens)
  • 任务：
    1. 调整整个模型的管理方式 (KDeepseekV2Model)。
    2. 找到最开始的“文字入口”（Embeddings）。
  • 动作：
    1. 设置层级预填充阈值为 0（技术细节，关乎调度策略）。
    2. 把入口层 (embed_tokens) 放在 CPU 上。
  • 通俗解释： 这是一个收尾工作。把查字典（Embedding）这种不怎么费劲但占内存的工作扔给 CPU，省点显存给更重要的地方。

📝 总结：这个配置到底实现了什么？

如果你运行了这个配置，你的 DeepSeek-V2 模型会变成这样：

  1. 显卡（CUDA）负责： 所有的逻辑调度、注意力计算、普通的神经元连接。这些需要高带宽、低延迟。
  2. 处理器（CPU）负责： 所有的“专家库”（MoE Experts）和“查字典”（Embeddings）。这些占据了模型 80% 以上的体积。
  3. 最终效果： 你可以在一张显存不大的显卡上，配合一颗支持 AMX 的强力 CPU，跑起来原本需要巨量显存才能运行的 DeepSeek-V2 模型。
