examples/kt_optimize_rules/DeepSeek-V2-Chat-sft-amx.yaml

这份文件实际上是一个“模型手术/改装指南”。

你可以把它想象成你在玩赛车游戏，或者在装修房子。你手里有一个原始的、巨大的 AI 模型（DeepSeek-V2），但是你的电脑（特别是显卡）可能跑不动它，或者跑得不够快。

这个 .yaml 文件的作用就是告诉 ktransformers 这个软件：“把原版模型的哪些部件拆下来，换成我们特制的、更高效的部件，并且规定这些部件是在显卡（GPU）上跑，还是在处理器（CPU）上跑。”

为了让你听懂，我把这个文件的逻辑拆解成一个 Task Todo List（任务清单），带你一步步执行这次“模型改装手术”。

任务清单：DeepSeek-V2 模型改装手术 (AMX版)

📋 任务一：确立手术目标 (Global Goal)

  • 目标：运行 DeepSeek-V2-Chat 模型。
  • 难点：这个模型很大，显存可能不够。
  • 策略：混合动力。能用显卡算的用显卡（CUDA），显卡装不下的或者 CPU 擅长的部分，扔给 CPU 算。
  • 核心技术：文件名里的 amx 是指利用英特尔 CPU 的 AMX 指令集加速（一种专门算 AI 的 CPU 技术）。

🛠️ 任务二：改装“位置导航系统” (RoPE)

原文对应： 第 1 段 (match: ...DeepseekV2YarnRotaryEmbedding) * 说明：这是模型用来理解“文字顺序”的部件。 * 执行动作： 1. 找到原版的旋转位置编码（YarnRotaryEmbedding）。 2. 替换成 ktransformers 优化过的版本。 3. 分配位置：全部放在显卡（cuda）上跑，因为这个计算量不大，显卡处理很快。

🛠️ 任务三：升级“普通计算单元” (Linear Layers)

原文对应： 第 2 段 (match: ...torch.nn.Linear) 和 第 3 段 (lm_head) * 说明：模型里有大量的普通线性层（矩阵乘法），就像汽车里无数的齿轮。 * 执行动作： 1. 用正则表达式找到所有的线性层（除了个别特殊的 kv_b_proj）。 2. 同时也找到最后的输出层 (lm_head)。 3. 替换成 KTransformersLinear（一种经过量化优化的计算核）。 4. 分配位置：全部放在显卡（cuda）上跑，追求速度。

⚠️ 任务四：改造“核心大脑群” (MoE Experts) —— 这是最重要的一步！

原文对应： 第 4 段 (DeepseekV2MoE) 和 第 5 段 (mlp.experts) * 说明：DeepSeek-V2 是一个 MoE（混合专家）模型。它就像拥有几百个“专家”的大脑，每次只有几个专家在工作。但这几百个专家的参数量极其巨大，显存根本塞不下。 * 执行动作 1 (架构)： * 把管理专家的架构换成 KDeepseekV2MoE。 * 执行动作 2 (专家本体)： * 找到 mlp.experts（专家组）。 * 替换成 KTransformersExperts。 * 分配位置 (关键点)： * prefill_device: "cuda"：刚开始阅读长文时，用显卡（如果显存够）。 * generate_device: "cpu"：生成回答时，强制用 CPU 跑！ * backend: "AMXInt8"：启用大招。指定 CPU 使用 AMX 指令集 进行 Int8（低精度）计算。 * 通俗解释：因为专家太占地方，显卡装不下，所以生成文字时，我们把这部分最重的活儿扔给 CPU 干。同时为了防止 CPU 算得太慢，我们开启了 CPU 的“氮气加速”（AMX技术）。

🛠️ 任务五：优化“注意力机制” (Attention)

原文对应： 第 6 段 (self_attn) * 说明：这是模型用来“回顾上下文”的部件，DeepSeek V2 用的是独特的 MLA 技术。 * 执行动作： 1. 找到原版的 self_attn。 2. 替换成 KDeepseekV2Attention（专门为 MLA 优化的版本）。 3. 分配位置：放在显卡（cuda）上，因为注意力计算对显卡很友好。

🛠️ 任务六：处理“输入输出大门” (Embeddings)

原文对应： 最后一段 (embed_tokens) * 说明：这是负责把文字转换成数字的第一层。 * 执行动作： 1. 找到 embed_tokens。 2. 分配位置：扔给 CPU (generate_device: "cpu")。 * 原因：这个词表矩阵非常大（DeepSeek 词表很大），而且计算密度低，放在显卡上浪费宝贵的显存，不如扔给 CPU 存着。

🏁 任务七：总装与收尾 (Model Wrapper)

原文对应： 倒数第二段 (match: "^model$") * 说明：给整个模型套一个外壳，管理整体流程。 * 执行动作： 1. 替换成 KDeepseekV2Model。 2. 设置一些预填充（Prefill）的阈值参数。

总结：这文件到底在干啥？

如果不写这个文件，DeepSeek-V2 可能需要好几张昂贵的 4090 显卡才能跑起来。

写了这个文件后，它的逻辑变成了： 1. 显卡（GPU） 负责：注意力机制、普通的线性计算（跑得快）。 2. 处理器（CPU） 负责：存储巨大的词表、以及计算最占内存的专家模型（MoE Experts）。 3. 优化手段：利用 CPU 的 AMX 硬件加速功能，让 CPU 跑专家模型时不至于太慢。

一句话概括： 这是一个“显卡 CPU 混合双打”的配置单，专门为了在支持 AMX 的英特尔 CPU 平台上，配合显卡高效运行 DeepSeek-V2 大模型。
