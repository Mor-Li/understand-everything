examples/kt_optimize_rules/DeepSeek-V3-Chat-amx.yaml

这份文件确实充满了技术术语，如果你不熟悉大模型底层架构，看懂它就像在看天书。

简单来说，这份 .yaml 文件是一份“改装清单”。

背景： 你有一辆原厂车（DeepSeek-V3 模型），但它的引擎太大（参数量巨大），你的车库（显卡显存）塞不下，或者跑得不够快。 目的： 使用 ktransformers 这个工具，把原厂车的某些零件拆下来，换成“高性能”或者“省空间”的改装件。

为了让你彻底理解，我为你列了一个 5步走的 Task List（任务清单），我们一步步来拆解这份文件：

✅ Task 1: 理解核心逻辑 —— "Match" 和 "Replace"

任务目标： 看懂文件的基本语法结构。

  • 原文逻辑： 文件里全是成对出现的 match 和 replace。
    • Match (匹配)： 告诉程序，“请找到模型里原来的这个零件（比如原来的线性层）”。
    • Replace (替换)： 告诉程序，“把它扔了，换成我指定的这个新零件（比如 ktransformers 优化过的层）”。
  • kwargs (参数)： 这是给新零件的说明书。比如告诉它在这个设备上运行（cuda 代表显卡，cpu 代表处理器）。

✅ Task 2: 解决最大的难题 —— MoE 专家模型的“分家” (最关键的一步)

任务目标： 理解文件中关于 experts（专家）的部分，这是DeepSeek-V3能跑起来的核心。

DeepSeek-V3 是一个混合专家模型（MoE），它的参数量非常大（几千亿），普通显卡根本装不下。

  • 对应代码段： ```yaml
    • match: name: "^model\.layers\..*\.mlp\.experts$" # 找到原来的专家层 replace: class: ktransformers.operators.experts.KTransformersExperts kwargs: prefill_device: "cuda" # 预处理（看提示词时）用显卡 generate_device: "cpu" # 生成（写回复时）用 CPU ！！！ backend: "AMXInt8" # 使用 Intel CPU 的 AMX 加速指令集 ```
  • 解读： 这是这份文件名为 ...-amx.yaml 的原因。它把模型最大、最占内存的“专家权重”部分，强制放在了 CPU 内存里（generate_device: "cpu"），而不是显卡里。 并且，它使用了 AMXInt8，这是 Intel 高端 CPU 特有的加速指令，为了让 CPU 跑模型也能稍微快一点。
    • 一句话总结： 显卡放不下，所以把大块头扔给 CPU 去算。

✅ Task 3: 压榨显卡性能 —— 线性层优化

任务目标： 理解那些标有 Linear 的部分。

除了专家部分，模型还有很多普通的矩阵计算（线性层）。这些通常还是放在显卡上算比较快。

  • 对应代码段： ```yaml
    • match: class: torch.nn.Linear # 找到普通的线性层 replace: class: ktransformers.operators.linear.KTransformersLinear kwargs: generate_op: "KLinearMarlin" # 使用 Marlin 算子 generate_device: "cuda" # 放在显卡上 ```
  • 解读： 把普通的 PyTorch 线性层，换成了 KTransformersLinear。 关键在于 KLinearMarlin。Marlin 是一种非常高效的 GPU 计算内核（Kernel），专门用来加速量化后的模型计算。
    • 一句话总结： 能塞进显卡的小零件，全部换成高性能版本（Marlin），让显卡跑得飞快。

✅ Task 4: 优化“大脑” —— 注意力机制与位置编码

任务目标： 理解 Attention 和 RotaryEmbedding。

DeepSeek-V3 使用了特殊的注意力机制（MLA），原版实现可能比较慢或占显存。

  • 对应代码段：
    • DeepseekV3RotaryEmbedding -> 替换为 YarnRotaryEmbeddingV3
    • self_attn -> 替换为 KDeepseekV2Attention
  • 解读： 这里是用 ktransformers 专门为 DeepSeek 写的高效算子，替换了原版的算子。 kwargs 里写着 generate_device: "cuda"，说明这些核心计算依然在显卡上进行，保证速度。

✅ Task 5: 杂项配置 —— 输入与总控

任务目标： 扫清剩下的边角料。

  • Gate (门控) / MoEGate：
    • MoE 模型需要一个“门”来决定把任务派发给哪个专家。这里把原来的门换成了 KMoEGate，放在显卡上 (cuda:0) 快速决策。
  • Embed_tokens (词嵌入)：
    • match: "^model.embed_tokens" -> replace: "default" (CPU)。
    • 把文本转成数字的第一步，放在 CPU 上做，为了省一点点显存。
  • Model (总模型)：
    • KDeepseekV2Model。这是整个模型的包装壳，用来协调上面所有的零件。

📝 最终总结 (Executive Summary)

看完这个 List，你应该能明白这份文件的战术意图了：

这是一个“CPU/GPU 混合推理”的方案，专门针对 Intel 支持 AMX 指令集的 CPU 优化的。

  1. 显卡 (GPU) 负责： 负责“门控”、“注意力机制”和“普通计算”，这些需要高带宽、低延迟，且显存占用相对较小。
  2. 处理器 (CPU) 负责： 负责扛起“专家模块 (Experts)”这个重担。因为这部分数据量太大（几百 GB），显卡装不下，只能放在系统内存里，利用 CPU 的 AMX 加速来计算。

如果你运行这个配置： 你会发现显存占用被控制住了（因为大头在内存里），但 CPU 负载会很高，且回复速度会比纯显卡慢，但至少能让你在有限的显卡上跑起这个巨型模型。
