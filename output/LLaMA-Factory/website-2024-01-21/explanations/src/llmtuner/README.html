src/llmtuner

📁 src/llmtuner/

欢迎来到 LLaMA Factory 的 “核心总部大楼”。

如果说整个项目是一个巨大的工厂，那么 src/llmtuner 就是这座工厂的实体建筑。所有的部门、车间、仓库、控制室全部都坐落在这个目录下。这里是所有魔法发生的地方。

1. 🏢 这个文件夹主要负责什么？

它是整个项目的 源代码根目录。 它的核心任务是：组织和封装。

它把原本复杂的大模型工程（数据处理、模型加载、训练算法、网页界面等）拆解成了一个个独立的部门（子文件夹），并把它们有机地组装在一起，形成一个一站式的大模型微调流水线。

2. 📄 直接文件是干什么的？

在这个根目录下，直接文件只有一个，但它非常关键：

💁 __init__.py —— 总部前台接待

  • 身份：指路人。
  • 作用：
    • 它是整个包的入口。当你写 import llmtuner 时，就是在这个文件里“登记”。
    • 对外：它把深藏在内部车间里的核心功能（如“开始训练”、“启动网页”、“导出模型”）直接请到了大门口。这样你不需要深入底层，在前台就能办完最重要的业务。
    • 对内：它定义了公司的“组织架构图”，规定了各个部门的层级关系（如 API > Train > Model）。

3. 📁 子文件夹的作用（部门分工）

为了让你一眼看懂，我们可以把这些子文件夹分为 四大职能区域：

A. 对外窗口区（怎么用？）

  • webui/ (网页界面)：驾驶舱。给喜欢点鼠标的人用的，提供可视化的控制台。
  • api/ (编程接口)：连接口。给其他软件用的，让别的程序能调用这里的功能。

B. 核心业务区（干什么？）

  • train/ (训练)：生产车间。这是工厂的心脏，负责让模型学习知识（预训练、微调、强化学习）。
  • eval/ (评测)：质检中心。负责给训练好的模型做试卷，打分评级。
  • chat/ (聊天)：体验中心。负责加载模型，让你能直接跟它对话，看看效果。

C. 资源与地基区（用什么干？）

  • data/ (数据)：原材料仓库。负责把各种乱七八糟的数据清洗、打包成模型能吃的格式。
  • model/ (模型)：设备维护部。负责加载底层的模型架构，处理适配器（LoRA）的拼接。

D. 后勤保障区（辅助支持）

  • hparams/ (超参数)：操作手册。定义了成百上千个配置选项（学习率、Batch Size等）的规则。
  • extras/ (杂项)：万能工具箱。存放日志记录、常量定义、绘图工具等通用的辅助工具。

4. 🧠 高层认知：如何快速理解这部分代码？

你可以把 src/llmtuner 看作是一个 “大模型微调的操作系统”。

  • 输入：你的数据（data） + 你的配置（hparams）。
  • 处理：在生产车间（train）里，利用原材料（model）进行加工。
  • 控制：你可以通过鼠标（webui）或代码（api）来指挥这个过程。
  • 输出：一个更聪明的模型，并且附带体检报告（eval）。

一句话总结：只要你想定制大模型，所有需要的工具、流程和逻辑，全都被打包在这个文件夹里了。
