src/llmtuner/webui

如果把整个 LLaMA-Factory 项目比作一艘“超级飞船”（用来训练和驾驶大模型），那么 src/llmtuner/webui/ 这个文件夹就是飞船的“驾驶舱”。

这里不负责造引擎（核心算法在别处），也不负责生产燃料（数据在别处），它的唯一任务就是：给人类提供一个看得见、摸得着的控制台（网页界面），让你不用敲代码就能开飞船。

下面我用最通俗的语言为你拆解这个“驾驶舱”的构造：

1. 📁 核心功能：它是干嘛的？

一句话总结：它是一个“翻译官” + “遥控器”。

  • 翻译官：它把你点击的“开始训练”按钮，翻译成后台复杂的 Python 代码命令。
  • 遥控器：它让你通过网页（Gradio）来控制模型的训练、评估和对话，并把后台的进度条和日志“直播”给你看。

2. 📄 直接文件：驾驶舱里的“工作人员”

为了维持这个控制台的运转，这里有一群分工明确的“工作人员”（Python 文件）：

🎨 负责“面子”工程的（界面与展示）

  • interface.py (装修队长)：它是总设计师。它负责把所有的按钮、窗口、标签页（Tab）组装在一起，搭建出完整的网页骨架。
  • css.py (室内设计师)：负责美化。它规定了按钮是圆的还是方的，弹窗要在正中间，暗黑模式下边框是什么颜色。
  • locales.py (语言翻译)：负责国际化。它是一本字典，把界面上的英文（如 Learning Rate）翻译成中文（学习率），让你能看懂。

🧠 负责“脑子”逻辑的（控制与执行）

  • engine.py (大堂经理)：它是控制台的总指挥。它协调各个部门，当你点按钮时，它指挥后台干活；当后台有进度时，它负责更新界面。
  • runner.py (执行官)：它是真正干苦力的。它负责把你在网页上填的参数打包，启动后台线程去跑训练（Training）或评估（Eval），并盯着进度条。
  • chatter.py (接线员)：专门负责“聊天”功能。当你和模型对话时，它负责把你的话传给模型，并把模型生成的字一个一个推送到屏幕上。

🔧 负责“后勤”保障的（辅助与管理）

  • manager.py (仓库管理员)：它手里有一本花名册，记录了界面上几十个按钮和输入框的“名字”和“位置”，确保程序能随时找到它们。
  • common.py (档案管理员)：负责记性好。它帮你保存网页上的设置（下次打开还在），并负责去硬盘里扫描有哪些模型和数据集可用。
  • utils.py (工具箱)：负责打杂。比如画那个“Loss 曲线图”、生成黑底白字的命令行代码、检查你输入的 JSON 格式对不对。
  • __init__.py (前台)：负责对外接待。它把最核心的启动功能暴露给外部，让别人一句 import 就能启动界面。

3. 📁 子文件夹：components/ 是什么？

它是“预制件仓库”。

如果 interface.py 是装修队长，那 components/ 文件夹里放的就是做好的房间。 * 里面有 train.py（训练房）、eval.py（评估房）、chatbot.py（聊天房）等。 * interface.py 不需要自己一砖一瓦地盖，它只需要去 components/ 里把这些现成的房间搬出来拼在一起就行了。

4. 🚀 高层认知：如何快速理解这部分代码？

你可以把 src/llmtuner/webui 看作是一个 Gradio 应用的典型架构。

  1. 前端（皮囊）：由 interface.py + components/ + css.py 负责画出来。
  2. 中转（神经）：由 manager.py + locales.py 负责管理元素和语言。
  3. 后端（灵魂）：由 engine.py + runner.py + chatter.py 负责响应你的操作，去调用底层的大模型算法。

简单来说：这里就是连接“你（人类）”和“大模型（机器）”的桥梁。
