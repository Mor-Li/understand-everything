src/llmtuner/webui/common.py

完全没问题。代码刚开始看的时候确实像天书，特别是这种“工具型”的代码，因为它不涉及核心的AI算法，全是琐碎的文件处理和界面逻辑。

你可以把这个文件 common.py 想象成一个 “Web界面的后勤大管家”。它的工作不是去训练AI，而是帮网页界面（WebUI）找文件、存设置、列清单。

为了让你读懂它，我为你制定了一个 6步走的学习任务清单 (Todo List)。我们一步一步来拆解：

📝 任务清单：破解 common.py

✅ Task 1: 搞清楚“我们在哪，要去哪” (基础配置)

目标：看懂代码开头的变量，它们定义了文件存放的“基地”。

  • 代码片段： python DEFAULT_CACHE_DIR = "cache" # 缓存目录 DEFAULT_DATA_DIR = "data" # 数据集目录 DEFAULT_SAVE_DIR = "saves" # 训练结果保存目录 USER_CONFIG = "user.config" # 用户配置文件名
  • 白话解释： 这就好比你要搬进一个新办公室，先贴好标签：文件柜在哪（data），草稿纸放哪（cache），做好的成品放哪（saves）。
  • 功能：get_save_dir 和 get_config_path 这两个函数，就是专门用来生成这些文件夹的具体路径的。

✅ Task 2: 学会“记性” (用户配置存取)

目标：看懂 load_config 和 save_config。

  • 场景：你在网页上填好了“模型路径”和“语言设置”，关掉网页再打开，希望它还在，对吧？
  • 代码逻辑：
    • load_config(): 尝试打开 cache/user.config 文件。如果打不开（比如第一次运行），就返回一个空的设置。
    • save_config(...): 把你在网页上选的语言（lang）、模型名称（model_name）和路径存进那个 json 文件里。
  • 一句话总结：这是给网页界面增加“记忆功能”，不用每次都重新填表。

✅ Task 3: 帮界面“找脑子” (获取模型路径)

目标：理解 get_model_path。

  • 痛点：模型可能存在你电脑的硬盘里，也可能需要从网下载。网页怎么知道去哪找？
  • 代码逻辑：
    1. 先看 用户配置 (user_config) 里有没有存过这个模型的路径？
    2. 如果没有，去查 支持的模型列表 (SUPPORTED_MODELS) 里的默认路径。
    3. 这里还有个彩蛋：如果你用了 use_modelscope()（国内的魔搭社区），它会优先去魔搭的路径找。
  • 一句话总结：这是一个“寻路指南”，确保程序能找到模型权重文件（.bin 或 .safetensors）到底在哪。

✅ Task 4: 识别“脑子的特性” (模型参数适配)

目标：理解 get_prefix, get_module, get_template。

  • 背景：不同的模型（比如 Llama, ChatGLM, Baichuan）脾气不一样。
    • Prefix: 名字的前缀（比如 Llama-2-7b 的前缀是 Llama）。
    • Module: 微调时要修改哪一层？（比如 q_proj,v_proj 是注意力层）。
    • Template: 对话时用什么格式？（比如“User: ... Assistant: ...”）。
  • 代码逻辑：
    • 这些函数就是根据你选的模型名字，自动去查表，返回对应的默认设置。
  • 一句话总结：这是“自动化填表”，你选了模型，它自动帮你填好适合这个模型的参数。

✅ Task 5: 盘点“外挂装备” (列出适配器/Adapters)

目标：理解 list_adapters。

  • 背景：LoRA 微调出来的结果，我们称为“Adapter（适配器）”，可以理解为给模型装的“外挂装备”。
  • 代码逻辑：
    1. 去 saves/模型名/lora/ 文件夹里扫描。
    2. 如果发现文件夹里有权重文件（adapter_model.bin 等），就把它加到列表里。
    3. 最后用 gr.update 通知网页界面：更新下拉菜单的选项。
  • 一句话总结：扫描硬盘，看看你之前训练过哪些 LoRA 模型，列在下拉框里供你加载。

✅ Task 6: 翻阅“教科书” (列出数据集)

目标：理解 load_dataset_info 和 list_dataset。

  • 背景：训练模型需要数据。数据都在 data 目录下，并且有一个 dataset_info.json 记录了所有数据的详情。
  • 代码逻辑：
    1. load_dataset_info: 读取那个 json 目录文件。
    2. list_dataset: 这是一个过滤器。
      • 如果你在做 SFT (指令微调)，它就只列出普通的问答数据。
      • 如果你在做 DPO 或 Reward Modeling (奖励模型)，它就只列出带有“排名/评分”的数据（ranking=True）。
  • 一句话总结：根据你当前想做的训练类型（SFT还是DPO），智能筛选出合适的数据集供你选择。

💡 总结

看完这 6 个 Task，再回头看整个文件，你会发现它其实就干了三件事：

  1. 读写配置：帮用户保存设置（Task 1, 2）。
  2. 智能推断：根据模型名字，猜路径、猜参数（Task 3, 4）。
  3. 扫描资源：扫描硬盘上的数据集和训练好的模型，展示在网页的下拉框里（Task 5, 6）。

这个文件是 WebUI 的 “胶水层”，连接了前端网页（Gradio）和后端的硬盘文件系统。
