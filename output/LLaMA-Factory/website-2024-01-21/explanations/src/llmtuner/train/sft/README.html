src/llmtuner/train/sft

这是一个非常核心的目录。为了让你一眼看透，我们可以把 src/llmtuner/train/sft/ 这个文件夹比作大模型培训学校里的 “刷题特训班”（SFT = Supervised Fine-Tuning，有监督微调）。

这里的代码只做一件事：拿着“问题”和“标准答案”，手把手教模型怎么好好说话。

以下是具体的通俗解释：

1. 🏢 这个文件夹是干嘛的？（核心功能）

功能定位： 有监督微调（SFT）的主战场。 如果说预训练（Pre-training）是让模型读万卷书，学会了“通识知识”；那么这里的 SFT 就是考前辅导。我们给模型一堆“模拟题（Prompt）”和“标准参考答案（Label）”，让它通过不断的练习和纠错，学会遵从人类的指令，变成一个能和你正常对话的聊天机器人。

2. 📄 各个文件是干什么的？（角色分工）

在这个“特训班”里，这 4 个文件分别扮演了不同的工作人员：

👮‍♂️ workflow.py —— 班主任（总指挥）

  • 真实身份：工作流管理器。
  • 作用：它负责统筹全局。它不直接教课，而是负责：
    • 把学生（模型）领进教室。
    • 把教材（数据）发下去。
    • 安排课表（配置参数）。
    • 最后喊一声：“开始上课！”（启动训练）。
  • 一句话：它是整个 SFT 流程的启动器和调度员。

👨‍🏫 trainer.py —— 特级教师（执行教练）

  • 真实身份：自定义训练器 (CustomSeq2SeqTrainer)。
  • 作用：它是真正陪着模型“练题”的人。
    • 它比普通的训练器更懂大模型，知道怎么处理变长的句子（Padding）。
    • 它知道怎么防止作弊（Masking），确保模型是在预测答案，而不是在背诵问题。
    • 它负责记录模型每一次练习的对错（Loss）。
  • 一句话：它是负责具体训练逻辑、盯着模型做题的教练。

📝 metric.py —— 阅卷老师（评分员）

  • 真实身份：评估指标计算器。
  • 作用：当模型做完题（生成了文本）后，这位老师负责打分。
    • 它看不懂数字，所以会先把模型输出的代码翻译成中文。
    • 然后拿着标准答案对比，算出 BLEU（准确度）和 ROUGE（相似度）分数。
    • 告诉班主任：这个学生考了多少分。
  • 一句话：它是负责把模型生成的答案转换成具体分数的阅卷人。

🚪 __init__.py —— 接待员（传达室）

  • 真实身份：包初始化文件。
  • 作用：它是个空架子，只负责对外挂个牌子。当外面的代码喊“我要做 SFT”时，它就把请求转接给班主任（workflow.py）。
  • 一句话：它是个接口，为了让外部调用更方便。

3. 📂 子文件夹的作用

(注：根据你提供的目录结构，当前层级下没有子文件夹。这是一个“扁平”的办事处，所有干活的人都在大厅里。)

4. 🧠 高层认知（一图胜千言）

如果你要在这个代码库里跑通 SFT 微调，流程是这样的：

  1. 外部指令 呼叫 __init__.py（接待员）。
  2. 接待员叫来 workflow.py（班主任）。
  3. 班主任准备好模型和数据，交给 trainer.py（教练）。
  4. 教练带着模型一轮轮训练，期间生成的作业交给 metric.py（阅卷老师）打分。
  5. 最终产出：一个学会了如何回答问题的新模型。

总结： 这个文件夹就是把“通用模型”变成“聊天助手”的加工车间。
