src/llmtuner/train/sft/workflow.py

这份代码是 LLaMA-Factory（或者类似的 LLM 微调框架）中用于 SFT（Supervised Fine-Tuning，有监督微调） 的核心工作流脚本。

简单来说，你可以把这个文件看作是一个 “施工队长”。它不负责具体的搬砖（计算梯度）或画图（模型架构），它的任务是协调：把模型拿来，把数据拿来，告诉工人怎么干活，最后验收成果。

为了让你更容易理解，我把 run_sft 这个函数拆解成一个 “微调大模型任务清单 (Todo List)”，我们一步步来看它干了什么。

📋 SFT 微调任务清单

1. 准备阶段：找工具和备料

  • Task 1.1: 加载模型 (Model) 和 分词器 (Tokenizer)。
  • Task 1.2: 获取并处理数据集。
  • Task 1.3: 调整分词器的设置（为了适应生成任务）。

2. 打包阶段：整理数据

  • Task 2.1: 设置数据整理器 (Data Collator)，负责把数据打包成一个个批次 (Batch)。

3. 组队阶段：初始化训练器

  • Task 3.1: 再次确认训练参数（比如生成文本的最大长度）。
  • Task 3.2: 启动 Trainer（训练器），把模型、数据、参数都交给它。

4. 执行阶段：训练、考试与应用

  • Task 4.1: (如果需要) 开始训练，并保存模型和画图。
  • Task 4.2: (如果需要) 进行评估，看看模型学得怎么样。
  • Task 4.3: (如果需要) 进行预测，让模型实际生成一些结果。

5. 收尾阶段：写报告

  • Task 5.1: 生成模型卡片 (Model Card) 并上传。

🧐 详细步骤讲解 (中英对照)

现在我们按照上面的清单，深入代码看看它是怎么实现的。

Task 1: 准备阶段 (Setup)

代码片段：

model, tokenizer = load_model_and_tokenizer(model_args, finetuning_args, training_args.do_train)
dataset = get_dataset(tokenizer, model_args, data_args, training_args, stage="sft")
  • 解读：
    • 第一行：去仓库把“大脑”（模型）和“字典”（Tokenizer）搬出来。
    • 第二行：根据配置读取训练数据（比如问答对），并用字典把文字转换成数字索引。
    • stage="sft" 告诉系统我们要进行的是有监督微调的数据处理。

代码片段：

if training_args.predict_with_generate:
    tokenizer.padding_side = "left"
  • 解读：
    • 这是一个小细节。如果我们要让模型生成文本（比如写作文），通常需要从左边填充空白（Left Padding），这样生成的字才能顺着往右写。

Task 2: 打包阶段 (Collator)

代码片段：

data_collator = DataCollatorForSeq2Seq(
    tokenizer=tokenizer,
    pad_to_multiple_of=8 ...
    label_pad_token_id=IGNORE_INDEX ...
)
  • 解读：
    • Data Collator 就像是一个打包员。因为每句话长度不一样，但显卡喜欢整齐的数据。
    • 它的工作是把短的句子补齐（Padding），把它们凑成一个整齐的方块（Batch）。
    • IGNORE_INDEX 是告诉模型：“这些补齐的空白部分你不用学，跳过不算分”。

Task 3: 组队阶段 (Trainer Initialization)

代码片段：

trainer = CustomSeq2SeqTrainer(
    model=model,
    args=training_args,
    tokenizer=tokenizer,
    data_collator=data_collator,
    **split_dataset(dataset, data_args, training_args),
)
  • 解读：
    • 这里初始化了 CustomSeq2SeqTrainer。这是最核心的“教练”。
    • 你把之前准备好的所有东西（模型、参数、字典、打包员、切分好的训练/验证集）都交给它。之后所有的累活都由它来调度。

代码片段：

gen_kwargs = generating_args.to_dict()
...
  • 解读：
    • 这里设置了“生成参数”。比如：模型在预测时，遇到什么词停止（eos_token），由于生成是一个字一个字蹦出来的，这些参数控制生成的行为。

Task 4: 执行阶段 (Execution)

Task 4.1: 训练 (Training)

if training_args.do_train:
    train_result = trainer.train(...) # 开始跑进度条训练
    trainer.save_model()              # 训练完保存模型权重
    trainer.log_metrics(...)          # 记录训练指标（比如Loss是多少）
    trainer.save_state()              # 保存训练状态
    if ... plot_loss(...)             # 画出 Loss 曲线图
  • 解读： 这是最耗时的部分，显卡开始发热，模型开始学习。

Task 4.2: 评估 (Evaluation)

if training_args.do_eval:
    metrics = trainer.evaluate(metric_key_prefix="eval", **gen_kwargs)
    ...
  • 解读： 训练中或训练后，用验证集考考模型。
  • predict_with_generate 如果开启，意味着我们会让模型真的去写答案，然后计算 BLEU 或 ROUGE 分数（文本相似度），而不仅仅是看 Loss（损失值）。

Task 4.3: 预测 (Prediction)

if training_args.do_predict:
    predict_results = trainer.predict(...)
    trainer.save_predictions(predict_results)
  • 解读： 用测试集让模型真正跑一遍，并把生成的结果保存成文件，方便人工检查。

Task 5: 收尾阶段 (Finalize)

代码片段：

create_modelcard_and_push(trainer, ...)
  • 解读：
    • 自动生成一个 README.md（模型卡片），里面记录了你用了什么参数、训练了多久、Loss 曲线长什么样。
    • 如果配置了 Hub token，还会自动把模型上传到 Hugging Face 网站。

总结

这个脚本 workflow.py 的逻辑其实非常线性：

  1. 加载 (Load) -> 模型和数据
  2. 配置 (Config) -> 修正参数和打包器
  3. 实例化 (Init) -> 创建 Trainer
  4. 运行 (Run) -> 根据开关决定是 Train(训练), Eval(评估) 还是 Predict(预测)
  5. 记录 (Log) -> 保存结果和文档

你看懂这个流程后，再回看代码，就会发现它只是在一步步填空而已。
