src/llmtuner/train/rm/trainer.py

这份代码的核心功能是定义了一个奖励模型（Reward Model）的训练器。

简单来说，它的任务是训练一个“裁判模型”，这个裁判需要学会：给定同一个问题的两个不同回答，判断哪一个更好（Chosen），哪一个更差（Rejected）。

为了让你听懂，我把这个代码的执行逻辑拆解成一个 Task To-Do List（任务清单）。每一项任务对应代码里的一段逻辑。

📋 奖励模型训练任务清单 (Task To-Do List)

  1. 准备阶段：拿到模型计算出的所有打分。
  2. 分组任务：把数据切分成“好学生（Chosen）”和“差学生（Rejected）”两组。
  3. 找不同任务（核心）：对比好坏两个回答，找出它们从哪里开始不一样的，忽略掉前面相同的提问部分。
  4. 打分任务：只对“不一样”的部分计算分数差距。
  5. 计算惩罚（Loss）：如果裁判认为“差学生”的分数比“好学生”高，就狠狠惩罚模型（Loss 变大）。
  6. 存档任务：把最终的预测分数存下来。

💡 逐步讲解

下面我按照这个清单，一步步带你看代码里的观点：

Task 1: 准备阶段 - 拿到打分

代码位置：compute_loss 函数开头

_, _, values = model(**inputs, output_hidden_states=True, return_dict=True)
  • 讲解：
    • inputs 里包含了问题和回答。
    • model(**inputs)：把数据喂给模型。
    • values：模型对每一个 token（字/词）都打了一个分（Reward）。

Task 2: 分组任务 - 区分“好”与“差”

代码位置：

batch_size = inputs["input_ids"].size(0) // 2
chosen_input_ids, rejected_input_ids = inputs["input_ids"][:batch_size], inputs["input_ids"][batch_size:]
chosen_rewards, rejected_rewards = values[:batch_size], values[batch_size:]
  • 观点/逻辑：
    • 训练数据的格式是特殊的：前半部分全是“好回答”，后半部分全是“差回答”。
    • 代码通过 // 2 把数据一分为二。
    • chosen 代表被人类选中的（好的），rejected 代表被人类拒绝的（差的）。

Task 3: 找不同任务 - 只要干货，不要废话（核心难点）

代码位置：for 循环内部

# 找出哪里是填充的空白（Padding），不要算进去
chosen_length = (chosen_input_ids[i] != self.tokenizer.pad_token_id).nonzero()[-1] + 1
rejected_length = ...

# 找出两个句子从哪里开始不一样的
check_divergence = (chosen_input_ids[i] != rejected_input_ids[i]).nonzero()
div_index = check_divergence[0] # 分歧点
  • 观点/逻辑：
    • 为什么要找分歧点（div_index）？
      • 因为输入里包含了“提问（Prompt）”。对于好坏两个样本，提问是一模一样的。
      • 如果模型去评价“提问”写得好不好，那是浪费时间，因为两边都一样。
      • 观点：我们只关心回答（Response）部分的差异。所以代码要找到两个句子开始不一样的地方，从那里开始算分。
    • 为什么要找长度？
      • 因为模型输入必须定长（比如 2048），不够长的部分补了 0（Padding）。我们不能给空白打分。

Task 4: 打分任务 - 截取有效片段

代码位置：

chosen_trunc_rewards = chosen_rewards[i, div_index:end_index]
rejected_trunc_rewards = rejected_rewards[i, div_index:end_index]
  • 观点/逻辑：
    • 根据刚才找到的“分歧点”和“结束点”，把中间这一段有效内容的分数截取出来。
    • 这才是真正代表“回答质量”的分数。

Task 5: 计算惩罚（Loss） - 好的必须比差的分高

代码位置：

loss += -torch.nn.functional.logsigmoid(chosen_trunc_rewards - rejected_trunc_rewards).mean()
  • 观点/逻辑：
    • 这是 Pairwise Loss（成对损失）的数学公式。
    • chosen - rejected：好回答的分数 减去 差回答的分数。
    • 目标：我们希望这个差值越大越好（正得越多越好）。
    • Loss：如果差值很大（比如好回答得10分，差回答得1分），Loss 就很小；如果差值很小甚至为负（模型认为差回答更好），Loss 就会非常大。
    • 结论：通过优化这个 Loss，迫使模型学会给“好回答”打高分，给“差回答”打低分。

Task 6: 存档任务 - 记录结果

代码位置：save_predictions 函数

json.dumps({"chosen": round(float(c_score), 2), "rejected": round(float(r_score), 2)})
  • 观点/逻辑：
    • 训练完或者评估完，我们想看看效果。
    • 这里把模型给“好回答”打的最终分，和给“差回答”打的最终分存进 generated_predictions.jsonl 文件里，方便人类检查。

总结

这个文件的核心观点是：训练奖励模型时，不要看整句话，而要对比“好回答”和“差回答”在差异部分的得分差距。

如果你能理解“老师改卷子，不仅看谁写得对，还要对比两个学生在同一道题上谁写得更好”，你就理解了这个代码的逻辑。
