src/llmtuner/model/adapter.py

完全没问题。这段代码对于刚接触大模型微调的人来说确实有点复杂，因为它集成了多种微调方式（全量、冻结、LoRA）以及一些像 DeepSpeed 或 Unsloth 这样的优化工具逻辑。

你可以把这个文件 adapter.py 看作是一个 “模型改装车间主任”。它的任务是：拿着一个原始的大模型（Base Model），根据你的需求（配置文件），把它改装成可以开始训练或者推理的状态。

为了让你听懂，我把这个“主任”的工作流程拆解成一个 To-Do List，然后一步一步对照代码给你讲。

📋 模型改装主任的 To-Do List

  1. 接待检查：你是来训练的还是只来做推理（使用）的？如果啥也不改，直接放行。
  2. 路径 A：全量改装 (Full)：如果要练整个模型，把所有零件精度调高。
  3. 路径 B：局部改装 (Freeze)：把模型大部分锁死，只留几层让你动。
  4. 路径 C：外挂改装 (LoRA) —— 这是最核心、最复杂的部分：
    • 4.1 旧挂件处理：如果有旧的外挂（Adapter），是把它融合进模型，还是接着练？
    • 4.2 新挂件安装：如果是新训练，挂件挂在哪里？（Target Modules）
    • 4.3 工具适配：有没有用 Unsloth 这种加速工具？
    • 4.4 正式挂载：使用 PEFT 库把 LoRA 挂上去。
  5. 最终安检：把需要训练的参数调整好数据格式（精度），打印日志，交货。

逐步讲解（对照代码）

1. 接待检查 (Entry Check)

代码开头部分：

if (not is_trainable) and model_args.adapter_name_or_path is None:
    # ... return model
  • 主任说：“如果你不是来训练的 (not is_trainable)，而且也没带任何外挂配件 (adapter_name_or_path is None)，那你把原始模型直接拿走吧，别浪费我时间。”

2. 路径 A：全量微调 (Full Fine-tuning)

if finetuning_args.finetuning_type == "full" and is_trainable:
    # ...
    model = model.float()
  • 观点：全量微调意味着模型的所有参数都要更新。
  • 操作：主任把模型的所有参数转成了 float32 格式。为什么？因为全量微调对精度要求高，用半精度（float16）容易数值溢出，训练不稳定。

3. 路径 B：冻结微调 (Freeze Fine-tuning)

if finetuning_args.finetuning_type == "freeze" and is_trainable:
    # ...
  • 观点：有时候显存不够，或者只想改改最后几层，就用 Freeze。
  • 操作：
    1. 计算层数：先看看模型一共有多少层。
    2. 确定白名单：根据配置 num_layer_trainable（比如最后3层），算出哪些层的 ID 是允许动的。
    3. 上锁：遍历模型所有参数。如果不在白名单里，设置 requires_grad_(False)（上锁，不更新）；如果在白名单里，转成 float32 准备训练。

4. 路径 C：LoRA 微调 (LoRA Fine-tuning) —— 重头戏

这是代码最长的部分 if finetuning_args.finetuning_type == "lora":。LoRA 就像是在模型旁边贴“贴纸”，不改原模型，只练贴纸。

4.1 处理既有适配器 (Handle Existing Adapters)

if model_args.adapter_name_or_path is not None:
    # ... 判断是否合并(merge) ...
    for adapter in adapter_to_merge:
        model = PeftModel.from_pretrained(model, adapter)
        model = model.merge_and_unload()
  • 场景：你可能已经有一个练了一半的 LoRA，或者你想在旧 LoRA 基础上练新的。
  • 操作：
    • Merge (融合)：有些情况下（比如量化模型或 DeepSpeed Zero3），不能挂多个外挂。主任会把旧的 LoRA 彻底融合 到基础模型里（变成模型的一部分），然后再进行下一步。
    • Resume (继续)：如果是接着练同一个 LoRA，就把它加载进来继续。

4.2 准备新 LoRA (Create New LoRA)

if is_trainable and adapter_to_resume is None:
    # ...
    if len(finetuning_args.lora_target) == 1 ...:
        target_modules = find_all_linear_modules(model)
    # ...
  • 观点：LoRA 需要挂在模型的特定层上（通常是 Linear 层，比如 Q、K、V 矩阵）。
  • 操作：
    • 如果你没指定挂哪，主任会用 find_all_linear_modules 自动寻找所有能挂的地方。
    • 准备好配置参数：r (秩，贴纸的大小), lora_alpha (贴纸的影响力) 等。

4.3 工具适配与挂载 (Unsloth & PEFT)

if model_args.use_unsloth:
    # ... 使用 Unsloth 加速库 ...
else:
    lora_config = LoraConfig(...)
    model = get_peft_model(model, lora_config)
  • 操作：
    • Unsloth：这是一个专门加速 Llama/Mistral 微调的库。如果开启了，主任会调用 Unsloth 特有的方法来创建 LoRA 模型。
    • PEFT：这是 HuggingFace 官方的标准库。如果没有特殊加速，就用标准的 get_peft_model 把 LoRA 挂载到模型上。

5. 最终安检 (Final Polish)

for param in filter(lambda p: p.requires_grad, model.parameters()):
    param.data = param.data.to(torch.bfloat16 if finetuning_args.lora_bf16_mode else torch.float32)
  • 观点：混合精度训练需要确定的数据类型。
  • 操作：主任最后检查一遍所有 需要更新的参数（比如 LoRA 的参数）。
    • 如果开启了 lora_bf16_mode，就把它们转成 bfloat16（这种格式在大显卡上又快又稳）。
    • 否则转成 float32 以保证计算稳定。

总结

这个文件的核心逻辑就是： 拿到模型 -> 看你怎么练(Full/Freeze/LoRA) -> 如果是 LoRA，处理好旧的挂件，装上新的挂件 -> 调整好参数精度 -> 返回改装好的模型。
