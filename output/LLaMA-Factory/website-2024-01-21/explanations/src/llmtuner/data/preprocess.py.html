src/llmtuner/data/preprocess.py

完全理解你的感受。这段代码涉及了大模型（LLM）训练中最核心、但也最繁琐的环节——数据预处理（Data Preprocessing）。

如果不了解背景，这就只是一堆难懂的列表操作。为了让你听懂，我们把这个文件看作是一个“食材加工车间”。

  • 原材料：原始的文本数据（用户说的话、书里的内容）。
  • 目标：把这些字变成模型能吃进去的“数字序列”（Token IDs），并且还要贴上标签（Labels）。

我为你列一个 Task Todo List，按照逻辑顺序，一步步拆解代码里的核心观点：

📋 数据预处理 Task Todo List

  1. 确定加工模式：你是要让模型“背书”（预训练），还是教它“对话”（微调），还是教它“判卷子”（奖励模型）？
  2. 数字化（Tokenization）：把人类的文字（"你好"）变成机器的数字（[101, 255]）。
  3. 加特技（Templating）：给对话加上特殊的标记，区分哪句是人说的，哪句是AI说的（比如 <user>...<assistant>...）。
  4. 做掩码（Masking / Labeling）：这是最关键的一步！告诉模型哪些字需要它预测（学习），哪些字只是给它看的提示（不计算损失）。
  5. 切分与打包（Truncation & Packing）：太长了要切断，太短了要拼凑，保证喂给模型的数据长度整整齐齐。

🧐 详细步骤讲解（对应代码中的函数）

下面我们按照上面的 List，结合代码里的函数来讲。

1. 预训练模式：preprocess_pretrain_dataset

场景：模型刚出生，或者要学习新的专业知识。不需要对话，只需要读懂海量文本。

  • 核心逻辑：
    • 代码把所有文本像贪吃蛇一样首尾相连拼起来。
    • 切块：按照固定的长度（block_size，比如 2048 或 4096）一刀刀切开。
    • 观点：在这个阶段，不需要区分提问和回答，模型只需要学会“预测下一个字是什么”。所以这里没有复杂的掩码操作。

2. 有监督微调模式（SFT）：preprocess_supervised_dataset

场景：这是最常用的。教模型怎么回答用户的问题。

  • 核心逻辑：
    • 输入格式：<bos> 用户的问题 AI的回答 <eos>
    • Label（标签）的处理（重点！）：
      • 代码片段：source_mask = [IGNORE_INDEX] * len(source_ids)
      • 解释：这是“掩码”。
        • 用户说的话（Prompt）：模型不需要预测，所以 Label 设为 IGNORE_INDEX（通常是 -100，意思是“考试时不考这一段”）。
        • AI 说的话（Response）：模型需要预测，所以 Label 就是原本的字。
    • 观点：只训练回答部分。我们不希望模型去学习“如何提问”，只希望它学习“如何根据提问来回答”。

3. “打包”微调模式：preprocess_packed_supervised_dataset

场景：为了省钱、省时间。

  • 核心逻辑：
    • 普通的 SFT 如果一句话很短（比如只有 100 个字），但模型要求输入 4096 个字，剩下的 3996 个位置都要补零（Padding），这很浪费显卡算力。
    • 打包（Packing）：把好几段不相关的对话拼在一条数据里。
      • 格式：对话A输入 对话A输出 <eos> 对话B输入 对话B输出 <eos>
    • 观点：榨干显卡的每一滴算力。通过塞满数据，让训练效率最大化。

4. 奖励模型模式（RM/DPO）：preprocess_pairwise_dataset

场景：教模型分辨“什么是好回答，什么是坏回答”。

  • 核心逻辑：
    • 数据必须成对出现：一个 Chosen（好的回答），一个 Rejected（坏的回答）。
    • 代码行为：它会把同一条提示词（Prompt），分别加上好回答和坏回答，生成两组数据。
    • 观点：对比学习。让模型通过比较两个答案的差异来学习人类的偏好。

5. 无监督/推理模式：preprocess_unsupervised_dataset

场景：模型训练好了，让它做题（推理），或者用于 PPO 的生成阶段。

  • 核心逻辑：
    • 只处理输入（Prompt），不需要处理 Label（因为不需要计算 Loss，或者 Loss 计算方式不同）。
    • 观点：只要题目，不要答案。

6. 总调度员：get_preprocess_and_print_func

场景：根据你的指令分配任务。

  • 核心逻辑：
    • 这是一个“分发器”。
    • 如果你传入参数 stage="pt"，它就叫来 preprocess_pretrain_dataset 干活。
    • 如果你传入 stage="sft"，它就看你要不要打包，叫来对应的 SFT 函数干活。

💡 总结一下文中的核心观点

这段代码其实就在通过 Python 列表操作实现一个核心思想：

“Teacher Forcing（教师强制）”与“Loss Masking（损失掩码）”

  1. 一切皆 Token：不管你是谁，都要先变成数字。
  2. 不该学的别学：通过 IGNORE_INDEX 把用户的问题“盖住”，强迫模型只关注如何生成正确的回答。
  3. 效率至上：通过 Packing（打包）和 Chunking（切块），确保喂给 GPU 的每一口数据都是满的，不吃空心馒头。
