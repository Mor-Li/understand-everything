src/llmtuner/data/formatter.py

这份代码确实看起来有点抽象，因为它属于 大模型微调/推理框架（如 LLaMA-Factory）的底层核心逻辑。

简单来说，这个文件的作用是：把原始的数据（比如用户说的话、工具的定义），“翻译”成模型能听懂的特定格式（Prompt Template）。

为了让你看懂，我为你设计了一个 6步的学习任务清单（Todo List）。我们一步步拆解，不涉及复杂的 Python 语法，只讲逻辑。

📋 学习任务清单 (Task List)

  1. Task 1：理解核心目标 —— 什么是 SLOTS？
  2. Task 2：理解最基础的“填空题” —— StringFormatter
  3. Task 3：理解“工具人”的说明书 —— default_tool_formatter
  4. Task 4：理解如何把说明书喂给模型 —— ToolFormatter
  5. Task 5：理解如何看懂模型的“暗号” —— default_tool_extractor
  6. Task 6：理解函数调用的格式化 —— FunctionFormatter

🚀 逐步讲解

Task 1：理解核心目标 —— 什么是 SLOTS？

  • 代码位置：SLOTS = Sequence[Union[str, Set[str], Dict[str, str]]]
  • 通俗解释： 想象你在拼积木。模型输入的不是一整块大石头，而是一串积木。 这里的 SLOTS 就是那串积木列表。
    • 通常它是字符串列表，比如 ["User:", "你好", "Assistant:"]。
    • 这个文件的所有类（Formatter），最终目的都是为了生成这个列表，喂给模型吃。

Task 2：理解最基础的“填空题” —— StringFormatter

  • 代码位置：class StringFormatter(Formatter)
  • 逻辑： 这是最常用的格式化器。它的工作原理就是做填空题。
    • 模板 (Slot)：比如 "User: {{content}}"
    • 输入 (kwargs)：比如 {"content": "今天天气怎么样"}
    • 动作：它会把 {{content}} 替换成 "今天天气怎么样"。
    • 结果："User: 今天天气怎么样"。
  • 观点：大部分对话数据，只需要这种简单的字符串替换就能搞定。

Task 3：理解“工具人”的说明书 —— default_tool_formatter

  • 代码位置：def default_tool_formatter(tools: List[Dict[str, Any]]) -> str
  • 背景： 现在的模型（Agent）可以使用工具（比如搜索、计算器）。但模型不知道它有哪些工具，你需要告诉它。
  • 逻辑：
    • 输入：一堆复杂的 JSON 数据，定义了工具有哪些参数。
    • 动作：这个函数把复杂的 JSON 转换成一段人类和模型都能读懂的文本说明书。
    • 生成的文本样子： ```text Tool Name: google_search Tool Description: 搜索互联网 Tool Args:
      • query (string, required): 搜索关键词 ```
    • 同时，它还会加上一段 TOOL_SYSTEM_PROMPT，告诉模型：“如果你要用工具，请按照 Action: xxx 的格式回答我”。

Task 4：理解如何把说明书喂给模型 —— ToolFormatter

  • 代码位置：class ToolFormatter(Formatter) 中的 apply 方法
  • 逻辑： 这是专门处理“工具定义”的格式化器。
    • 当系统发现输入里包含工具定义（tools）时，就会调用这个类。
    • 它内部调用了 Task 3 里的那个函数，把工具列表变成一串文本。
    • 观点：如果用户没给工具，就返回空；如果给了工具，就生成一份“工具使用指南”塞到 Prompt 里。

Task 5：理解如何看懂模型的“暗号” —— default_tool_extractor

  • 代码位置：def default_tool_extractor(content: str)
  • 背景： 当模型决定使用工具时，它不会直接运行代码（它只是个生成文字的 AI）。它会输出一段“暗号”文本。
  • 逻辑：
    • 模型输出的文本可能是：Action: calculate\nAction Input: {"x": 1, "y": 2}
    • 这个函数利用 正则表达式 (re) 去扫描这段文本。
    • 提取目标：
      1. 想用什么工具？（提取出 calculate）
      2. 参数是什么？（提取出 {"x": 1, "y": 2}）
  • 观点：这是模型与外部世界连接的桥梁，把模型的“胡言乱语”解析成程序能执行的指令。

Task 6：理解函数调用的格式化 —— FunctionFormatter

  • 代码位置：class FunctionFormatter(Formatter)
  • 逻辑： 这和 StringFormatter 很像，但它是专门为历史记录中的函数调用准备的。
    • 有时候我们需要把“模型以前调用过函数”这件事，作为历史记录喂回给模型。
    • 它会读取 JSON 格式的函数调用记录，把 name（函数名）和 arguments（参数）填入模板中。
    • 目的：让模型记得它之前干过什么（比如“哦，我上一轮已经调用过搜索了”）。

💡 总结全文观点

这个文件 formatter.py 实际上就是一个转换器工厂：

  1. 普通对话：用 StringFormatter 做简单的文本替换。
  2. 告诉模型有哪些工具：用 ToolFormatter + default_tool_formatter 把 JSON 变成说明书。
  3. 解析模型对自己说的话：用 default_tool_extractor 把模型的文本回复解析成函数调用指令。

一句话概括： 它是大模型微调框架中的“翻译官”，负责把人类的数据整理好喂给模型，再把模型想用工具的意图解析出来给程序执行。
