src/llmtuner

这里是 src/llmtuner 目录的“高层认知”说明。

如果说整个项目是一个巨大的工厂，那么 src/llmtuner 就是厂房内部。所有的车间、仓库、控制室都在这里面。

1. 🏢 这个文件夹主要负责什么？

核心职责：封装大模型微调的全流程逻辑。

这里是源代码的根目录。它把复杂的底层代码（PyTorch, Transformers）封装成了简单易用的功能模块。它的目标是：不管你是想改参数、处理数据、训练模型还是部署服务，都在这个文件夹里找对应的部门。

2. 📄 直接文件的作用

在这个层级下，只有一个核心文件：__init__.py。

  • __init__.py (对外办事窗口 / 菜单)
    • 作用：它定义了当别人 import llmtuner 时，能用到哪些功能。
    • 比喻：它是工厂的接待大厅。
    • 虽然干活的是里面的各个部门（子文件夹），但客户（用户脚本）不需要直接跑去车间喊人。
    • 你只需要在这个大厅里喊一声：“我要训练参数配置（get_train_args）”、“我要开始SFT微调（run_sft）”或者“我要开启聊天模式（ChatModel）”，这个文件就会把你指引到正确的子文件夹去执行。

3. 📁 子文件夹的作用 (部门分工)

我们可以把这些子文件夹看作工厂里的不同职能部门：

🛠️ 准备阶段 (原料与图纸)

  • hparams/ (配置部)：负责解析各种参数（学习率、显卡数量、模型路径）。就像图纸设计室，决定了今天要造什么样的产品。
  • dsets/ (数据部)：负责加载数据、预处理数据。就像原料处理车间，把原始的文本清洗、切分成模型能吃的格式。

⚙️ 核心生产 (加工车间)

  • tuner/ (训练部)：这是最核心的部门。负责执行预训练、微调、强化学习等任务。就像核心流水线，模型在这里经过千锤百炼，学会各种技能。

📦 辅助支持 (工具与后勤)

  • extras/ (后勤部)：提供保存模型、画图、日志记录等通用工具。就像维修与打包车间，哪里需要帮忙去哪里。

🚀 对外交付 (产品展示)

  • chat/ (对话部)：提供命令行聊天功能。就像内部测试室，训练完直接在这里跟模型聊两句试试。
  • api/ (接口部)：提供 Web API 服务。就像发货窗口，把模型包装成接口，供外部软件调用。

4. 🧠 高层认知：一句话理解这个目录

src/llmtuner 是一个高度模块化的“大模型加工厂”。

  • 左边输入：配置 (hparams) + 数据 (dsets)。
  • 中间加工：训练 (tuner) + 辅助工具 (extras)。
  • 右边输出：聊天体验 (chat) + 对外服务 (api)。
  • __init__.py 是指挥这一切的总调度台。
