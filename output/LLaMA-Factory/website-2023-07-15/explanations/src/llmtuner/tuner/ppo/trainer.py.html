src/llmtuner/tuner/ppo/trainer.py

这份代码是 LLaMA-Factory (原 LLM-Tuner) 项目中用于 PPO（Proximal Policy Optimization） 训练的核心逻辑。

简单来说，这是大模型训练的“第三阶段”——RLHF（基于人类反馈的强化学习）。在这个阶段，模型不再是简单地背诵课文（SFT），而是像学生一样，写出答案，老师（奖励模型）打分，然后模型根据分数调整自己，争取下次得分更高。

为了让你更容易理解，我将这份代码的逻辑拆解为一个 “任务清单 (Todo List)”，然后一步步对应代码给你讲解。

📋 PPO 训练流程任务清单 (Todo List)

想象这是一个正在运行的机器人，它的任务列表如下：

  1. 准备工作：初始化环境，确定要训练多少轮，准备好数据。
  2. 开始循环（针对每一个训练步）：
    • Task A: 做作业 (Generate) —— 给模型看题目（Query），让模型生成答案（Response）。
    • Task B: 老师打分 (Compute Rewards) —— 把题目和答案拿给“奖励模型”看，算出一个分数。
    • Task C: 订正学习 (PPO Step) —— 根据分数，调整模型的参数（如果分数高就强化这种写法，分数低就避免）。
    • Task D: 记录与存档 (Log & Save) —— 记下这一轮的平均分、Loss，如果到了存档点就保存模型。

🔍 逐步代码讲解

下面我按照上面的清单，带你读懂代码中的关键点。

1. 类的定义与初始化 (准备工作)

代码开头定义了 PPOPeftTrainer 类。

class PPOPeftTrainer(PPOTrainer, PeftTrainer):
    # ...
  • 观点：这是一个“混血儿”。它继承了 PPOTrainer（来自 trl 库，专门做强化学习）和 PeftTrainer（专门处理 LoRA 等高效微调）。
  • 含义：这意味着我们不是全量微调大模型，而是用轻量级的 LoRA 技术来进行 PPO 训练，节省显存。

2. 核心函数 ppo_train (主循环)

这是代码中最长的方法，也是核心逻辑所在。

Task A: 做作业 (Generate)

在 for step in tqdm(...) 循环内部：

# 1. 关掉梯度检查点和缓存，为了推理加速
unwrapped_model.gradient_checkpointing_disable()
unwrapped_model.config.use_cache = True

# 2. 获取题目 (Query)
query_tensors: torch.Tensor = batch["input_ids"]

# 3. 让模型生成答案 (Response)
response_tensors = self.generate(batch, length_sampler=output_length_sampler, return_prompt=False, **gen_kwargs)
  • 解释：这里模型处于“推理模式”。它看到 batch 里的 Prompt，然后自由发挥生成文本。
  • 细节：代码后面有一段 for i in range(len(query_tensors)) 的循环，那是为了把 padding（填充符）去掉，只保留有效的文本，因为 PPO 对 padding 很敏感。

Task B: 老师打分 (Compute Rewards)

这是这份代码里比较特殊且巧妙的地方：

# 1. 切换模型身份！
replace_model(unwrapped_model, target="reward")

# 2. 计算分数
_, _, values = self.model(**self.prepare_model_inputs(queries, responses))
rewards = [reward for reward in values[:, -1].to(torch.float32)]

# 3. 切回模型身份！
replace_model(unwrapped_model, target="default")
  • 核心观点：同一个基础模型，挂载了两个不同的 LoRA 适配器（Adapter）。
    • 一个是用于生成的（Actor/Default）。
    • 一个是用于打分的（Reward）。
  • 操作：
    • replace_model(..., target="reward")：把模型瞬间变成“奖励模型”。
    • 计算出 rewards（分数）。
    • replace_model(..., target="default")：把模型瞬间变回“生成模型”，准备接下来的训练更新。
  • 为什么这么做？ 为了省显存。不需要加载两个巨大的模型，只需要加载一个模型主体和两份很小的 LoRA 参数。

Task C: 订正学习 (PPO Step)

# 1. 开启梯度检查点 (为了省显存进行反向传播)
unwrapped_model.gradient_checkpointing_enable()
unwrapped_model.config.use_cache = False

# 2. 执行 PPO 更新
stats = self.step(queries, responses, rewards)
  • 解释：self.step 是父类 PPOTrainer 提供的方法。
  • 内部逻辑：它会拿刚才生成的“题目+答案”以及“分数”，去计算 PPO Loss（包括策略梯度的 Loss 和 KL 散度惩罚）。KL 散度是为了防止模型为了拿高分而“胡言乱语”，偏离原始模型太远。这一步会真正更新模型的参数。

Task D: 记录与存档 (Log & Save)

if self.is_world_process_zero() and (step+1) % self.args.logging_steps == 0:
    logs = {
        "loss": round(loss_meter.avg, 4),
        "reward": round(reward_meter.avg, 4), # 最重要的指标：看分数有没有上涨
        # ...
    }
    print(logs)
    # ...
  • 解释：每隔几步打印一次日志。在 RLHF 中，我们最关注 reward 指标。如果 reward 曲线稳步上升，说明模型变聪明了。

3. 辅助函数 generate

def generate(self, ...):
    # ...
    self.model, layer_norm_params = cast_layernorm_dtype(self.model)
    # ...
    response = unwrapped_model.generate(**inputs, **generation_kwargs)
    # ...
    self.model, _ = cast_layernorm_dtype(self.model, layer_norm_params)
    return response
  • 观点：为了生成时的数值稳定性。
  • 解释：在半精度（FP16/BF16）训练时，生成的概率分布有时候会溢出。这里用 cast_layernorm_dtype 临时把 LayerNorm 层转成 FP32（全精度）来生成，生成完再转回去。这是一种工程上的 Trick（技巧）。

💡 总结

这个文件的核心故事是：

  1. 利用 LoRA 的灵活性：在一个模型上动态切换“演员（生成）”和“裁判（打分）”的身份。
  2. 标准的 RL 循环：
    • 采样：模型自己生成数据。
    • 打分：奖励模型给出评价。
    • 更新：利用 PPO 算法优化模型，让它生成的答案更符合奖励模型的口味。

如果你要修改或调试代码，重点关注 ppo_train 里的循环部分，特别是 replace_model 前后的逻辑，那是 LLaMA-Factory 独特的设计。
