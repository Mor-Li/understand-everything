src/llmtuner/tuner/core/loader.py

这份代码文件 loader.py 的核心作用是 “组装”。

你可以把它想象成一个汽车改装车间的主管。它的工作是从仓库（HuggingFace 或 本地）把汽车引擎（大模型）搬出来，给它配上变速箱（分词器），根据你的需求（微调还是推理），决定是给它瘦身（量化），还是加装涡轮（LoRA 适配器），最后把车交给你。

为了让你更容易理解，我把这个过程拆解成一个 “任务清单 (Todo List)”，然后逐步解释代码是怎么执行这些任务的。

📋 任务清单 (Task Todo List)

  1. 环境安检：检查工具包（库版本）是否齐全。
  2. 准备翻译机 (Tokenizer)：加载分词器，让模型能看懂人类语言。
  3. 制定瘦身计划 (Quantization)：如果显存不够，决定是否把模型压缩成 8-bit 或 4-bit。
  4. 搬运引擎 (Load Model)：从硬盘加载基础模型权重。
  5. 改装准备 (Pre-processing)：如果是为了训练，做一些前置处理（比如开启梯度检查点）。
  6. 加装外挂 (Adapters)：如果不是全量微调，就给模型挂载 LoRA 等适配器。
  7. 特殊改装 (RLHF)：如果是做奖励模型 (RM) 或 PPO 训练，给模型加装“打分头” (Value Head)。
  8. 出厂检查：打印一下有多少参数需要训练，把模型交出去。

🧐 逐步解析 (Step-by-Step Walkthrough)

现在我们对照代码，一步步看它是怎么完成上面这个清单的：

1. 环境安检 (Imports & Version Checks)

代码开头的一堆 import 和 check_min_version。 * 观点：工欲善其事，必先利其器。 * 动作：代码检查 transformers, peft (微调库), bitsandbytes (量化库) 的版本。如果版本太老，直接报错，防止后面出现莫名其妙的 bug。

2. 准备翻译机 (Load Tokenizer)

对应代码：

tokenizer = AutoTokenizer.from_pretrained(...)
if tokenizer.pad_token_id is None ...:
    tokenizer.pad_token_id = 0
  • 观点：模型听不懂中文或英文，它只认识数字。
  • 动作：加载 Tokenizer。
  • 细节：代码里特意处理了 pad_token_id。有些模型（比如早期的百川）没有定义“填充符”，这里强制给它指定一个，防止训练时报错。

3. 制定瘦身计划 (Quantization Config)

对应代码：

if model_args.quantization_bit is not None:
    if model_args.quantization_bit == 8:
        ...
    elif model_args.quantization_bit == 4:
        ...
  • 观点：大模型太大了，显卡装不下怎么办？用更低的精度（量化）。
  • 动作：
    • 如果你设置了 quantization_bit=8 或 4，它会配置 BitsAndBytesConfig。
    • 这相当于告诉加载器：一会加载模型的时候，把原本 16 位的参数压缩成 4 位，这样 10GB 的模型可能只需要 3GB 显存就能跑起来。

4. 搬运引擎 (Load Base Model)

对应代码：

model = AutoModelForCausalLM.from_pretrained(
    model_to_load,
    config=config,
    ...
)
  • 观点：这是最核心的一步，把大家伙搬进显存。
  • 动作：使用 AutoModelForCausalLM 加载模型。
  • 细节：
    • device_map="auto"：如果不是训练模式，它会自动把模型切分到不同的显卡上。
    • torch_dtype：决定是用半精度 (float16) 还是 bf16 加载。

5. 改装准备 & 6. 加装外挂 (Adapters)

对应代码：

model = prepare_model_for_training(...) 
model = init_adapter(model, ...)
  • 观点：也就是所谓的“微调 (Fine-tuning)”。通常我们不动原模型（太贵、太慢），而是在旁边挂一个小模型（Adapter/LoRA）来训练。
  • 动作：
    • prepare_model_for_training：为了省显存，开启一些技术（如 gradient checkpointing）。
    • init_adapter：这是关键。它会调用另一个文件的方法，把 LoRA 层“插入”到大模型里。以后训练只更新这些 LoRA 层。

7. 特殊改装 (RLHF - RM/PPO)

对应代码：

if stage == "rm" or stage == "ppo":
    model = AutoModelForCausalLMWithValueHead.from_pretrained(model)
  • 观点：RLHF（人类反馈强化学习）需要模型不仅能说话，还能“打分”。
  • 动作：
    • 如果任务阶段是 rm (奖励模型) 或 ppo，代码会把模型包装进 AutoModelForCausalLMWithValueHead。
    • 这就好比给汽车装了一个“计价器”，原来的模型负责跑，新加的头负责评价跑得好不好（输出一个分数值）。
    • 如果是 PPO 阶段，它甚至会加载两个模型：一个负责生成，一个负责打分（Reward Model）。

8. 出厂检查 (Finalize)

对应代码：

if not is_trainable:
    model.requires_grad_(False) # 冻结所有参数
...
print_trainable_params(model)
return model, tokenizer
  • 观点：不管是训练还是推理，最后都要确认状态。
  • 动作：
    • 如果只是拿来用（推理），就把所有参数冻结（requires_grad_(False)），防止不小心改动了权重。
    • print_trainable_params：会在控制台打印：“当前模型有 70亿参数，其中只有 0.1% 是可训练的”。这让你确认 LoRA 挂载成功了。
    • 最后 return，把准备好的模型和分词器交给下一个流程（训练循环或聊天界面）。

总结

这个文件的逻辑就是： 加载配置 -> 加载分词器 -> 决定是否压缩模型 -> 加载模型本体 -> 挂载微调模块 (LoRA) -> (可选) 挂载强化学习模块 -> 返回成品。
