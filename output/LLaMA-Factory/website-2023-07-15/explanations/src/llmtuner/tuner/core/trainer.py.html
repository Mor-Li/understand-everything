src/llmtuner/tuner/core/trainer.py

这段代码确实涉及很多底层逻辑，如果没接触过 HuggingFace 的 Trainer 或者大模型微调（PEFT/LoRA），看起来会很晕。

你可以把这个 PeftTrainer 类想象成一个“大模型装修工”。普通的 Seq2SeqTrainer 是一个通用的装修工，而这个类是专门为了省钱装修（参数高效微调/PEFT）而定制的。

为了让你看懂，我把它拆解成一份“装修工的工作清单 (To-Do List)”，我们一步步来看它是怎么工作的。

📋 装修工 (PeftTrainer) 的任务清单

Task 1: 报到与准备 (Initialization)

对应代码： __init__ 和 _remove_log

  • 我是谁？ 我继承自 Seq2SeqTrainer（HuggingFace 的标准训练器）。这意味着原本训练器能干的事（比如安排训练进度、记录日志）我都能干。
  • 我要干啥？ 我在入职（初始化）的时候，除了拿标准的工具包（kwargs），我还专门拿了一份“微调施工图纸” (finetuning_args)。
  • 清理现场： 在开工前，我会检查一下输出目录里有没有旧的日志文件（trainer_log.jsonl）。如果有，我就把它删了，免得记混了（_remove_log）。

Task 2: 收工存档 (Saving Model)

对应代码： _save （这是最核心的部分）

普通的装修工收工时，是把整栋房子（整个模型）都打包存起来。但我这个“省钱装修工”不一样，我得看情况存东西。

  • 步骤 2.1：剥洋葱

    • 代码：model = unwrap_model(self.model)
    • 解释：先把模型外面包裹的并行计算、加速的外壳剥掉，拿到最核心的模型本体。

  • 步骤 2.2：检查有没有“奖励探头” (Value Head)

    • 代码：if hasattr(model, "pretrained_model"): ...
    • 解释：如果是做 RLHF（像 ChatGPT 那样的人类反馈强化学习），模型上会多长一个“脑袋”（Value Head）。如果发现了它，我得把它单独存到一个叫 value_head.bin 的文件里。

  • 步骤 2.3：根据装修类型存档 (关键！)

    • 情况 A：如果是 LoRA (贴壁纸模式)
      • 代码：if self.finetuning_args.finetuning_type == "lora": ...
      • 解释：LoRA 只是在原模型上挂了一些小参数（相当于只贴了壁纸）。我只保存这些“壁纸”（Adapter），不保存原来的房子（底座模型）。这样存下来的文件很小。
    • 情况 B：如果是全量微调/冻结微调 (拆墙重装模式)
      • 代码：else: ...
      • 解释：这种情况下，模型大改了。我必须把整个大模型的所有参数都存下来。同时为了兼容性，我会临时开启 use_cache 配置，存完再关掉。

  • 步骤 2.4：保存说明书

    • 解释：最后，我会把这次训练的参数配置写到 json 文件里，方便你下次查阅。

Task 3: 恢复最佳状态 (Loading Best Model)

对应代码： _load_best_model

训练过程中，我们会评估哪个时间点的模型效果最好。训练结束后，我需要把那个“最佳状态”找回来。

  • 步骤 3.1：根据装修类型回档
    • 情况 A：如果是 LoRA
      • 代码：backbone_model.load_adapter(...)
      • 解释：我找到那个最佳时间点的存档，把那时候的“壁纸”（Adapter）重新贴回到模型上。
      • 如果有“奖励探头”（Value Head），我也要把那个探头的参数读回来。
    • 情况 B：如果是全量微调
      • 代码：load_trainable_params(...)
      • 解释：直接把那个最佳时间点的所有参数覆盖回来。

💡 总结一下文中的核心观点

这段代码其实只解决了一个核心痛点：

HuggingFace 原生的 Trainer 不知道什么是 LoRA。

如果你用原生 Trainer 去存 LoRA 模型，它可能会傻乎乎地把整个几十 GB 的大模型都存下来，或者存错东西。

这个 PeftTrainer 重写了 _save 和 _load_best_model，就是为了告诉程序：

"嘿，如果我们在做 LoRA 微调，只存那几百 MB 的增量参数就好，别把底座模型也存了；但在加载的时候，记得要把这几百 MB 的参数挂载回底座模型上。"
