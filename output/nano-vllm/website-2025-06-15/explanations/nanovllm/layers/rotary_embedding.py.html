nanovllm/layers/rotary_embedding.py

这份代码实现的是大模型（LLM）中非常核心的RoPE（旋转位置编码）。如果直接看代码和公式确实很晕。

我们可以把它想象成你在指挥一支仪仗队。每个词（Token）就是一个士兵。为了让士兵知道自己站在第几排，我们不是直接告诉他“你是第5个”，而是给他一个旋转的角度。

下面我列一个 学习 To-Do List，把代码拆解成 4 个任务，带你一步步看懂。

📋 学习任务清单 (To-Do List)

  • [ ] Task 1: 理解核心概念 —— 为什么要“切两半”和“旋转”？
  • [ ] Task 2: 搞定准备工作 (__init__) —— 提前算好所有可能用到的“角度表”。
  • [ ] Task 3: 定义旋转动作 (apply_rotary_emb) —— 具体怎么对向量进行旋转？
  • [ ] Task 4: 实际执行流程 (forward) —— 来了新数据，怎么查表并旋转？

✅ Task 1: 理解核心概念

在看代码前，先建立一个直觉： RoPE 的核心思想是：通过旋转向量的角度来表示位置。

想象一个二维平面（X轴，Y轴）。 * 第 0 个词，不转（0度）。 * 第 1 个词，转 10 度。 * 第 2 个词，转 20 度。

代码里你会看到 x1 和 x2，这是因为旋转是在二维平面上进行的。所以我们需要把一个长的向量（比如 64 维），两两配对，切成 32 对，每一对都在自己的平面上转圈圈。

✅ Task 2: 搞定准备工作 (__init__)

代码位置： class RotaryEmbedding -> def __init__

既然每个位置对应的角度是固定的，我们没必要每次都在运行的时候算，不如提前算好一张表，存起来查表用。这就是 __init__ 做的事。

步骤解析：

  1. 计算频率 (inv_freq): python inv_freq = 1.0 / (base**(torch.arange(0, self.rotary_dim, 2, dtype=torch.float) / self.rotary_dim))

    • 这行看着很复杂，其实是在计算“旋转的速度”。
    • 向量的不同维度，旋转速度不一样（有的转得快，有的转得慢）。这保证了不同位置的区分度。

  2. 生成位置索引 (t): python t = torch.arange(self.max_position_embeddings, dtype=torch.float)

    • 这就是生成一个序列：[0, 1, 2, ..., 2047]（假设最大长度是2048）。代表第几个词。

  3. 计算角度表 (freqs): python freqs = torch.einsum("i,j -> ij", t, inv_freq)

    • 这是个矩阵乘法。它计算出了 “第 i 个位置，在第 j 个维度，应该转多少角度”。

  4. 把角度变成 Cos 和 Sin (cache): python cos = freqs.cos() sin = freqs.sin() cache = torch.cat((cos, sin), dim=-1) self.register_buffer("cos_sin_cache", cache, persistent=False)

    • 计算机旋转不用角度，用三角函数。所以把角度算成 cos 和 sin。
    • 关键点：它把结果存进了 cos_sin_cache。这就是我们的“作弊小抄表”。以后只要告诉它是第几个位置，直接从这里取数就行，不用再算了。

✅ Task 3: 定义旋转动作 (apply_rotary_emb)

代码位置： 文件最上方的函数 def apply_rotary_emb(...)

拿着上面算好的 cos 和 sin，具体怎么把一个向量 x 转一下呢？这里用的是高中数学里的复数旋转公式（或者叫二维旋转矩阵）。

公式原理：$(x + iy) * (cos + isin) = (x \cdot cos - y \cdot sin) + i(x \cdot sin + y \cdot cos)$

代码解析：

  1. 切分向量 (chunk): python x1, x2 = torch.chunk(x.to(torch.float32), 2, dim=-1)

    • 把输入向量劈成两半。比如向量是 [a, b]，切成 x1=[a], x2=[b]。这就是 Task 1 说的“两两配对”的逻辑实现。

  2. 执行旋转公式: python y1 = x1 * cos - x2 * sin y2 = x2 * cos + x1 * sin

    • 这就是上面那个数学公式的代码版。
    • y1 是旋转后的前半部分。
    • y2 是旋转后的后半部分。

  3. 拼回去 (cat): python return torch.cat((y1, y2), dim=-1).to(x.dtype)

    • 把转好的两半拼回一个完整的向量。

✅ Task 4: 实际执行流程 (forward)

代码位置： class RotaryEmbedding -> def forward

现在模型正在运行（推理或训练），来了具体的输入 query 和 key，以及它们对应的位置 positions。

步骤解析：

  1. 查表 (Look up): python cos_sin = self.cos_sin_cache[positions] cos, sin = cos_sin.chunk(2, dim=-1)

    • 拿着当前这些词的 positions（比如第5个词），去 Task 2 准备好的 cos_sin_cache 里把对应的数值取出来。
    • 把取出来的缓存拆回 cos 和 sin。

  2. 调整形状 (view): python query = query.view(num_tokens, -1, self.head_size)

    • 把数据整形成方便计算的样子。

  3. 开始旋转 (apply): python query = apply_rotary_emb(query, cos, sin).view(query_shape) key = apply_rotary_emb(key, cos, sin).view(key_shape)

    • 这是最关键的一步。调用 Task 3 写的函数。
    • 注意：RoPE 只旋转 Query 和 Key，不旋转 Value。这是因为注意力机制（Attention）是靠 Q 和 K 的点积来计算相似度的，旋转就是为了影响这个点积结果，注入位置信息。

总结

这整个文件的逻辑就是：

  1. __init__: 我先造一张巨大的表，记录下所有位置对应的旋转参数（Cos/Sin）。
  2. apply_rotary_emb: 我定义一个数学计算器，只要给我向量和参数，我就能算出旋转后的向量。
  3. forward: 每次来数据，我根据数据的位置去查表，然后丢给计算器，最后把转好的 Q 和 K 还给你。
