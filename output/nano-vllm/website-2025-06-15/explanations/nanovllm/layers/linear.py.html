nanovllm/layers/linear.py

这份代码的核心主题是：如何在多个 GPU 上并行地运行大模型（LLM）的线性层（Linear Layer）。

在大模型中，矩阵乘法（Linear）是最耗费显存和计算量的部分。为了跑得动大模型，我们需要把巨大的矩阵“切分”开，分给不同的显卡去算，这就是所谓的 张量并行（Tensor Parallelism, TP）。

为了让你听懂，我把这个过程拆解成一个 “多显卡分工合作”的 Task Todo List，我们一步步来看代码是怎么实现这个目标的。

任务清单：构建一个多显卡并行的线性层系统

✅ Task 1: 搞清楚“我是谁”和“咱们有多少人” (基础建设)

对应代码： LinearBase 类

在开始干活前，每个显卡（GPU）必须知道自己的身份。 * 代码解读： * dist.get_rank(): 我是第几号显卡？（比如一共2张卡，我是0号还是1号）。 * dist.get_world_size(): 咱们一共有几张卡？（TP size）。 * divide 函数：一个辅助工具，用来确保切分矩阵时能除尽，除不尽就报错。

✅ Task 2: 最简单的方案——“每人存一份完整的”

对应代码： ReplicatedLinear 类

这是最“笨”但最兼容的方法。 * 场景：假设矩阵不大，或者为了简单起见。 * 做法：不切分。每张显卡都加载完整的权重（Weight）。 * 代码解读： * weight_loader：直接把加载进来的权重 copy 给自己，不进行任何切片（slice）操作。 * forward：就是普通的 F.linear，跟单卡跑没区别。

✅ Task 3: 竖着切一刀——“列并行” (Column Parallel)

对应代码： ColumnParallelLinear 类

  • 场景：通常用于 MLP 的第一层（升维）或者 Attention 的 QKV 计算。
  • 原理：
    • 假设权重矩阵 $W$ 的形状是 [输出维度, 输入维度]。
    • 我们把 输出维度（列）切开。
    • 比如 $W$ 是 $100 \times 100$，有2张卡。卡0拿前50行，卡1拿后50行（注意 PyTorch Linear 权重通常是转置存储的，所以代码里切的是 tp_dim）。
  • 结果：卡0 算出来的结果是最终结果的“上半部分”，卡1 算是“下半部分”。大家算出来的结果形状不一样，拼起来才是完整的。
  • 代码解读：
    • self.output_size_per_partition = divide(output_size, self.tp_size): 计算每张卡只负责算多少输出。
    • weight_loader 中的 narrow(...): 这是核心。它根据我的 rank（卡号），只从完整的权重里“抠”出属于我的那一小块。

✅ Task 4: 进阶切法——“把多个层拼起来切” (Merged Column Parallel)

对应代码： MergedColumnParallelLinear 类

  • 场景：在 Llama 等模型中，MLP 层通常有 Gate 和 Up 两个投影层。为了快，我们把这两个矩阵拼在一起算。
  • 做法：这其实还是“列并行”，但是因为原来的权重是两个分开的矩阵，加载的时候比较麻烦。
  • 代码解读：
    • weight_loader 变得复杂了：它需要知道你现在加载的是第几块碎片（loaded_shard_id），然后根据设定好的 output_sizes 列表，精确地计算出每张卡该拿哪一段数据。

✅ Task 5: 最复杂的切法——“QKV 注意力层切分”

对应代码： QKVParallelLinear 类

  • 场景：专门用于 Attention 层的 Q（Query）、K（Key）、V（Value） 投影。
  • 难点：现在的模型流行 GQA (Grouped Query Attention)，意思是 Q 的头数（Heads）很多，但 K 和 V 的头数很少。
    • 比如：Q 有 32 个头，K 和 V 只有 4 个头。
    • 如果有 2 张卡，我们不能简单地除以 2。我们需要保证每张卡分到的 Q、K、V 的比例是对的。
  • 代码解读：
    • __init__ 里算了一堆数学题：根据总头数和卡数，算出每张卡负责多少个 Q 头、多少个 KV 头。
    • weight_loader：这是全文件最复杂的逻辑。
      • 如果加载的是 "q"：切分 Q 的权重。
      • 如果加载的是 "k"：切分 K 的权重，并把它拼在 Q 的后面。
      • 它确保了即使 Q 和 K 大小不一样，每张显卡也能拿到正确对应的那一部分。

✅ Task 6: 横着切一刀——“行并行” (Row Parallel)

对应代码： RowParallelLinear 类

  • 场景：通常用于 MLP 的第二层（降维）或者 Attention 的输出层（O_proj）。
  • 原理：
    • 这次我们切 输入维度（行）。
    • 数学原理：$Y = X_1 W_1 + X_2 W_2$。
    • 卡0 拿着输入的一部分 $X_1$ 和权重的一部分 $W_1$ 算出 $Y_1$。
    • 卡1 拿着输入的一部分 $X_2$ 和权重的一部分 $W_2$ 算出 $Y_2$。
    • 关键点：最终结果 $Y$ 等于 $Y_1 + Y_2$。这意味着两张卡算完后，必须通信，把结果加起来。
  • 代码解读：
    • weight_loader：这次切的是输入维度（input_size_per_partition）。
    • forward 中的 dist.all_reduce(y): 这是全文件最重要的通信代码。
      • 它的意思是：所有显卡停下来，把大家手里的 y 加在一起，然后把加好的结果同步给所有人。
    • Bias 处理：Bias（偏置项）只需要加一次。所以代码里写了 self.bias if self.tp_rank == 0 else None，只有 0 号卡加 Bias，其他卡不加，防止重复加。

总结：这代码到底在干啥？

想象你要搬一块巨大的砖头（做矩阵运算）：

  1. ReplicatedLinear: 每个人都搬一块一模一样的砖头（费力，不拆分）。
  2. ColumnParallelLinear: 把砖头竖着劈开，你搬左半边，我搬右半边。最后我们把两半拼在一起。
  3. RowParallelLinear: 把砖头横着劈开，你搬上半截，我搬下半截。最后我们需要把各自的结果加起来（All-Reduce）。
  4. QKVParallelLinear: 这是特殊的砖头（Attention），形状怪异（GQA），需要精细地切分，保证每个人手里的 Q、K、V 比例合适。

这个文件就是实现这些“切砖头”和“分配砖头”逻辑的底层代码，是自己写一个简易版 vLLM 或推理框架的基础。
