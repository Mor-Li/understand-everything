nanovllm/layers/linear.py

这份代码确实涉及了大模型（LLM）推理中最核心、也是最硬核的底层技术：张量并行（Tensor Parallelism, 简称 TP）。

简单来说，当一个模型（比如 Llama-3-70B）太大了，一张显卡装不下，我们需要把它“切开”放在多张显卡上运行。这个文件就是在定义“怎么切这个蛋糕（矩阵）”以及“切完之后怎么算”。

为了让你读懂，我制定了一个 5步走的学习 Task List。我们一步步拆解，不要试图一下子看完。

📋 学习任务清单 (Task List)

  • Task 3: 进阶概念 —— 什么叫“行并行” (RowParallel) 及其代价？
  • Task 4: 业务场景 —— QKV 和 Merged 是为了解决什么具体问题？
  • Task 5: 后勤保障 —— weight_loader 是干嘛的？

🟢 Task 1: 搞懂基础 (Base & Replicated)

目标：理解最普通的线性层在多卡环境下的状态。

代码对应：LinearBase, ReplicatedLinear

  1. LinearBase:

    • 这只是一个父类（基类）。
    • 它定义了所有线性层共有的属性：输入大小、输出大小。
    • 关键点：注意 self.tp_rank (我是第几张卡) 和 self.tp_size (总共有几张卡)。虽然代码里暂时写死了 1，但在实际运行中，比如 8 卡运行，tp_size 就是 8。

  2. ReplicatedLinear (复制线性层):

    • 含义：这就是普通的 nn.Linear。
    • 为什么叫 Replicated（复制）？ 意思是每一张显卡上都持有完整的权重（没有切分）。
    • 用途：通常用于模型中比较小的层（比如最后的分类头有时候不切），或者在不需要并行的时候。
    • 操作：F.linear(x, self.weight, self.bias)，就是最标准的矩阵乘法 $Y = XW^T + b$。

🟡 Task 2: 核心概念 (Column Parallel)

目标：理解怎么把矩阵“竖着切”。

代码对应：ColumnParallelLinear

场景： 假设权重的形状是 [输出维度, 输入维度]，比如 [100, 50]。现在你有 2 张显卡。

  1. 怎么切？

    • 列并行 (Column Parallel) 意味着我们将输出维度（Output Features）切分。
    • 显卡 A 拿 [0~49, 50] 的权重。
    • 显卡 B 拿 [50~99, 50] 的权重。
    • 代码体现：divide(output_size, self.tp_size)。它计算每张卡只负责一小部分的输出。

  2. 前向传播 (Forward)：

    • 输入 x 是完整的（所有卡都一样）。
    • 每张卡用自己那一小块权重进行计算。
    • 结果：显卡 A 算出结果的前半部分，显卡 B 算出结果的后半部分。大家手里的结果是不完整的，拼起来才是完整的。

  3. tp_dim=0:

    • 构造函数里传了 0，意思是在第 0 维度（行，对应输出维度）上进行切分。

🟠 Task 3: 进阶概念 (Row Parallel)

目标：理解怎么把矩阵“横着切”以及随之而来的通信问题。

代码对应：RowParallelLinear

场景： 通常在 Transformer 结构中，ColumnParallel 后面会接一个 RowParallel。

  1. 怎么切？

    • 行并行 (Row Parallel) 意味着我们将输入维度（Input Features）切分。
    • 权重形状 [100, 50]，2 张卡。
    • 显卡 A 拿 [100, 0~24]。
    • 显卡 B 拿 [100, 25~49]。
    • 代码体现：divide(input_size, self.tp_size)。

  2. 前向传播 (Forward) 的特殊性：

    • 输入也是切分的：因为上一层通常是 Column Parallel，显卡 A 手里只有前半部分输入，显卡 B 只有后半部分。
    • 计算：显卡 A 用“前半部分输入”乘“前半部分权重”，得到一个部分结果。
    • All-Reduce (关键点)：
      • 代码最后有一句 if self.tp_size > 1: dist.all_reduce(y)。
      • 因为矩阵乘法是行乘列求和。显卡 A 算了一半的和，显卡 B 算了另一半的和。
      • 必须通信！ 大家把手里的结果加起来，同步给所有人。这样每张卡最终都得到了完整的输出结果。

🔵 Task 4: 业务场景 (QKV & Merged)

目标：了解针对 Transformer (LLM) 的特殊优化。

代码对应：MergedColumnParallelLinear, QKVParallelLinear

这俩其实都是 ColumnParallel 的变种，只是切分逻辑更复杂。

  1. MergedColumnParallelLinear (合并列并行)：

    • 场景：在 Llama 等模型的 MLP 层（前馈网络），通常有 Gate_proj 和 Up_proj 两个线性层。
    • 优化：为了效率，我们把这两个层拼成一个大矩阵一次算完。
    • 逻辑：构造函数接受 output_sizes 列表（比如 [4096, 4096]）。它负责算出每张卡应该从第一层拿多少，从第二层拿多少，拼在一起。

  2. QKVParallelLinear (注意力层并行)：

    • 场景：Transformer 的 Attention 机制需要计算 Query (Q), Key (K), Value (V)。
    • 难点：Q 的头数 (Heads) 可能和 K, V 不一样（比如 Grouped Query Attention）。
    • 逻辑：
      • 它计算 Q, K, V 分别有多少个 Head。
      • 然后根据卡数，计算每张卡分到几个 Q Head，几个 K/V Head。
      • weight_loader 里有大量的 if loaded_shard_id == "q"，就是在精准地从完整权重文件中，把属于当前显卡的那几块肉（Head）割下来填进去。

🟣 Task 5: 后勤保障 (Weight Loader)

目标：理解如何把模型权重文件加载进这些切碎的层里。

代码对应：每个类里的 weight_loader 方法

你下载的模型文件（比如 pytorch_model.bin）通常是完整的。但是现在的代码把层切碎了。

  • 问题：显卡 A 说：“我只需要矩阵的前半截，别给我整个文件。”
  • 解决：
    • narrow(dim, start, length)：这是 PyTorch 的切片操作。
    • 逻辑：
      1. param.data 是当前显卡上的（切分后的）小权重容器。
      2. loaded_weight 是外部传进来的完整大权重。
      3. start_idx = self.tp_rank * shard_size：计算当前显卡该从哪里开始读。
      4. copy_：把切出来的那一小条数据，复制进参数里。

总结 (Summary)

看完这个 List，你再回头看代码，就会发现它其实只干了一件事：

为了让大模型在多张卡上跑起来，我们把矩阵乘法拆解了。

  • ColumnParallel：把结果拆了，一人算一部分输出。
  • RowParallel：把输入拆了，一人算一部分和，最后大家 All-Reduce 加在一起。
  • QKV / Merged：是为了适配 Transformer 结构的特殊切分方式。

建议你先只看 ColumnParallelLinear 的 __init__ 和 weight_loader，弄懂了“切分”和“加载”，其他的就都通了。
