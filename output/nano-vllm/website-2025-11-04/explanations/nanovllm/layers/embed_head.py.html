nanovllm/layers/embed_head.py

这份代码确实涉及到了大模型（LLM）底层比较硬核的知识：张量并行（Tensor Parallelism, TP）。简单来说，就是显卡显存不够大，或者为了算得更快，把一个巨大的神经网络层“切开”，分给好几张显卡一起算。

为了让你读懂，我制定了一个 5步学习清单（Task List）。我们把这个复杂的流程拆解开，就像剥洋葱一样，一步步看它是怎么把任务分给多张显卡的。

📋 学习任务清单 (Task List)

  1. Task 1: 理解“切蛋糕”的概念 —— 怎么把词表（Vocabulary）分给多张卡？
  2. Task 2: 看懂 VocabParallelEmbedding 的初始化 —— 每个人只领自己的那份工资（权重）。
  3. Task 3: 看懂 Embedding 的 forward 过程 —— 如何做到“各算各的，最后汇总”？
  4. Task 4: 进阶到 ParallelLMHead —— 最后的输出层是怎么反向操作的？
  5. Task 5: 理解特殊的优化细节 —— 为什么只取最后一个 token？

🚀 逐步讲解

✅ Task 1: 理解“切蛋糕”的概念 (Context)

在大模型中，词表（Vocabulary）通常很大（比如 32,000 个词或更多）。 * 普通做法：一张显卡存下整个 32000 x 4096 的矩阵。 * 并行做法（本文做法）：如果有 2 张显卡，每张卡只存 16000 x 4096。 * 显卡 0 负责词 ID：0 ~ 15999 * 显卡 1 负责词 ID：16000 ~ 31999

文中关键变量： * tp_rank: 当前显卡的编号（我是老几？）。 * tp_size: 总共有几张显卡。

✅ Task 2: VocabParallelEmbedding 的初始化

我们先看第一个类 VocabParallelEmbedding 的 __init__ 部分。它的核心任务是计算自己该管哪一段数据。

代码对应： python self.num_embeddings_per_partition = self.num_embeddings // self.tp_size self.vocab_start_idx = self.num_embeddings_per_partition * self.tp_rank self.vocab_end_idx = self.vocab_start_idx + self.num_embeddings_per_partition

白话解释： 假设一共 100 个词，2 张卡。 * 显卡 0：start_idx = 0, end_idx = 50。它只创建大小为 50 的权重矩阵。 * 显卡 1：start_idx = 50, end_idx = 100。它也只创建大小为 50 的权重矩阵。

注意：self.weight 在这里只有完整大小的 1/tp_size。这就是省显存的关键。

✅ Task 3: Embedding 的 forward 过程 (核心难点)

现在输入来了一句话，比如 token ID 是 [5, 80]（假设词表一共100，两张卡分）。 显卡 0 负责 0-49，显卡 1 负责 50-99。

代码逻辑拆解：

  1. 判断归属 (Masking): python mask = (x >= self.vocab_start_idx) & (x < self.vocab_end_idx) x = mask * (x - self.vocab_start_idx)

    • 显卡 0 看到 [5, 80]：
      • 5 在它的范围内 -> 保留。
      • 80 不在范围内 -> mask 设为 0，把 80 变成 0（为了防止报错，因为它的表里只有50个词）。
    • 显卡 1 看到 [5, 80]：
      • 5 不在范围内 -> 变成 0。
      • 80 在范围内 -> 减去偏移量 50，变成 30（因为它只查自己那张表里的第30行）。

  2. 查表 (Lookup): python y = F.embedding(x, self.weight)

    • 大家各自去查自己的小本本。
    • 显卡 0 查到了 5 的向量，但在 80 的位置查出来的是“假数据”（或者是0）。
    • 显卡 1 查到了 80 的向量，但在 5 的位置查出来的是“假数据”。

  3. 修正与合并 (All Reduce): python y = mask.unsqueeze(1) * y # 把不归自己管的位置彻底清零 dist.all_reduce(y) # 关键一步！

    • dist.all_reduce(y) 的意思是：把所有显卡上的 y 加起来，然后同步给所有人。
    • 位置 1 (Token 5): 显卡0的真值 + 显卡1的0 = 真值。
    • 位置 2 (Token 80): 显卡0的0 + 显卡1的真值 = 真值。
    • 结果：所有显卡都拿到了完整的、正确的向量表示。

✅ Task 4: 进阶到 ParallelLMHead

这个类是 LLM 的最后一层。它的作用是把向量变回词的概率（Logits）。它继承了上面的类，但方向是反的。

区别在于： Embedding 是 输入 ID -> 查向量。 LMHead 是 输入向量 -> 算每个词的得分。

代码逻辑：

logits = F.linear(x, self.weight)
  • 因为权重被切分了，显卡 0 只能算出前 16000 个词的得分；显卡 1 只能算出后 16000 个词的得分。
  • 现在的 logits 是不完整的（只有一半词表）。

收集结果 (Gather):

if self.tp_size > 1:
    # 准备一个列表来接收大家的结果
    all_logits = [torch.empty_like(logits) for _ in range(self.tp_size)] ...
    # 把大家的碎片收集到 rank 0 (主显卡)
    dist.gather(logits, all_logits, 0)
    # 拼起来
    logits = torch.cat(all_logits, -1)
  • 主显卡（Rank 0）把大家算出来的半截结果拼在一起，得到了完整的 32000 个词的得分，用于后续生成文字。

✅ Task 5: 理解特殊的优化细节 (Optimization)

在 ParallelLMHead 中有一段奇怪的代码：

context = get_context()
if context.is_prefill:
    last_indices = context.cu_seqlens_q[1:] - 1
    x = x[last_indices].contiguous()

这是在干什么？ 这是为了推理加速。

  • 场景：你发给 ChatGPT 一段话：“今天天气不错，适合去...”
  • Prefill (预填充阶段)：模型在读你的问题。此时，我们其实只需要模型预测最后一个字（“去”）后面接什么（比如“公园”）。
  • 优化：虽然输入了 10 个字，但我不需要把这 10 个字的下一个词都算一遍。我只把最后一个字的向量挑出来 (x[last_indices])，扔给全连接层算 Logits。
  • 这样大大减少了计算量。

💡 总结

这个文件其实就讲了两件事：

  1. 怎么省显存：把巨大的词表矩阵切成几块，分给不同的显卡存（VocabParallelEmbedding 的 __init__）。
  2. 怎么协同计算：
    • 输入层：大家各查各的，查不到的填0，最后相加（all_reduce）。
    • 输出层：大家各算各的（算出自己负责的那部分词的得分），最后拼起来（gather + cat）。
