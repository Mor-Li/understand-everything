nanovllm/layers/rotary_embedding.py

这段代码实现的是目前大语言模型（如 LLaMA）中最核心的位置编码技术：旋转位置编码（Rotary Positional Embedding，简称 RoPE）。

如果不理解背后的数学，这段代码确实像天书。为了帮你理解，我制定了一个 5步学习 Task List。我们不谈复杂的数学公式，只谈它是怎么运作的。

📋 你的学习 Task List

  1. Task 1：理解核心概念 —— 为什么要“旋转”？
  2. Task 2：理解准备工作 (__init__) —— 制造“角度表”。
  3. Task 3：理解核心操作 (apply_rotary_emb) —— 执行“旋转”动作。
  4. Task 4：理解流程整合 (forward) —— 查表并应用。
  5. Task 5：理解辅助功能 (get_rope) —— 避免重复造轮子。

🟢 Task 1：理解核心概念 —— 为什么要“旋转”？

在 Transformer 模型中，文字本身变成了向量（一串数字）。但是，“我爱你”和“你爱我”，字是一样的，顺序不同意思就变了。模型必须知道每个字的位置。

  • 以前的方法：直接给向量加上一个代表位置的数字。
  • RoPE的方法：通过旋转向量的角度来表示位置。

想象一下： 把向量看作钟表上的指针。 * 第1个字，把指针顺时针转 10 度。 * 第2个字，把指针顺时针转 20 度。 * 通过指针旋转的角度，模型就能知道这个字在第几个位置。

代码目的： 就是算出每个位置该转多少度，然后把输入的向量（Query 和 Key）转一下。

🟢 Task 2：理解准备工作 (__init__)

在 RotaryEmbedding 类的 __init__ 函数里，代码在做“预计算”。因为旋转角度是固定的，没必要每次算，先算好存起来（缓存）。

代码片段：

inv_freq = 1.0 / (base**(torch.arange(0, rotary_dim, 2, dtype=torch.float) / rotary_dim))
t = torch.arange(max_position_embeddings, dtype=torch.float)
freqs = torch.einsum("i,j -> ij", t, inv_freq)
cos = freqs.cos()
sin = freqs.sin()
cache = torch.cat((cos, sin), dim=-1).unsqueeze_(1)
self.register_buffer("cos_sin_cache", cache, persistent=False)

人话解释： 1. inv_freq (频率)：定义旋转的速度。向量的不同维度旋转速度不一样（有的转得快，有的转得慢，为了捕捉不同距离的关系）。 2. t (位置)：生成一个序列 [0, 1, 2, ..., max_pos]，代表第0个字、第1个字…… 3. freqs (角度)：用“位置”乘以“频率”，算出来每个位置、每个维度具体的角度（Theta）。 4. cos / sin：为了做旋转操作，我们需要角度的余弦值和正弦值。这里直接算好存起来。 5. register_buffer：把算好的这张巨大的“正余弦表”存进显存里，这就叫 cos_sin_cache。

总结：这一步造了一张巨大的“查阅表”，告诉我们在第 N 个位置，向量该转多少度。

🟢 Task 3：理解核心操作 (apply_rotary_emb)

这是整个文件最核心的函数，它执行真正的数学“旋转”。

代码片段：

def apply_rotary_emb(x, cos, sin):
    x1, x2 = torch.chunk(x.float(), 2, dim=-1) # 把向量劈成两半
    y1 = x1 * cos - x2 * sin
    y2 = x2 * cos + x1 * sin
    return torch.cat((y1, y2), dim=-1).to(x.dtype) # 拼回去

人话解释： 如何在二维平面旋转一个点 $(x_1, x_2)$？初中/高中数学公式是： * 新 $x = x_1 \cos(\theta) - x_2 \sin(\theta)$ * 新 $y = x_2 \cos(\theta) + x_1 \sin(\theta)$

代码对应： 1. torch.chunk(x, 2)：RoPE 把向量两两配对。比如向量长度是128，它把它切成两个长度64的向量 x1 和 x2。这就好比把它们看作 64 个 $(x, y)$ 坐标点。 2. y1 = ... 和 y2 = ...：这就是上面那个数学公式的直接翻译！ * y1 对应 $x_1 \cos - x_2 \sin$ * y2 对应 $x_2 \cos + x_1 \sin$ 3. torch.cat：旋转完之后，再把它们拼回原来的形状。

总结：这个函数就是拿着 Task 2 算好的 cos 和 sin，把输入向量 x 强行扭转了一个角度。

🟢 Task 4：理解流程整合 (forward)

这是模型运行时真正调用的地方。

代码片段：

def forward(self, positions, query, key):
    cos_sin = self.cos_sin_cache[positions] # 1. 查表
    cos, sin = cos_sin.chunk(2, dim=-1)     # 2. 拆分 Cos 和 Sin
    query = apply_rotary_emb(query, cos, sin) # 3. 旋转 Query
    key = apply_rotary_emb(key, cos, sin)     # 4. 旋转 Key
    return query, key

人话解释： 1. 输入： * positions：当前处理的是第几个字？（比如 [0, 1, 2]）。 * query, key：注意力机制需要的两个核心向量。 2. 查表 (self.cos_sin_cache[positions])：根据位置索引，从 Task 2 里的那个大表里取出对应的 cos 和 sin 值。 3. 应用：调用 Task 3 的函数，把 query 和 key 都转一下。 4. 返回：把转好的向量还给模型，拿去算注意力分数。

🟢 Task 5：理解辅助功能 (get_rope)

这只是一个外壳函数。

代码片段：

@lru_cache(1)
def get_rope(...):
    ...
    return RotaryEmbedding(...)

人话解释： * @lru_cache(1)：这是一个装饰器。意思是“如果参数没变，就直接返回上次创建好的对象，不要重新创建”。 * 作用：防止每次模型跑的时候都重复创建 RotaryEmbedding 类，节省一点点开销。

🏁 全文总结

这段代码其实只做了一件事：

  1. 预习 (__init__)：根据数学规则，算出所有位置对应的旋转角度（Cos/Sin值）。
  2. 考试 (forward / apply)：当数据进来时，根据它是第几个字，查表拿到角度，然后用旋转公式（$x\cos - y\sin$）把向量转一下。

这就完成了“把位置信息注入到向量里”的任务。
