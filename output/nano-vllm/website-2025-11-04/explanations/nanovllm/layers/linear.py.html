nanovllm/layers/linear.py

这份代码的核心主题是张量并行（Tensor Parallelism, TP）。

简单来说，就是模型（比如 Llama 3）的矩阵（权重）太大了，一张显卡装不下，或者算得太慢。我们需要把一个大矩阵“切”成好几块，分给不同的显卡（GPU）去算，最后再把结果拼起来。

这份代码就是定义了“怎么切”、“怎么算”、“怎么拼”的规则。

为了让你看懂，我给你列了一个 5步走的 Task List，我们一步步来拆解。

Task 1: 建立直觉 —— 为什么要切？(不看代码)

在看代码前，先建立一个心理模型。 假设全连接层（Linear Layer）的计算是：输入 x 权重 = 输出 ($Y = X \times W$)。

  • 现状：权重矩阵 $W$ 特别大（比如 $4096 \times 4096$）。
  • 目标：要把 $W$ 切开放在 2 张显卡上（TP Size = 2）。
  • 两种切法：
    1. 竖着切（按列切，Column Parallel）：每张卡存一半的输出特征。
    2. 横着切（按行切，Row Parallel）：每张卡处理一半的输入特征。

你的任务： 记住这两个方向。竖着切影响输出维度，横着切影响输入维度。

Task 2: 搞懂基建 —— LinearBase 类

现在看代码的前半部分。LinearBase 是所有切分方式的“爸爸”（父类）。

重点看 __init__ 方法：

class LinearBase(nn.Module):
    def __init__(self, ...):
        # ...
        self.tp_rank = dist.get_rank()      # 我是第几号显卡？(比如 0号 或 1号)
        self.tp_size = dist.get_world_size() # 总共有几张显卡？

        # 定义权重，注意这里只是初始化，还没有真正加载切分后的数据
        self.weight = nn.Parameter(torch.empty(output_size, input_size))

        # 这是一个钩子函数，用来定义“如何从完整的模型文件里，只加载属于我的那一块权重”
        self.weight.weight_loader = self.weight_loader

观点总结： * 这个类不干活（forward 报错），它只负责记录“我是谁（Rank）”以及“我要多大的坑（Shape）”。 * 它引入了一个概念 weight_loader，这是为了解决“大模型文件是完整的，但我只需要加载一小块”的问题。

Task 3: 最简单的切分 —— ColumnParallelLinear (竖着切)

这是代码中最直观的并行方式。

1. 看构造函数 __init__：

super().__init__(input_size, divide(output_size, tp_size), bias, 0)
  • 核心逻辑：input_size 没变，但 output_size 被除以了 tp_size。
  • 解释：如果你有 2 张卡，原本输出 4096 维，现在每张卡只负责输出 2048 维。

2. 看 weight_loader (怎么加载权重)：

start_idx = self.tp_rank * shard_size
loaded_weight = loaded_weight.narrow(self.tp_dim, start_idx, shard_size)
  • 解释：假如我是 1号卡。我就从完整权重的中间开始，切出属于我的一条（narrow 就是切片操作）。

3. 看 forward (怎么算)：

return F.linear(x, self.weight, self.bias)
  • 解释：计算逻辑居然没变！因为每张卡虽然只算出了一部分结果，但不需要和其他卡通信。
  • 结果：卡0 算出结果的左半边，卡1 算出结果的右半边。它们合起来才是完整的输出。

Task 4: 稍微难点的切分 —— RowParallelLinear (横着切)

这个类通常接在 ColumnParallel 后面使用。

1. 看构造函数 __init__：

super().__init__(divide(input_size, tp_size), output_size, bias, 1)
  • 核心逻辑：这次是 input_size 被除以了 tp_size。
  • 解释：每张卡只接受一部分输入特征进行计算。

2. 看 forward (最关键的区别！)：

def forward(self, x: torch.Tensor) -> torch.Tensor:
    # 1. 算出局部结果
    y = F.linear(x, self.weight, self.bias if self.tp_rank == 0 else None)

    # 2. 通信！All-Reduce
    if self.tp_size > 1:
        dist.all_reduce(y) # 把所有卡的结果加起来
    return y
  • 核心观点：
    • 因为大家是横着切输入计算的，卡0算了一部分和，卡1算了另一部分和。数学上 $Y = X_1 W_1 + X_2 W_2$。
    • 必须通信：dist.all_reduce(y) 的作用是让所有显卡把手里的 y 加在一起，同步给所有人。
    • Bias 的细节：代码里写了 bias if self.tp_rank == 0 else None。意思是 Bias 只能加一次！如果每张卡都加 bias，最后求和时 bias 就被加了 N 次，结果就错了。

Task 5: LLM 专属定制 —— QKV 和 Merged

LLM（特别是 Transformer 架构）有一些特殊的层，不能简单地切一刀，这两个类就是为了处理这些特殊情况。它们本质上都是 ColumnParallelLinear 的变体。

1. QKVParallelLinear (处理注意力机制的 Q, K, V) * 背景：Attention 层需要三个矩阵 Q、K、V。通常它们在模型文件里是拼在一起的大矩阵，或者分开存放。 * 难点：如果你直接按列切，可能会把 Q 切断，或者把 K 切断。我们需要的是：每张卡都分到“完整的几个头（Heads）”的 Q、K、V。 * 代码解读： * 它计算了 num_heads (Q的头数) 和 num_kv_heads (K/V的头数)。 * weight_loader 极其复杂：它根据你是加载 "q"、"k" 还是 "v"，计算出复杂的偏移量（offset），确保每张卡拿到的数据是逻辑上正确的（比如卡0拿到 Q的第0-4头，K的第0头...）。

2. MergedColumnParallelLinear (处理 MLP 层) * 背景：像 Llama 这样的模型，MLP 层有 Gate_proj 和 Up_proj，这两个通常并行执行。 * 做法：把这两个层拼成一个大的 Column Parallel 层。 * 代码解读：output_sizes 是一个列表（比如 [4096, 4096]）。weight_loader 负责把这两个不同的矩阵块切好分给不同的卡。

总结回顾

把这份文件看作是 “切披萨指南”：

  1. LinearBase: 披萨店老板，定义了谁负责吃哪块。
  2. ReplicatedLinear: 每个人都吃一整块披萨（不切，显存占用大）。
  3. ColumnParallelLinear: 竖着切披萨。每个人拿一长条。大家吃完放在桌上拼起来就是完整的披萨。
  4. RowParallelLinear: 横着切披萨（通常因为面饼是分层的）。大家吃进肚子里后，需要互相通气（all_reduce）才能消化。
  5. QKV... / Merged...: 拼盘披萨。上面有香肠(Q)、蘑菇(K)、洋葱(V)。切的时候要小心，不能把香肠切碎了，要保证每个人盘子里都有完整的香肠片。

现在的你再回去看代码，重点看 __init__ 里的除法（切哪里），和 forward 里的 all_reduce（要不要通信），应该就能看懂了。
