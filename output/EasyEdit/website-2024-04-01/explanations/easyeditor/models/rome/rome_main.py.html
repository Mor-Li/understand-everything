easyeditor/models/rome/rome_main.py

这份代码实现了 ROME (Rank-One Model Editing) 算法的核心逻辑。简单来说，它的目的是像做微创手术一样，修改大模型（如GPT）里的某一条特定知识（例如把“埃菲尔铁塔在巴黎”修改为“埃菲尔铁塔在罗马”），而不破坏模型里的其他知识。

这份代码读起来难懂，是因为它把“计算怎么改”和“实际动手改”分开了。

我们可以把这个过程想象成给模型做一次“记忆移植手术”。下面是一个按步骤执行的 Task Todo List，对应代码中的执行逻辑：

📋 ROME 算法执行清单 (Task Todo List)

Phase 1: 术前准备 (Setup)

  1. [ ] 接收修改请求: 获取用户想要修改的内容（比如：把“Steve Jobs”是“Apple”的创始人，改成是“Microsoft”的创始人）。
  2. [ ] 复制模型 (可选): 如果不想破坏原模型，就先克隆一个备份 (deepcopy)。
  3. [ ] 准备提示词模版: 为了让修改更稳健（不仅仅死记硬背这一句话），生成一堆上下文模版（比如“因为 Steve Jobs...”，“我说 Steve Jobs...”），这对应代码里的 get_context_templates。

Phase 2: 制定手术方案 (对应 execute_rome 函数)

这一步只计算数据，不产生永久性修改。

  1. [ ] 锁定目标层: 决定在神经网络的第几层动刀（由 hparams.layers 决定）。
  2. [ ] 计算“手术位置”向量 (Compute $u$):
    • 任务: 找到模型大脑中处理“Steve Jobs”这个主语的具体神经元位置。
    • 代码: 调用 compute_u。
    • 原理: 这是一个“键 (Key)”向量，代表“我们要改哪里”。
  3. [ ] 计算“新记忆”向量 (Compute $v$):
    • 任务: 计算出一个新的数值向量，使得当模型读到“Steve Jobs”时，直接输出“Microsoft”。
    • 代码: 调用 compute_v。
    • 原理: 这是一个“值 (Value)”向量，代表“我们要改成什么内容”。
  4. [ ] 验证并记录方案:
    • 暂时在内存里模拟修改一下，看看效果。
    • 把计算出的 $u$ 和 $v$ 打包成一个“增量包 (deltas)”。
    • 重要: 计算完后，把模型恢复原状（execute_rome 里的 weights[...]=weights_copy），保证这一步纯粹只是为了算出方案。

Phase 3: 执行手术 (对应 apply_rome_to_model 函数)

这一步是真正的写入操作。

  1. [ ] 读取增量包: 拿到刚才算出来的 $u$ 和 $v$。
  2. [ ] 格式对齐: 检查矩阵形状是否匹配（有的模型矩阵是转置的），对应 upd_matrix_match_shape。
  3. [ ] 注入新权重:
    • 核心公式: New_Weight = Old_Weight + (u * v)。
    • 代码: w[...] += upd_matrix。
    • 这相当于在原有的大脑连接上，叠加了一个修正补丁。
  4. [ ] 清理现场: 如果不需要保留原始权重备份，就释放内存。
  5. [ ] 出院: 返回修改后的模型 (model)。

1. 入口函数：apply_rome_to_model

这是手术的主刀医生，负责统筹。

def apply_rome_to_model(...):
    # ... 省略部分代码

    # 1. 制定方案：调用 execute_rome 计算出 u 和 v
    deltas = execute_rome(model, tok, request, hparams)

    # 2. 执行手术：真正修改模型的权重
    with torch.no_grad():
        for w_name, (delta_u, delta_v) in deltas.items():
            # 核心数学操作：计算改变量矩阵 = u 乘 v
            upd_matrix = delta_u.unsqueeze(1) @ delta_v.unsqueeze(0)

            # 获取模型原本的权重参数
            w = nethook.get_parameter(model, w_name)

            # 形状对齐（防止矩阵长宽搞反）
            upd_matrix = upd_matrix_match_shape(upd_matrix, w.shape)

            # !!! 这一步是真正的修改 !!! 
            # 把计算出的变化量加到原权重上
            w[...] += upd_matrix

    return model, weights_copy

2. 核心大脑：execute_rome

这是负责计算的麻醉师和分析师。它的特点是：计算完会把模型还原，只返回计算结果。

def execute_rome(...):
    # ... 预处理 prompt ...

    # 备份当前层的原始权重，方便计算完后还原
    weights_copy = {k: v.detach().clone() for k, v in weights.items()}

    # 循环处理每一层（通常 ROME 只改一层，但代码支持多层）
    for layer in sorted(hparams.layers):
        # Todo Step 5: 算出 u (在哪里改)
        left_vector = compute_u(...) 

        # Todo Step 6: 算出 v (改成什么)
        right_vector = compute_v(...)

        # ... 
        # 记录下这两个向量，存入 deltas
        deltas[weight_name] = (left_vector, right_vector)

    # !!! 恢复现场 !!!
    # 把刚才为了计算临时改动的权重恢复成原始状态
    # 因为真正的修改要交给 apply_rome_to_model 去做
    with torch.no_grad():
        for k, v in weights.items():
            v[...] = weights_copy[k]

    return deltas # 返回计算好的 u 和 v

3. 辅助工具：get_context_templates

这是为了防止模型“死记硬背”。

  • 观点: 如果我们只教模型“Steve Jobs founded Microsoft”，它可能换个问法“Who created Microsoft?”就答不上来了。
  • 做法: 代码里生成了很多前缀，比如 "I think...", "Because...", "The..."。
  • 目的: 在计算 $v$ (新记忆) 时，让模型在各种语境下都能输出正确的新结果，增强泛化能力。

总结

这篇代码其实就在干一件事： $W_{new} = W_{old} + u \times v^T$

  • apply_rome_to_model 负责执行这个加法。
  • execute_rome 负责算出 $u$ 和 $v$ 是多少。
  • compute_u 找主语（Subject）的位置。
  • compute_v 找新目标（Target）的信息。
