easyeditor/models/rome

这个目录 easyeditor/models/rome/ 是 ROME (Rank-One Model Editing) 算法的大本营。

如果把大模型比作一个拥有海量知识的“大脑”，那么 ROME 算法就是一种精准的微创脑科手术。它的目的是修改大脑里的某一条特定记忆（比如把“埃菲尔铁塔在巴黎”改成“埃菲尔铁塔在罗马”），同时绝不破坏大脑里的其他知识。

以下是这个目录的通俗解读：

1. 🏥 这个文件夹主要负责什么？

功能：AI 记忆定点修改器。

它负责执行一套复杂的数学流程： 1. 定位：找到某条知识在大模型神经网络中的具体位置（哪个神经元、哪个方向）。 2. 计算：算出需要把参数改成什么样，才能让模型说出新知识。 3. 植入：把计算好的新参数“注射”进模型里，完成修改。

2. 📂 各个文件的角色分配

我们可以把这套算法想象成一台精密的手术机器，每个文件都是机器的一个关键零件：

  • rome_main.py —— 【主刀医生 / 总指挥】

    • 作用：这是整个手术的入口。它负责统筹全局，先指挥 compute_u 找位置，再指挥 compute_v 算参数，最后拿起手术刀（apply_rome_to_model）把新参数写进模型里。

  • compute_u.py —— 【定位仪 / 导航系统】

    • 作用：负责寻找 Key（钥匙）。
    • 比喻：它的任务是回答“我们要改哪里？”。它通过分析模型对“Steve Jobs”这个词的反应，结合背景噪音（协方差），计算出一个精确的向量 u，标记出手术的具体切入点。

  • compute_v.py —— 【处方生成器 / 写入器】

    • 作用：负责计算 Value（新值）。
    • 比喻：它的任务是回答“我们要改成什么？”。它通过优化算法，算出一个向量 v，保证当模型被切入点 u 激活时，能够输出我们想要的新答案（比如“Rome”）。

  • layer_stats.py —— 【术前 CT 扫描 / 背景调查】

    • 作用：计算模型的“协方差矩阵”。
    • 比喻：为了不把模型改傻，我们需要知道模型平时“大脑”里的背景电流是什么样的。这个文件负责扫描大量的普通文本（如维基百科），建立一个“正常标准”，防止手术误伤。

  • repr_tools.py —— 【探针 / 显微镜】

    • 作用：提取隐藏层状态（Hidden States）。
    • 比喻：这是一个底层工具。它负责把“探针”伸进模型的某一具体层，把那里的神经元数值读取出来，交给上面那些文件去分析。

  • rome_hparams.py —— 【手术方案书 / 配置文件】

    • 作用：定义参数。
    • 比喻：这里面写满了设置：要在第几层动刀？学习率设多少？用哪个模型结构？它是手术前的“填空表”。

  • tok_dataset.py —— 【资料管理员】

    • 作用：处理文本数据。
    • 比喻：负责把用来做 CT 扫描（统计计算）的那些大量文本，整理成模型能读懂的格式（Tokenization）。

3. 📁 子文件夹的作用

4. 🧠 高层认知：一句话理解 ROME

你可以把这个文件夹看作是 神经网络参数层面的“查找与替换” (Find and Replace) 工具。

  • 普通的“查找替换”是针对文本的（把文档里的 A 换成 B）。
  • ROME 是针对数学矩阵的。它利用线性代数原理（Rank-One Update），计算出一个微小的补丁矩阵，加到大模型的权重里，从而“物理上”改变了模型的记忆。

公式总结： 这个文件夹就在努力计算两个向量 $u$ 和 $v$，然后执行： $$W_{新} = W_{旧} + (v \times u^T)$$ (旧的脑子 + 新的补丁 = 拥有新记忆的脑子)
