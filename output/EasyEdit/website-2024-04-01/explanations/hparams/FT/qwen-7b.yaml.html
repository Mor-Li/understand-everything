hparams/FT/qwen-7b.yaml

这份文件其实是一份“手术方案”或者说是“烹饪菜谱”。

它的应用场景是大模型知识编辑（Knowledge Editing）。简单来说，就是你想让大模型（这里是 Qwen-7b）学会一个新的知识点（比如“现在的美国总统是谁”），或者纠正一个错误的知识，但又不想重新训练整个模型，只修补其中极小的一部分。

为了让你读懂它，我为你列了一个“从宏观到微观的学习 Task List”，我们一步步来拆解：

🟢 Task 1：搞清楚我们在做什么（宏观定位）

目标：理解这份文件的作用。 * 文件名：hparams/FT/qwen-7b.yaml * 解释： * hparams = Hyperparameters（超参数），意思是这是用来控制程序运行的配置参数。 * FT = Fine-Tuning（微调）。这是我们使用的算法名字。 * qwen-7b = 通义千问 7B 模型。这是我们要“动手术”的病人。

结论：这是一个用来告诉程序“如何对 Qwen-7b 模型进行微调（Fine-Tuning）以修改其知识”的配置文件。

🟢 Task 2：理解核心策略（最难懂的注释部分）

目标：读懂文件开头那段让人头大的英文注释。 * 关键参数：objective_optimization: "prompt_last" * 原文注释翻译： * prompt_last: 模仿 ROME 论文的方法。它的逻辑是：只看输入（Prompt）的最后一个字，去预测目标。这通常用于让模型把某个特定的词（主语）和新的知识（宾语）强行关联起来。 * target_new: 标准的自回归方法。逻辑是：让模型学会把整句新话顺畅地说出来。 * 当前设定： * 文件中选用了 "prompt_last"。这意味着这次微调，我们更关注“点对点”的修正，而不是整句的生成流畅度。注释还提到这在他们的综述论文里对应 FT-L 这一类方法。

🟢 Task 3：确定“手术”位置与强度（超参数）

目标：理解我们要修改模型的哪一部分，以及修改多大。

  1. 在哪里动刀？

    • layers: [31]
    • 解释：Qwen-7b 有很多层（通常是32层），这里指定只修改第31层（也就是倒数第二层）。通常大模型越靠后的层，存储的具体知识和语义越丰富，所以改这里效果最直接。

  2. 动刀多久？

    • num_steps: 25
    • 解释：针对这一个知识点，我们只训练 25 步。这非常快，属于“微创手术”。

  3. 力度多大？

    • lr: 5e-4 (Learning Rate)
    • 解释：学习率。决定了修改参数的幅度。
    • norm_constraint: 5e-5
    • 解释：参数约束。这是一个“安全锁”，防止我们在修改模型时改得太猛，导致模型“变傻”或忘记其他东西。

🟢 Task 4：理解模型的“解剖图”（模型架构映射）

目标：告诉代码，Qwen 模型的内部零件叫什么名字。 * 背景：不同的模型（Llama, GPT, Qwen），它们内部代码的变量名是不一样的。代码需要知道去哪里找“第31层”。 * 配置内容： * rewrite_module_tmp: "transformer.h.{}.mlp.c_proj" * layer_module_tmp: "transformer.h.{}" * ... * 解释： * 这些像路径一样的字符串，是 Qwen 模型在 PyTorch 代码中的变量名路径。 * {} 是一个占位符，会被上面的 31 填进去。 * 例如：代码会去寻找 transformer.h.31.mlp.c_proj 这个具体的神经网络层，并只更新它的权重。

总结（Human Language Version）

如果把这看作是给医生（程序）的指令，这段代码的意思是：

  1. 病人：Qwen-7b 模型 (model_name)。
  2. 手术方式：传统的微调 (FT)，但采用类似 ROME 的优化目标 (prompt_last)，即重点修正最后一个token的预测概率。
  3. 手术部位：只动第 31 层 (layers: [31]) 的 MLP 投影层 (rewrite_module_tmp)。
  4. 手术时长：只训练 25 步 (num_steps)。
  5. 注意事项：动作幅度不要太大，不要破坏原有的参数结构 (norm_constraint)。
