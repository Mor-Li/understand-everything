hparams

你好！欢迎来到 hparams/ 目录。

如果把整个 AI 项目比作一家“超级医院”，专门负责给各种大模型（病人）做脑部手术（修改知识），那么这个文件夹就是医院的“核心档案室”。

以下是通俗易懂的解读：

1. 📁 当前这个文件夹 (hparams) 主要负责什么功能？

核心功能：存放所有的“手术方案”和“操作说明书”。

  • hparams 是 Hyperparameters（超参数） 的缩写。
  • 这里的代码不负责具体的开刀动作（那是 editors 或 methods 目录的事）。
  • 这里只负责告诉医生：
    • “今天要用哪种手术刀？”（算法选择）
    • “病人是谁？”（模型选择）
    • “刀切哪里？切多深？麻药打多少？”（具体的参数设置）

简单来说，这里是控制整个项目运行逻辑的“大脑配置区”。

2. 📄 这个文件夹下的各个直接文件分别是干什么的？

这里只有一个非常关键的直接文件：

  • 📄 config.yaml
    • 角色：总指挥官 / 任务派发单。
    • 功能：它是整个程序的总入口。当你启动程序时，它负责回答三个终极问题：
      1. 我们要用什么方法？（例如：alg_name: KN，告诉程序去调用 KN 算法）。
      2. 我们要修哪个模型？（例如：hparams_name: KN/t5-3b，告诉程序去加载 T5 模型的具体参数）。
      3. 结果存哪去？（定义了 save_dir 和 log_dir）。
    • 比喻：这就好比你进医院挂号，这张单子上写着：“请去 KN 科室，找 T5 医生，病历本存到 models 柜子里”。

3. 📁 子文件夹的作用是什么？

这些子文件夹（如 ROME/, LoRA/, MEND/ 等）就是“不同科室的专属档案柜”。

  • 分类依据：每一个文件夹代表一种特定的编辑算法（手术流派）。
  • 内容概括：
    • ROME/：存放 ROME 算法针对不同模型（Llama, GPT等）的配置。
    • LoRA/：存放 LoRA 微调针对不同模型的配置。
    • MEND/：存放 MEND 算法针对不同模型的配置。
    • ...以此类推。
  • 作用：因为不同的算法需要的参数完全不同（有的需要算梯度，有的需要算矩阵），所以必须分门别类地存放。

4. 🧠 给你一个高层的认知（Mental Model）

为了让你瞬间理解这个文件夹，请记住这个比喻：

“万能遥控器的代码表”

  • 你的核心代码 是一把 “万能遥控器”（它能控制所有电器）。
  • 各种 AI 模型（Llama, Qwen, GPT）是 “不同品牌的电视机”。
  • hparams 文件夹 就是那本厚厚的 “代码查询手册”。

当你想要控制 Llama 电视机 时，你不能乱按，你必须先翻开这本手册（hparams），找到 Llama 专页（对应的 .yaml 文件），查到它的特定频率代码（参数），输入给遥控器，这样才能精准地换台（编辑模型），而不会把电视弄坏。
