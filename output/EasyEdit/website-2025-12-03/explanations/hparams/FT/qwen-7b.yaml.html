hparams/FT/qwen-7b.yaml

这份文件其实是一个“手术方案”或者说“设置菜单”。

它的背景是：你有一个叫 Qwen-7b 的大模型，你想通过 FT (Fine-Tuning，微调) 的方法来修改它的某些记忆或知识（比如把“法国首都是哪里”的答案从“巴黎”改成“罗马”）。这个文件就是告诉代码具体该怎么改。

为了让你彻底搞懂，我制定了一个5步走的 Task List（任务清单）。我们一步步来拆解：

📋 学习任务清单 (To-Do List)

  1. Task 1：搞清楚“我们要对谁动手术？” (模型与环境配置)
  2. Task 2：核心难点——“怎么给模型打分？” (解读文件中最难懂的 objective_optimization 注释)
  3. Task 3：确定“手术要在哪里做？” (定位模型内部的具体层)
  4. Task 4：设定“手术的力度和时长” (超参数设置)
  5. Task 5：识别“具体的血管和神经” (模型架构映射)

🚀 详细讲解

✅ Task 1：搞清楚“我们要对谁动手术？”

文件对应内容：

alg_name: "FT"
model_name: "./hugging_cache/qwen-7b"
device: 0
  • 解读：
    • alg_name: 我们用的算法叫 FT (Fine-Tuning，微调)。这是最基础的模型编辑方法。
    • model_name: 病人是 Qwen-7b（通义千问7B版本）。
    • device: 使用第0号显卡进行计算。

✅ Task 2：核心难点——“怎么给模型打分？”

这是你觉得最看不懂的部分，也是文件的核心。 文件对应内容：

# We provide two implementations (objective_optimization):
#   1. prompt_last: ... ROME's original paper ...
#   2. target_new: ... standard autoregressive method ...
objective_optimization: "prompt_last"
  • 解读： 我们在教模型新知识时，需要一种方法来计算“误差”（Loss）。这里提供了两种流派：
    • 流派 A (prompt_last) [当前被选中]：
      • 意思：只看输入问题（Prompt）的最后一个字，来预测目标答案。
      • 来源：这是模仿 ROME 算法（一种著名的模型编辑算法）的做法。
      • 学术代号：在论文里叫 FT-L (Fine-Tuning on Last token)。
      • 比喻：做填空题，老师只盯着你填空前的那一个词，看你能不能直接反应出答案。
    • 流派 B (target_new)：
      • 意思：标准的语言模型训练方法。让模型把目标句子完整地说一遍，每一个字都要算误差。
      • 学术代号：在论文里叫 FT-M (Fine-Tuning on Model)。
      • 比喻：背诵全文，老师会检查你整句话通不通顺，每一个字对不对。

结论：这个配置文件目前选择了 流派 A (prompt_last)。

✅ Task 3：确定“手术要在哪里做？”

文件对应内容：

layers: [31]
  • 解读：
    • Qwen-7b 模型像是一个 32 层的大楼（从 0 到 31）。
    • 这里指定只修改 第 31 层。
    • 为什么？ 通常模型的深层（靠后的层）存储着更抽象的语义和事实知识，修改这里效果比较直接。

✅ Task 4：设定“手术的力度和时长”

文件对应内容：

num_steps: 25        # 练 25 次
batch_size: 1        # 每次只拿 1 条数据练
max_length: 40       # 句子的最长长度
lr: 5e-4             # 学习率：修改参数的步子迈多大
weight_decay: 0      # 权重衰减：一种防止过拟合的手段，这里关掉了
kl_factor: 0         # KL散度：防止模型改傻了的约束，这里关掉了
norm_constraint: 5e-5 # 参数范数约束：限制参数不能改得太离谱
  • 解读：
    • 这些是控制微调过程的“旋钮”。
    • lr: 5e-4 这是一个相对较大的学习率（对于微调来说），说明我们想快速强行改变模型的记忆。
    • norm_constraint 是一个保险丝，防止把模型改崩了。

✅ Task 5：识别“具体的血管和神经”

文件对应内容：

rewrite_module_tmp: "transformer.h.{}.mlp.c_proj"
layer_module_tmp: "transformer.h.{}"
mlp_module_tmp: "transformer.h.{}.mlp"
...
  • 解读：
    • 这些奇怪的字符串是 Qwen 模型的内部变量名。
    • 代码需要知道具体的“路径”才能找到参数。
    • {} 是一个占位符，会被上面的 layers: [31] 替换。
    • 重点：rewrite_module_tmp 指向了 mlp.c_proj。这说明该算法专门修改 MLP 层的投影矩阵。在很多研究中，MLP 层被认为是存储“知识”（比如 巴黎-法国）的关键区域。

💡 总结一下这篇文章（配置文件）在讲啥：

“嘿，代码！请帮我把 Qwen-7b 模型拿来。 我们用 FT（微调） 算法。 具体的策略是 FT-L (只看最后一个token)。 请直接定位到模型的 第31层，专门修改它的 MLP投影层。 咱们动作快点，学习率设为 5e-4，跑 25步 就行。 记得加上一点点约束 (norm_constraint) 别把模型搞坏了。”
