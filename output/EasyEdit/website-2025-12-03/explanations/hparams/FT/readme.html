hparams/FT/readme

这份文件其实是一个“手术方案”或者说“装修图纸”。

它的背景通常是：你有一个已经训练好的大模型（InternLM-7b），现在你想微调（Fine-Tuning, FT）它，比如让它学会一条新知识，或者修正一个错误的回答。这份文件就是告诉程序：“我要改哪个模型？改哪里？怎么改？”

为了让你彻底看懂，我们把阅读这份文件拆解成 4 个 Task（任务），由浅入深一步步来：

Task 1：搞清楚“我是谁，我在哪？”（基本身份信息）

首先，我们需要知道这次操作的基本对象是谁。

  • alg_name: "FT"
    • 解读：这是 Algorithm Name（算法名称）的缩写。FT 代表 Fine-Tuning（微调）。意思是：“我们要用的方法是基础微调”。
  • model_name: "/mnt/16t/xzwnlp/model/internlm/internlm-7b"
    • 解读：这是模型的家庭住址。程序会去这个路径下加载 InternLM-7b 这个大模型。
  • device: 0
    • 解读：这是指显卡编号。使用第 0 号 GPU 来干活。

Task 2：制定“手术强度”（训练超参数）

确定了对象后，我们需要设定训练的力度。如果力度太大，模型会变傻（遗忘旧知识）；力度太小，学不会新东西。

  • layers: [31]
    • 解读：这是重点！ 大模型通常由几十层像三明治一样的结构叠起来。这里指定：只修改第 31 层。其他的层保持不动。这通常是为了节省资源或进行特定层的各种实验。
  • num_steps: 25
    • 解读：学习次数。针对我们要教它的数据，反复学 25 步。
  • batch_size: 1
    • 解读：一口吃多少。每次只喂给模型 1 条数据进行学习。
  • max_length: 30
    • 解读：句子长度限制。输入的文本最长处理 30 个 token（字/词）。
  • lr: 5e-4
    • 解读：学习率 (Learning Rate)。这是修改参数的步幅。5e-4 (0.0005) 在微调中属于中规中矩的大小。
  • weight_decay: 0 和 kl_factor: 0
    • 解读：这些是约束条件。通常用于防止模型“学偏”或“过拟合”。这里设为 0 意味着暂时不加这些特定的约束。

Task 3：绘制“解剖地图”（模型内部结构定位）

这是你觉得最难懂的部分（也就是 #edit parameters 下面的内容）。 不同的模型（比如 Llama, GPT, InternLM），它们内部给零件起的名字是不一样的。这部分配置就是告诉代码，如何找到模型里的具体零件。

你可以把模型想象成一栋大楼，这一部分就是门牌号索引：

  • layer_module_tmp: "model.layers.{}"
    • 解读：这是楼层模板。
    • 那个 {} 是个占位符。如果我们之前说的 layers: [31]，代码就会把 31 填进去，变成 model.layers.31，从而定位到第 31 层。
  • mlp_module_tmp: "model.layers.{}.mlp"
    • 解读：这是全连接层（大脑思考区）的位置。
    • 它告诉程序：在第 {} 层里，那个叫 mlp 的东西就是我们要找的组件。
  • attn_module_tmp: "model.layers.{}.self_attn"
    • 解读：这是注意力机制（观察区）的位置。
    • 它告诉程序：在第 {} 层里，叫 self_attn 的就是注意力模块。
  • rewrite_module_tmp: "model.layers.{}.mlp.down_proj.weight"
    • 解读：这是真正的“手术点”！
    • 它精确到了具体的权重矩阵（Weight）。意思是：我们要修改的是第 {} 层，mlp 模块下，名为 down_proj 的那个投影层的权重。
    • 通俗理解：这里就是最后要动刀子修改参数的具体位置。

Task 4：总结与执行

现在我们把上面的碎片拼起来，这段代码的完整含义是：

“嘿，程序！请去硬盘里加载 InternLM-7b 模型，用第 0 号显卡。我们要用 FT (微调) 算法。

请你只盯着模型的第 31 层。具体来说，我们要修改这一层里 mlp.down_proj.weight 这个位置的参数。

训练的时候，每次喂 1 条数据，句子最长 30 个词，以 0.0005 的学习率，反复训练 25 次。”

为什么会有这个文件？

这个文件通常出现在 EasyEdit 或类似的大模型知识编辑项目中。因为不同的模型架构（Llama, BLOOM, ChatGLM）内部变量名都不一样，开发者为了不改写核心代码，就用这种 .yaml 配置文件来适配不同的模型。
