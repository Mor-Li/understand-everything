.github/ISSUE_TEMPLATE/feature-report.yaml

这份文件其实是一个 “许愿单”的模版。

简单来说，它的作用是：当有人想给 EasyEdit 这个软件（一个用来修改大模型知识的工具）提建议或想要新功能时，为了防止大家乱写，开发者设定了一个填空题表格。

如果你是一个想要提建议的用户，这份文件就是要求你按照以下 Todo List（任务清单） 一步步完成你的“许愿”：

任务背景：

假设你在使用 EasyEdit 这个工具时，发现它不支持某个新出的 AI 模型（比如 LLaMA），你很想让开发者加上这个功能。你需要填写这个表格。

你的 Todo List (填表步骤)：

✅ 第一步：给你的建议分个类 (Context)

  • 对应文件内容： id: context
  • 你要做的事： 这是一个多选题。你需要告诉开发者，你的建议属于哪一方面？
    • 是关于某种特定的编辑算法（比如 MEND, ROME）？
    • 是希望支持新的模型（比如 LLaMA）？
    • 是觉得好用的 API 不够好用？
    • 还是关于评估数据的？
  • 目的： 让开发者一眼看出这是哪个领域的建议，方便分配给懂的人看。

✅ 第二步：吐槽你遇到的困难 (Problem)

  • 对应文件内容： id: problem
  • 你要做的事： 必填项。你需要写一段话，描述你现在的痛点。
    • 举例思考： “我现在想用 MEND 算法去改 LLaMA 模型，但是 EasyEdit 现在不支持，所以我没法干活，这让我很头秃。”
  • 目的： 让开发者理解如果你没有这个功能，会有多麻烦。

✅ 第三步：描述你想要的“完美方案” (Proposal)

  • 对应文件内容： id: proposal
  • 你要做的事： 必填项。你需要具体描述你希望这个新功能长什么样。
    • 举例思考： “我希望你们能加一个 wrapper 模块，这样我调用的时候只需要改一行代码就能支持 LLaMA 了。”
  • 目的： 给开发者提供解决思路，或者明确你的期待值。

✅ 第四步：说说你想过的“笨办法” (Alternatives)

  • 对应文件内容： id: alternatives
  • 你要做的事： 选填。你需要告诉开发者，在没有这个新功能之前，你是怎么凑合用的？或者你有没有考虑过其他替代方案？
    • 举例思考： “我试过手动去改模型权重文件，但是太容易出错了，而且和你们的评估脚本不兼容，所以还是需要官方支持。”
  • 目的： 证明你不是随口一说，而是真的尝试过解决但失败了，这样开发者会更重视。

✅ 第五步：补充额外情报 (Additional context)

  • 对应文件内容： id: additional-context
  • 你要做的事： 选填。有没有什么参考链接、论文或者截图能辅助说明的？
    • 举例思考： “现在社区里大家都在用 Baichuan 和 InternLM 模型，支持这些模型对你们的项目很有好处哦。”
  • 目的： 提供更多背景信息，帮助开发者做决定。

✅ 第六步：签署“文明公约” (Code of Conduct)

  • 对应文件内容： id: code-of-conduct
  • 你要做的事： 必填勾选。
    • 意思就是： “我保证我说话文明，不骂人，遵守社区规则。”
  • 目的： 法律/规则层面的确认。

总结

这份 YAML 文件就是生成上述这个表单的“源代码”。

它不是给机器读的配置，而是给 GitHub 这个网站看的。GitHub 看到这个文件后，会在网页上自动生成一个漂亮的界面，让提建议的人只能按照这个 Todo List 的顺序填写，从而保证每一个建议都有理有据、格式清晰。
