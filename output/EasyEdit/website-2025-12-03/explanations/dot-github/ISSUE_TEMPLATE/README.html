.github/ISSUE_TEMPLATE

你好！这是一个非常生动且实用的文件夹。我们可以把它想象成这个开源项目的“客服办事大厅”。

如果不加控制，用户来提问（Issue）时可能会乱写一通（比如只写一句“救命，报错了”），这会让开发者很头疼。这个文件夹就是为了解决这个问题而存在的。

下面我用最通俗的语言为你解答：

1. 当前文件夹 (.github/ISSUE_TEMPLATE) 主要负责什么功能？

它的功能是：给“客服中心”设立规矩和专用表格。

想象一下，你走进一家银行或医院。如果没有这个文件夹，就像是你直接冲进去对着柜员大喊大叫，效率很低。 有了这个文件夹，就像是大厅里摆放的“自助填单台”。它强制要求用户在提问前，先想清楚自己要干嘛，然后领取对应的表格（模板）填写。这样，开发者收到的每一份反馈都是格式标准、信息齐全的。

2. 这个文件夹下的各个直接文件分别是干什么的？

根据你提供的列表，这里有三张“单子”：

  • 📄 bug-report.yaml（报修单）

    • 作用：专门用来捉虫。
    • 比喻：这是给遇到故障的用户准备的“维修申请表”。
    • 核心逻辑：它会强制你填写“哪里坏了？”、“怎么坏的？”、“你的电脑环境是什么？”。不填完这些，就不让你提交。目的是让开发者能快速复现并修好 Bug。

  • 📄 feature-report.yaml（许愿单）

    • 作用：专门用来提新需求。
    • 比喻：这是给有想法的用户准备的“建议箱”或“许愿卡”。
    • 核心逻辑：如果你觉得软件缺了什么功能，或者想支持新的模型，就填这张表。它引导你写清楚“你想要什么功能？”、“为什么需要它？”、“你觉得应该怎么实现？”。

  • 📄 config.yaml（大厅管理规定）

    • 作用：用来配置大厅规则。
    • 比喻：这是写给 GitHub 这个“大厅管理员”看的“内部守则”。
    • 核心逻辑：它决定了用户进来时能看到什么。最关键的一点是，它决定了“是否允许用户拿一张白纸随便写（Blank Issue）”。在这个项目里，它允许用户不填那两张表，直接创建一个空白的提问。

3. 子文件夹的作用是什么？

(注：在你提供的目录结构中，目前没有列出子文件夹，只有三个文件。但通常如果这里有子文件夹的话，遵循以下逻辑)

  • 作用：归档杂物或特定素材。
  • 概括：如果说外面那几个 .yaml 文件是“表格”，那子文件夹通常用来存放这些表格需要用到的图标、图片，或者是更复杂的、不常用的备用表格。它们是辅助性质的，普通用户填表时一般不需要直接去翻这些子文件夹。

4. 给我一个高层的认知，让我能快速理解这部分代码的作用

一句话总结：它是“沟通的过滤器”。

  • 没有它：用户和开发者的沟通是“菜市场吵架”模式——混乱、嘈杂、抓不住重点。
  • 有了它：沟通变成了“流水线作业”模式——
    • 是 Bug？走左边通道填红表；
    • 是建议？走右边通道填绿表；
    • 开发者拿到表单，一眼就能看懂问题在哪，干活效率直接起飞。

所以，这部分代码不是用来“跑程序”的，而是用来“管理那个跑程序的人（开发者）和用程序的人（用户）之间关系”的。
