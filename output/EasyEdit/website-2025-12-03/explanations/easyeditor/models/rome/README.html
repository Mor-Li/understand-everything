easyeditor/models/rome

这是一个非常形象的“大模型脑外科手术室”。

这个文件夹 easyeditor/models/rome/ 封装了 ROME (Rank-One Model Editing) 算法的所有核心代码。它的任务只有一个：在不重新训练模型的情况下，精准地修改模型大脑里的某一条具体知识（比如把“埃菲尔铁塔在罗马”改成“在巴黎”）。

下面我用“做微创手术”的比喻来回答你的问题：

1. 当前文件夹主要负责什么功能？

这里是 ROME 算法的“手术室”。 如果说 easyeditor 是整家医院，那么这个文件夹就是专门负责做 “单点知识修改手术” 的科室。它包含了一整套流程：从术前检查（统计数据）、定位病灶（找神经元）、制定手术方案（计算参数），到最后实施手术（修改权重）。

2. 这个文件夹下的各个直接文件分别是干什么的？

我们可以把这些文件看作手术室里的不同角色和工具：

核心主刀团队： * rome_main.py (主刀医生/总指挥)： * 它是整个手术的控制中心。它负责协调各个步骤，调用下面提到的工具，最终完成把新知识注入模型的过程。 * compute_u.py (病灶定位仪)： * 负责“找位置”。它通过复杂的计算，找出模型到底是哪一个神经元（Key向量，$u$）负责存储了那个错误的知识。 * compute_v.py (药物调配师)： * 负责“配药”。它计算我们要把这个神经元的输出改成什么样子（Value向量，$v$），才能让模型说出正确的新知识。

术前准备与保障团队： * layer_stats.py (术前CT/体检中心)： * 负责“防副作用”。它提前扫描模型在处理普通文本时的状态（协方差统计），确保手术在修改知识的同时，不会破坏模型的语言能力（比如改完后模型不会变成哑巴）。 * rome_hparams.py (手术处方单)： * 负责“参数设置”。定义手术的强度、修改哪一层、学习率是多少等配置信息。

后勤支援工具： * tok_dataset.py (营养师/供餐员)： * 负责“数据处理”。把文本处理成模型能吃的格式（Token），喂给模型进行计算。 * repr_tools.py (探针/显微镜)： * 负责“提取信号”。它是一个底层工具，用来从模型深处提取特定位置的隐藏层向量，供定位仪和调配师使用。 * __init__.py (科室接待员)： * 负责“对外接口”。它把复杂的内部工具打包好，只暴露出最简单的接口给外部调用。

4. 高层认知：如何快速理解这部分代码？

要把 ROME 算法想象成“修改字典里的一个词条”。

大模型虽然是神经网络，但 ROME 把其中的一层（MLP层）看作是一个巨大的 Key-Value（键-值）存储器： 1. Key ($u$)：代表“看到什么”（比如看到“埃菲尔铁塔”）。 2. Value ($v$)：代表“联想到什么”（比如联想到“巴黎”）。

这个文件夹的所有代码就在做三件事： 1. 找到 Key (compute_u)：找到“埃菲尔铁塔”对应的那个键。 2. 算出新 Value (compute_v)：算出代表“罗马”的新值。 3. 更新映射 (rome_main)：利用数学公式（Rank-One Update），把这个键值对更新进模型的参数里，同时利用统计数据 (layer_stats) 保证不干扰别的键值对。

总结：这就是一套给大模型做“定点清除记忆并植入新记忆”的精密手术工具包。
