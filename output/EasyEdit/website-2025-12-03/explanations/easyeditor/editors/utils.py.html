easyeditor/editors/utils.py

这份代码文件 utils.py 在 EasyEditor 项目中扮演的是一个 “后勤大管家” 的角色。它不负责核心的“修改模型神经元”这种高难度手术，而是负责把数据整理好送进手术室，以及手术结束后统计病人的康复情况。

为了让你更容易理解，我们可以把这个文件的功能拆解成一个 “任务清单 (To-Do List)”。想象你是一个项目经理，你把这些任务分配给了这个脚本。

以下是按逻辑顺序排列的任务清单：

✅ Task 1: 准备“手术”所需的标准数据包

对应函数： _prepare_requests (这是最长、最复杂的一个函数)

情景： 你要修改大模型的一个知识点（比如把“美国总统”从“拜登”改成“特朗普”）。原始数据可能很乱，有的只有一句话，有的是一堆话。你需要把它们整理成统一的格式，方便后续算法处理。

具体步骤： 1. 统一格式 (Standardization)： * 不管输入是一个字符串还是一个列表，统统转成列表。 * 把 prompt (提示词)、target_new (新目标)、ground_truth (原始真相) 像拉链一样一一对应打包成字典 (dict)。 2. 处理“反例” (Negative constraints)： * 代码逻辑： 检查有没有 target_neg。 * 目的： 告诉模型“不要说什么”。比如修改后，模型不应该再说“美国总统是拜登”。 3. 确认“主语” (Subject handling)： * 代码逻辑： 检查 subject 参数。 * 目的： 确认我们要改的主体是谁（比如“美国”）。代码会检查这个词是不是真的出现在了提示词里。 4. 添加“连带测试” (Locality & Portability)： * 这是模型编辑中最重要的评估指标，这个函数负责把测试题塞进数据包里。 * Locality (局部性/不遗忘)： 修改了“美国总统”，但不应该影响“法国总统”的知识。代码把这些测试题打包进 request['locality']。 * Portability (可移植性/泛化)： 如果教了“美国总统是特朗普”，问模型“白宫现在的居住者是谁”，它也得能答对。代码把这些测试题打包进 request['portability']。

一句话总结： 把零散的输入参数，组装成一个个包含所有修改信息和测试题的标准化 request 对象。

✅ Task 2: 像切蛋糕一样切分数据

对应函数： _chunks

情景： 如果你有一万条数据要处理，一次性塞给显卡（GPU），显卡会爆显存（内存溢出）。

具体步骤： 1. 设定一个 n (比如 32 或 64)。 2. 把巨大的列表切成一小块一小块 (Batch)。 3. 每次只吐出一块给后面去处理。

一句话总结： 这是一个简单的辅助工具，用来做 Batch 处理，防止内存爆炸。

✅ Task 3: 寻找哪里藏着“分数”

对应函数： get_all_acc_keys

情景： 模型编辑完后，会产生很多层级的评估结果，字典套字典。你需要把所有代表“准确率 (accuracy)”的指标找出来。

具体步骤： 1. 递归搜索： 像剥洋葱一样打开每一层字典。 2. 关键词匹配： 只要看到键名（Key）是以 'acc' 结尾的（比如 rewrite_acc, locality_acc），就把它记录下来。

一句话总结： 自动扫描结果字典，找出所有需要统计的准确率指标名称。

✅ Task 4: 撰写最终的“体检报告”

对应函数： summary_metrics

情景： 所有的编辑和测试都做完了，你手头有一大堆原始数据（比如 100 次实验的每一次结果）。现在老板要看总表：平均成功率是多少？

具体步骤： 1. 存档 (Log)： 先把所有原始数据保存到 ./logs/results.json，防止数据丢失。 2. 计算平均分 (Calculate Mean)： * 它会区分 pre (编辑前) 和 post (编辑后) 的状态。 * 核心指标： 算一下 rewrite_acc (修改成功率)、rephrase_acc (换个说法能不能懂) 等的平均值。 * 连带指标： 利用 Task 3 找到的 Keys，去计算 locality (有没有改坏别的地方) 和 portability (能不能举一反三) 的平均分。 3. 打印汇报： 最后 print 出一个漂亮的 mean_metrics 字典。

一句话总结： 汇总所有实验数据，计算编辑前后的各项能力平均分，并保存文件。

总结全流程

如果把 EasyEditor 看作一个工厂，这个 utils.py 的工作流是：

  1. 进货： 用 _prepare_requests 把原材料（提示词、目标）打包成标准箱子。
  2. 传送带： 用 _chunks 每次送几个箱子去加工（编辑模型）。
  3. 质检： 加工完后，用 get_all_acc_keys 看看要检查哪些指标。
  4. 报表： 用 summary_metrics 算出良品率，打印最终报告。
