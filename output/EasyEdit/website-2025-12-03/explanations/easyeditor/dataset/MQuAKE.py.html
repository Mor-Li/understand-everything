easyeditor/dataset/MQuAKE.py

这段代码定义了一个名为 MQuAKEDataset 的类，它是用于处理 MQuAKE 数据集的。MQuAKE 通常用于测试大模型（LLM）的多跳知识编辑（Multi-hop Knowledge Editing）能力。简单来说，就是教模型一个新的知识，看它能不能推理出基于这个新知识的后续结论。

为了让你更容易理解，我把这段代码做的事情拆解成一个 Task Todo List，然后一步步讲解。

📋 Task Todo List (代码逻辑清单)

  1. 准备阶段 (__init__):

    • [ ] 读取配置（Config），确定要用什么模型。
    • [ ] 加载对应的分词器 (Tokenizer)（比如 GPT2, Llama, Mistral 等）。
    • [ ] 针对不同模型，设置特殊的填充（padding）规则。

  2. 加载与清洗数据 (__init__ 内部):

    • [ ] 打开存放数据的 JSON 文件。
    • [ ] 核心循环：遍历每一条数据，把多跳的问题和答案拼接起来。
    • [ ] 整理成统一的字典格式（包含：提问 prompt，新答案 target_new，重述问题 rephrase_prompt 等）。

  3. 取数据 (__getitem__):

    • [ ] 实现一个简单的接口，允许通过索引 dataset[i] 拿到单条数据。

  4. 打包数据 (collate_fn 和 collate_gpt_fn):

    • 这是深度学习训练前的最后一步，把多条数据打包成一个 Batch。
    • [ ] 通用打包 (collate_fn): 分别对问题和答案进行分词、编码。
    • [ ] GPT专用打包 (collate_gpt_fn): 针对 GPT 类模型（Decoder-only），把“问题+答案”拼在一起进行分词。
    • [ ] 构建训练目标: 生成 input_ids（输入）和 labels（标签），并处理 attention_mask。

🧐 逐步详细讲解

第一步：准备阶段 (初始化与分词器)

在 __init__ 函数的开头，代码主要在做“基建工作”。

  • 目的：模型不认识字，只认识数字，所以需要 Tokenizer。
  • 代码细节：
    • 它会检查 config.model_name。
    • 如果是 GPT2 或 Llama 或 Mistral，它会特别设置 padding_side = 'left'（左侧填充）。这是因为生成式模型通常要求从左边补 0，以便让生成的文字在右边延续。
    • 如果是 Qwen (千问)，它设置了一些特殊的结束符 <|endoftext|>。

第二步：加载与清洗数据 (核心逻辑)

这是代码中最“业务逻辑”的部分，处理 MQuAKE 数据集的特殊格式。

# 代码片段摘要
for i, record in enumerate(raw):
    prompt = ""
    subject = ""
    target_new = ""
    # ...
    for x in record["requested_rewrite"]:
        prompt = prompt + x["prompt"].format(x["subject"]) + "?"
        # ...
  • 背景：MQuAKE 数据集通常包含一连串相关的知识修改。
  • 动作：
    1. 它遍历 record["requested_rewrite"]。
    2. 它把多个重写请求（Rewrite）拼接在一起。
    3. 提取关键字段：
      • prompt: 相当于输入的问题（比如：“美国现在的总统是谁？”）。
      • target_new: 模型需要学会的新答案（比如强行改成：“特朗普”）。
      • rephrase_prompt: 换个问法（比如：“谁是美利坚的现任元首？”），用来测试模型是不是真的懂了，还是死记硬背。
      • portability_prompt: 多跳推理问题（比如：“美国现任总统的夫人是谁？”），这是 MQuAKE 的精髓，测试模型能不能根据新知识（总统变了）推理出新结论（夫人也变了）。

第三步：打包数据 (Collate Functions)

这里有两个函数，根据你使用的模型类型选择其一。

1. collate_fn (通用/Encoder-Decoder 模式) 适用于像 T5, BART 这种模型，或者某些特定的编辑算法（如 ROME, MEMIT）。 * 逻辑：它把 prompt（问题）当作输入，把 target_new（答案）当作输出标签。它们是分开分词的。

2. collate_gpt_fn (GPT/Decoder-only 模式) 适用于 GPT-2, Llama, ChatGLM 等主流大模型。 * 逻辑： * GPT 模型是“接龙”高手。训练时，它看的是一整句话。 * 代码执行：src = [src_ + ' ' + trg_ for src_, trg_ in zip(src, trg)]。 * 意思是：把“问题”和“答案”拼成一个字符串。 * Label 处理：get_edit_labels 函数会将 prompt 部分的 Label 设为 -100（PyTorch 中代表忽略，不计算 Loss），只计算 target_new 部分的 Loss。这意味着：模型读到问题时不扣分，只有预测出正确的新答案才得分。

第四步：构建输出字典 (Batch Output)

最后，这两个函数都会返回一个复杂的字典，主要包含三个部分，对应模型编辑的三个指标：

  1. edit_inner:
    • 用于训练模型记住这个新知识。
    • 包含：输入 ID，Mask，以及对应的 Label。
  2. edit_rephrase:
    • 用于测试泛化性（Generalization）。
    • 输入是“换个问法”，看模型能不能输出同样的“新答案”。
  3. loc (Locality):
    • 用于测试局部性（Locality/Side Effects）。
    • 输入是无关的问题（比如“中国的首都是哪？”），目标是让模型保持原有的正确答案（“北京”），不要因为学了新知识把旧知识搞坏了。

总结

这个文件的作用是：把 MQuAKE 原始的 JSON 数据，转换成 PyTorch 可以直接喂给大模型进行“知识编辑”训练的 Tensor 格式。 它特别处理了多跳数据的拼接，并针对 GPT 类模型做了专门的输入拼接处理。
