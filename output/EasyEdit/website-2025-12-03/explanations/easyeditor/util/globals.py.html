在编程中，我们管这个叫 “日志系统 (Logging)”。它的作用是记录程序运行过程中发生了什么，方便出错时排查问题。

目标： 搞懂这段代码到底是干嘛的。 * 通俗解释： 想象你在做一个复杂的实验。你需要两样东西： 1. 一本实验记录本：把所有细节写在纸上存档（保存到文件）。 2. 一个实时显示屏：把你正在做的步骤实时显示出来给你看（打印到屏幕）。 * 代码对应： 这个文件里的 get_handler 函数，就是负责制造这“两样东西”的工厂。

✅ Task 3: 拆解函数 get_handler —— 第一步：找地方 (第 9-16 行)

目标： 确定日记本放在哪里。

def get_handler(path, log_name):
    # 1. 拼凑出完整的文件路径，比如 "logs/my_log.txt"
    log_file_path = os.path.join(path, log_name)

    try:
        # 2. 检查文件夹是否存在？如果不存在...
        if not os.path.exists(path):
            print("We are creating the logger files")
            # 3. ...就强制创建一个文件夹
            os.makedirs(path)
    except:
        pass
  • 白话翻译：
    • 你要我把日记存哪？（path）
    • 我看了一眼，那个文件夹居然没有？
    • 没事，我帮你新建一个文件夹（os.makedirs），免得待会报错。

✅ Task 4: 拆解函数 get_handler —— 第二步：造“记录本” (第 17-19 行)

目标： 创建一个能把字写进硬盘文件的工具。

    # 1. 创建一个“文件处理器” (FileHandler)
    # 它的任务是：把程序说的话，写进 log_file_path 这个文件里
    file_handler = logging.FileHandler(log_file_path)

    # 2. 设置记录级别为 DEBUG
    # 意思是：不管多琐碎的小事（DEBUG级别），都要记下来，不要遗漏。
    file_handler.setLevel(logging.DEBUG)

    # 3. 设置格式
    # 意思是：每条日记都要按 "时间 - 名字 - 级别 - 内容" 的格式写。
    file_handler.setFormatter(logging.Formatter('%(asctime)s - %(name)s - %(levelname)s - %(message)s'))
  • 白话翻译： 这是刚才说的“实验记录本”。它会默默地把所有运行细节写进文件里，留着以后查阅。

✅ Task 5: 拆解函数 get_handler —— 第三步：造“大喇叭” (第 21-23 行)

目标： 创建一个能把字打印在黑色屏幕（控制台）上的工具。

    # 1. 创建一个“流处理器” (StreamHandler)
    # 它的任务是：把程序说的话，直接打印在你的屏幕上（控制台）
    stream_handler = logging.StreamHandler()

    # 2. 同样设置为 DEBUG 级别，事无巨细都显示
    stream_handler.setLevel(logging.DEBUG)

    # 3. 设置同样的格式，带上时间戳
    stream_handler.setFormatter(logging.Formatter('%(asctime)s - %(name)s - %(levelname)s - %(message)s'))
  • 白话翻译： 这是刚才说的“实时显示屏”。如果你不加这个，程序运行的时候可能屏幕上一片漆黑，你不知道它卡住了还是在跑。有了它，你就能看到滚动的文字。

总结

这个文件 globals.py 就是一个后勤部门。
