🧠 hparams/FT/：传统微调的“处方集”

如果把修改大模型比作“治病”或“教学”，那么 hparams 目录就是整个医院的档案室。而这个 FT 子目录，专门存放“传统疗法”（Fine-Tuning，微调）的具体方案。

这里没有花哨的新技术（比如 ROME 或 MEMIT），只有最朴素、最基础的梯度下降微调配置。

1. 这个文件夹主要负责什么？

核心功能：定义“传统微调”的所有参数细节。

在这个项目中，FT（Fine-Tuning）通常被用作对照组（Baseline）。 当研究人员发明了像 ROME 这样厉害的新手术时，他们需要证明新手术比老办法好。这个文件夹里的文件就是那个“老办法”的标准操作手册——告诉程序如何用最普通的方式去训练模型，以便和新方法进行 PK。

2. 这些文件分别是干什么的？

这里的文件虽然多，但其实只有三种类型的“手术方案”，针对不同的“病人”（GPT-2, GPT-J 等）：

🅰️ 类型一：小心翼翼型 (_constr.json)

  • 代表文件：gpt2-xl_constr.json, EleutherAI_gpt-j-6B_constr.json
  • 通俗解释：“戴着脚镣跳舞”。
    • 这是受约束（Constrained）的微调。
    • 方案里写着：“你可以修改模型参数，但幅度必须很小（Norm Constraint），千万别把模型原来的知识改坏了！”
    • 这通常是为了测试：在极度小心的情况下，微调能不能奏效。

🅱️ 类型二：放飞自我型 (_unconstr.json)

  • 代表文件：gpt2-xl_unconstr.json, EleutherAI_gpt-j-6B_unconstr.json
  • 通俗解释：“大力出奇迹”。
    • 这是无约束（Unconstrained）的微调。
    • 方案里写着：“别管副作用，死记硬背也要把这个新知识记住！不需要限制参数变化的幅度。”
    • 这通常用来测试：如果不顾一切地修改，模型能学多快（但往往副作用很大）。

🆎 类型三：特定部位型 (_attn.json 等)

  • 代表文件：gpt2-xl_attn.json
  • 通俗解释：“只动眼睛，不动脑子”。
    • 标准微调通常修改 MLP（记忆区），但这个文件指定修改 Attention（注意力机制）。
    • 这是为了对比：到底改哪里效果更好？

📄 总控型 (.yaml)

  • 代表文件：gpt2-xl.yaml, gptj-6B.yaml
  • 通俗解释：这是更通用的总配置单。它可能包含了默认的设置，或者作为运行脚本时的默认入口，指定了使用哪张显卡、默认跑多少步等基础信息。

3. 子文件夹的作用是什么？

当前目录下没有子文件夹。 这是一个扁平的目录，所有配置文件都直截了当地摆在这里，随取随用。

4. 高层认知：一句话理解它

如果把整个项目比作一场“模型手术大赛”：

hparams/FT/ 目录里装的，是“传统保守派医生”的全部手术方案。 它们的存在，主要是为了和那些“激进派新医生”（比如 ROME, MEMIT 算法）做对比，看看谁的手术做得更精准、副作用更小。
