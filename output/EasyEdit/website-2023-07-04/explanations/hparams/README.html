hparams

你好！这是为你准备的 hparams 根目录的通俗指南。

🎛️ hparams/：项目的“中央控制室”

欢迎来到 hparams（Hyper-parameters，超参数）目录。如果把整个项目比作一家专门给 AI 做脑部手术的超级医院，那么这里就是“处方档案室”和“总调度台”。

1. 这个文件夹主要负责什么？

核心功能：把“怎么做”和“做什么”分离开。

  • 代码（Code） 是医生手中的手术刀，负责执行切割、缝合的动作。
  • hparams 是医生手里的处方单，负责规定：
    • 今天给哪个病人（模型）做手术？
    • 用哪种手术方案（算法）？
    • 麻醉剂打多少（学习率）？
    • 手术要在哪一层神经元进行？

这里的配置决定了程序的运行模式。你不需要修改代码逻辑，只需要改改这里的参数，就能让同一个程序跑出完全不同的实验。

2. 直接文件 (config.yaml) 是干什么的？

这里只有一个光杆司令：config.yaml。

  • 角色：它是“总调度令”或者“入院登记表”。
  • 功能：
    • 当你运行主程序时，程序首先会读这个文件。
    • 它就像一个路标，告诉程序：“嘿，这次我们要用 KN算法 (alg_name: KN)，去给 T5-3b模型 (hparams_name: KN/t5-3b) 做手术。”
    • 它还顺便告诉程序：“做完手术把病人送去 models/ 房，手术日记写在 logs/ 本子上。”
  • 总结：它是一个全局开关，用来指定去哪个子文件夹里读取更详细的参数。

3. 子文件夹的作用是什么？

这些子文件夹代表了不同的“手术流派”（不同的算法）。

  • 📁 FT (Fine-Tuning)：
    • 传统疗法科。存放最基础的微调方案，通常用来做对比实验（看看新算法比老办法好多少）。
  • 📁 ROME / MEMIT / KN / MEND / IKE / SERAC / KE：
    • 各个专科门诊。每一个文件夹都对应一种特定的模型编辑算法。
    • 比如 ROME/ 里装的是 ROME 算法专用的参数，MEMIT/ 里装的是 MEMIT 算法专用的参数。它们互不干扰，各成一派。
  • 📁 TRAINING：
    • 医生培训中心。
    • 有些算法（比如 MEND, SERAC）不仅仅是修改模型，它们本身需要先训练一个小模型（Hypernetwork）来辅助手术。这个文件夹里装的就是“如何训练这些辅助小模型”的配置。

4. 高层认知：一句话秒懂

请把这个目录想象成“电子游戏的设置菜单”。

你的代码是游戏引擎，而 hparams 是你保存的配置文件。

  • config.yaml 是主菜单（选择玩哪一关）。
  • 各个子文件夹（如 ROME/, FT/）是针对不同角色的详细属性表（攻击力设为多少、防御力设为多少）。

想要改变实验内容，不需要重写游戏代码，只需要来这里改改数字即可。
