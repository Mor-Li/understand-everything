easyeditor/util/globals.py

这份代码其实不是在“做算法”或“训练模型”，而是在做“后勤管理”。

你可以把这个文件看作是一个大管家。它的任务是帮整个项目处理杂务：比如“日记本在哪里买（日志）”、“文件存哪里（路径）”、“每次实验的结果怎么分类（文件夹管理）”。

为了让你看懂，我把这个代码拆解成一个 “项目启动前的 To-Do List（待办清单）”。我们一步步来看，每一步是为了解决什么问题：

📋 待办清单 (To-Do List)

Task 1: 准备好记日记的工具 (配置 Logging)

代码对应部分： def get_handler(path, log_name): ...

  • 痛点： 程序运行的时候如果出错了，或者我想知道它跑到哪一步了，我需要它打印出来，最好还能存成文件，方便我以后查。
  • 代码在做什么：
    1. 找地方： 看看存日志的文件夹存不存在？不存在就新建一个 (os.makedirs).
    2. 准备笔（FileHandler）： 设置一个“把字写进文件里”的记录员。
    3. 准备嘴（StreamHandler）： 设置一个“把字打印在屏幕上”的记录员。
    4. 定格式： 规定每一条日志必须包含：时间、名字、等级、具体信息。
  • 结论： 这个函数就是用来生成“记录员”的，以后谁想记日志，调用这个函数就行。

Task 2: 读取“藏宝图” (读取配置文件)

代码对应部分：

with open("globals.yml", "r") as stream:
    data = yaml.safe_load(stream)
  • 痛点： 我的数据放在 C 盘，你的数据放在 D 盘。如果我们把路径写死在代码里，换台电脑就报错了。
  • 代码在做什么：
    1. 打开一个外部文件叫 globals.yml（这通常是一个设置文件，类似说明书）。
    2. 把里面的内容读出来，存到 data 变量里。
  • 结论： 这步是为了灵活。具体的路径不要写在代码里，写在外部的 .yml 文件里。

Task 3: 给重要地点挂牌子 (定义全局路径变量)

代码对应部分： (LOG_DIR, RESULTS_DIR, ...) = (Path(z) for z in ...)

  • 痛点： 刚才读进来的 data 只是普通的字符串。在 Python 里操作路径（比如拼接文件名）用字符串很麻烦，容易出错。
  • 代码在做什么：
    1. 从刚才读到的 data 里取出各个关键路径：日志目录、结果目录、数据目录等。
    2. 把它们全部转换成 Python 的 Path 对象（这是 pathlib 库的功能，比用字符串更高级，操作更方便）。
    3. 把它们赋值给大写的变量名（如 DATA_DIR），方便其他代码直接引用。
  • 结论： 以后在别的代码里，只要引用 DATA_DIR，程序就知道去哪里找数据，不用再手写路径了。

Task 4: 自动分配“工位” (创建实验运行目录)

代码对应部分： def get_run_dir(dir_name): ...

  • 痛点： 我今天跑了一次实验，生成了结果。明天我又跑了一次，如果名字一样，旧的结果就被覆盖（删除）了！我希望结果能像 run_000, run_001, run_002 这样自动排号。
  • 代码在做什么：
    1. 去查房： 看看结果目录下，你要用的那个算法文件夹里，已经有了哪些 run_xxx 的文件夹。
    2. 算号码：
      • 如果里面是空的，那这次就是 run_0。
      • 如果里面已经有 run_5 了，那这次就是 run_6（取最大值 + 1）。
    3. 建房子： 创建这个新的文件夹 run_006。
    4. 通知： 打印一句话告诉你：“结果会存在 xxx 这里哦”。
  • 结论： 这个函数是为了保证你每次跑实验，结果都能独立保存，不会把自己之前的辛苦成果覆盖掉。

💡 总结一下

这个 globals.py 文件其实就是一个基础设施配置中心。

如果不看这个文件，你的整个项目可能会： 1. 不知道去哪里读数据。 2. 不知道把结果存哪里。 3. 每次跑代码都把上次的结果覆盖了。 4. 报错了也不知道去哪里看日志。

你现在只需要知道： 这个文件一旦运行，它会读取 globals.yml 里的配置，然后准备好所有的文件夹路径，并且提供了一个帮你的实验结果“自动编号”的功能。
