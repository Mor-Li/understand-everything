easyeditor/trainer/algs/ft.py

这份代码 ft.py 的全称是 Fine-Tuning (微调)。

在模型编辑（Model Editing）的领域里，它的核心逻辑非常简单粗暴：“如果你想让模型学会一个新知识，或者修正一个错误，那就直接在这个新数据上对着模型进行几十步的梯度下降（训练）。”

虽然逻辑简单，但为了保证“改得准”且“不把别的地方改坏”，代码里加了很多技巧。

为了让你看懂，我把你（作为程序员/算法工程师）需要完成的任务列成了一个 TODO List。我们按照这个清单，一步步对照代码来讲解。

任务清单 (TODO List)

  1. 准备阶段：把模型变成“可编辑”状态，并决定要改哪些层。
  2. 定义“补丁” (Residuals)：我们不直接改原始参数，而是训练一个“增量矩阵”（Delta）。
  3. 开启循环 (Training Loop)：开始针对这条新知识进行多轮迭代。
  4. 计算损失 (Loss)：既要学会新知识（Edit Loss），又要防止模型变傻（Locality Loss）。
  5. 更新参数：利用梯度下降更新“补丁”。
  6. 收尾：如果学会了或者超时了，就停止并返回新模型。

详细步骤讲解

1. 准备阶段：把模型变成“可编辑”状态

代码位置：edit 函数的前几行。

def edit(self, batch, condition=None, detach_history=False):
    edit_model = self.model.eval()
    # ...
    if not isinstance(edit_model, higher.patch._MonkeyPatchBase):
        edit_model = make_functional(
            self.model, track_higher_grads=False, in_place=True
        )
  • 观点/解释：
    • 普通的 PyTorch 模型参数是存死在模型里的。
    • 这里用了一个库叫 higher (make_functional)。它的作用是把模型变成“无状态函数”。
    • 为什么？ 这样我们就可以手动把一套新的参数（edited_params）传给模型去跑前向传播，而不用真的修改模型内部的 self.weight。这对于做实验和回滚非常方便。

2. 定义“补丁” (Residuals)：我们改哪里？怎么改？

代码位置：edit 函数中的 for n, p in _inner_params(...) 循环。

    packed_residuals = {}
    opt_params = []
    for n, p in _inner_params(...): # 遍历配置文件里指定要修改的层
        if self.config.ft.rank is not None:
            # 技巧：低秩分解 (Low-Rank)
            u = nn.Parameter(...)
            v = nn.Parameter(...)
            res = [u, v]
        else:
            # 普通模式：全参数微调
            res = [nn.Parameter(torch.zeros_like(p, device=p.device))]

        packed_residuals[n] = res
        opt_params.extend(res)
  • 观点/解释：
    • 只改关键层：我们通常不改整个大模型，只改某几层（由 config.model.inner_params 定义，比如只改第20层的 MLP）。
    • Residuals (残差/补丁)：代码逻辑是 $W_{new} = W_{old} + \Delta W$。这里的 res 就是那个 $\Delta W$。初始时全是 0。
    • Low-Rank (低秩/LoRA思想)：如果配置了 rank，代码不会生成一个和原参数一样大的矩阵，而是生成两个小矩阵 $u$ 和 $v$。
      • 原理：$\Delta W = u \times v$。
      • 好处：参数量极少，训练更快，不容易过拟合。

3. 开启循环 (Training Loop)：特训开始

代码位置：for edit_step in range(self.config.ft.max_edit_steps):

    opt = OptClass(opt_params, lr=self.config.edit_lr) # 定义优化器

    for edit_step in range(self.config.ft.max_edit_steps):
        # ... (时间限制检查)

        # 这一步最关键：合成新参数
        # 新参数 = 老参数 + 补丁
        residuals = {
            k: v[0] @ v[1] if len(v) == 2 else v[0] # 如果是低秩就相乘，否则直接用
            for k, v in packed_residuals.items()
        }
        edited_params = [
            p if n not in residuals else p.detach() + residuals[n] for n, p in p0
        ]
  • 观点/解释：
    • 这是一个标准的微调循环。
    • 每次循环，我们都用当前的“补丁”加上“原始参数”，组合出一套临时的 edited_params。

4. 计算损失 (Loss)：既要学新，又要保旧

代码位置：调用 self._edit_loss(...) 以及 _edit_loss 函数内部。

        loss, l_edit, l_loc, acc = self._edit_loss(
            edit_model, [p for n, p in p0], edited_params, batch
        )

进入 _edit_loss 函数看细节：

    def _edit_loss(self, model, p0, p_edited, edit_batch):
        # 1. 编辑损失 (l_edit): 让模型学会新知识 (比如: "美国总统是?" -> "特朗普")
        output = _logits(model(**edit_batch, params=p_edited))
        loss_dict = self.edit_loss_fn(output, edit_batch["labels"])
        l_edit = loss_dict["nll"]

        # 2. 局部性损失 (l_loc): 别把旧知识忘了 (比如: "1+1=?" 还得是 "2")
        if self.config.ft.locality.enabled:
            # ... 获取一些无关的数据 loc_batch ...
            with torch.no_grad():
                original_base_logits = _logits(model(**loc_batch, params=p0)) # 原模型输出
            edited_base_logits = _logits(model(**loc_batch, params=p_edited)) # 新模型输出

            # KL散度：强迫新模型的输出分布 和 原模型 保持一致
            l_loc = self.locality_loss_fn(original_base_logits, edited_base_logits, ...)

            # 总 Loss = 编辑Loss + 权重 * 局部性Loss
            loss = l_loc + self.config.ft.locality.cedit * l_edit
        else:
            loss = l_edit
        return loss, ...
  • 观点/解释：
    • Trade-off (权衡)：这是模型编辑最核心的难点。
    • 如果只优化 l_edit，模型会发生“灾难性遗忘”，为了学会这句话，把别的全忘了。
    • 所以加入了 l_loc (Locality Loss)。它通过 KL散度 (KL Divergence) 约束模型：在无关数据上，新模型的表现必须和老模型尽可能一样。

5. 更新参数

代码位置：循环的末尾。

        # 标准的 PyTorch 反向传播
        for p, g in zip(opt_params, torch.autograd.grad(loss, opt_params)):
            p.grad = g
        torch.nn.utils.clip_grad_norm_(opt_params, self.config.grad_clip) # 梯度裁剪防止爆炸
        opt.step() # 更新补丁参数 (u, v 或者 res)
        opt.zero_grad()
  • 观点/解释：
    • 这里更新的 opt_params 实际上就是步骤2里定义的 packed_residuals。
    • 我们没有修改模型的原始权重，我们只是在训练那个“补丁”。

6. 收尾

代码位置：循环结束后。

        if detach_history:
            new_model = self.model_constructor()
            # 把最终计算好的补丁应用进去，变成一个普通模型
            new_model.load_state_dict(edit_model.state_dict()) 
            edit_model = new_model

        return (FT(edit_model, ...), {})
  • 观点/解释：
    • 如果训练成功（比如 acc == 1.0 或者步数到了），就退出循环。
    • 最后返回一个新的 FT 对象，里面装着修改后的模型。

总结：这篇代码的核心观点

  1. FT (Fine-Tuning) 也是一种编辑方法：不要觉得微调很土，它是最基础的编辑手段。
  2. Delta Rule (增量更新)：为了安全和高效，不要直接改参数，而是训练一个 $\Delta$ (补丁)。
  3. 约束优化：编辑不仅仅是“学会”，更是“不忘”。代码里通过 l_loc (KL散度) 显式地强迫模型在其他区域保持不变。
  4. Functional Model：使用 higher 库把模型函数化，是为了更方便地在内存里做这种“假设性”的参数替换和梯度计算。
