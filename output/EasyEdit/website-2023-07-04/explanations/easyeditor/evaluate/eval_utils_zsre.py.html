easyeditor/evaluate/eval_utils_zsre.py

这份代码主要是在做模型编辑（Model Editing）后的“体检”。

简单来说，当我们试图修改大模型里的某个知识（比如把“埃菲尔铁塔在巴黎”改成“埃菲尔铁塔在罗马”）之后，我们需要用这份代码来评估修改得好不好。

为了让你更容易理解，我把这个过程想象成“老师给刚补完课的学生出考卷”。

下面是一个逻辑上的 Task To-Do List，我会按照这个列表一步步带你读代码。

📋 评估任务 To-Do List

  1. 准备考题（提取数据）：从记录里拿出我们要考的题目、标准答案。
  2. 区分考试科目（分类提示词）：准备三种不同类型的题目来全方位测试：
    • 科目一：死记硬背题（你记住我教你的那句话了吗？）
    • 科目二：举一反三题（换个说法问你，你还能答对吗？）
    • 科目三：不该忘的旧知识（你有没有因为学新知识把隔壁无关的知识搞乱了？）
  3. 学生答题（模型预测）：让模型去跑这些题目。
    • 注意：不同类型的学生（T5 vs GPT）答题方式不一样，要分情况处理。
  4. 批改试卷（计算准确率）：对比模型的回答和标准答案。
  5. 发成绩单（打包返回）：把各项分数整理成字典返回。

逐步讲解（对应代码逻辑）

第一步：准备考题 (Prepare Data)

代码位置：compute_rewrite_quality_zsre 函数的开头。

# 提取核心信息
subject, target_new, target_true = (
    record["requested_rewrite"][x] for x in ["subject", "target_new", "target_true"]
)
  • 解释：这里是在解包数据。
    • subject: 主语（比如“埃菲尔铁塔”）。
    • target_new: 我们想让模型记住的新知识（比如“罗马”）。
    • target_true: 原本正确的事实（比如“巴黎”）。

第二步：区分考试科目 (Define Prompts)

rewrite_prompts = [record["requested_rewrite"]["prompt"].format(subject)]
paraphrase_prompts = record["paraphrase_prompts"]
neighborhood_prompts = record["neighborhood_prompts"]
  • 解释：这里准备了三类考题：
    1. Rewrite Prompts (重写提示词)：就是编辑时用的原话。测试有效性（Efficacy）。
    2. Paraphrase Prompts (同义改写提示词)：意思一样但说法不同的句子。测试泛化性（Generalization）。比如编辑时用“埃菲尔铁塔位于哪里？”，这里问“埃菲尔铁塔的所在地是？”。
    3. Neighborhood Prompts (邻域提示词)：跟这事儿无关，但长得很像的知识。测试特异性/局部性（Specificity/Locality）。比如问“自由女神像在哪里？”。我们希望模型不要把这个也改成“罗马”。

第三步：学生答题 (Model Prediction)

这里代码分成了两由路：if 't5' in model_name 和 elif 'gpt' in model_name。这是因为 T5 和 GPT 的架构不同，推理方式不同。

情况 A：如果是 T5 模型 (Seq2Seq 架构) T5 像做翻译题，输入问题，直接输出答案。

if 't5' in model_name.lower():
    # 批量测试 rewrite 和 paraphrase
    stuff_probs = test_seq2seq_batch_prediction_acc(..., target_new["str"])
    # 单独测试 neighborhood
    neighborhood_correct = test_seq2seq_batch_prediction_acc(..., neighborhood=True)
  • 它直接调用 test_seq2seq_batch_prediction_acc，把问题喂给模型，看模型生成的答案是不是 target_new。

情况 B：如果是 GPT 模型 (Causal LM 架构) GPT 是像连词成句一样，一个字一个字往后猜。

elif 'gpt' in model_name.lower():
    # ... 省略了复杂的切词代码 ...
    # 核心逻辑是：
    # 比如目标是 "Rome" (假设分词为 Ro, me)
    # 第一次输入: "Where is Eiffel? " -> 预测 "Ro"
    # 第二次输入: "Where is Eiffel? Ro" -> 预测 "me"
    stuff_probs = test_batch_prediction_acc(model, tok, inp_prompts, inp_targets)
  • 这段代码看起来很复杂（inp_prompts 生成列表推导式那里），是因为它在手动构造“Teacher Forcing”。它在测试模型能不能在给定前缀的情况下，准确预测出目标单词的每一个 Token。

第四步：批改试卷 (Grading)

这一步其实融合在上面的 test_..._acc 函数里了。我们看底部的辅助函数：

  • 核心逻辑：
    1. 让模型算概率 (logits)。
    2. 找概率最大的那个词 (argmax)。
    3. 看它是不是标准答案 (ans == correct_id)。
    4. 如果是，得1分（True），不是得0分（False）。

第五步：发成绩单 (Return Results)

ret = {

  • 解释：最后函数返回一个字典 ret。使用者拿到这个字典，就能知道：
    • 编辑成功了吗？(rewrite_correct)
    • 换个问法还懂吗？(paraphrase_correct)
    • 有没有把别的东西搞坏？(neighborhood_correct)

总结

这个文件的核心作用就是“阅卷老师”。

  1. 它不管怎么编辑模型（那是别人的事）。
  2. 它只负责拿编辑好的模型，去跑一遍 ZsRE 数据集里的相关问题。
  3. 它针对 T5 和 GPT 两种主流架构写了不同的“监考逻辑”。
  4. 最后告诉你：编辑得准不准（Rewrite）、稳不稳（Paraphrase）、有没有副作用（Neighborhood）。
