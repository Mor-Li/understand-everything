easyeditor/evaluate/evaluate.py

这份代码 evaluate.py 的核心作用是：给做完“脑部手术”（知识编辑）的大模型做一次全面的“术后体检”。

当我们修改了模型里的某一条知识（比如把“埃菲尔铁塔在巴黎”改成“埃菲尔铁塔在罗马”），我们需要确认三件事： 1. 改成功了吗？ (Efficacy) 2. 模型变傻了吗？ (Locality/Side Effects) 3. 模型能举一反三吗？ (Generalization/Portability)

为了让你看懂，我把这个文件的逻辑拆解成一个 Task Todo List（任务清单），带你一步步走完这个体检流程。

📋 任务清单：模型编辑效果评估流程

Task 1: 准备体检数据 (Unpack Record)

目标：拿到“手术”前后的对比数据。 * 输入：record 字典。 * 动作：提取出 Prompt（提示词，如“埃菲尔铁塔在”）、Target New（新目标，如“罗马”）、Ground Truth（原始事实，如“巴黎”）。 * 代码对应：compute_edit_quality 函数的开头部分。

Task 2: 检查手术是否成功 (Rewrite Accuracy)

目标：直接问模型新知识，看它能不能答对。 * 动作：输入 Prompt（“埃菲尔铁塔在”），看模型输出是不是 Target New（“罗马”）。 * 代码对应：调用 compute_rewrite_or_rephrase_quality，参数 test_rephrase=False。

Task 3: 检查是否能听懂人话 (Rephrase Accuracy)

目标：换个说法问同一个知识，看模型是不是死记硬背。 * 动作：输入 Rephrase Prompt（比如“那个著名的铁塔位于哪里？”），看模型是否依然回答 Target New（“罗马”）。 * 代码对应：调用 compute_rewrite_or_rephrase_quality，参数 test_rephrase=True。

Task 4: 检查有无副作用 (Locality / Specificity)

目标：确保模型没有忘记无关的知识（不要把“奥巴马是美国人”也改成了“罗马人”）。 * 动作：输入无关的 Locality Prompt（比如“奥巴马是哪国人？”），看模型是否保持回答 Ground Truth（“美国”）。如果它回答“罗马”，说明手术失败，破坏了其他记忆。 * 代码对应：遍历 record['locality']，调用 compute_locality_quality。

Task 5: 检查举一反三能力 (Portability)

目标：看模型能不能利用新知识进行推理。 * 动作：输入需要推理的问题（比如“埃菲尔铁塔所在城市的特色菜是什么？”）。如果模型真的认为铁塔在罗马，它应该回答“披萨”而不是“法式蜗牛”。 * 代码对应：遍历 record['portability']，调用 compute_portability_quality（这个函数是从外部引用的）。

Task 6: 判卷打分 (Compute Metrics)

目标：把模型的输出转化成 0 或 1 的分数。 * 动作：比较模型生成的 Token 和我们期望的 Token 是否一致。 * 如果是 GPT 类模型（Decoder-only）：预测下一个词。 * 如果是 T5 类模型（Seq2Seq）：生成完整的答案序列。 * 代码对应：底层函数 test_batch_prediction_acc (GPT) 和 test_seq2seq_batch_prediction_acc (T5)。

🧐 详细代码逻辑讲解

现在我们带着上面的 Task List，深入看几个核心函数：

1. 总指挥官：compute_edit_quality

这是主入口函数。 * 它接收 model（刚改完的模型）和 record（数据）。 * 它依次执行 Task 2 (Rewrite), Task 3 (Rephrase), Task 4 (Locality), Task 5 (Portability)。 * 最后把所有分数打包成一个字典 ret 返回。

2. 核心检测员：compute_rewrite_or_rephrase_quality

这个函数负责 Task 2 和 Task 3。 * 它会判断模型是 T5 还是 GPT。 * 如果是 GPT：它会把 Prompt 和 Target 拼起来，看模型预测 Target 每一个 Token 的概率是不是最大。 * 如果是 T5：它直接让模型生成答案，看生成的跟 Target 是否一样。

3. 副作用检测员：compute_locality_quality

这个函数负责 Task 4。 * 逻辑和上面类似，但它的目标是保持不变。 * 它会检查模型对无关问题的回答，并返回模型的原始输出（Token ID），方便后续比较是否和编辑前一致。

4. ICL 特供版：compute_icl_edit_quality

这个函数是独立的，专门用于 In-Context Learning (ICL) 的评估。 * 背景：有时候我们不改模型参数，只是在 Prompt 里给几个例子（Few-shot）让模型临时学会新知识。 * 逻辑：它会构建一个包含示例的超长 Prompt（例如：New Fact: ... Prompt: ...），然后看模型能不能根据上下文答对。 * 它同样会计算 rewrite_acc (重写准确率), rephrase_acc (重述准确率), 和 locality (邻域保持)。

5. 底层打分器：test_batch_prediction_acc

这是最底层的“苦力”函数，专门给 GPT/Llama 这类模型打分。 * 输入：Prompt 和 目标答案。 * 操作： 1. model(**prompt_tok): 把 Prompt 喂给模型，拿到 Logits（概率分布）。 2. torch.argmax: 找出模型觉得概率最大的那个词。 3. ans == correct_id: 比较模型选的词和标准答案的词是否一样。 * 输出：如果是 locality=True，直接返回模型输出了啥；否则返回准确率（0或1）。

总结

你不需要逐行读懂每一句 Python 代码。只需要记住： 这个文件就是一个全自动化的考官。它手里拿着一份试卷（record），试卷里有必答题（Rewrite）、变式题（Rephrase）和干扰题（Locality）。它负责把这些题喂给模型，然后批改打分。
