easyeditor/models/rome/rome_main.py

这份代码实现了 ROME (Rank-One Model Editing) 算法的核心逻辑。简单来说，ROME 是一种像“脑科手术”一样的技术，它不需要重新训练整个大模型，而是精准地修改模型中某一层的一个微小参数，从而改变模型对某个特定知识的记忆（比如把“埃菲尔铁塔在巴黎”改成“埃菲尔铁塔在罗马”）。

为了让你读懂，我们将这个过程拆解成一个 “给模型做手术”的 Todo List。

核心任务清单 (Todo List)

  1. 准备手术单 (Preparation)：整理用户的输入，把“提示词”和“目标”格式化。
  2. 锁定病灶 (Locating)：找到模型中负责存储这个知识的具体权重层（Weights）。
  3. 计算“手术刀”位置 (Compute $u$)：找出代表“主语”（比如“埃菲尔铁塔”）的神经元激活值，这叫左向量 $u$。
  4. 计算“植入”内容 (Compute $v$)：算出为了让模型输出新结果（比如“罗马”），我们需要把权重改成什么样，这叫右向量 $v$。
  5. 模拟与还原 (Simulation)：先在计算过程中临时改一下试试，算出具体的差值（Delta），然后把模型还原（为了保持纯净，最后统一修改）。
  6. 正式缝合 (Application)：把算出来的差值真正加到模型的权重里去。

逐步代码讲解

下面我按照上面的 Todo List，带你一步步看代码具体在干嘛。

Task 1: 准备手术单 (Preparation)

在 execute_rome 函数的开头。我们需要确保输入的格式是模型能读懂的。

# 这里的 request 包含 prompt（如 "{} lies in"）和 subject（如 "Eiffel Tower"）
if('{}' not in request['prompt']):
    # 如果 prompt 里没写占位符 {}，就把 subject 替换成 {}
    request['prompt'] = request['prompt'].replace(request['subject'], '{}')

print(f"Executing ROME algorithm for... [{request['prompt']}] -> [{request['target_new']}]")
  • 白话解释：这步就是把“Steve Jobs was the founder of”变成模板 “{} was the founder of”，方便后面填空。

Task 2: 锁定病灶 (Locating)

ROME 认为知识存储在 MLP（多层感知机）层的权重里。我们需要把这些权重提取出来。

# hparams.layers 定义了我们要修改哪几层（比如第 5 层）
weights = {
    f"{hparams.rewrite_module_tmp.format(layer)}.weight": nethook.get_parameter(
        model, f"{hparams.rewrite_module_tmp.format(layer)}.weight"
    )
    for layer in hparams.layers
}
# 备份一份旧的权重，防止改坏了或者为了计算差值
weights_copy = {k: v.detach().clone() for k, v in weights.items()}
  • 白话解释：就像手术前要把“心脏”部位露出来，这里把要修改的权重层（Weight Matrices）拿出来备用。

Task 3: 计算“手术刀”位置 (Compute $u$)

这是 ROME 的核心第一步。我们需要知道模型看到“主语”（Subject）时，神经元的反应是什么。

# 在 execute_rome 的循环里
left_vector: torch.Tensor = compute_u(
    model,
    tok,
    request,
    hparams,
    layer,
    # get_context_templates 是一堆随机前缀，为了让修改更通用，不只是死记硬背这一句话
    get_context_templates(model, tok, hparams.context_template_length_params),
)
  • 白话解释：compute_u 计算的是 Key (键)。想象一下，模型是一个巨大的键值对数据库。我们要修改“埃菲尔铁塔”这个词条，首先得拿到打开这个词条的“钥匙” ($u$)。

Task 4: 计算“植入”内容 (Compute $v$)

这是 ROME 的核心第二步。我们需要算出一个新的向量，让模型拿着上面的钥匙 ($u$) 去开锁时，得到的新结果是我们要的（比如“罗马”）。

right_vector: torch.Tensor = compute_v(
    model,
    tok,
    request,
    hparams,
    layer,
    left_vector, # 把刚才算的 u 传进去
    get_context_templates(...)
)
  • 白话解释：compute_v 计算的是 Value (值)。我们希望 $Weight \times u = v$。这个函数通过优化算法算出这个 $v$ 应该是多少，才能让模型吐出“罗马”这个词。

Task 5: 模拟与还原 (Simulation)

在 execute_rome 内部，它其实是在算“差值”（Deltas）。

# 算出更新矩阵：u 和 v 的外积 (Rank-One Update)
upd_matrix = left_vector.unsqueeze(1) @ right_vector.unsqueeze(0)

# 调整形状（因为有些模型矩阵是转置存的）
upd_matrix = upd_matrix_match_shape(upd_matrix, weights[weight_name].shape)

# 把这次计算的结果存到 deltas 里，告诉外面：u 是啥，v 是啥
deltas[weight_name] = (left_vector.detach(), right_vector.detach())

# --- 重点 ---
# 在函数最后，它把模型权重还原了！
with torch.no_grad():
    for k, v in weights.items():
        v[...] = weights_copy[k]
  • 白话解释：execute_rome 这个函数是个“军师”，它只负责计算方案（Deltas），虽然中间为了计算下一层可能临时改了权重，但离开函数前它把模型恢复原状了。它返回的是一个“修改计划书”。

Task 6: 正式缝合 (Application)

回到最外层的 apply_rome_to_model 函数。这里才真正动手修改模型。

# 拿到“修改计划书”（deltas）
deltas = execute_rome(model, tok, request, hparams)

with torch.no_grad():
    for w_name, (delta_u, delta_v) in deltas.items():
        # 重新构建更新矩阵： Delta W = u * v^T
        upd_matrix = delta_u.unsqueeze(1) @ delta_v.unsqueeze(0)

        # 找到模型真实的权重参数
        w = nethook.get_parameter(model, w_name)
        upd_matrix = upd_matrix_match_shape(upd_matrix, w.shape)

        # 真正的修改发生在这里：旧权重 + 更新矩阵
        w[...] += upd_matrix
  • 白话解释：这是最后一步。根据计算出的 $u$ 和 $v$，生成一个更新矩阵，直接加到模型的原始参数上。从此，这个模型就“被洗脑”了。

总结文中的核心观点

  1. Rank-One Update (一阶修正)：代码的核心逻辑是 upd_matrix = u @ v。这意味着我们不需要训练整个巨大的矩阵，只需要在这个矩阵上加一个“补丁”，这个补丁是由两个向量相乘得到的（数学上叫秩为1的矩阵）。
  2. 计算与应用分离：execute_rome 负责复杂的数学计算（算 u 和 v），apply_rome_to_model 负责简单的加法操作。
  3. 鲁棒性 (Robustness)：代码中出现的 get_context_templates 是为了防止模型过拟合。比如我们要改“埃菲尔铁塔在罗马”，我们不希望模型只在这句话上生效，而是希望它在“埃菲尔铁塔的位置是...”或者“游客去埃菲尔铁塔...”等语境下都能生效。

现在再看代码，是不是清晰一点了？就是一个 “定位(u) -> 计算新值(v) -> 生成补丁(Delta) -> 打补丁(Add)” 的过程。
