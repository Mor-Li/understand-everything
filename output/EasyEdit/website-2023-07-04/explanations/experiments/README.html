experiments

这里是 experiments 文件夹的通俗版说明书。

如果把整个项目比作一家“大模型脑科医院”，那么这个 experiments 文件夹就是最核心的 “临床实验中心”。所有的诊断、手术、术后检查都在这里进行。

1. 🧪 这个文件夹主要负责什么？

它的核心任务只有三个字：做实验。

所有的理论代码（在其他文件夹里定义的算法）都要拿到这里来“跑一跑”。这里负责： * 诊断：找出模型把知识藏在哪。 * 手术：真正执行修改模型权重的操作。 * 体检：改完之后，测试模型有没有变聪明，或者有没有变傻。 * 调优：自动尝试不同的“手术方案”，看哪个效果最好。

2. 📄 直接文件分别是干什么的？

这里有 4 个“员工”（脚本），各司其职：

(1) __init__.py —— 沉默的门卫

  • 角色：通行证。
  • 作用：它是个空文件，但它的存在告诉 Python：“这里是一个正规的包，外面的代码可以进来调用我们。”没它，外人进不来。

(2) causal_trace.py —— CT 扫描仪 (找病灶)

  • 角色：神经侦探 / 定位专家。
  • 作用：在做手术前，必须先知道知识藏在哪。
    • 它通过给模型“大脑”的不同部位加干扰（电击）和恢复（治疗），来观察模型的反应。
    • 目的：精确定位出“埃菲尔铁塔在巴黎”这句话到底是存储在第几层的第几个神经元里。画出的热力图就是它的诊断报告。

(3) evaluate.py —— 手术室与体检中心 (干正事)

  • 角色：主刀医生 + 监考老师。
  • 作用：这是最忙的一个脚本。
    • 手术：它调用算法（如 ROME），把模型脑子里的知识改掉（比如把“埃菲尔铁塔”搬到“罗马”）。
    • 体检：手术后立刻给模型做一套卷子。
      • 成功率：你现在认为铁塔在罗马了吗？
      • 副作用：你还记得美国首都是华盛顿吗？（防止改傻了）。
    • 它会生成详细的 JSON 报告，记录手术是否成功。

(4) sweep.py —— 自动化助手 (试配方)

  • 角色：勤奋的实习生 / 试错机器人。
  • 作用：做实验需要调参（比如学习率用 0.1 还是 0.01？）。
    • 你给它一个列表 [0.1, 0.5, 1.0]，它就会自动指挥 evaluate.py 跑三遍，每遍用不同的参数。
    • 目的：通过大量重复实验，帮你找出效果最好的那一组参数配置。

3. 📁 子文件夹的作用

  • py/：这是一个杂物间或演示厅。里面通常放一些独立的演示脚本（如 demo.py）或者辅助的小工具，它们不属于核心的批量实验流程，更多是给人看效果用的。

4. 🧠 高层认知：一句话看懂流程

这个文件夹的工作流就是一套完整的医疗方案：

  1. 先用 causal_trace.py 做 CT扫描，找到知识藏在哪；
  2. 为了确定最佳手术方案，让 sweep.py 指挥 evaluate.py 进行 批量试药；
  3. evaluate.py 既负责 动手术（修改模型），也负责 术后体检（打分评估）。
