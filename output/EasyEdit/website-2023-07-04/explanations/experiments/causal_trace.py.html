experiments/causal_trace.py

这份代码确实比较硬核，它是出自著名的论文 ROME (Rank-One Model Editing) 项目中的核心实验代码，叫做 “因果追踪” (Causal Tracing)。

简单来说，这个脚本的目的是：像神经外科医生一样，通过“电击”（加噪声）和“修复”（恢复状态）大脑皮层（神经网络层），来精准定位大模型把知识（比如“埃菲尔铁塔在巴黎”）存在了哪一层、哪一个Token上。

为了让你看懂，我把它拆解成一个 “侦探任务清单” (Task List)，然后逐步讲解每一步在做什么。

侦探任务清单 (To-Do List)

我们要搞清楚模型到底是怎么“想”出答案的。

  1. [准备工作] 装备侦探工具
    • 加载模型（GPT-2, GPT-J 等）和分词器。
    • 准备“审讯”问题列表（比如：“Steve Jobs founded [Apple]”）。
  2. [制造混乱] 设定干扰方案 (Noise)
    • 计算如何给模型的输入（Subject，比如 "Steve Jobs"）加上噪声，让模型“失忆”或者变糊涂，答不出正确答案。
  3. [核心实验] 开始手术 (The Trace)
    • 第一刀 (Clean Run): 让模型正常跑一遍，记录下所有神经元原本正确的反应。
    • 第二刀 (Corrupt Run): 给输入加噪声，确认模型答错了。
    • 第三刀 (Patching/Restoring): 这是一个循环过程：
      • 在模型“糊涂”的状态下，强行把某一层、某一个Token的数值，恢复成“清醒”时的数值。
      • 观察：模型是不是突然“想起来”正确答案了？
      • 如果是，说明这个位置对这个知识点至关重要。
  4. [生成报告] 绘制热力图
    • 把所有测试结果画成一张图：X轴是层数，Y轴是Token位置。颜色越深，说明这里藏着知识。

逐步讲解 (Step-by-Step)

下面我结合代码中的关键函数，把上面的清单展开讲。

第一步：准备工作 (Main Setup)

代码位置：main() 函数的前半部分。

  • 做什么：读取命令行参数，决定用哪个模型（args.model_name），读取事实数据（knowns，比如“埃菲尔铁塔在巴黎”）。
  • 代码对应： python mt = ModelAndTokenizer(args.model_name, ...) # 加载模型 knowns = KnownsDataset(DATA_DIR) # 加载一堆事实数据

第二步：设定干扰 (Noise Calculation)

代码位置：main() 中处理 noise_level 的部分。

  • 做什么：为了做实验，我们必须能把模型搞“坏”。这里计算了Embedding层的标准差或协方差。
  • 为什么：我们要给输入向量（比如 "Steve Jobs" 的向量）加上高斯噪声。噪声太小模型不受影响，噪声太大模型就坏了。代码里的 collect_embedding_std 就是去算一个合适的噪声强度。

第三步：核心实验循环 (The Loop)

代码位置：main() 中的 for knowledge in tqdm(knowns):

  • 做什么：遍历每一个知识点（例如 "Space Needle is in downtown [Seattle]"）。
  • 关键调用：calculate_hidden_flow(...)。这是整个文件的灵魂函数。

第四步：手术过程 (Causal Tracing Logic)

这是最难懂的部分，主要在 calculate_hidden_flow 和 trace_with_patch 这两个函数里。

逻辑流：

  1. 确定目标：

    • Prompt: "The Space Needle is in downtown"
    • Subject: "The Space Needle" (我们要破坏这部分的理解)
    • Expect: "Seattle"

  2. 运行 trace_with_patch (带补丁的追踪)： 这个函数是实验的执行者。它做了三件事：

    • Corrupt (破坏)：把输入中的 Subject ("The Space Needle") 对应的向量加上噪声。此时模型可能会预测成 "London" 或其他乱码。
    • Patch (打补丁/修复)：
      • 代码里有一个参数 states_to_patch。
      • 它告诉模型：“虽然你现在输入是乱的，但是当运行到 第L层 的 第T个Token 时，请强制把神经元的数值替换回 正常（Clean）状态 下的数值。”
    • Observe (观察)：
      • 替换完这一个点后，看模型输出 "Seattle" 的概率恢复了多少？

  3. 扫描全脑 (calculate_hidden_flow 调用 trace_important_states)：

    • 它写了一个双重循环：
      • for layer in all_layers: (遍历每一层)
      • for token in all_tokens: (遍历每一个词)
    • 对每一个 (Layer, Token) 组合，都运行一次 trace_with_patch。

第五步：绘制热力图 (Visualization)

代码位置：plot_trace_heatmap

  • 结果：你最终会得到一个二维矩阵 differences。
    • differences[token_i, layer_j] 的值很高，意味着：只要恢复 (Token_i, Layer_j) 这个点的状态，模型就能从混乱中找回正确答案。
    • 这证明了 (Token_i, Layer_j) 是存储该知识的关键节点。
  • 输出：代码会把这个矩阵画成紫色/绿色的热力图并保存为 PDF。通常你会看到在 Subject 的最后一个 Token 的中层或高层区域有高亮，这就是 ROME 论文著名的结论（知识存储在 MLP 层）。

总结：这段代码到底在干嘛？

他在做一个控制变量法的科学实验：

  1. 让模型正常回答 -> 记下答案。
  2. 把主语（Subject）打码（加噪声） -> 此时模型变傻。
  3. 一次只恢复一个神经节点的状态 -> 看看模型有没有变聪明。
  4. 如果恢复了某个节点，模型瞬间变聪明了，说明这个节点就是知识的所在地。
