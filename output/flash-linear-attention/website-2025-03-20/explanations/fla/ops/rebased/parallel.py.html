fla/ops/rebased/parallel.py

这份代码确实比较晦涩，因为它使用了 Triton 语言来编写高性能的 GPU 算子。Triton 的写法和普通的 PyTorch 很不一样，它更接近底层硬件的调度（比如显存管理、线程块划分）。

这份代码实现的是 Rebased Linear Attention 的并行（Parallel）版本。简单来说，它是一种改进的注意力机制，把标准 Transformer 的 Softmax(QK^T) 换成了 (QK^T)^2，并增加了归一化项。

为了让你看懂，我列了一个 学习任务清单 (To-Do List)，我们把这个文件拆解成 5 个步骤来阅读。

Task 1: 搞懂数学原理（我们在算什么？）

在看代码前，必须知道公式，否则全是天书。 普通的 Attention 是： $$ O = \text{Softmax}(\frac{QK^T}{\sqrt{d}})V $$

Rebased Attention （文中实现的算法）去掉了 Softmax，改用平方，并引入了一个分母 $Z$ 来做归一化： 1. 打分函数：不再是 $e^{qk}$，而是 $(q \cdot k)^2$。 2. 前向公式： $$ S = (Q K^T)^2 $$ $$ Z = \sum S $$ $$ O = \frac{S \cdot V}{Z} $$

代码对应点： 请看 parallel_rebased 函数的最后几行：

o, z = ParallelBasedFunction.apply(...) # 算出分子 o 和 分母 z
o = o / (z[..., None] + eps)            # 做除法归一化

Task 2: 理解入口函数 parallel_rebased_fwd_kernel 的“分块”策略

Triton 为了快，使用了类似 FlashAttention 的分块（Tiling）策略。 假设你的序列长度 $T=1024$，显存放不下 $1024 \times 1024$ 的矩阵。 它把 $Q$ 切成长度为 BTL (Block Time L) 的块，把 $K, V$ 切成长度为 BTS (Block Time S) 的块。

  • i_c: 当前处理的 Q 的块索引（第几个时间段）。
  • p_q, p_k, p_v: 指向显存中数据的指针。

代码对应点：

# 这里的 make_block_ptr 就是在显存中定位：
# "我要取第 i_bh 个 batch，第 i_c 块时间段的数据"
p_q = tl.make_block_ptr(...) 
b_q = tl.load(p_q, ...) # 把这块 Q 加载到更快的 SRAM (片上内存) 中

Task 3: 核心逻辑 —— 前向传播的两个循环

这是最难懂的部分。为了计算当前块 $Q$ 的注意力输出，它需要看所有的 $K, V$。由于是 Causal（因果） 的（只能看过去，不能看未来），计算被分成了两部分。

3.1 第一个循环：处理“以前”的数据 (Inter-chunk)

这部分计算当前块之前的所有 $K, V$。 * 特点：不需要 Mask（掩码）。因为以前的时间点肯定小于当前时间点，全都能看见。 * 数学操作：算 $Q \cdot K^T$，然后平方 b_s * b_s。

代码对应点：

# 遍历当前块之前的所有 KV 块
for _ in range(0, i_c*BTL, BTS):
    b_k = tl.load(p_k, ...)
    b_v = tl.load(p_v, ...)

    b_s = tl.dot(b_q, b_k)  # 算出分数 QK^T
    b_s = b_s * b_s         # Rebased 的核心：平方！
    b_z += tl.sum(b_s, axis=1) # 累加分母 Z
    b_o += tl.dot(b_s, b_v)    # 累加分子 O

3.2 第二个循环：处理“当前”的数据 (Intra-chunk)

这部分计算当前块内部的 $K, V$。 * 特点：需要 Causal Mask。因为在同一个块里，时间点 $t=5$ 不能看到 $t=6$ 的数据。 * 操作：生成一个掩码 m_s，把未来的分数设为 0。

代码对应点：

# 遍历当前时间段内的 KV
for _ in range(i_c*BTL, (i_c + 1) * BTL, BTS):
    # ... 加载 k, v ...

    # 生成因果掩码：只保留 Query时间 >= Key时间 的部分
    m_s = o_q[:, None] >= o_k[None, :] 

    b_s = tl.dot(b_q, b_k)
    b_s = b_s * b_s
    b_s = tl.where(m_s, b_s, 0) # 如果是未来信息，置为0

Task 4: 反向传播 (Backward) - 扫一眼即可

_parallel_rebased_bwd_dq 和 _parallel_rebased_bwd_dkv 是在算梯度。 这是为了训练用的。 * dq: 也就是 $\frac{\partial Loss}{\partial Q}$。它需要用到前向传播算出来的梯度 do 和原始的 k, v。 * dk, dv: 同理，计算 K 和 V 的梯度。

这部分逻辑是前向传播的逆运算，通常比前向更复杂，因为需要重新计算一遍注意力分数 $S$ 才能算出梯度。如果不做底层算法开发，只需要知道这里在利用链式法则算梯度即可。

Task 5: 总结 Python 包装类

最后看 ParallelBasedFunction 类。 * forward: 设置 Grid（GPU 线程网格），调用 parallel_rebased_fwd_kernel。 * backward: 接收梯度 do, dz，调用 parallel_rebased_bwd_kernel。

总结：这段代码到底在干嘛？

  1. 输入：Q, K, V。
  2. 核心算子：计算 $(QK^T)^2 V$。
  3. 加速手段：
    • 利用 Triton 写 CUDA 核心。
    • IO 优化：使用分块加载，避免反复读写显存。
    • 计算优化：区分“历史块”（无 Mask，纯矩阵乘法，快）和“当前块”（有 Mask，慢），最大化 GPU 吞吐量。
  4. 输出：未归一化的 $O$ 和归一化因子 $Z$。

建议阅读顺序： 先看最后的 parallel_rebased (Python) -> 再看 parallel_rebased_fwd_kernel (Triton) -> 重点看里面的两个 for 循环。反向传播代码可以先跳过。
