legacy

这是一个非常典型的项目“历史遗迹”目录。让我们把 legacy 文件夹比作整个项目的 “旧档案室” 或 “老厂区”。

以下是通俗易懂的解读：

1. 当前文件夹 (legacy) 主要负责什么？

这里是 Fla 项目的“历史博物馆”。

  • 功能：它的存在主要是为了存档。这里存放的是那些曾经有用，但现在已经被更新、更好、更独立的代码库所取代的功能。
  • 状态：“仅供参观”。就像你走进一家大公司的老办公楼，虽然灯还亮着，但核心业务部门都已经搬到隔壁的摩天大楼去了。开发者保留它可能是为了方便查阅旧代码逻辑，或者给还没来得及迁移的老用户一个缓冲。

2. 这个文件夹下的各个直接文件是干什么的？

根据你提供的目录结构，legacy/ 这一层级 没有任何直接文件（比如 README 或 .py 文件）。

  • 形象理解：这就像你走进了“旧档案室”的大门，发现走廊里空空荡荡，只有一扇通往里间（子文件夹）的门。这里没有总览说明书，你需要直接走进具体的房间去找东西。

3. 子文件夹的作用是什么？

这里只有一个子文件夹，它是这个“旧档案室”里唯一还在陈列东西的房间：

  • 📁 training/（旧版训练车间）
    • 这就是你刚才详细描述的那个“退役工厂”。它保留了旧版的模型训练代码和说明。现在的核心作用是指路，告诉大家：“训练业务已经搬家了，请去新地址！”

4. 高层认知：如何快速理解这部分代码？

你可以把它想象成 “早已过期的藏宝图”：

  • 核心逻辑：这里是项目过去的样子，而不是现在的样子。
  • 它的价值：它的价值在于“考古”。如果你想研究这个项目早期的训练流程是怎么搭建的，可以翻翻看；但如果你想跑通现在的模型，这里不是你应该呆的地方。
  • 你的行动：看到 legacy 这个名字，你的第一反应应该是 “路过，别进”。除非报错信息明确把你指向这里，否则在日常开发和使用中，你可以完全忽略这个文件夹的存在。
