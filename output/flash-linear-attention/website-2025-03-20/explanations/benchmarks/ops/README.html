benchmarks/ops

这是一个非常硬核但目标非常单纯的目录。为了让你一眼看懂，我们用“赛车场”来打比方。

1. 这个文件夹 (benchmarks/ops) 是干嘛的？

这里是 FLA (Fast Linear Attention) 库的“算子赛车场”。

  • 核心功能：测速（跑分）。
  • 它的任务：这里不负责“教”模型变聪明（训练准确率），只负责测模型里的零件（算子）跑得有多快。
  • 工作流程：它会生成一堆随机的数字（假数据），喂给不同的算法，然后用秒表（Triton 计时器）记录它们处理这些数据需要几毫秒。

简单说：如果你想知道哪个 Attention 算法处理长文本最快，就看这里的比赛结果。

2. 各个直接文件 (📄) 是干什么的？

这些 benchmark_xxx.py 文件，每一个都是一场特定主题的赛车比赛。

文件名里的后缀（如 abc, gla, rwkv6）就是这场比赛的主角（参赛选手）。

我们可以把它们分为三类：

A. 单一赛道测试（绝大多数文件）

这些文件是用来测试自家算法的不同实现版本（比如“普通版” vs “加速版”）。 * 例如：benchmark_gla.py, benchmark_rwkv6.py, benchmark_retention.py, benchmark_titans.py 等。 * 比赛内容： * 选手：同一个算法的 Chunk 版（分块计算）、Fused 版（融合加速）、Parallel 版（并行计算）。 * 陪跑嘉宾：通常会拉上 FlashAttention（业界的法拉利）作为参照物。 * 赛制：看谁在序列长度（T）越来越长时，耗时最少。

B. 跨界对决（1v1 PK）

有些文件是专门为了对比两个不同家族的强者。 * 例如：benchmark_simple_gla_vs_mamba2.py。 * 比赛内容：这是 Simple GLA 算法和当红炸子鸡 Mamba2 算法的正面硬刚。看谁是真正的“长序列之王”。

C. 基础/通用测试

  • 例如：benchmark_abc.py, benchmark_based.py。
  • 比赛内容：测试 ABC 算法或 Based 架构的基础算子性能。

4. 🚀 高层认知：一句话读懂它

如果说 layers 目录是造车间（把零件组装成层），那么 benchmarks/ops 就是试车场。

这里的代码不产生智慧，只产出图表。它们存在的唯一意义，就是用数据证明：

“看！我们写的这个新算法（或优化过的算子），比 PyTorch 原生的写法快了 X 倍，甚至比 FlashAttention 还要强！”
