utils/convert_from_rwkv7.py

这个脚本 convert_from_rwkv7.py 的核心作用只有一个：搬家 + 装修。

它把 原始 RWKV7 格式 的模型权重文件（.pth），转换成 FLA 库（基于 Hugging Face 格式） 能识别的模型格式。

因为两边的“房间布局”（代码结构）和“家具命名”（变量名）不一样，所以不能直接加载，必须写个脚本来一一对应。

下面我把这个脚本的工作拆解成一个 Task To-Do List，带你一步步看它是怎么完成“搬家”的：

✅ Task 1: 摸清底细 (读取旧权重 & 推导配置)

目标：打开旧包裹，看看里面有多少东西，以此来决定新房子要盖多大。

  • 动作：
    1. torch.load(rwkv7): 加载原始的 .pth 权重文件。
    2. 自动侦探：脚本没有让你手动输入配置，而是通过读取权重的形状（Shape）来反推配置 RWKV7Config。
      • 看 emb.weight 的大小 $\rightarrow$ 推算出 词表大小 (vocab_size)。
      • 看 ffn.key.weight 的大小 $\rightarrow$ 推算出 隐藏层维度 (hidden_size)。
      • 循环检查 blocks.0, blocks.1... $\rightarrow$ 数出一共有多少层 (num_hidden_layers)。
      • 读取 att.w1, att.g1 等 $\rightarrow$ 推算出 LoRA 相关的维度参数。

✅ Task 2: 建造空房 (初始化新模型)

目标：根据刚才推导出的图纸，造一个空的 FLA 风格的模型壳子。

  • 动作：
    1. AutoModelForCausalLM.from_config(config): 用刚才推导的配置，创建一个全新的、没填数据的 FLA 模型。
    2. 精度转换：根据用户参数 precision (比如 bf16, float16)，把这个空模型的精度转好。
    3. 拿到新模型的“花名册” (model.state_dict() 和 model_names)，准备往里面填数据。

✅ Task 3: 编写翻译字典 (核心逻辑)

目标：旧模型叫 blocks.0.att.key，新模型可能叫 model.layers.0.attn.k_proj。需要一个函数把名字对上。

  • 动作：定义了内部函数 translate_into_fla(name)。
    • 改名：把 blocks 改成 model.layers，把 att 改成 attn，把 ln0 改成 pre_norm 等等。
    • 丢弃垃圾：如果遇到 unused_names (如 v0, v1)，直接标记为不要，因为新模型不需要这些旧参数。
    • 处理 LoRA 命名：把原始的 w1, g2 这种命名，转换成 FLA 里的 _lora.lora.0.weight 这种 Hugging Face 风格的层级命名。
    • 标记是否转置：有些矩阵在原始代码里是横着的，在 Hugging Face 里要求竖着，这里会返回一个 transposed 标记（告诉后面要不要旋转矩阵）。

✅ Task 4: 搬运与组装 (填充权重)

目标：把旧数据填进新壳子。这是代码里的 for name in weights: 循环。

  • 动作：
    1. 查字典：调用 translate_into_fla 拿到新名字。
    2. 形状调整：
      • 如果标记了 transposed，就执行 .t_() 把矩阵转置。
      • 如果有维度是 [1, 1, hidden] 这种多余的维度，执行 .squeeze_() 把它压扁。
    3. 特殊组装 (Fusing)：
      • 难点：原始 RWKV7 把 x_r, x_w, x_k, x_v, x_a, x_g 分成了 6 个不同的小参数。
      • FLA的做法：FLA 把它们合并成了一个大的张量叫 x_x。
      • 代码逻辑：if fla_name.endswith('attn.x_x')，它会根据当前参数名字的最后一个字母（r, w, k...），把数据复制到 x_x 对应的切片位置里去。
    4. 普通搬运：对于其他普通参数，直接 copy_ 复制数值。
    5. 销项：每填好一个，就从 model_names 清单里划掉。

✅ Task 5: 最终检查与交房 (保存)

目标：确保所有必须填的坑都填了，然后保存文件。

  • 动作：
    1. 查缺补漏：检查 model_names 是否为空。如果还有剩下来的名字（除了允许缺失的 pre_norm），说明转换不完整，报错 KeyError。
    2. model.save_pretrained(output): 把填好数据的模型保存到指定文件夹。这就是你最后能用来推理的 Hugging Face 模型了。

总结

这篇文章其实就是在做一个 格式转换器。

  • 输入：RWKV 官方原始权重的路径。
  • 处理：
    1. 读形状猜配置。
    2. 建新模型。
    3. 名字映射 + 矩阵转置 + 参数合并(x_r/w/k/v/a/g -> x_x)。
  • 输出：一个可以直接用 transformers 库加载的文件夹。
