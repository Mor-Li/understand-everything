.github/ISSUE_TEMPLATE/rfc.yml

没问题，这段代码乍一看全是英文和符号，确实容易让人晕。

简单来说，这个文件不是用来“运行”的程序，而是一张“设计图”或“配置单”。

它的作用是：告诉 GitHub，当有人想在你的项目里提建议（提 Issue）时，给他展示一个什么样的“填空题”表单。

我为你列了一个 “学习任务清单 (Todo List)”，我们一步一步来拆解它：

✅ Task 01：搞懂场景 —— 这文件是干嘛的？

  • 场景： 你知道 GitHub 上有一个功能叫 Issue（问题/议题） 吗？通常大家用它来报 Bug 或者提新功能。
  • 痛点： 如果没有这个文件，用户点击“新建 Issue”时，就是一个白板，用户可能会乱写，比如只写一句“不好用”。
  • 解决： 这个 .yml 文件就是一个模版（Template）。它强制要求用户按格式填写，比如“你的建议是什么？”、“你为什么要这么做？”。
  • 文件名 RFC： 这是一个缩写，全称 Request for Comments（请求意见稿）。意思是：“我有一个新想法，但我还没开始做，我想先写出来大家讨论一下，看看合不合适。”

✅ Task 02：拆解头部 —— 门面长什么样？

这部分代码定义了用户在选择模版时看到的信息，以及 Issue 创建后的默认属性。

  • name: 📝 Request for Comments
    • 含义： 当用户点击“New Issue”时，GitHub 会弹出一个菜单让他选。这一行就是菜单上显示的选项名字。用户看到这个就知道：“哦，我要提建议点这里。”
  • description: Propose a new feature ...
    • 含义： 这是菜单名字下面的小字说明，解释这个选项是用来干嘛的（“提新功能或修改，并收集反馈”）。
  • title: "[RFC] "
    • 含义： 当用户选了这个模版，标题栏会自动填好 [RFC] 这几个字。用户只需要在后面补全，比如 [RFC] 增加夜间模式。
  • labels: ["enhancement"]
    • 含义： 自动打标签。只要用这个模版创建的帖子，自动打上“enhancement”（增强/改进）的标签，方便管理员分类。

✅ Task 03：拆解身体 (body) —— 用户要填什么空？

这部分是核心，它定义了具体的表单输入框。代码里有两个 - type: textarea，说明有两个大的文本输入框。

第一个输入框：

  - type: textarea
    id: proposal
    attributes:
      label: Proposal
      description: Provide a brief description...
    validations:
      required: true
  • 翻译过来就是：
    • 题目（label）： Proposal（提议/建议）
    • 提示语（description）： 请简要描述你关于新功能或修改的建议。
    • 必填吗（required）： true (是)。如果不填，提交按钮是灰色的，发不出去。

第二个输入框：

  - type: textarea
    id: rationale
    attributes:
      label: Rationale
      description: Why do you think this feature is important...
    validations:
      required: false
  • 翻译过来就是：
    • 题目（label）： Rationale（理由/依据）
    • 提示语（description）： 你为什么觉得这个功能很重要或有益处？
    • 必填吗（required）： false (否)。这个框可以空着不填。

✅ Task 04：脑补最终效果

把你刚才看的所有东西合起来，想象一下用户在网页上看到的画面：

  1. 用户点击 New Issue。
  2. 看到一个选项叫 📝 Request for Comments。
  3. 点击进去后，看到一个表单：
    • 标题栏： 已经自动填好了 [RFC]。
    • 第一栏： 粗体字写着 Proposal，下面有个大框给用户打字（必填）。
    • 第二栏： 粗体字写着 Rationale，下面有个大框给用户打字（选填）。
  4. 用户填完点提交，这个 Issue 会自动带上 enhancement 的标签。

总结

这个文件就是在说： “嘿 GitHub，如果有人想提‘RFC（讨论稿）’，请给他一张包含‘建议内容’和‘理由’的表格，别让他随便乱写。”
