.github/ISSUE_TEMPLATE

这份 .github/ISSUE_TEMPLATE 文件夹，其实就是这个开源项目的 “办事大厅接待处”。

为了让你快速理解，我们可以把它想象成一个 “政府办事大厅” 或 “医院挂号处” 的场景。

以下是具体的通俗解释：

1. 🏛️ 这个文件夹 (ISSUE_TEMPLATE) 主要负责什么？

它的作用是：“规范办事流程，防止乱喊乱叫”。

如果没有这个文件夹，用户来提问（提 Issue）就像是一个人冲进办事大厅随便大喊：“我不舒服！”或者“这东西坏了！”。工作人员（程序员）会很头大，因为不知道他具体哪里坏了，还得反复追问。

有了这个文件夹，GitHub 就会在门口设立一个 “自动取号机”。用户必须先选你要办什么业务，然后领一张对应的 “填空表格”，把信息填完整了才能提交。

2. 📄 各个直接文件分别是干什么的？

这里面的 4 个文件，分别对应 “取号机” 上的 4 个按钮和对应的表格：

  • 📄 config.yml —— 【分流指引牌 / 导诊台】

    • 角色：这是你就诊的第一站。
    • 作用：它不是表格，而是指路牌。它会告诉用户：“如果你只是想闲聊，请去左边的 Discord 聊天室；如果你想下载模型，请去右边的 Hugging Face。”
    • 目的：把那些不需要程序员修代码的“闲杂人等”分流出去，别占用宝贵的开发资源。

  • 📄 bug.yml —— 【故障报修单】

    • 角色：你要修东西时填的表。
    • 作用：当你发现程序报错（Bug）时，这张表强迫你填写：你用的什么版本？怎么复现错误的？报错截图是什么？
    • 目的：让程序员拿到单子就能直接开始修，不用再问你“你电脑是啥配置？”。

  • 📄 feature-request.yml —— 【许愿单 / 需求申请表】

    • 角色：你想要新功能时填的表。
    • 作用：当你觉得“如果能加个夜间模式就好了”时，这张表强迫你思考：为什么要这个功能？这个功能解决了什么痛点？
    • 目的：防止用户乱提无意义的需求，确保每个建议都是经过深思熟虑的。

  • 📄 rfc.yml —— 【提案讨论稿 / 意见征集书】

    • 角色：你要搞大动作之前填的表。
    • 作用：RFC (Request for Comments) 意思是“请求大家给点意见”。当你有一个很大的想法（比如想重构整个系统），但还没想好细节，就填这张表，召集大家开会讨论。
    • 目的：在正式动工前，先从理论上论证可行性，避免走弯路。

3. 📁 子文件夹的作用是什么？

(注：在你提供的目录结构中，ISSUE_TEMPLATE 内部没有更深层的子文件夹，所以这里指的是 ISSUE_TEMPLATE 本身作为 .github 的子文件夹的作用)

  • 作用：它是 GitHub 约定的专用目录。
  • 解释：这就好比你电脑里的“我的文档”或者安卓手机里的“DCIM（相册）”文件夹。只要你把这些 .yml 文件放在名为 ISSUE_TEMPLATE 的文件夹里，GitHub 网站就会自动识别并启用这套“取号系统”。如果你随便改个文件夹名字，这套系统就失效了。

4. 🧠 高层认知：一句话总结

这部分代码不是用来“跑程序”的，而是用来“管人”的。

它是项目管理者与用户之间的“契约”：

“为了提高效率，请不要发只有一句话的抱怨。请按我设计好的格式，把问题交代清楚，这样我才能更快地帮你解决问题。”
