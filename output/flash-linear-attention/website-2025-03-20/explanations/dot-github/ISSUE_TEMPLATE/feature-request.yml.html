.github/ISSUE_TEMPLATE/feature-request.yml

这段代码看起来全是英文和符号，确实容易让人晕头转向。但其实它不是用来写程序的，它是一份“问卷设计的说明书”。

简单来说，这个文件告诉 GitHub：“当有人想给这个项目提新功能建议（Feature Request）时，请给他们展示这样一个填空表格。”

为了帮你理解，我们把它拆解成一个“任务清单（Todo List）”。假设你是这个项目的管理员，你正在设计这张表格，下面是你一步步设定的规则：

📋 任务清单：读懂这份“问卷设计图”

✅ 第一步：给问卷起个名 (Header Info)

我们要先定义这张表单在菜单里长什么样。

  • 代码对应： yaml name: 🚀 Feature Request description: Suggest an idea for this project.
  • 你的观点/设定：
    • 名字：叫“🚀 Feature Request”（新功能申请）。
    • 描述：告诉用户，如果你有点子，就点这里。

✅ 第二步：预设标题和标签 (Meta Data)

为了方便管理，当用户打开表单时，我们要自动帮他填好一些信息。

  • 代码对应： yaml title: "[Feature Request] " labels: ["enhancement"]
  • 你的观点/设定：
    • 标题格式：自动在标题栏填上 [Feature Request]，用户只需要在后面补全具体内容（比如：[Feature Request] 增加夜间模式）。
    • 自动打标签：一旦提交，系统自动给这个帖子贴上 enhancement（增强/改进）的标签，方便程序员分类查看。

✅ 第三步：设计第 1 个问题 —— “你想要啥？” (Body Field 1)

现在开始设计正文里的填空题了。

  • 代码对应： ```yaml
    • type: textarea id: feature-request attributes: label: Feature Request description: Provide a clear and concise description of your feature proposal. validations: required: true ```
  • 你的观点/设定：
    • 题目类型：多行文本框 (textarea)，允许写长篇大论。
    • 问题标题：Feature Request（功能请求）。
    • 提示语：请清晰简洁地描述你的建议。
    • 强制规则：required: true（必填）。如果不填，不许提交。

✅ 第三步：设计第 2 个问题 —— “为什么要这个？” (Body Field 2)

光说要啥不行，得说服我为什么这个很重要。

  • 代码对应： ```yaml
    • type: textarea id: motivation attributes: label: Motivation description: | Please explain the motivation... Is your feature request addressing a specific problem? ... validations: required: true ```
  • 你的观点/设定：
    • 问题标题：Motivation（动机/理由）。
    • 提示语：解释一下背景。是不是遇到了什么痛点？（比如：“我经常因为没有这个功能而感到沮丧...”）。
    • 强制规则：required: true（这也是必填项）。

✅ 第五步：设计第 3 个问题 —— “你能帮上忙吗？” (Body Field 3)

最后，问问提建议的人愿不愿意自己动手。

  • 代码对应： ```yaml
    • type: textarea id: contribution attributes: label: Your Contribution description: | How can you contribute to this feature? For example, could you help by submitting a PR? validations: required: true ```
  • 你的观点/设定：
    • 问题标题：Your Contribution（你的贡献）。
    • 提示语：你能为此做点什么吗？比如你会写代码提交一个 PR（Pull Request）来帮忙实现吗？
    • 强制规则：required: true（必填，哪怕填“我不会写代码”也得填）。

💡 总结：这到底是个啥？

把上面的步骤合起来，这个文件的作用就是生成下面这样一个网页界面：

🚀 Feature Request

标题： [Feature Request] _____

1. Feature Request (必填) [ 请输入你想建议的功能... ]

2. Motivation (必填) [ 请输入你为什么要这个功能，解决了什么痛点... ]

3. Your Contribution (必填) [ 请输入你能帮什么忙（比如写代码）... ]

[ 提交按钮 ]

文中的核心观点是： 这是一个结构化的提问方式。作者不希望用户随便发一句“加个功能呗”，而是强迫用户思考清楚：要做什么、为什么要做、以及用户自己能不能出力。这能大大提高沟通效率。
