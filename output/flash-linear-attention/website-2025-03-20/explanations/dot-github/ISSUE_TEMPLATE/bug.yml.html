.github/ISSUE_TEMPLATE/bug.yml

这份文件其实不是一段程序代码（比如 Python 或 C++），而是一份“问卷调查的设计图”。

它的作用是：当有人在 GitHub 上给这个项目提 Bug（报错） 时，GitHub 会根据这份文件，自动生成一个填空表格，强迫提问者按规矩填写信息，而不是随便乱写一句话“程序跑不通”就完了。

为了让你完全理解，我们可以把这份文件想象成给提问者列的一个 Todo List（任务清单）。

这份文件实际上是在对提问者说：“如果你想报错，请按照以下 5 个步骤，把作业做完再提交：”

任务清单 (Todo List)

📋 步骤 0：准备工作 (对应文件头部的设置)

  • 任务：系统会自动给你的提问单贴上标签。
  • 对应代码： yaml name: 🐞 Bug Report title: "[Bug] " labels: ["bug"]
  • 解释：这部分你看不见具体操作，但它设定了当你点击“新建 Issue”时，你会看到一个叫“🐞 Bug Report”的选项。一旦你提交，标题会自动加上 [Bug] 前缀，并且自动打上 bug 的标签，方便管理员分类。

✅ 步骤 1：签署“承诺书” (Checklist)

  • 任务：你必须勾选两个确认框。
  • 对应代码： ```yaml
    • type: checkboxes ... options:
      • label: "I have checked FAQs..."
      • label: "Please report this bug in English..." ```
  • 解释：这是第一道关卡。
    1. 你必须确认你已经看过常见问题解答（FAQs）了（防止重复提问）。
    2. 你必须承诺用英语提问（方便国际开发者交流）。

📝 步骤 2：简单描述发生了什么 (Describe the Bug)

  • 任务：用文字清楚地写下 bug 是什么。
  • 对应代码： ```yaml
    • type: textarea id: description attributes: label: Describe the Bug validations: required: true ```
  • 解释：这是一个必填的大文本框。你得在这里写“我运行了什么功能，结果报错了”之类的文字描述。

💻 步骤 3：提供“犯罪现场”证据 (Steps to Reproduce)

  • 任务：贴出代码，证明这个 Bug 是可以复现的。
  • 对应代码： ```yaml
    • type: textarea id: reproduction attributes: label: Steps to Reproduce the Bug description: ...Please include a code sample... validations: required: true ```
  • 解释：这是最重要的一步。开发者最怕用户只说“坏了”但不给代码。这里强制要求你贴出一段代码（Code Snippet）或者 Colab 链接，让开发者能在他自己的电脑上重现这个错误。

🎯 步骤 4：描述你原本的期待 (Expected Behavior)

  • 任务：告诉开发者，如果没有 Bug，程序本来应该输出什么？
  • 对应代码： ```yaml
    • type: textarea id: expected-behavior attributes: label: Expected Behavior ```
  • 解释：比如“我本来以为它会输出 100，结果它输出了 Error”。这有助于开发者理解逻辑差异。

⚙️ 步骤 5：交代你的“作案工具” (Environment Information)

  • 任务：填写你的软件版本号。
  • 对应代码： ```yaml
    • type: textarea id: environment-info attributes: label: Environment Information value: |
      1. Torch:
      2. Triton: ```
  • 解释：AI 项目（看样子这个项目用了 Torch 和 Triton）非常依赖版本。这里预设了一个填空题，强迫你填上：
    1. 你用的 PyTorch 是什么版本？
    2. 你用的 Triton 是什么版本？ 如果不填这个，开发者可能无法解决问题，因为很多 Bug 是版本不兼容导致的。

总结

这份 YAML 文件的核心观点就是：“为了高效解决 Bug，请提问者必须提供：确认查过文档、英语描述、复现代码、预期结果、以及运行环境版本。”

如果没有这份文件，用户可能会发一个只有一句话的 Issue，开发者就得反复追问“你代码呢？”、“你版本多少？”，效率非常低。
