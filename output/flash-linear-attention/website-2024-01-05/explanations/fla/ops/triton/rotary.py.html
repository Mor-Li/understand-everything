fla/ops/triton/rotary.py

这份代码是用 OpenAI Triton 编写的，目的是在 GPU 上极其高效地计算 RoPE (Rotary Positional Embeddings，旋转位置编码)。这是目前大模型（如 LLaMA, Mistral）中最常用的位置编码方式。

简单来说，它的作用是：把输入向量两两分组，按照它们在序列中的位置进行旋转。

为了让你看懂，我把这个代码的执行逻辑拆解成一个 “任务清单 (Todo List)”。我们假装自己是 GPU 的一个线程（Thread），看看我们要按什么步骤完成这个任务。

任务清单：GPU 执行 RoPE 的 5 个步骤

✅ Task 1: 搞清楚“我是谁” (定位与索引)

目标：确定当前线程负责处理哪个 Batch、哪个 Head、以及序列中的哪一段数据。 代码对应：rotary_kernel 函数的开头部分。

  • 逻辑解读： GPU 是大规模并行的。Triton 启动了成千上万个“程序块”（Program）。

    • pid_m: 我负责序列长度方向的哪一块？
    • pid_batch: 我负责第几个样本？
    • pid_head: 我负责第几个注意力头（Head）？

  • 难点（Variable Length）： 代码里有一个 if not IS_VARLEN: ... else: ...。

    • 定长模式 (not IS_VARLEN)：普通的 Batch 数据，形状整整齐齐 (Batch, Seq, Head, Dim)。直接算内存地址。
    • 变长模式 (IS_VARLEN)：为了省显存，把所有句子的 token 拼成了一长条（Packed Sequence）。这时需要查 CU_SEQLENS 表，找出当前句子在长条中的起始位置 start_idx。

✅ Task 2: 找到数据的内存地址 (Pointer Arithmetic)

目标：算出输入数据 X 和输出数据 OUT 在显存里的精确指针位置。 代码对应：X = X + ... 和 OUT = OUT + ...。

  • 逻辑解读：
    • 利用 Stride (步长)：Triton 需要知道跳过多少个元素才能到达下一行。
    • X 指针移动到了当前 Batch、当前 Head 的起始位置。

✅ Task 3: 准备旋转参数 (加载 Cos 和 Sin)

目标：根据当前处理的 Token 在句子中的位置，去查表读取对应的 $\cos$ 和 $\sin$ 值。 代码对应：rm_cs = ... 以及 tl.load(COS/SIN ...)。

  • 逻辑解读：
    • 位置偏移 (SEQLEN_OFFSETS)：如果是推理阶段（KV Cache），虽然只需要计算新生成的 1 个 token，但它的位置可能是第 100 个。所以需要加上这个偏移量，确保读到第 100 个位置的 $\cos/\sin$。
    • 加载数据：从显存加载 $\cos$ 和 $\sin$ 到寄存器。

✅ Task 4: 核心数学计算 (执行旋转)

目标：这是最关键的一步。根据不同的 RoPE 变体，对向量进行旋转。 代码对应：if not INTERLEAVED: 和 else: 分支。

这里有两种常见的 RoPE 内存排列方式，代码都支持：

  • 模式 A：普通模式 (LLaMA 默认, not INTERLEAVED)

    • 切分方式：把向量切成两半。比如向量是 [x0, x1, x2, x3]。它把 [x0, x1] 看作一半，[x2, x3] 看作一半。
    • 配对：x0 和 x2 配对旋转，x1 和 x3 配对。
    • 代码行为：
      1. 加载前半段 x0，加载后半段 x1。
      2. 公式： $$Out_0 = x_0 \cdot \cos - x_1 \cdot \sin$$ $$Out_1 = x_0 \cdot \sin + x_1 \cdot \cos$$ (注：如果 CONJUGATE 为 True，代表反向旋转/求导，符号会变)

  • 模式 B：交替模式 (HuggingFace 风格, INTERLEAVED)

    • 切分方式：相邻元素配对。[x0, x1] 是一对，[x2, x3] 是一对。
    • 代码行为：
      1. 这部分比较 tricky。为了内存读取效率，它没有按 0,1,2,3 读，而是用了技巧加载 X0 和 X1。
      2. rk_swap：用于交换索引，把 (0, 1) 变成 (1, 0)。
      3. 最终也是做旋转计算。

✅ Task 5: 写回显存 (Store)

目标：把算好的结果存回 OUT 指针指向的位置。 代码对应：tl.store(OUT, ...)。

  • 逻辑解读：
    • Masking (掩码)：这是 GPU 编程的保护机制。因为 GPU 是按块（Block）操作的，如果序列长度是 5，但块大小是 8，多出来的 3 个线程不能乱写内存，必须被 mask 掉。

Python 包装层 (apply_rotary) 的 Todo List

除了上面的 Kernel，底下的 apply_rotary 函数是给 PyTorch 调用的接口。它的任务很简单：

  1. 检查参数：
    • 确保 cos 和 sin 形状对得上。
    • 确保维度不超过 256（Triton kernel 里的 Block 限制）。
  2. 处理内存连续性：
    • .contiguous()：Triton 要求内存最好是连续的，否则计算步长会很麻烦。
  3. 部分旋转 (Partial RoPE)：
    • 有些模型只旋转向量的前半部分（比如 GPT-NeoX）。代码里有 if rotary_dim < headdim，如果不需要旋转的部分，直接把原始数据 copy_ 到输出。
  4. 计算 Grid：
    • 决定启动多少个 GPU 线程块。
  5. 启动 Kernel：
    • 把所有指针、步长（Stride）、常量传给 GPU 函数。

总结：这段代码的“核心观点”

  1. 性能优先：它没有用 PyTorch 的 torch.cat 或 torch.stack 来做旋转，而是直接写 Triton Kernel。这能极大地减少显存读写（IO），因为旋转操作是“计算密集型”较弱但“访存密集型”较强的操作，融合算子速度最快。
  2. 兼容性强：它同时支持了两种主流的 RoPE 格式（Interleaved 和 Non-Interleaved），以及支持变长序列（VarLen/FlashAttention 格式）和定长序列。
  3. 显存安全：大量使用了 Mask 和边界检查，防止 GPU 越界访问。

一句话概括：这是一个通用的、高性能的、底层的 RoPE 算子实现，专门为了让大模型跑得更快。
