fla/module/rotary.py

这份代码实现的是大语言模型（LLM）中非常核心的一个组件：旋转位置编码（Rotary Positional Embedding，简称 RoPE）。

简单来说，它的作用是给模型的 Query（查询）和 Key（键）向量加上“位置信息”，让模型知道每个词在句子里的顺序。

为了让你更容易理解，我把它拆解成一个 “学习任务清单 (Todo List)”，我们一步步来完成这个代码的阅读任务。

✅ Task 1: 理解核心数学操作 (最底层的积木)

我们先看最上面的两个函数，这是 RoPE 的数学基础。

目标代码： rotate_half 和 apply_rotary_emb_torch

  1. rotate_half(x):

    • 原理：RoPE 的核心动作是旋转。想象一个二维向量 $(x_1, x_2)$，旋转它需要变成 $(-x_2, x_1)$。
    • 代码逻辑：它把向量切成两半，把第二半取负号放到前面，第一半放到后面。
    • Interleaved 参数：这是两种不同的旋转风格（GPT-J 风格 vs GPT-NeoX 风格），只是切分维度的方式不同，数学本质一样。

  2. apply_rotary_emb_torch:

    • 原理：这是标准的 RoPE 公式：$f(x) = x \cdot \cos(\theta) + \text{rotate}(x) \cdot \sin(\theta)$。
    • 代码逻辑：
      1. 把输入的向量 x 拿来。
      2. 生成对应维度的 cos 和 sin 值。
      3. 执行公式：一部分乘 cos，加上 旋转后的部分乘 sin。
    • 注意：这个函数是纯 PyTorch 实现，用来做参考或者在不支持 GPU 加速时兜底使用。

✅ Task 2: 理解加速黑科技 (Triton 优化)

大模型计算量很大，纯 PyTorch 算得慢，所以作者用了 Triton（一种 GPU 编程语言）来加速。

目标代码： class ApplyRotaryEmb(torch.autograd.Function)

  1. 为什么要写这个类？

    • 这是一个自定义的自动求导函数。它告诉 PyTorch：
      • Forward (前向传播)：怎么算结果？ -> 调用 apply_rotary (这是从 fla.ops.triton.rotary 导入的底层加速内核)。
      • Backward (反向传播)：怎么算梯度？ -> 自己写了 backward 函数，手动计算梯度的旋转，比 PyTorch 自动推导更快、更省显存。

  2. 关键点：

    • ctx.save_for_backward: 保存前向传播时的 cos, sin 等数据，给反向传播用。
    • 这个类是用来“替换”上面那个慢速的 apply_rotary_emb_torch 的。

✅ Task 3: 理解大管家 (Module 封装)

有了计算函数还不够，我们需要一个类来管理这些状态（比如缓存 cos/sin 表），这就是我们在模型里实际调用的层。

目标代码： class RotaryEmbedding(torch.nn.Module)

  1. __init__ (初始化)：

    • 设定维度 dim。
    • inv_freq (逆频率)：这是 RoPE 的数学基础。它生成一串频率数值（比如 $10000^{-2i/d}$），决定了位置编码的波长。
    • scale (缩放)：代码里还兼容了 XPos（一种 RoPE 的变体），如果 scale_base 不为空，就会对位置编码进行缩放，但这属于进阶功能，通常是 None。

  2. _update_cos_sin_cache (缓存管理 - 重点！)：

    • 问题：每次 forward 都重新算一遍 cos 和 sin 太慢了。
    • 解决：
      • 检查当前的序列长度 seqlen 是否超过了缓存的长度。
      • 如果超过了，或者设备变了（CPU->GPU），就重新计算一次超长的 cos 和 sin 表。
      • 把算好的表存到 self._cos_cached 和 self._sin_cached 里。
    • 细节：这里有很多关于 dtype (数据类型 fp32/bf16) 的判断，是为了保证精度不丢失（位置编码对精度很敏感）。

✅ Task 4: 最终执行 (Forward)

最后一步，把所有东西串起来。

目标代码： RotaryEmbedding.forward

  1. 输入：

    • q (Query) 和 k (Key)。注意：RoPE 只作用于 Q 和 K，不作用于 V (Value)。
    • seqlen_offset: 在推理（Inference）阶段，因为有 KV Cache，我们不需要从头算，只需要算新生成的 token 的位置，这个 offset 就是告诉模型“现在的绝对位置在哪里”。

  2. 流程：

    • 第一步：看长度够不够？调用 _update_cos_sin_cache 确保缓存里的 cos/sin 表够长。
    • 第二步：调用加速函数 apply_rotary_emb_func (其实就是 Task 2 里的 Triton 加速版)。
    • 第三步：把加上了位置信息的 q 和 k 返回回去。

📝 总结：这个文件在讲什么？

如果用一句话总结： 这是一个高性能（Triton加速）、支持长序列推理（带缓存管理）、兼容性强（支持 XPos 和不同精度）的旋转位置编码（RoPE）实现。

你的大脑处理流程应该是： 1. 数学层：$x$ 怎么转？ -> rotate_half 2. 算子层：怎么算得快？ -> ApplyRotaryEmb (Triton) 3. 应用层：怎么管理缓存和调用？ -> RotaryEmbedding (nn.Module)
