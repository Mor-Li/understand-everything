.github/workflows/model.yml

这份文件是一个 GitHub Actions 的配置文件。简单来说，它是一个自动化脚本，告诉 GitHub：“每当有人修改了代码，请帮我自动在有一堆显卡的机器上运行这些测试，看看代码有没有把模型训练的功能搞坏。”

为了让你一步步看懂，我把它拆解成一个 “任务清单 (Todo List)”，我们按照这个清单的顺序来阅读这份文件。

任务清单：理解 model.yml

✅ 第一步：理解“我在哪里，我要测什么？” (对应文件开头的注释)

文件最上面的一大段注释（# 开头的内容）是在介绍整个项目的测试地图。

  • 核心观点：
    • tests/ 文件夹下的代码是按功能分类的（比如 trainer 测训练器，models 测模型）。
    • special_ 开头的文件夹是特殊测试（比如 special_distributed 专门测多卡分布式训练）。
    • 本文件的定位：这是一个 “重型多 GPU 单元测试” (Heavy multi-GPU unit tests)。它不是跑跑 CPU 就能完事的，必须要有真的显卡。

✅ 第二步：设定“什么时候干活？” (对应 on 部分)

脚本需要知道何时触发。

  • 触发条件 (on)：
    • 动作：当有代码 push (推送) 或者提 pull_request (合并请求) 时。
    • 分支：只针对 main 分支或者 v0.* 版本分支。
    • 路径过滤器 (paths)：这是为了省钱省资源。只有当修改了 verl/ 目录下的 Python 代码，或者修改了本配置文件及特定的测试脚本时，才会运行。如果只是改了个 README.md，这个脚本是不会跑的。

✅ 第三步：准备“干活的环境” (对应 jobs -> env & container)

要在 8 张显卡上跑测试，环境配置很关键。

  • 硬件 (runs-on)：指定在 [L20x8] 的机器上跑。意思是用 8 张 L20 型号的显卡。
  • 网络 (env)：配置了 HTTP 代理和 HuggingFace 的镜像（hf-mirror.com），这通常是为了在国内或者内网环境能更快下载模型。
  • 软件镜像 (container)：它不直接用裸机，而是用了一个 Docker 镜像 (whatcanyousee/verl:...)。这个镜像里已经预装好了 CUDA、vLLM、SGLang 等深度学习通过环境。

✅ 第二步：执行“主线任务” (对应 jobs -> model_rmpad -> steps)

这是脚本最长、最核心的部分。它在一步步执行测试命令。

  1. 下载代码 (actions/checkout)：把当前仓库的代码拉下来。
  2. 安装依赖：
    • pip3 install ... -e .[test]: 安装当前项目及其测试依赖。
    • pip3 install --upgrade transformers: 确保用的是最新版的 transformers 库。
  3. 基础模型测试 (test_transformer.py)：
    • 运行 pytest 测试 Transformer 模型的基本功能。
  4. FSDP 分布式测试 (test_fsdp_ckpt.py)：
    • 使用 torchrun 在 8 张卡上模拟分布式训练，测试 Checkpoint (模型存档) 功能。这里用的策略是 fsdp。
  5. 兼容性大挑战 (重点) (test_transformers_ulysses.py)：
    • 你会看到脚本反复运行同一个测试，但是每次运行前都重装不同版本的 transformers 库。
    • 它从 最新版 -> 4.49.0 -> 4.48.0 -> ... 一直到 4.45.0。
    • 目的：确保你的代码（Ulysses 序列并行功能）能兼容各种旧版本的 HuggingFace Transformers 库，防止用户因为版本不同而报错。
  6. 最后的综合测试 (run_all.sh)：
    • 运行一个 shell 脚本，里面可能包含了一组复杂的分布式测试命令。

✅ 第五步：处理“支线任务/实验性任务” (对应 model_rmpad_fsdp2_unstable)

文件最后还有一个独立的 Job。

  • 任务名：model_rmpad_fsdp2_unstable。
  • 目的：测试 FSDP2 (PyTorch 的新一代全分片数据并行策略)。
  • 为什么分开写？：注释里写了 TODO: Move this back... once FSDP2 is stable。说明 FSDP2 目前还不稳定，把它单独列出来，就算它挂了，也不会影响上面那个“主线任务”变绿（通过）。方便开发人员单独排查问题。

总结

这篇文档就是在说：

“只要有人改了核心代码，就去给我找一台 8卡 L20 的机器。 先把环境配好，然后 疯狂测试 模型功能。 尤其是要测 分布式训练 (FSDP) 和 序列并行 (Ulysses)。 并且要保证从 4.45 到最新版 的 transformers 库都能跑通。 最后，顺便试一下不稳定的 FSDP2，挂了也没关系，单独报出来就行。”
