.github/workflows/sgl.yml

这份文件是一个 自动化测试脚本（GitHub Actions Workflow）。

你可以把它想象成一个 “极其严谨的机器人质检员”。每当有人修改了代码，这个机器人就会自动醒来，按照这张“清单”去检查代码有没有把功能改坏。

这份文件专门负责检查一个叫 SGLang 的功能模块（SGLang 是一个用于加速大模型推理的后端引擎）。

为了让你看懂，我把这份文件翻译成一个 “机器人执行任务的 Todo List”，分为四个阶段：

📋 阶段一：判断是否需要干活 (Trigger)

机器人手里拿着一份规则表，只有满足条件才会启动。

  • Todo 1: 检查触发方式
    • 有人手动点击了运行按钮吗？（workflow_dispatch）
    • 有人往 main 或 v0.2.x 分支提交了代码吗？（push）
    • 有人提交了合并请求（Pull Request）吗？（pull_request）
  • Todo 2: 检查修改的文件范围
    • 关键点： 机器人很懒，如果修改的文件跟 SGLang 没关系，它就不干活。
    • 它会检查：修改的是不是 .py 文件？是不是 vllm.yml？
    • 它会排除：如果只改了 examples、megatron（另一种架构）、fsdp 等不相关的文件，机器人继续睡觉。
    • 特例：如果修改了 sgl.yml 本身，或者 tests/rollout/*sglang* 相关的测试代码，必须立刻醒来干活。

🛠️ 阶段二：准备工作环境 (Environment Setup)

一旦决定干活，机器人需要先搭建一个“实验室”。

  • Todo 3: 申请计算资源
    • 申请一台配置极其豪华的电脑：8张 L20 显卡 的机器（runs-on: [L20x8]）。
    • 设置超时时间：20分钟。如果20分钟没跑完，直接强制停止。
  • Todo 4: 配置系统环境
    • 加载一个打包好的镜像环境（Docker Image）：verl:ngc-cu124...。这相当于给电脑装好了一个预装了 CUDA、vLLM 和 SGLang 的操作系统。
    • 设置网络代理（Proxy）和 HuggingFace 镜像站（方便快速下载模型）。
    • 开启所有 GPU (--gpus all)。

📦 阶段三：准备测试材料 (Installation)

实验室搭好了，现在要把被测试的代码和模型拿进来。

  • Todo 5: 下载代码
    • 把 GitHub 仓库里最新的代码拉取到本地（actions/checkout）。
  • Todo 6: 安装依赖软件
    • 安装 Python 库：hf_transfer（加速下载用的）。
    • 安装当前项目的代码库，并开启 test, gpu, sglang 相关的插件功能。
  • Todo 7: 下载测试用的大模型
    • 从网上下载 Qwen/Qwen2-7B-Instruct 这个模型。因为测试代码需要跑这个模型来验证功能对不对。

🧪 阶段四：正式开始考试 (Testing)

这是最核心的部分。机器人会依次运行 5 个测试脚本。如果任何一步报错，整个任务就会显示“失败（Fail）”。

  • Todo 8: 测试 SGLang 的基础功能 (SPMD)
    • 动作：进入 tests/workers/rollout 目录。
    • 命令：用 torchrun 启动 2 个进程，运行 test_sglang_spmd.py。
    • 目的：测试在多卡并行（SPMD）的情况下，SGLang 能不能正常工作。
  • Todo 9: 测试带“工具”的异步推理
    • 命令：运行 test_sglang_async_rollout_w_tools.py。
    • 目的：测试 SGLang 在异步生成内容时，能不能正常调用外部工具（Tools）。
  • Todo 10: 测试沙盒融合工具 (Sandbox Fusion)
    • 命令：运行 test_sglang_async_rollout_sf_tools.py。
  • Todo 11: 测试搜索工具 (Search Tools)
    • 命令：运行 test_sglang_async_rollout_search_tools.py。
  • Todo 12: 测试 MCP 搜索工具
    • 命令：运行 test_sglang_async_rollout_mcp_tools.py。

💡 补充解释：文件开头的注释是啥？

你可能看到文件最上面有一大堆 # 开头的文字，那些不是代码，是写给人类程序员看的 “项目说明书”：

  1. Tests layout（测试目录结构）：告诉程序员，如果要写测试代码，请把文件分门别类放好。比如测试模型的放 tests/models，测试训练器的放 tests/trainer。
  2. Special folders（特殊文件夹）：有些测试很特殊，比如 special_distributed 是必须多显卡跑的，special_npu 是华为 NPU 芯片专用的。
  3. Workflow layout（工作流概览）：列出了这个项目里所有的自动化测试文件：
    • 有跑得快的 CPU 测试（查查标题、代码格式）。
    • 有跑得慢的重型 GPU 测试（比如你现在看的这个 sgl.yml，还有 vllm.yml）。
    • 有端到端（E2E）的完整流程测试。

总结

一句话概括： 这个文件定义了一个自动化任务，当代码更新时，它会在一台 8卡 GPU 服务器上，下载 Qwen2 模型，并运行 5个针对 SGLang 后端的 Python 测试脚本，以确保新代码没有把 SGLang 的推理功能搞挂。
