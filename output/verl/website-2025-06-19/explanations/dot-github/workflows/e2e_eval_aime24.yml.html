.github/workflows/e2e_eval_aime24.yml

这份文件确实包含了两部分内容：上半部分是“说明书”（注释），下半部分是“执行指令”（代码）。对于不熟悉 CI/CD（持续集成/持续部署）的人来说，确实容易晕。

你可以把这份文件想象成一个“自动化测试机器人的任务清单”。

为了让你看懂，我把它拆解成一个 4个阶段的学习 Task List，你只需要跟着这个清单一步步走，就能明白它在干什么。

📝 Task 1：读懂“说明书” (文件头部的注释)

任务目标：了解这个项目里的测试文件都是怎么摆放的，以及哪些测试跑在 CPU 上，哪些跑在 GPU 上。

文中的 # # Tests layout 和 # # Workflow layout 部分是在告诉开发者这个项目的“家规”：

  1. 文件夹分类：
    • tests/trainer：专门测训练功能的。
    • tests/models：专门测模型功能的。
    • special_e2e：端到端（End-to-End）测试，也就是从头到尾跑通一个流程（比如训练+生成），这个文件就属于这一类。
  2. 硬件规则：
    • 默认情况下，测试都在 GPU 上跑。
    • 如果文件名里带有 on_cpu.py，或者在 special_npu 文件夹里，才会在 CPU 或 NPU 上跑。
  3. 测试分级：
    • 有的测试很轻（CPU sanity），每次提交必跑。
    • 有的测试很重（Multi-GPU），比如这个文件，是跑 AI 模型的，比较耗资源。

🚦 Task 2：搞懂“触发开关” (on 部分)

任务目标：弄清楚这个测试机器人在什么情况下才会被启动。

看代码中的 on: 部分：

  1. Push（推送代码）时：
    • 只要有人往 main 分支或者 v0.* 版本分支推送代码，立刻启动。
  2. Pull Request（提代码合并请求）时：
    • 只有合并到 main 分支时才检查。
    • 由“白名单”和“黑名单”决定是否启动（这是为了省钱省资源，因为跑这个测试要用 8 张显卡）：
      • ✅ 监测：所有的 .py 文件。
      • ❌ 忽略：examples 文件夹、tests 文件夹（除非是特定的脚本）。
      • ✅ 特例：如果修改了 recipe/r1（R1算法配方）或者本文件自己，必须跑。

一句话总结：这是个很“贵”的测试，平时别乱跑，只有修改了核心代码或核心算法（R1）时才跑。

🏗️ Task 3：检查“施工现场” (jobs 环境配置)

任务目标：了解这个测试是在什么样的电脑和环境里跑的。

看 jobs: e2e_eval_aime24 下面的内容：

  1. 机器配置 (runs-on)：
    • [L20x8]：哇，这很豪华。它指定了一台装有 8块 L20 显卡 的机器来跑这个任务。
  2. 软件环境 (container)：
    • 使用了一个打包好的 Docker 镜像：verl:ngc-cu124...。这意味着环境里已经装好了 CUDA、vLLM 等深度学习基础库。
  3. 网络环境 (env)：
    • 配置了 HTTP_PROXY，并且把 HuggingFace 的下载地址改成了国内镜像 hf-mirror.com（为了下载模型更快、更稳）。

▶️ Task 4：执行“具体步骤” (steps 部分)

任务目标：看机器人启动后，具体干了哪几件事（这是最核心的逻辑）。

看 steps: 下面的每一个 - name：

  1. Step 1: 复制代码 (Checkout)
    • 把 GitHub 仓库里的最新代码拉到这台 8 卡机器上。
  2. Step 2: 安装依赖 (Install)
    • pip3 install ...：安装当前项目的代码，并安装 math-verify（用来验证数学题答案对不对的工具）。
  3. Step 3: 准备数据 (Prepare aime24 dataset)
    • python3 recipe/r1/data_process.py --task aime2024：运行一个 Python 脚本，下载并处理 AIME 2024（美国数学邀请赛）的数据集。
  4. Step 4: 开始考试 (Running generation and evaluation)
    • bash tests/special_e2e/run_r1_distill_qwen_aime24_eval.sh：这是大结局。
    • 它运行了一个 Shell 脚本，大概率是加载一个叫 Qwen（通义千问）的模型，用 R1 算法微调或者直接推理，做 AIME 2024 的数学题，最后算分。

💡 总结：这个文件到底是干啥的？

用人话翻译：

这是一个自动化测试流程。 每当开发者修改了核心代码，GitHub 就会自动找一台 8张显卡的服务器，装好环境，下载 AIME 2024 数学竞赛题，让模型（Qwen）做一遍题，看看修改后的代码有没有导致模型变笨（做题分数下降）或者报错。
