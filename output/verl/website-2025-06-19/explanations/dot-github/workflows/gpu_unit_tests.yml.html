.github/workflows/gpu_unit_tests.yml

这份文件其实是一个 自动化测试流程说明书（GitHub Actions Workflow）。

你可以把它想象成是一个项目经理写给测试机器人的一张“任务清单（Todo List）”。它的核心目的是：每当代码有更新时，自动在 GPU 机器上跑一遍测试，确保代码没改坏。

为了让你看懂，我们将这份文件拆解成一个 5步走的 Todo List。我们按照逻辑顺序，从“设计理念”到“实际执行”一步步来看。

Task 1: 理解测试的“地图”规划 (Design Layout)

观点来源： 文件开头的 # # Tests layout 和 # # Workflow layout 注释部分。

在让机器人干活前，先要告诉它我们的文件是怎么摆放的，以及哪些归谁管。

  • Todo 1.1 - 认清文件夹结构：
    • tests/trainer 里的代码是测训练器的。
    • tests/models 里的代码是测模型的。
    • 带有 special_ 前缀的文件夹（如 special_npu）是特殊用途（比如专门测 NPU 芯片的，或者测分布式的），平时不要乱跑。
  • Todo 1.2 - 区分 CPU 和 GPU 任务：
    • 默认原则：所有测试都默认要用 GPU。
    • 例外情况：如果文件名里写了 on_cpu.py，或者在 special_npu 文件夹里，那就不归这个 GPU 流程管。
  • Todo 1.3 - 明确分工（不要重复干活）：
    • 有些重型测试（比如 model.yml, vllm.yml）有专门的负责人（其他的 yml 文件）。
    • 本文件 (gpu_unit_tests.yml) 的职责是： 捡漏。除了那些重型测试、CPU 测试、E2E 测试之外，剩下的 普通 GPU 单元测试 都归我管。

Task 2: 设定“上班”时间 (Trigger Rules)

观点来源： on: 和 concurrency: 部分。

机器人什么时候开始工作？

  • Todo 2.1 - 监听主要分支：
    • 当有人往 main 分支或者 v0.4.x 版本分支 推送代码 (push) 时，立即启动。
    • 当有人给这两个分支 提合并请求 (pull request) 时，也启动。
  • Todo 2.2 - 过滤无关文件（偷懒原则）：
    • 如果只改了文档、或者只改了 examples 文件夹，不要启动（省钱省资源）。
    • 只有修改了 .py 文件，或者修改了测试配置本身，才启动。
  • Todo 2.3 - 避免排队冲突：
    • 如果同一个分支短时间内提交了两次，取消上一次还没跑完的任务，直接跑最新的（concurrency 部分）。

Task 3: 准备“办公环境” (Environment Setup)

观点来源： jobs: gpu_unit_tests 下的 runs-on, container, steps 前几步。

这活儿普通的电脑干不了，得配高配电脑。

  • Todo 3.1 - 申请硬件：
    • 申请一台代号为 L20x8 的服务器（这意味着机器上有 8 张 L20 显卡）。
  • Todo 3.2 - 配置软件环境（Docker）：
    • 使用这个镜像：verl:ngc-cu124...。你可以理解为装好了一套预装了 CUDA、PyTorch 和各种加速库的操作系统。
    • 开启所有 GPU (--gpus all)。
  • Todo 3.3 - 安装依赖包：
    • 把代码下载下来 (checkout)。
    • 安装 Python 依赖包 (pip install ...)，包括 ray (分布式框架) 和 cupy (GPU 加速库)。

Task 4: 执行核心任务——普通 GPU 测试 (Run General Tests)

观点来源： name: Run all GPU unit tests 这一步。

这是最关键的一步，机器人开始批量跑测试了。

  • Todo 4.1 - 运行 Pytest：
    • 命令机器人扫描 tests/ 文件夹下的所有测试文件。
  • Todo 4.2 - 排除不归我管的（关键点）：
    • 排除 test_linear_cross_entropy_tp.py（下面 Task 5 单独跑）。
    • 排除 *on_cpu.py（那是 CPU 测试流程的事）。
    • 排除 *test_vllm*, *_sglang*, tests/models/（这些太重了，有专门的 yml 文件负责）。
    • 排除 tests/special*（特殊测试不在这里跑）。
  • 结论： 这一步跑的是除了上述排除项以外的所有 GPU 单元测试。

Task 5: 执行特种任务——分布式测试 (Run Distributed Test)

观点来源： 最后的 name: Testing LinearCrossEntropyTP ... 这一步。

有一个特定的测试非常重要，且需要模拟多卡环境，所以单独列出来跑。

  • Todo 5.1 - 启动分布式运行：
    • 使用 torchrun 命令（这是 PyTorch 专门用来跑分布式任务的工具）。
    • 设定 nproc-per-node=8：告诉机器“我要同时用 8 张显卡/8个进程”来跑这个测试。
  • Todo 5.2 - 跑什么？
    • 跑 tests/utils/test_linear_cross_entropy_tp.py。这是测试“线性交叉熵张量并行”功能的，需要验证计算正确性、时间和显存占用。

总结

这份文件的逻辑是： 1. 我是谁？ 我是负责跑 GPU 单元测试的管理员。 2. 什么时候干活？ 主分支有 Python 代码变动时。 3. 用什么干活？ 用一台 8 卡 L20 的服务器。 4. 干什么活？ * 先安装环境。 * 然后用排除法，把不归我管的（CPU的、超大模型的）剔除，剩下的 GPU 测试统统跑一遍。 * 最后专门用 8 张卡跑一下那个复杂的“交叉熵”测试。
