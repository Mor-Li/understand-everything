.github/workflows/disabled

这是一个非常直观的目录。为了让你快速理解，我们可以把 .github/workflows/ 看作是工厂的 “自动化车间”，而这个 disabled 子目录则是车间里的 “封存仓库”。

以下是具体的通俗解释：

1. 📁 当前文件夹 (.github/workflows/disabled) 主要负责什么？

角色：自动化任务的“冷宫”或“封存仓库”。

  • 功能：GitHub Actions（那个自动化机器人）通常只会在 .github/workflows/ 的根目录下找活干。一旦把配置文件移动到这个 disabled 文件夹里，就相当于给这些任务贴上了 “暂停使用” 的标签。
  • 为什么这么做？：
    • 有些测试太贵了（比如需要8张显卡），不能每次都跑。
    • 有些测试暂时坏了，或者还在开发中，不想让它报错干扰大家。
    • 这是一个“备份”，以防万一以后还要用，先别删，存这儿。

2. 📄 这个文件夹下的直接文件是干什么的？

这里只有一个文件：e2e_prime.yml。

  • 角色：一位正在休假的“重量级大力士”。
  • 具体工作：
    • 它原本的任务是去借一台 8张 L20 显卡 的超级电脑（非常昂贵且强大的资源）。
    • 它的工作是跑 PRIME 算法 的端到端（E2E）测试，做 GSM8K 数学题。
  • 现状：因为它躺在这个 disabled 文件夹里，所以平时它不会自动干活。只有当你把它移出去，或者手动触发特定的分支（disabled_ci）时，这位大力士才会醒过来去干重活。

3. 📁 子文件夹的作用是什么？

(注：在你提供的目录结构中，disabled 目录下没有进一步的子文件夹。如果有的话，它们通常是用来给这些“被封存的任务”分类的。)

4. 🧠 高层认知：如何快速理解这部分代码？

你可以这样理解这个文件夹：

这里面放的都是 “好用但暂时不跑” 的测试计划。

里面的 e2e_prime.yml 是一个 极度消耗资源（8卡）的重型测试。正因为它太“贵”太“重”了，所以默认是关闭状态，被收纳在这个“仓库”里，以免浪费算力资源。只有在极特殊的情况下（比如要发布重大版本，或者专门调试这个算法时），开发人员才会把它“解封”拿出来跑一次。
