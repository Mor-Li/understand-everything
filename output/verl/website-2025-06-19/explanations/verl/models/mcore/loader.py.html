verl/models/mcore/loader.py

这份代码确实比较晦涩，因为它处理的是分布式大模型训练中最麻烦的部分之一：权重加载（Weight Loading）。

简单来说，这个文件的任务是：把一个完整的模型权重文件（通常是 HuggingFace 格式），“切碎”并塞进已经被分布在多张显卡上的 Megatron 模型里。

因为 Megatron-LM 使用了模型并行（Tensor Parallelism, TP）和流水线并行（Pipeline Parallelism, PP），模型不是完整存在一张卡上的，而是像拼图一样散落在不同显卡里。所以不能直接 load_state_dict，必须一边读权重，一边切分，一边分发。

下面我为你列一个 “权重分发大队的工作清单（To-Do List）”，带你一步步看懂在这个代码里发生了什么。

📋 任务清单：从单机权重到分布式模型

第一阶段：准备工作（谁负责什么？）

  1. [定位] 搞清楚当前显卡是谁（Rank几？），属于哪个并行组（TP组？PP组？）。
  2. [制图] 制定一张“藏宝图”（_megatron_calc_layer_map）：计算全局第 N 层 Transformer Layer 到底存放在哪张显卡（Pipeline Rank）的哪个位置。
  3. [拆包] 只有“总指挥”（通常是 Global Rank 0）负责读取完整的权重字典（state_dict），其他显卡等着接收数据，不要重复读硬盘。

第二阶段：核心循环（开始分发）

  1. [分发] Embedding 层：把词向量表切分或广播给对应的显卡。
  2. [分发] Transformer 层（循环 N 次）：
    • LayerNorm：直接广播（大家参数一样）。
    • QKV Attention：这是难点。要把 Q、K、V 的权重矩阵切开（TP切分），分给不同的显卡。
    • MLP (Gate/Up/Down Proj)：同样要把巨大的全连接层矩阵切开分发。
  3. [分发] Final LayerNorm：处理最后一层的归一化参数。
  4. [分发] LM Head / Value Head：处理最后的输出层（生成词的概率或打分）。

第三阶段：收尾

  1. [同步] 确保所有显卡都拿到了属于自己的那部分数据。
  2. [清理] 清空缓存，结束计时。

🔍 详细步骤解析（对应代码逻辑）

现在我们结合代码，逐步拆解上面的清单：

1. 制图：_megatron_calc_layer_map

  • 代码位置：文件开头的函数。
  • 在干嘛：如果你的模型有 32 层，分成了 4 个流水线阶段（PP=4）。那么：
    • GPU 0 负责第 0-7 层。
    • GPU 1 负责第 8-15 层...以此类推。
  • 这个函数就是生成这个映射关系：全局第10层 -> 属于 PP_Rank_1 的第 2 层。

2. 定义分发工具：Helper Functions

在 load_state_dict_to_megatron_gptmodel 内部，定义了几个非常重要的内部函数（闭包），用来处理不同类型的张量：

  • _broadcast_tensor：

    • 场景：处理不需要切分的参数（比如 LayerNorm 的 gamma/beta，或者 Bias）。
    • 动作：Rank 0 拿着数据，大喊一声（dist.broadcast），所有同一组的显卡都把数据抄下来。

  • _broadcast_tp_shard_tensor：

    • 场景：处理普通的线性层（Linear），需要按行或按列切分。
    • 动作：Rank 0 先把大矩阵切成几块（torch.chunk），然后把第 1 块发给 TP Rank 0，第 2 块发给 TP Rank 1...

  • _broadcast_tp_shard_tensor_qkv（最复杂）：

    • 场景：处理 Attention 的 Query, Key, Value 权重。
    • 动作：因为 Q、K、V 通常在权重文件里是拼在一起的，或者是分头（Heads）存储的。这里需要精细地把它们拆开，保证每张卡拿到的 Attention Head 是完整的且正确的。代码里写了一大堆逻辑来处理 num_query_groups 和 hidden_size 的对齐问题。

  • _broadcast_tp_shard_tensor_gate_up：

    • 场景：处理 LLaMA/Mistral 架构中的 MLP 层（Gate proj 和 Up proj 通常是合并计算的）。
    • 动作：把 Gate 和 Up 权重拼接后再切分，分发给各张卡。

3. 执行分发循环（主逻辑）

代码从 if dp_rank == 0: 开始进入正题：

  • 加载 Embeddings： 调用 _broadcast_tp_shard_tensor_vocab。因为词表很大（比如 32000 或 100000+），一张卡存不下，所以每张卡只存一部分词向量。

  • 加载 Transformer Layers (For Loop)： 代码遍历 range(config.num_hidden_layers)。

    • 利用第一步做的“地图”，判断当前这层是不是归我管 (if dst_pp_rank == pp_rank)。
    • 如果归我管，就等着接收数据；如果不归我管，就跳过（但因为是广播机制，实际上是在通信组里配合占位）。
    • 依次加载：
      1. input_layernorm
      2. self_attn (Q, K, V, O) -> 用到 QKV 切分函数
      3. post_attention_layernorm
      4. mlp (Gate, Up, Down) -> 用到 Gate/Up 切分函数

  • 加载 LM Head (输出层)：

    • 如果是 Value Model（比如 PPO 里的 Critic 模型），输出通常是一个标量（维度为1），逻辑稍微不同，代码里有专门的 if is_value_model: 判断。
    • 如果是普通生成模型，则按 TP 切分加载。

4. 最后的同步

  • dist.barrier()：大家停下来报数，确保没有人掉队。
  • broadcast_params(wrapped_model)：这步是为了处理 Data Parallel (DP)。
    • 刚才的过程主要是在处理 TP 和 PP（把模型切碎）。
    • 如果还有 DP（比如有 8 张卡，4 张卡存一个模型副本，另外 4 张卡存一模一样的另一个副本），那么刚才只加载了第一个副本。
    • 这一步把加载好的权重，从第一个副本直接复制到所有其他的 DP 副本中。

总结

这篇文章的观点（或者说核心逻辑）是：

不要让每张显卡都去读硬盘上的权重文件（太慢且显存会爆）。让 Rank 0 读入内存，然后像“切蛋糕”分给孩子们一样，根据每个人在模型并行组里的位置，精准地把属于它的那一片权重“投喂”过去。
