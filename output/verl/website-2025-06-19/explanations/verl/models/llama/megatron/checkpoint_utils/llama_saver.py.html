verl/models/llama/megatron/checkpoint_utils/llama_saver.py

这份代码确实比较硬核，因为它涉及到深度学习分布式训练中最复杂的底层逻辑：如何把分散在几十甚至几百张显卡上的“碎片化”模型参数，重新拼凑成一个完整的模型文件。

为了让你看懂，我们可以把这个过程想象成“拼图回收任务”。

核心背景：为什么要写这个文件？

在使用 Megatron-LM 训练大模型（如 Llama）时，为了放下巨大的模型，我们使用了两种切分技术： 1. TP (Tensor Parallel - 张量并行)：把一个大的矩阵（比如 $4096 \times 4096$）切成几块，分给不同的显卡算。 2. PP (Pipeline Parallel - 流水线并行)：把模型的层（比如一共 32 层）切分，显卡 A 存 0-7 层，显卡 B 存 8-15 层...

这个脚本 (llama_saver.py) 的作用是： 训练结束或保存时，由主进程（Rank 0）充当“组长”，指挥所有显卡把各自手里的“碎片”交上来，组长负责把它们拼回原本完整的形状，最后生成一个可以在单卡上加载的 HuggingFace 格式权重字典 (state_dict)。

任务清单 (Todo List)

为了看懂代码，我们可以把这个脚本的工作流程拆解为以下几个步骤：

  1. 准备工作：确认显卡排位，解包模型。
  2. 定义工具：制造“抓取工具”，用来从其他显卡把数据抓到主进程。
  3. 收集 Embedding 层：拼凑词表向量。
  4. 循环收集 Transformer 层 (核心)：
    • 找到每一层到底在哪张显卡上。
    • 拼凑 Attention 部分 (Q, K, V, Output)。
    • 拼凑 MLP 部分 (Gate, Up, Down)。
    • 拼凑 LayerNorm。
  5. 收集输出层：拼凑最后的 LM Head。
  6. 收尾：转换数据类型，清理显存。

逐步代码讲解

1. 准备工作 (Setup)

代码开头的一大段逻辑（merge_megatron_ckpt_llama 函数的前半部分）都是在做身份确认。

  • 你需要知道：mpu.get_... 这些函数是在问当前显卡：“我是谁？我在哪？”
  • 解包模型：unwrap_model 是为了剥离掉 PyTorch DDP 的外壳，拿到最原始的模型对象。

2. 定义工具 (Helper Functions)

这是代码里最难懂但最重要的部分，定义了三个内部函数（闭包），专门用来“隔空取物”。

  • 工具 A: _broadcast_tensor (简单搬运)

    • 场景：LayerNorm 的参数没有被切分（TP不切 Norm），只是可能不在主进程手里（因为 PP）。
    • 逻辑：如果东西在显卡 A，显卡 A 就把它广播出来，主进程（Rank 0）接收并存起来。

  • 工具 B: _broadcast_tp_shard_tensor (拼凑切片)

    • 场景：比如 MLP 的 down_proj 矩阵被横着切成了两半。
    • 逻辑：
      1. 主进程创建一个空的“大桶”（buffer）。
      2. 循环遍历所有持有切片的显卡。
      3. 每张卡把自己那部分发过来。
      4. 主进程用 torch.concat 把它们粘起来，还原成大矩阵。

  • 工具 C: _broadcast_tp_shard_tensor_qkv / gate_up (复杂拼凑)

    • 场景：Megatron 为了加速，把 Q、K、V 三个矩阵合并成了一个大矩阵存着。但是 HuggingFace 的格式要求 Q、K、V 分开存。
    • 逻辑：
      1. 先把分散在各卡上的大矩阵拼回来。
      2. 切蛋糕：在主进程里，按照 hidden size 把大矩阵切几刀，分离出 Q、K、V。
      3. 分别存入字典。

3. 收集 Embedding 层

    if dp_rank == 0:
        # ...
        _broadcast_tp_shard_tensor(
            gpt_model_module.model.embed_tokens.weight if pp_rank == 0 else None,
            "model.embed_tokens.weight",
            src_pp_rank=0, # Embedding 层一定在流水线的第一张卡(Rank 0)上
        )
  • 解释：Embedding 矩阵通常很大，是被 TP 切分的。这里调用工具 B，从流水线的第一阶段（src_pp_rank=0）把切片收集回来拼好。

4. 循环收集 Transformer 层 (核心循环)

这是代码中最长的 for layer in range(config.num_hidden_layers): 循环。

  • 第一步：定位 (Where is it?) python layer_map = _megatron_calc_layer_map(config) # ... src_pp_rank, src_virtual_pp_rank, src_layer_idx = layer_map[layer] 因为用了 PP（流水线并行），第 30 层可能不在本地，而是在第 4 张显卡上。这个 layer_map 就是一张地图，告诉程序去哪张卡找第 N 层的数据。

  • 第二步：收集 Attention (Q, K, V) python _broadcast_tp_shard_tensor_qkv( sync_layer.self_attn.qkv_proj.weight, f"{layer_name}.self_attn.q_proj.weight", # 目标名字 Q f"{layer_name}.self_attn.k_proj.weight", # 目标名字 K f"{layer_name}.self_attn.v_proj.weight", # 目标名字 V src_pp_rank=src_pp_rank, ) 这里用了工具 C。Megatron 存的是 qkv_proj，我们要把它还原并拆解成 HF 格式的 q_proj, k_proj, v_proj。

  • 第三步：收集 MLP (Gate, Up) Llama 的 MLP 比较特殊，有一个 SwiGLU 结构，包含 Gate 和 Up 两个投影层。Megatron 也是把它们拼在一起存的。 python _broadcast_tp_shard_tensor_gate_up( sync_layer.mlp.gate_up_proj.weight, f"{layer_name}.mlp.gate_proj.weight", f"{layer_name}.mlp.up_proj.weight", src_pp_rank=src_pp_rank, ) 同样是把拼在一起的权重拉回来，拆成 gate_proj 和 up_proj。

  • 第四步：收集其他简单层 对于 input_layernorm、post_attention_layernorm 等，直接用工具 A (_broadcast_tensor) 拿回来即可，不需要拼接。

5. 收集 Final Norm 和 LM Head

    # Final Layernorm
    _broadcast_tensor(..., src_pp_rank=pp_size - 1) # 最后一层 Norm 肯定在流水线的最后一张卡

    # LM Head (输出层)
    _broadcast_tp_shard_tensor(..., src_pp_rank=pp_size - 1)
  • 解释：模型的最后几层（归一化层和预测词的 Head 层）肯定位于流水线的末端（pp_size - 1）。Head 层也是大矩阵，需要拼凑（TP Shard）。

6. 收尾 (Finalize)

    if torch.distributed.get_rank() == 0:
        # ...
        for k, v in state_dict.items():
            if dtype != v.dtype:
                state_dict[k] = v.to(dtype)
    return state_dict
  • 解释：所有拼图都完成了，存在 state_dict 字典里。最后确认一下数据类型（比如转成 float16 或 bfloat16），然后把这个巨大的字典返回。外部程序拿到这个字典后，就可以直接 torch.save() 保存成 .bin 或 .safetensors 文件了。

总结

这段代码看起来乱，是因为它在处理 “分布式存储”到“单机存储”的映射。

  • Megatron 里的样子：权重被横切、竖切（TP），还被按层分发到不同机器（PP），而且为了计算快，把 QKV、GateUp 这种矩阵都粘在一起了。
  • 我们想要的样子 (HuggingFace)：完整的矩阵，每一层都在一起，Q/K/V 是独立的 key。

这个脚本就是负责做这个繁琐的搬运和拆解工作的苦力。
