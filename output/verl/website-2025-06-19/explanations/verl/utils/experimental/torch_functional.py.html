verl/utils/experimental/torch_functional.py

这份代码的核心目的是为了省显存。

在训练大语言模型（LLM）进行强化学习（PPO算法）时，通常需要计算两个东西：Token的对数概率（Log Probs） 和 熵（Entropy）。

如果按照常规做法，需要把所有 hidden_states（隐藏层状态）乘以 vocab_weights（词表权重），生成一个巨大的 [Batch, Sequence_Length, Vocab_Size] 的张量（Logits）。对于 7B 以上的模型，词表通常很大（比如 32k 或 128k），这个中间结果会瞬间撑爆显存。

这份代码通过手动实现反向传播和切片（Chunking）计算，避免了显存爆炸。

下面我列一个 Task List（任务清单），带你一步步看懂它是怎么完成这个目标的：

Task 1: 定义基本数学运算（Forward - 前向传播）

目标：计算 PPO 需要的两个数值：token_log_probs（你选的那个词的概率）和 entropy（当前分布的混乱程度）。 对应函数：_fused_linear_for_ppo_fwd

  1. 算 Logits：用 hidden_states 乘以 vocab_weights，算出下一个词的预测分数。
  2. 转概率：计算 Softmax 和 Log Softmax。
  3. 提取目标概率：用 gather 函数，只把 input_ids 对应的那个词的概率拿出来（其他的几万个词的概率这里不需要存下来）。
  4. 算熵：计算当前概率分布的熵（用于 PPO 的正则化，防止模型过早收敛）。
  5. 返回：只返回 token_log_probs 和 entropy，丢弃巨大的 Logits 以节省空间。

Task 2: 手写梯度计算（Backward - 反向传播）

目标：因为我们为了省显存，没有保留前向传播时的计算图，所以必须手动推导公式来计算梯度。 对应函数：_fused_linear_for_ppo_bwd

  1. 重算 Logits：因为前向传播没存 Logits，这里利用保存下来的输入（hidden_states）重新计算一遍 Logits（用时间换空间）。
  2. 算梯度来源 1（dlog_probs）：如果 PPO 损失函数传回了对数概率的梯度，根据公式计算它对 Logits 的梯度贡献。
  3. 算梯度来源 2（dentropy）：如果损失函数传回了熵的梯度，根据熵的导数公式计算它对 Logits 的梯度贡献。
  4. 链式法则：把 Logits 的梯度传回给 hidden_states 和 vocab_weights。

Task 3: 显存优化的大管家（Chunking - 切片处理）

目标：把长序列切成小块，一块一块地算，永远不把完整的“大矩阵”放进显存。 对应类：FusedLinearForPPOFunction (继承自 torch.autograd.Function)

Step 3.1: 前向传播 (forward 静态方法) 1. 准备空容器：申请两块较小的内存，用来存最终结果（log_probs 和 entropy）。 2. 切片循环 (Chunking Loop)： * 比如序列长度是 4096，设定 chunk_size=512。 * Loop 1: 取第 0-512 个 token，调用 Task 1 的函数计算，把结果填入容器。 * Loop 2: 取第 512-1024 个 token，计算，填入... * ...直到算完。 3. 保存现场：保存 hidden_states 和 input_ids 等原始输入（供反向传播用），但不保存中间巨大的 Logits。

Step 3.2: 反向传播 (backward 静态方法) 1. 准备空梯度：给 hidden_states 和 vocab_weights 申请全零的梯度张量。 2. 切片循环 (Chunking Loop)： * 同样把梯度切成小块（0-512, 512-1024...）。 * Loop: 取出一小块对应的输入和上层传来的梯度，调用 Task 2 的函数计算这一小块的梯度。 * 累加：把算出来的梯度加到总梯度张量上。 3. 返回梯度：把最终算好的梯度返回给 PyTorch 引擎。

Task 4: 包装成积木（Module Wrapper）

目标：让这个复杂的优化代码看起来像一个普通的 PyTorch 层，方便在模型里调用。 对应类：FusedLinearForPPO (继承自 torch.nn.Module)

  1. 初始化：设置 chunk_size（比如一次算多少个token）。
  2. Forward 接口：把输入数据整理一下（比如把 input_ids 转成 int64），然后直接调用 Task 3 写好的那个 Function。

总结：为什么要写这个文件？

如果不写这个文件，直接用 PyTorch 原生的 F.linear + F.cross_entropy： * 显存占用：极大。因为 PyTorch 会自动保存整个 [Batch, Seq, Vocab] 的 Logits 图用于求导。 * 结果：OOM (Out Of Memory) 错误。

用了这个文件： * 显存占用：极小。显存占用只取决于 chunk_size（切片大小），与序列总长度无关。 * 代价：计算速度稍微慢一点点（因为反向传播时重算了一次 Logits），但能让你训练本来跑不起来的大模型。
