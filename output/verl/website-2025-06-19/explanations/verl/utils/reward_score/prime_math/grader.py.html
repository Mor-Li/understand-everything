verl/utils/reward_score/prime_math/grader.py

这段代码其实就是一个“极其严格且智能的数学阅卷老师”。

它的核心任务只有一个：判断“模型生成的答案（Prediction）”和“标准答案（Reference）”在数学上是否相等。

因为数学表达很灵活（比如 $\frac{1}{2}$ 和 $0.5$ 是一样的，$\pi$ 和 $3.14159...$ 是一样的，或者 $x+y$ 和 $y+x$ 是一样的），所以不能只看字面一不一样，必须看数学含义。

为了让你看懂，我把这个阅卷老师大脑里的工作流程（Workflow）拆解成了一个 Todo List。程序运行时，就是按照这个清单一步步往下查，只要有一步通过，就算你对。

📝 阅卷老师的任务清单 (Todo List)

✅ Task 1: 考卷预处理 (清洗数据)

目标： 把答案里的杂质去掉，统一格式，方便后续比对。 * 动作 1 (去符号): 如果答案里有 $ (美元符) 或者 % (百分号)，把它们删掉。 * 动作 2 (处理进制): 如果看到下划线（比如 10_2 表示二进制），把它转成十进制整数。 * 动作 3 (召唤圆周率): 如果看到 LaTeX 格式的 \pi，把它替换成具体的数字 3.14159... 或者代码里的 math.pi。 * 函数对应： normalize(), handle_base(), handle_pi()

✅ Task 2: 一眼定真假 (字符串比对)

目标： 如果两人写的一模一样，直接给分，不用动脑子算。 * 动作 1: 忽略大小写，忽略首尾空格。如果 prediction == reference，判定为：对。 * 动作 2: 把所有空格都删了再比一次。如果不考虑空格也一样，判定为：对。

✅ Task 3: 按计算器 (数值比对)

目标： 解决 $\frac{1}{2}$ vs $0.5$ 这种问题。 * 动作 1: 尝试把两个答案都转换成浮点数（Float）。 * 动作 2: 考虑到百分数的问题，老师会把标准答案 x，以及 x/100 和 x*100 都算一下。 * 动作 3: 只要两个数字足够接近（误差在 1e-4 以内），判定为：对。 * 函数对应： is_digit(), math.isclose()

✅ Task 4: 检查“容器” (列表、区间、矩阵)

目标： 解决答案是一组数的情况，比如 [1, 2] 或者 (3, 5]。 * 动作 1 (处理括号): 识别圆括号 ()、方括号 []、花括号 {}。如果是集合或列表，去掉括号看里面的内容。 * 动作 2 (处理区间): 专门识别 Interval.open(a, b) 这种写法，把它转成数学上的 (a, b)。 * 动作 3 (逐个比对): 如果两边都是列表（比如逗号分隔的数字），那就把列表拆开，递归地去比较里面的每一个数字。如果每个都对，判定为：对。 * 动作 4 (处理矩阵): 识别 LaTeX 的矩阵格式 \begin{pmatrix}...，解析成行和列，逐个元素比对。 * 函数对应： format_intervals(), math_equal 内部的递归调用

✅ Task 5: 请出“数学教授” (符号推导)

目标： 解决最难的情况，比如代数式 $2x$ vs $x+x$，或者复杂的 LaTeX 公式。 * 动作 1 (解析): 使用 Python 的数学库 SymPy，把字符串解析成数学表达式对象。 * 动作 2 (化简求差): 计算 Simplify(学生答案 - 标准答案)。如果结果等于 0，说明数学上完全等价。判定为：对。 * 动作 3 (数值估算): 如果化简太难，就试着把变量代入数值算一下结果（N()），如果结果数值非常接近，判定为：对。 * 限制: 为了防止死机，这步操作有“超时限制”（timeout），算太久就算了。 * 函数对应： symbolic_equal()

总结

这代码就是个层层递进的过滤器： 1. 先看字面一样吗？ 2. 再看数值一样吗？ 3. 再看列表/结构一样吗？ 4. 最后用高数库算一下逻辑上一样吗？

如果以上所有 Task 都走完了还没通过，那就判定为：错 (False)。
