verl/utils/reward_score/sandbox_fusion/utils.py

这份代码的核心功能是一个“远程代码判题器”（Code Grader）。

简单来说，它的作用是：把AI写的代码，连同测试题目（输入/输出），发送到一个安全的沙盒环境中运行，然后检查代码对不对。

为了让你听懂，我把这个文件的逻辑拆解成一个“监考老师的任务清单 (To-Do List)”。想象你自己就是这个程序，你要完成以下步骤才能批改完一份试卷。

任务清单 (To-Do List)

第一步：准备“打电话”的工具 (通信基础)

对应函数： call_sandbox_api * 背景： 你的电脑不能直接运行不安全的代码，必须送到远程服务器（沙盒）去跑。 * 任务： 1. 把代码（Code）、输入数据（Stdin）、编程语言（Language）打包成一个数据包。 2. 发送请求： 尝试把包发给远程服务器。 3. 重试机制 (Retry Logic)： 如果网络不好（比如服务器报 504 超时），不要马上放弃。 * 先等 1 秒，再试一次。 * 还不行？等 2 秒，再试。 * 最多试 3 次（MAX_RETRIES）。 4. 结果： 要么拿到服务器返回的运行结果（JSON），要么报错说“打不通”。

第二步：给代码“穿外套” (代码预处理)

对应函数： _process_single_case 中的 wrapper_code 部分 * 背景： AI 写代码通常只写一个函数，比如 def solution(a, b): return a+b。但是沙盒环境通常是运行一个完整的脚本，需要读取输入并打印输出。 * 任务： 如果是 Python 代码，你需要在 AI 的代码外面套一层“壳”： 1. 引入库： 自动加上 import json, import math 等常用库，防止 AI 忘了写。 2. 处理输入： 写一段代码从系统标准输入（sys.stdin）读取测试数据。 3. 调用函数： 找到 AI 写的那个函数（或者 Solution 类），把数据传进去。 4. 处理输出： 把函数的返回值转换成 JSON 格式打印出来（print），这样沙盒才能捕获到答案。

第三步：批改“单道”题目 (单例判题)

对应函数： _process_single_case * 背景： 一次考试有很多道题（Test Cases）。这里只负责批改其中一道。 * 任务： 1. 抢资源 (Semaphore)： 如果并发太高，先排队，拿到令牌（信号量）再执行。 2. 调用第一步的工具： 把包装好的代码发给沙盒运行。 3. 分析成绩： 拿到沙盒的返回结果后，进行判断： * 编译错误 (Compile Error)： 代码语法不对，直接给 -4 分。 * 超时 (Timeout)： 跑太久了，给 -3 分。 * 运行报错 (Runtime Error)： 比如除以零、数组越界，给 -2 分。 * 系统错误 (API Error)： 沙盒坏了，给 -1 分。 * 运行成功 (Success)： 拿出沙盒跑出来的结果，跟“标准答案”对比。 * 一样 -> True (通过) * 不一样 -> False (答案错误)

第四步：组织“全场考试” (并发管理)

对应函数： check_correctness (这是主入口) * 背景： 给了一段代码和 10 组测试输入/输出。不能一道一道测，太慢了。 * 任务： 1. 检查试卷： 确认输入和输出的数量是不是对等的。 2. 招聘阅卷组 (ThreadPoolExecutor)： 开启多线程（默认最多 32 个线程或 CPU 核心数的 5 倍）。 3. 并发分发： 把每一组输入/输出都丢给第三步去处理，让它们同时跑。 4. 收集结果： 等所有题目都改完，把结果存到一个列表里 results。

第五步：处理“没必要考了”的情况 (错误剪枝)

对应函数： check_correctness 的后半部分 * 观点： 如果第一道题就编译报错（语法错误），那剩下的题肯定也都跑不起来，测了也是浪费时间。 * 任务： 1. 检查结果列表。 2. 一旦发现有 -4 (编译错误)。 3. 把这个错误之后的所有题目状态全部强行改成 -4，并在元数据里标记为 compile_error_skipped（因编译错误跳过）。

总结：这个文件到底输出了什么？

当你调用 check_correctness 时，它会返回两个列表：

  1. results (分数条):

    • True: 答案正确。
    • False: 答案错误。
    • -1: 沙盒挂了。
    • -2: 代码运行报错 (Runtime Error)。
    • -3: 代码超时 (Timeout)。
    • -4: 代码写错了，编译不过 (Compile Error)。

  2. metadata_list (详细报告):

    • 包含了每一道题的具体运行时间、报错信息、标准输出内容等，用于调试。

一句话总结： 这是一个带有多线程并发、自动重试、Python代码自动封装功能的远程判题客户端。
