verl/utils/reward_score/math_dapo.py

这份代码的核心功能可以理解为一位“数学阅卷老师”。它的工作是：拿着“标准答案（Ground Truth）”去批改模型生成的“解答（Solution）”，最后给出一个分数（对给 1 分，错给 -1 分）。

为了让你容易理解，我把这个代码的执行逻辑拆解成一张“阅卷工作流 To-Do List”。代码运行时，就像在按顺序执行下面这些任务：

📝 阅卷工作流 To-Do List

Task 1: 准备工作 (入口函数 compute_score)

  • 任务描述：拿到学生的考卷（solution_str）和标准答案（ground_truth）。
  • 动作：
    1. 为了提高效率，防止学生废话太多，只截取考卷的最后 300 个字符（因为答案通常在最后）。
    2. 确定阅卷模式：是“严格按格式判卷”还是“智能提取判卷”？
    3. 把任务派发给下一步的验证员（verify 函数）。

Task 2: 选择判卷策略 (分流函数 verify)

  • 任务描述：根据设置，决定用哪种方式找答案。
  • 分支 A（严格模式 strict_box_verify）：
    • 要求学生必须把最终答案写在 LaTeX 的方框里，比如 \boxed{123}。如果没有框或者框里不对，直接算错。
  • 分支 B（通用/Minerva模式 is_correct_minerva）：
    • 比较灵活，会尝试去理解学生的回答，通常寻找 "Answer:" 这样的关键词。

Task 3: 提取答案 (核心提取逻辑)

  • 如果是严格模式 (last_boxed_only_string)：
    • 动作：在文本里从后往前找 \boxed{...}。
    • 细节：它需要通过数花括号 { 和 } 的数量来确保完整提取出框里的内容，去掉外面的框，只留内容。
  • 如果是通用模式：
    • 动作：用正则表达式找 "Answer:" 后面的内容。

Task 4: 答案“清洗”与标准化 (最关键的一步 normalize_final_answer)

  • 任务描述：学生写的答案格式五花八门，必须把它们统一成标准格式才能对比。
  • 清洗清单（按代码逻辑）：
    1. 去废话：如果是 x = 5，只保留等号后面的 5。
    2. 去修饰词：把 "approx"（大约）、"dollars"（美元）、"degrees"（度）等单位统统删掉。只比数字/核心表达式。
    3. 统一 LaTeX 写法：
      • 把 \text{and} 变成逗号。
      • 把简写的 \fracab 变成标准的 \frac{a}{b}。
      • 把 \sqrt2 变成 \sqrt{2}。
    4. 去标点：去掉千分位逗号（如 1,000 变成 1000），去掉结尾的句号。
    5. 去空格：把所有空格删掉，防止因为多敲一个空格导致判错。

Task 5: 最终比对 (判决时刻)

  • 任务描述：拿着清洗过的“学生答案”和清洗过的“标准答案”进行对比。
  • 动作：
    • 如果是字符串完全相等 (pred == gt)，判定为 True。
    • 否则判定为 False。

Task 6: 打分并归档 (返回结果)

  • 任务描述：生成最终的成绩单。
  • 动作：
    • 如果 Task 5 是 True，分数设为 1.0。
    • 如果 Task 5 是 False，分数设为 -1.0。
    • Return：打包返回 {分数, 是否正确, 提取出的答案内容}。

总结一下文中的核心观点（逻辑）：

  1. 数学答案只看核心值：代码花了大量篇幅在 normalize_final_answer 上，观点是：数学题里，"5 meters"、"5 m"、"x=5"、"Answer: 5" 本质上都是同一个答案 5。必须把单位、文字说明全部剥离，才能进行公平的自动化评分。
  2. LaTeX 格式必须统一：因为数学公式写法不唯一（比如分数和根号的写法），代码必须强制把不规范的写法转换成标准写法，否则模型算对了但写丑了会被误判。
  3. 倒序查找原则：代码假设最终答案一定出现在生成的文本段落的最后面（无论是找 \boxed 还是截取后300字），这是基于大模型通常遵循“推理过程 -> 最终结论”的输出习惯。

简单一句话： 这个文件就是一个强迫症阅卷老师，先把你的答案里的单位、废话、格式差异通通擦掉，只留下最纯粹的数字或公式，然后和标准答案比对，对就是 1 分，错就是 -1 分。
