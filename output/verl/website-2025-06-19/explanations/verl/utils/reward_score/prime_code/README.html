verl/utils/reward_score/prime_code

这是一个专门用于评估 AI 写代码能力的“全自动阅卷系统”。

简单来说，当 AI 生成了一段 Python 代码来解决某个编程问题时，这个文件夹里的代码负责运行这段代码，并根据它能不能跑通、答案对不对，给出一个分数（Reward）。

为了让你秒懂，我们可以把这个文件夹看作是一个“严密的编程考场”。

1. 📂 核心功能：全自动编程阅卷

verl/utils/reward_score/prime_code/

这个文件夹就是“考场控制中心”。它的核心任务是： 1. 拿到 AI 写的代码（试卷）。 2. 拿到对应的测试用例（标准答案）。 3. 安全地运行代码（防止 AI 写死循环把服务器跑崩）。 4. 对比输出结果，算出得分（是 0 分、1 分，还是 0.7 分）。

2. 📄 文件分工详解

这三个文件就像考场里的三个核心角色，配合非常默契：

1. 👨‍🏫 阅卷组长：__init__.py

  • 角色：总指挥 / 阅卷组长。
  • 他在干嘛：
    • 他是对外的接口。外部系统只跟他打交道，把代码给他。
    • 他负责清洗卷面（提取纯代码）。
    • 他制定评分策略：是“一票否决”（错一个就 0 分），还是“按步骤给分”（对几个测试点给几分）。
    • 他指挥下面的保安和机器去干活，最后汇总出一个总分交上去。

2. 👮 考场保安：utils.py

  • 角色：安全隔离员 / 计时员。
  • 他在干嘛：
    • 负责安全：因为 AI 生成的代码可能包含病毒、死循环或者恶意指令，不能直接在主程序里跑。
    • 关小黑屋：他会开辟一个独立的进程（Process），像把考生关进一个独立的“防爆玻璃房”里去考试。
    • 掐表：如果代码运行超过规定时间（比如 10 秒），他会直接把“小黑屋”强制销毁（Kill Process），判定为超时。
    • 防爆：确保就算代码炸了，也只炸小黑屋，不影响外面的主系统。

3. 🤖 判题机器：testing_util.py

  • 角色：具体的执行引擎 / 阅卷机。
  • 他在干嘛：
    • 他是被保安关在“小黑屋”里真正干活的那个。
    • 伪造环境：他负责欺骗代码，把测试用例塞进 input()，并截获 print() 的输出。
    • 模糊匹配：这是最难的地方。他负责对比“学生答案”和“标准答案”。因为编程题的输出格式千奇百怪（比如 1.0 和 1，或者列表 [1,2] 和元组 (1,2)），他需要用复杂的逻辑去判断“这俩算不算相等”。

3. 🚀 高层认知总结

你可以这样理解这一套代码的运作流程：

  1. __init__.py (组长) 接到任务，把代码和题目交给 utils.py (保安)。
  2. utils.py (保安) 创建一个安全的独立房间，把 testing_util.py (阅卷机) 和代码扔进去，并开始倒计时。
  3. testing_util.py (阅卷机) 在房间里疯狂跑代码，对比答案，把结果写在纸条上。
  4. 时间到，utils.py (保安) 把房间销毁，把纸条捡回来交给 __init__.py (组长)。
  5. __init__.py (组长) 算出最终得分。

一句话总结： 这是一个带防爆盾（多进程安全隔离）、懂变通（模糊答案匹配）的Python 代码自动化评分组件。
