recipe/spin/run_spin.sh

这份文件其实就像是一个“装修工程的施工单”或者“大厨的菜谱”。

它是一段 Shell 脚本（.sh），唯一的目的就是启动一个 AI 模型的训练任务。因为训练 AI 需要设置非常多的参数（用哪张显卡、用什么数据、模型多大、学多快），所以把这些参数都写在一个文件里，方便管理。

这个特定的任务使用的是一种叫 SPIN (Self-Play Fine-Tuning) 的技术，你可以把它理解为“左右互搏”或者“自我博弈”，让模型自己生成数据来提升自己。

为了让你看懂，我们将这个“施工单”拆解成 5 个具体的 Task（任务），一步步带你读懂它。

Task 1: 准备工作环境 (硬件与调试)

代码对应：

set -e
set -x
VISIBLE_DEVICES="4,5,6,7"
export HYDRA_FULL_ERROR=1
CUDA_VISIBLE_DEVICES=${VISIBLE_DEVICES} ...

解读： * 动作： 这一步是在告诉电脑：“如果出错了就立刻停下（-e），并且把每一步执行的命令都打印出来给我看（-x）。” * 硬件： 指定了这次训练要用的 显卡（GPU）。 * VISIBLE_DEVICES="4,5,6,7" 意思是我们只用服务器上的第 4、5、6、7 号这四张显卡。 * 目的： 圈定干活的“场地”和“工具”。

Task 2: 确认教材 (数据准备)

代码对应：

  data.train_files=$HOME/data/gsm8k/train.parquet \
  data.val_files=$HOME/data/gsm8k/test.parquet \
  data.train_batch_size=1024 \
  data.max_prompt_length=1024 \
  data.max_response_length=1024 \

解读： * 教材内容： 这里出现了 gsm8k。GSM8K 是一个非常著名的小学数学应用题数据集。 * 这意味着：我们这次训练的目的是让 AI 更擅长做数学题和逻辑推理。 * 阅读方式： * batch_size=1024：一次性打包 1024 道题给模型看（批量学习）。 * length=1024：限制题目和答案的最大长度，太长了截断，防止显存爆掉。 * 目的： 告诉模型今天要学什么课本。

Task 3: 选定“学生” (模型选择)

代码对应：

  actor_rollout_ref.model.path=Qwen/Qwen2.5-0.5B-Instruct \

解读： * 学生是谁： Qwen/Qwen2.5-0.5B-Instruct。 * 这是阿里通义千问（Qwen）系列的 2.5 版本。 * 0.5B 代表它是一个很小的模型（只有 5 亿参数），通常用于测试代码能不能跑通，或者做轻量级实验。 * 目的： 确定我们要训练的基础底座是哪一个模型。

Task 4: 制定训练方法 (SPIN 算法的核心配置)

这是最复杂但也最核心的部分。SPIN 算法需要模型扮演三个角色，所以你会看到 actor_rollout_ref 这种前缀。

代码对应：

  actor_rollout_ref.actor.optim.lr=1e-6 \
  actor_rollout_ref.actor.ppo_mini_batch_size=64 \
  actor_rollout_ref.rollout.tensor_model_parallel_size=1 \
  algorithm.kl_ctrl.kl_coef=0.001 \

解读（通俗版）： 在 SPIN（自我博弈）训练中，模型分裂成了三个分身： 1. Actor (演员/学生)： 正在被修改参数、正在学习的那个模型。 * lr=1e-6：学习率。意思是每次修改参数只改一点点，像“微雕”一样，防止改坏了。 2. Rollout (探索者)： 负责做题的模型。它用当前的智商去生成答案，产生数据。 3. Ref (Reference/参照系)： 老师/旧模型。它是训练开始前的原始模型，用来做对比。 * kl_coef=0.001：这是一个“惩罚项”。意思是：学生（Actor）虽然要创新，但不能偏离老师（Ref）太远，不能胡言乱语。

目的： 配置 SPIN 算法的内部齿轮，让模型通过“自己生成答案”->“自我对比”来进化。

Task 5: 安排课程表 (训练流程控制)

代码对应：

  trainer.n_gpus_per_node=4 \
  trainer.save_freq=-1 \
  trainer.test_freq=1 \
  trainer.total_epochs=1000 2>&1 | tee verl_demo.log

解读： * 资源分配： n_gpus_per_node=4，确认使用 4 张卡并行训练。 * 考试频率： test_freq=1，每训练一轮就测试一次，看看效果。 * 存盘频率： save_freq=-1，通常表示不频繁保存中间结果，或者只保存最后的结果（节省硬盘）。 * 学期长度： total_epochs=1000，总共要学 1000 个学期（这个数字设得很大，通常中间会手动停，或者有早停机制）。 * 写日记： | tee verl_demo.log，把屏幕上显示的所有训练进度文字，同时保存到一个叫 verl_demo.log 的文件里，方便以后查错。

总结：这个脚本在干嘛？

如果用一句话概括：

“嘿电脑，用 4 张显卡，加载 Qwen-0.5B 这个小模型，让它反复做 GSM8K 的数学题。用 SPIN 自我博弈的方法，让它自己跟自己学，每一步都记录在日志里。”

你现在只需要运行这个脚本，机器就会开始嗡嗡转，屏幕上会开始疯狂跳动数字（Loss值），模型就开始变聪明了。
