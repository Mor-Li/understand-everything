recipe/sppo/dp_actor.py

这份代码实现的是 SPPO (Self-Play Preference Optimization) 算法中的 Actor（策略模型） 更新逻辑。

简单来说，这段代码的任务就是：拿着数据（提示词、模型生成的回答、奖励分数），去调整模型参数，让模型生成的回答的概率变化趋势，尽可能逼近奖励分数所指示的方向。

为了让你听懂，我把这段代码拆解成一个 “训练大模型的 Todo List”，我们按照这个清单一步步看它是怎么工作的。

核心任务清单 (Todo List)

✅ Task 1: 定义“我们要优化的目标是什么？” (核心数学公式)

对应代码函数： compute_sppo_loss

这是整个文件的灵魂。SPPO 和传统的 PPO 不一样，它把强化学习问题转化为了一个回归问题。

  • 步骤 1.1：计算“观点变化量” (log_ratios)
    • 代码：log_ratios = log_prob_sum - old_log_prob_sum
    • 解释： 模型现在的参数（log_prob）对这个回答的信心，减去模型之前的参数（old_log_prob）对这个回答的信心。这代表模型更新后，对这个回答的偏好增加了多少。
  • 步骤 1.2：计算“目标变化量” (scaled_rewards)
    • 代码：scaled_rewards = eta * (rewards)
    • 解释： 这个回答实际得了多少分（Reward）。这就好比老师给的标准答案：如果分高，模型就应该大幅增加对这个回答的信心。
  • 步骤 1.3：计算“差距”并尝试缩小它 (Loss)
    • 代码：loss_vec = (log_ratios - scaled_rewards) ** 2
    • 解释： 这是一个 均方误差 (MSE)。
    • 核心观点： SPPO 认为，模型对某个回答的信心增量（Log Ratio），应该等于它获得的奖励（Reward）。如果奖励很高，模型就该大大增加生成这句话的概率；如果奖励很低（甚至是负的），模型就该保持不变甚至降低概率。代码就是在最小化这两者之间的差距。

✅ Task 2: 准备训练流水线 (Actor 类初始化)

对应代码类： DataParallelSPPOActor -> update_policy 方法开头

  • 步骤 2.1：开启训练模式
    • 代码：self.actor_module.train()
    • 解释： 告诉 PyTorch，我们要开始更新参数了。
  • 步骤 2.2：整理数据包
    • 代码：batch = data.select(...)
    • 解释： 从一大堆数据里挑出我们需要的东西：
      • input_ids: 问题是什么。
      • responses: 模型回答了什么。
      • old_log_probs: 之前模型生成这句话的概率是多少（用于 Task 1.1）。
      • seq_level_rewards: 这个回答得了几分（用于 Task 1.2）。

✅ Task 3: 切分数据 (Batching)

对应代码： dataloader = ... 和 micro_batches = ...

  • 步骤 3.1：大块切小块 (Mini-batch)
    • 解释： 显存有限，不能一次性把所有数据塞进去，要分成若干个 Mini-batch。
  • 步骤 3.2：小块切微块 (Micro-batch)
    • 解释： 为了支持更长的序列或更大的模型，把 Mini-batch 再切得更碎，一点点喂给 GPU 吃（这叫梯度累积）。

✅ Task 4: 开始循环训练 (Training Loop)

对应代码： for epoch in ..., for batch_idx ..., for data in micro_batches ...

这是一个三层循环： 1. Epoch 循环： 同样的数据学几遍？ 2. Mini-batch 循环： 遍历数据块。 3. Micro-batch 循环： 实际执行计算的最小单元。

✅ Task 5: 模型前向计算 (Forward Pass)

对应代码： self._forward_micro_batch(...)

  • 步骤 5.1：现在的模型怎么看？
    • 解释： 把数据喂给当前的模型，算出当前的 log_prob（生成概率）。
    • 注意： 这里需要拿到最新的概率，才能去和 old_log_prob 比较，计算 Task 1 中的 log_ratios。

✅ Task 6: 计算总损失 (Calculate Total Loss)

对应代码： pg_loss, ... = compute_sppo_loss(...) 及后续几行

这是把各种 Loss 加在一起的过程：

  • 步骤 6.1：计算 SPPO 核心损失
    • 调用 Task 1 中的逻辑，强制让模型的概率变化去拟合奖励分数。
  • 步骤 6.2：(可选) 加上熵惩罚 (Entropy)
    • 代码：policy_loss = pg_loss - entropy_loss * entropy_coeff
    • 解释： 防止模型这就变得太“独断专行”，保持一定的随机性（探索性）。
  • 步骤 6.3：(可选) 加上 KL 散度惩罚 (KL Loss)
    • 代码：kld = kl_penalty(...)
    • 解释： 防止模型为了拿高分，改得面目全非，变得不像“人话”或者偏离原始模型太远。让它不要“忘本”。

✅ Task 7: 反向传播与更新 (Backward & Step)

对应代码： loss.backward() 和 self._optimizer_step()

  • 步骤 7.1：计算梯度
    • 解释： 根据刚才算出的总 Loss，反推每个参数应该怎么调。
  • 步骤 7.2：更新参数
    • 解释： 实际修改神经网络的权重。
  • 步骤 7.3：记录日志
    • 代码：metrics["actor/loss"] = ...
    • 解释： 记下这次考了多少分，方便画图看训练曲线。

总结：这代码讲了个什么观点？

这段代码的核心观点是 SPPO (Self-Play Preference Optimization) 的实现逻辑：

  1. 它不像传统 PPO 那样需要复杂的 Advantage（优势函数）计算和 Clipping（截断）。
  2. 它的核心假设很简单：如果一个回答奖励高，模型更新后生成它的概率增量（Log Ratio）就应该大。
  3. 它的实现方式：直接用 均方误差 (MSE) 强迫 概率增量 等于 缩放后的奖励。

你看懂这个 List，就看懂了这个文件的逻辑。
