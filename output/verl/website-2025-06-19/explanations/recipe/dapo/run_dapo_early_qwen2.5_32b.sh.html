recipe/dapo/run_dapo_early_qwen2.5_32b.sh

这份脚本（.sh 文件）本质上是一个启动大规模AI模型训练任务的“配置文件”兼“启动器”。

它主要在做一个叫 DAPO 的实验，使用的是 Qwen2.5-32B 这个大模型，针对数学任务（Math）进行强化学习或对齐训练。

为了让你更容易理解，我把这份脚本拆解成一个 “项目经理的待办清单 (Task List)”。想象你是指挥官，脚本是传令兵，以下是它执行的步骤：

📋 任务清单：启动 DAPO 训练计划

✅ Task 1: 确认身份与目标 (基本设置)

  • 项目代号: DAPO
  • 实验名称: DAPO-Early-Qwen2.5-32B (表示这是一个早期版本的实验，用的是阿里千问32B模型)。
  • 核心算法: grpo (Group Relative Policy Optimization，一种类似于 PPO 的强化学习算法，最近在 DeepSeek R1 中很火)。

✅ Task 2: 制定学习规则 (算法超参)

  • KL 惩罚: 0.0 (关闭)。通常 RL 训练会防止模型偏离原模型太远，但这里设为 0，说明允许模型放飞自我，或者通过其他方式（如 Clip）来约束。
  • 更新幅度限制 (Clip Ratio): 0.2 到 0.28。这是为了防止模型一次学太多“走火入魔”，限制每次参数更新的幅度。

✅ Task 3: 设定考试大纲 (输入输出长度)

  • 题目长度 (Prompt): 最多 2048 个 token。
  • 回答长度 (Response): 最多 20480 个 token (约为 20k)。
    • 解读：这是一个极长思维链 (Chain-of-Thought) 的训练。2万 token 的输出非常长，说明模型被训练来进行复杂的数学推理步骤。

✅ Task 4: 准备教材 (数据路径)

  • 训练教材: dapo-math-17k.parquet (1.7万条数学题)。
  • 模拟考卷: aime-2024.parquet (用 AIME 竞赛题来测试能力)。

✅ Task 5: 调配算力资源 (硬件与分布式)

  • 计算集群: 使用 Ray 框架进行分布式调度。
  • 机器数量: NNODES=16 (动用了16台服务器，规模很大)。
  • 显卡策略:
    • 每台机器 8 张卡。
    • gen_tp=4: 生成时使用 4 卡张量并行。
    • sp_size=8: 使用 Ulysses 序列并行，跨 8 张卡处理超长序列（为了那 20k 的长度）。
    • offload=True: 开启显存卸载，防止显存爆掉。

✅ Task 6: 最终发射 (执行命令)

  • 动作: 运行 ray job submit，调用 Python 代码 recipe.dapo.main_dapo 并把上面定义的所有变量传进去。

🔍 逐步代码对照讲解

如果你想看懂代码细节，我们可以按这个逻辑逐步过一遍：

第一步：设置环境变量与基础信息

#!/usr/bin/env bash
set -xeuo pipefail  # 只要有一步出错，立刻停止，方便排错

project_name='DAPO'
exp_name='DAPO-Early-Qwen2.5-32B'
adv_estimator=grpo  # 算法核心：估计优势函数的方法

第二步：定义“奖惩机制”（RL 参数）

use_kl_in_reward=False # 不把 KL 散度放进奖励里
kl_coef=0.0            # KL 系数为 0
clip_ratio_low=0.2     # 策略更新的下限
clip_ratio_high=0.28   # 策略更新的上限

第三步：定义“长跑能力”（序列长度）

这是这个脚本最特殊的地方：

max_prompt_length=$((1024 * 2))    # 提问限 2k
max_response_length=$((1024 * 20)) # 回答限 20k (非常长！)
enable_overlong_buffer=True        # 允许缓冲区处理超长内容

第四步：定义“学习强度”（Batch Size）

gen_prompt_bsz=512     # 生成数据时的批次大小
train_prompt_bsz=512   # 训练时的总批次大小
train_prompt_mini_bsz=32 # 显卡显存有限，切分成小批次(32)以此更新
n_resp_per_prompt=16   # 每个问题让模型生成 16 个不同的回答（用于 GRPO 算法对比好坏）

第五步：指定“基础设施”（Ray 与 路径）

NNODES=${NNODES:-16}   # 默认使用 16 个节点
MODEL_PATH=.../Qwen2.5-32B # 模型权重位置
TRAIN_FILE=...         # 训练数据位置

第六步：性能优化（显存与并行）

为了跑起来 32B 模型 + 20k 长度，必须做优化：

sp_size=8             # 序列并行：把长句子切成8段放在不同卡上处理
offload=True          # 显存不够时，把参数卸载到 CPU 内存
gen_tp=4              # 推理时，模型切分到 4 张卡上并行计算

第七步：发射台（Ray Submit）

最后这一大段 ray job submit ... 实际上就是在拼凑一条巨长的 Python 命令。 它把上面定义的 sp_size, max_length, lr (学习率 1e-6) 等所有参数，通过 -- 的形式传给 python 脚本。

💡 总结

这个脚本在说： “嘿，Ray 集群！请动用 16 台机器，加载 Qwen2.5-32B 模型。我们要用 GRPO 算法训练它做数学题。注意，允许它进行长达 20k token 的超长思考。每个问题生成 16 个答案来对比学习。显存不够就用 Offload 和序列并行(SP)硬抗。开始干活吧！”
