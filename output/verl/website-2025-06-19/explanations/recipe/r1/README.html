recipe/r1

这是一个非常棒的问题。如果把整个 verl 项目比作一个庞大的“AI 训练工厂”，那么 recipe/r1 这个文件夹就是工厂里专门为了“复刻 DeepSeek R1”这个大项目而建立的“特种兵实验室”。

这里不搞通用的训练，只专注于一件事：重现 DeepSeek R1 模型的辉煌，并对它进行严格的考试（评测）。

以下是通俗易懂的解读：

1. 核心功能：这个文件夹是干嘛的？

一句话总结：这是“DeepSeek R1 复刻计划”的总指挥部。

它的主要功能不是训练模型怎么“说话”，而是侧重于“考试”和“验证”。它负责把各路考题（数学、代码、科学）收集起来，让模型做题，然后自动批改，最后看看我们复刻出来的模型是不是跟 DeepSeek 官方说的一样强。

2. 只有这几个文件，它们各司其职：

我们将整个流程比作“组织一场大型期末考试”，这些文件就是考务组的成员：

  • 📄 README.md（项目进度板/大字报）
    • 这是贴在实验室门口的告示。上面写着：“我们的目标是复刻 R1！现在进度如何？看，这是我们跑出来的分数，跟官方分数的对比表。”
  • 📄 __init__.py（门牌/工牌）
    • 这是一个空的“身份证”。它告诉 Python 程序：“recipe/r1 是一个正经的代码包，里面的东西可以被别人调用。”里面通常只写了版权声明。
  • 📄 data_process.py（试卷印刷机）
    • 负责出题。 它的工作是从网上把数学题（AIME）、科学题（GPQA）、代码题（LiveCodeBench）下载下来，然后清洗干净，打印成统一格式的“标准试卷”（.parquet 文件），准备发给模型做。
  • 📄 run_r1_distill_qwen.sh（全自动考试按钮）
    • 负责统筹全流程。 这是一个脚本文件，相当于一个“一键启动”按钮。你只要按一下它，它就会自动按顺序执行：印刷试卷 -> 把模型叫来做题 -> 老师阅卷 -> 输出成绩单。
  • 📄 main_eval.py（阅卷处/计分室）
    • 负责统分。 考试结束了，这个脚本负责把所有考生的答题卡收上来。它组织了一批“阅卷老师”（并行计算），计算每个科目的平均分，最后生成一张总成绩单。
  • 📄 reward_score.py（标准答案/评分细则）
    • 负责判断对错。 它是阅卷老师手里的那本“参考答案”。它知道数学题该怎么对答案（看数字），代码题该怎么对答案（运行代码）。main_eval.py 会不断调用它来给每一道题打分。

3. 子文件夹的作用（概括）

如果上面是考务组的核心成员，那这两个文件夹就是后勤仓库和专家组：

  • 📁 config/（考试规则设定）
    • 这里存放的是配置文件（yaml）。比如：这次考试用几张显卡？每个题给模型多少时间思考？要考哪些科目？相当于考试的“考场纪律手册”。
  • 📁 tasks/（各科教研组）
    • 这里住着各学科的专家。因为数学题、代码题和科学题的处理逻辑完全不同，所以这里面有 math.py（数学组）、gpqa.py（科学组）等。上面的 reward_score.py 遇到不懂的题，就会去这里请教对应的专家。

4. 高层认知：一图胜千言

为了让你快速理解，请在这个文件夹的脑海中构建这样一个流水线：

  1. 准备：data_process.py 把题库整理好。
  2. 启动：你运行 run_r1_distill_qwen.sh。
  3. 做题：模型（Qwen）开始疯狂做题（这一步调用了外部的生成器）。
  4. 判卷：main_eval.py 拿着 reward_score.py 里的答案，去问 tasks/ 里的专家，给模型打分。
  5. 结果：最后你在 README.md 里看到了能跟 DeepSeek 媲美的分数。

总结： recipe/r1 就是一套专门用来验证 DeepSeek R1 复刻效果的“全自动考试系统”。
