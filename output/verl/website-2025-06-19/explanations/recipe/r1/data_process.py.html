recipe/r1/data_process.py

这份代码其实就像是一个“数据加工流水线”。

它的核心目的是：从网上（HuggingFace）下载几个特定的测试数据集，把它们全部整理成统一的格式，最后打包成一个文件（Parquet格式），方便后续用来测试 AI 模型的能力。

为了让你听懂，我把这个脚本的工作流程拆解成一个 Task To-Do List，然后一步一步带你完成这些任务。

📋 脚本任务清单 (To-Do List)

这个脚本主要完成了以下 7 件事：

  1. [ ] 制定标准：定义好所有数据必须长什么样（统一格式）。
  2. [ ] 加工食材 A (AIME 2024)：处理一个数学竞赛数据集。
  3. [ ] 加工食材 B (GPQA Diamond)：处理一个高难度多选题数据集（需要随机打乱选项）。
  4. [ ] 加工食材 C (CNMO 2024)：处理中国数学奥赛数据集（要把中英文合并）。
  5. [ ] 加工食材 D (LiveCodeBench)：处理代码生成数据集（需要把测试用例压缩打包）。
  6. [ ] 总装：根据用户的指令，决定要处理哪些数据集，并将它们拼接在一起。
  7. [ ] 发货：把处理好的数据保存到本地，或者上传到云端（HDFS）。

逐步讲解 (Step-by-Step)

现在我们按照上面的清单，一步一步看代码是怎么实现的。

1. 制定标准 (统一格式)

代码位置：example_map_fn 函数 解释： 不管原来的数据长什么样（有的叫"Problem"，有的叫"Question"），最后都要变成统一的字典格式。 * prompt: 这里面放题目（Role是User）。 * reward_model: 这里面放标准答案（ground_truth），用来给模型打分。 * data_source: 记录数据来源。

# 这是一个通用的模具
def example_map_fn(example, idx, process_fn, data_source, ability, split):
    question, solution = process_fn(example) # 用特定的处理函数提取问题和答案
    data = {
        "data_source": data_source,
        "prompt": [{"role": "user", "content": question}], # 统一变成对话格式
        "ability": ability, # 能力类型（比如 Math, Code）
        "reward_model": {"style": "rule", "ground_truth": solution}, # 统一放答案
        # ... 其他信息
    }
    return data

2. 加工食材 A：AIME 2024 (数学)

代码位置：build_aime2024_dataset 解释： 这个比较简单。 * 从 HuggingFace 下载 Maxwell-Jia/AIME_2024。 * 把原来的 Problem 字段变成问题，Answer 字段变成答案。 * 打上标签：能力是 "English"（虽然是数学，但可能是英文题目）。

3. 加工食材 B：GPQA (多选题)

代码位置：build_gpqa_dimond_dataset 解释： 这个稍微复杂一点，因为它是选择题。 * 洗牌：代码里用了 random.shuffle。它把正确的选项和错误的选项混在一起，随机分配 A、B、C、D。这样模型就不能靠猜“选C的概率最大”来作弊。 * 组装：把问题和四个选项拼成一个文本（Prompt）。 * 答案：记录正确的选项字母（比如 "B"）。

4. 加工食材 C：CNMO 2024 (中英数学)

代码位置：build_cnmo2024_dataset 解释： 这个源数据分成了“英文版”和“中文版”。 * 它分别下载了 v202412_CNMO_en (英文) 和 v202412_CNMO_cn (中文)。 * 分别处理后，用 concatenate_datasets 把它们拼起来，算作同一个任务的数据。

5. 加工食材 D：LiveCodeBench (代码)

代码位置：build_livecodebench_dataset 解释： 这是最复杂的。因为代码题不仅有题目，还有“测试用例”（输入什么，程序应该输出什么）。 * Prompt：它拼接了一大段提示词，告诉 AI “你要写一个 Python 程序...”。 * 压缩数据：代码里用了 base64, zlib, pickle。这是因为测试用例可能很长，它把这些测试数据压缩成了一串乱码一样的字符串，存放在答案字段里。评测的时候会解压出来运行代码。 * 过滤时间：代码里有一行 dataset.filter，它只保留了 2024年8月到2025年1月之间的题目（为了防止模型在训练数据里见过旧题目，这叫防止数据泄露）。

6. 总装 (Main 函数逻辑)

代码位置：if __name__ == "__main__": 下面的部分 解释： * 接单：args.tasks。用户运行脚本时可以说“我全都要”（all），也可以说“我只要 aime2024”。 * 循环生产： python datasets = [] for task in args.tasks: datasets.append(TASK2DATA[task]()) # 调用上面定义的函数，生成数据 test_dataset = concatenate_datasets(datasets) # 把所有做好的数据拼成一个大表

7. 发货 (保存)

代码位置：最后几行 解释： * 本地保存：test_dataset.to_parquet(...)。把大表保存成 .parquet 文件（一种高效的数据存储格式）。 * 云端备份：如果用户提供了 hdfs_dir（Hadoop分布式文件系统），它会把生成的文件复制到远程服务器上。

总结 (Takeaway)

一句话概括这个文件： 它是为 R1 模型（DeepSeek-R1 复现或相关项目）准备测试数据的脚本。它把数学（AIME, CNMO）、科学（GPQA）和代码（LiveCodeBench）这四种不同来源的考题，清洗并统一格式，最终生成一个 test.parquet 文件，用来考试，看看模型到底有多聪明。
