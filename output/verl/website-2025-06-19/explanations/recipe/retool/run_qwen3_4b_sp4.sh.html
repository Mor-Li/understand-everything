recipe/retool/run_qwen3_4b_sp4.sh

完全没问题。这份文件其实就是一个AI 模型的“训练启动清单”。

把它想象成你雇佣了一个名为 torchrun 的大厨，你给他写了一张便条（就是这个脚本），告诉他：“用什么食材、什么锅、炒多久、怎么摆盘”。

这个脚本的核心目标是：在一台有 8 张显卡的机器上，微调（训练）一个叫 Qwen3-4B 的模型，让它学会使用工具（Retool），并且能处理很长的对话。

为了让你看懂，我把这个脚本拆解成一个 “7步走”的任务清单 (Todo List)，一步步解释它在干嘛：

✅ Task 1: 准备厨房环境 (环境配置)

在开始做饭前，先要把厨房打扫好，规则定好。

  • 代码对应： bash export PYTHONUNBUFFERED=1 export RUST_BACKTRACE=1 ulimit -n 65535 EXPERIMENT_NAME=retool-multiturn-sft-qwen3-4b-sp4
  • 白话解释：
    1. PYTHONUNBUFFERED=1: 告诉 Python 不要把日志憋在肚子里，有一句打印一句，方便我看进度。
    2. ulimit: 把系统允许打开的文件数量上限调大，防止训练时文件太多报错。
    3. EXPERIMENT_NAME: 给这次训练起个名字，叫“retool-多轮对话-微调-Qwen3-4B-序列并行4”。方便以后找文件。

✅ Task 2: 呼叫厨师团队 (启动分布式训练)

我们要炒一盘大菜，一个人（一张显卡）搞不定，需要叫 8 个人一起来。

  • 代码对应： bash torchrun --nnodes=1 --nproc_per_node=8 \ -m verl.trainer.fsdp_sft_trainer \
  • 白话解释：
    1. torchrun: 这是总指挥。
    2. --nproc_per_node=8: 意思是“这台机器上有 8 张显卡，全部用上”。
    3. -m verl.trainer.fsdp_sft_trainer: 这是我们要运行的主程序。
      • verl: 这是一个训练框架的名字。
      • sft: 代表 Supervised Fine-Tuning（有监督微调），就是让模型上“补习班”。
      • fsdp: 是一种省显存的技术（把模型切碎了放在不同显卡里），防止显存爆炸。

✅ Task 3: 准备食材 (数据设置)

告诉模型我们要学什么课本。这里的课本是关于“如何使用工具”的多轮对话。

  • 代码对应： bash data.max_length=16384 \ data.train_files=$HOME/.../train.parquet \ data.multiturn.enable=true \ data.multiturn.messages_key=messages \ data.multiturn.tools_key=tools \
  • 白话解释：
    1. max_length=16384: 重点！ 这次训练允许的对话长度非常长（1.6万字/token）。通常模型只能处理 4k 或 8k，这里为了处理复杂任务加长了。
    2. train_files: 训练数据的路径（parquet 是一种高效的数据格式）。
    3. multiturn.enable=true: 开启“多轮对话”模式。模型不仅要回答一句，还要能记住上下文，跟你来回聊。
    4. tools_key: 数据里包含了“工具(Tools)”的信息，说明这个模型是专门训练来调用 API 或使用软件工具的（Retool）。

✅ Task 4: 选择大脑 (模型设置)

我们要训练哪个模型？

  • 代码对应： bash model.partial_pretrain=$HOME/models/Qwen/Qwen3-4B \ model.trust_remote_code=true \
  • 白话解释：
    1. 使用的是 Qwen3-4B（通义千问第三代，40亿参数版本）。这是一个中等大小的模型，速度快，效果也不错。
    2. 它是从预训练好的底座开始练起，不是从零开始。

✅ Task 5: 使用黑科技 (序列并行优化)

这部分是这个脚本文件名的由来 (sp4)，也是最难懂的部分。

  • 代码对应： bash ulysses_sequence_parallel_size=4 \ use_remove_padding=true
  • 白话解释： 还记得 Task 3 里我们设定的长度是 16384 吗？这么长的数据，单张显卡可能塞不下。
    1. ulysses_sequence_parallel_size=4: 使用了“尤利西斯序列并行”技术。它把那 1.6 万长的句子切成 4段，分别丢给不同的显卡去计算，最后再拼起来。这就是为什么文件名里有 sp4。
    2. use_remove_padding: 把数据里的废话（填充用的空白字符）删掉再算，节省计算资源。

✅ Task 6: 设定火候 (训练参数)

怎么练？练多久？

  • 代码对应： bash data.train_batch_size=128 \ optim.lr=1e-6 \ trainer.total_epochs=12 \
  • 白话解释：
    1. batch_size=128: 每次打包 128 条数据一起学。
    2. lr=1e-6: 学习率（Learning Rate）。设得很小（0.000001），说明是“微调”，小心翼翼地修改模型参数，生怕把原来的能力改坏了。
    3. total_epochs=12: 所有的课本要反复读 12 遍。

✅ Task 7: 记录与保存 (收尾工作)

练好了放哪里？过程怎么监控？

  • 代码对应： bash trainer.default_local_dir=$HOME/checkpoints/... \ trainer.logger=['console','wandb'] \
  • 白话解释：
    1. default_local_dir: 训练好的模型（存档点/Checkpoints）保存在这个文件夹里。
    2. logger:
      • console: 在黑框框屏幕上打印进度。
      • wandb: 把训练曲线（比如准确率有没有上升）发送到 "Weights & Biases" 这个网站上，方便画图表看。

总结

这个脚本在说： “嘿，电脑！用 8 张显卡，加载 Qwen3-4B 模型。我要用超长的 16k 长度的数据训练它学会使用工具（Retool）。因为数据太长，记得把数据切成 4 份（SP4）并行处理。小心点慢点学（低学习率），一共学 12 遍。”
