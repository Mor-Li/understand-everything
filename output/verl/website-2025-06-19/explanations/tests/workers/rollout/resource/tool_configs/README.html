tests/workers/rollout/resource/tool_configs

这是一个非常清晰的 “AI 技能包配置中心”。

为了让你快速理解这个文件夹（tests/workers/rollout/resource/tool_configs）的作用，我们可以把它想象成一个 “特工装备库的说明书架”。

这里存放的不是工具本身（代码逻辑），而是告诉 AI 如何使用这些工具的“使用说明书”和“连接凭证”。

1. 📁 这个文件夹主要负责什么功能？

核心功能：给测试中的 AI “安装外挂”并设定规则。

当我们在测试（Test）AI 的时候，我们希望它不仅仅会聊天，还能上网、能写代码。这个文件夹里的文件就是负责定义： * AI 有哪些超能力（搜索、跑代码）？ * 这些超能力的开关在哪里？ * 使用这些超能力有什么限制（比如每秒只能用几次）？

简单说：这里是给 AI 发放“武器”和“使用守则”的地方。

2. 📄 各个直接文件的作用（通俗解读）

这里有 4 个文件，我们可以把它们分成三组不同的“装备”来看：

第一组：通用万能插头 (MCP)

这是一种新的标准接口，让 AI 可以连接各种外部服务。

  • 📄 mcp_server.json
    • 角色：“保密通讯录”。
    • 作用：这里面记着外部工具（比如 Tavily 搜索）的服务器地址和进门密码（Token）。它不负责具体操作，只负责存“钥匙”和“门牌号”。
  • 📄 mcp_tool_config
    • 角色：“万能插头使用手册”。
    • 作用：它告诉 AI：“我们要用 MCP 这个标准来连接工具。具体的地址和密码去查上面那个通讯录 (mcp_server.json)。还有，记得别搜太快，会被封号。”

第二组：代码实验室 (Sandbox)

让 AI 可以运行 Python 代码。

  • 📄 sandbox_fusion_tool_config
    • 角色：“远程实验室通行证”。
    • 作用：它告诉 AI：“如果你想运行 Python 代码，不要在自己脑子里算，把代码打包发送到火山引擎的一个安全屋（沙盒）里去跑，那里比较安全。”

第三组：本地搜索引擎 (Search)

一个基础的搜索功能。

  • 📄 search_tool_config
    • 角色：“本地图书馆指南”。
    • 作用：它告诉 AI：“如果你需要搜资料，我们本地搭建了一个小的搜索引擎（在 127.0.0.1）。你可以向它提问，它会给你网页内容。”

3. 📁 子文件夹的作用

(注：根据你提供的列表，当前目录下没有子文件夹。如果未来有了，通常也是存放更多特定类型的工具配置。)

在此场景下，我们可以认为没有子文件夹，所有配置都平铺在这里，方便测试程序直接读取。

4. 🧠 高层认知：一句话秒懂

想象你要送你的 AI 机器人去参加一场考试（测试），在进考场前，你往它的背包里塞了三本技能书：

  1. 《如何使用通用搜索神器 (MCP)》（配合一张写着密码的小纸条）。
  2. 《如何远程运行代码》。
  3. 《如何查询本地资料库》。

这个文件夹，就是存放这三本技能书和那张密码小纸条的地方。
