tests/special_sanity/check_device_api_usage.py

这份代码其实是一个“代码警察”（CI/CD检查脚本）。

它的核心目的是：防止程序员在代码里随手写死（Hardcode）跟 NVIDIA 显卡相关的关键词（如 cuda, nccl）。

为什么要做这个？因为这个项目（verl）可能想要兼容多种硬件（比如 AMD 显卡、TPU 等），如果代码里到处都是 .cuda()，那换了硬件就跑不起来了。所以它强制要求大家使用统一的工具类（verl/utils/device.py）来管理设备，而不是直接调用 CUDA。

下面按照你要求的 Task To-Do List 格式，一步一步拆解这个脚本在干什么：

📋 脚本任务清单 (Task To-Do List)

✅ Task 1: 定义“违禁词” (What to ban)

目标：确定哪些写法是不允许出现在普通代码里的。 代码对应：

SEARCH_KEYWORDS = [".cuda", '"cuda"', '"nccl"']

解释：脚本规定，如果代码里出现了 .cuda（调用方法）、"cuda"（字符串）或者 "nccl"（通信库），那就是违规的。

✅ Task 2: 发放“特权卡” (Whitelist)

目标：有些底层文件必须得写 cuda，或者引用的第三方库改不了，得把它们排除在外。 代码对应：

CUDA_KEYWORD_CHECK_WHITELIST = [ ... ] # 允许出现 cuda 的文件列表
NCCL_KEYWORD_CHECK_WHITELIST = [ ... ] # 允许出现 nccl 的文件列表
SEARCH_WHITELIST = ...                 # 汇总所有特权文件

解释：比如 verl/utils/device.py 这个文件本身就是用来封装设备的，它里面肯定得写 cuda，所以它是合法的，给它发一张“免检金牌”。

✅ Task 3: 确定巡逻范围 (Input Directory)

目标：告诉脚本要去检查哪个文件夹。 代码对应：

parser.add_argument("--directory", "-d", required=True, type=str)
# ...
pathlist = Path(directory_in_str).glob("**/*.py")

解释：脚本启动时接收一个文件夹路径，然后找出里面所有的 .py（Python）文件。

✅ Task 4: 逐个盘查 (The Loop)

目标：拿着文件列表，一个一个检查。 代码对应：

for path in pathlist:
    # ...

解释：开始遍历每一个找到的 Python 文件。

✅ Task 5: 检查是否拥有“特权” (Check Whitelist)

目标：如果是特权文件，直接放行，不检查了。 代码对应：

for sw in SEARCH_WHITELIST:
    if sw in path_in_str:
        print(f"[SKIP] ...") # 跳过检查
        path_in_whitelist = True
        break
if path_in_whitelist:
    continue

解释：看当前文件的路径是否包含在 Task 2 定义的白名单里。如果是，打印 SKIP 并跳过。

✅ Task 6: 搜身 (Search Content)

目标：如果不是特权文件，打开文件内容，搜索违禁词。 代码对应：

with open(path_in_str, encoding="utf-8") as f:
    file_content = f.read()
    for sk in SEARCH_KEYWORDS:
        if sk in file_content:
            find_invalid_device_management = True # 抓到了！
            break

解释：打开文件，读取所有代码，看看里面有没有 Task 1 里定义的 .cuda 或 nccl。

✅ Task 7: 宣判 (Assert)

目标：如果发现了违禁词，报错并停止测试；如果没发现，通过。 代码对应：

assert not find_invalid_device_management, f'file {path_in_str} contains ...'

解释： * 如果没有抓到违规（not find_invalid_device_management 为 True），脚本继续运行，最终成功。 * 如果抓到了违规，程序直接 崩溃报错（AssertionError），并提示程序员：“你这个文件里用了 cuda/nccl，请改用 verl/utils/device.py 里的接口！”

总结

这个脚本就是一个自动化的代码规范检查器。

  • 它的观点：普通业务代码里不许直接写 cuda，要解耦。
  • 它的做法：除了白名单里的文件，其他文件只要出现 cuda 字样就报错。
