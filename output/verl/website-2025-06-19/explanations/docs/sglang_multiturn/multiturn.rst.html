这份文档主要是在讲如何配置和处理“多轮对话”（Multi-turn）的强化学习训练，特别是在使用 sglang 引擎和 verl 框架时。

之所以难懂，是因为它涉及了很多工程细节（比如怎么算 token、怎么处理特定模型的 bug）。

为了让你好理解，我把你当作一个正在配置 AI 训练系统的工程师，列一份Task Todo List。你按照这个步骤去做，就能读懂文档里的每一个环节了。

📋 任务清单：配置多轮对话训练系统

✅ Task 1: 打开“多轮对话”开关 (Basic Configuration)

目标：告诉系统，我现在要训练模型进行连续对话，而不是只问答一次。 操作： * 去你的配置文件（YAML）里，找到 actor_rollout_ref -> rollout。 * 把 multi_turn 设为 True。 * 解释：这部分很简单，就是个总开关。

✅ Task 2: 给模型装备工具 (Custom Tool Configuration)

目标：如果你的多轮对话需要用到工具（比如计算器、搜索引擎），你需要告诉系统工具在哪里。 操作： * 写好你的工具代码（继承 BaseTool）。 * 写一个工具的配置文件（YAML），定义工具的名字和参数。 * 在总配置里，把 tools_config_file 指向你的工具配置文件路径。 * 解释：文档里提到了 GSM8K（数学题）作为一个例子，告诉你可以去参考它的配置。

✅ Task 3: 解决“计分”难题 (Multi-turn Tokenization)

目标：这是文档最核心的技术点。你需要确保系统能精准识别出哪部分是模型这一轮新生成的，哪部分是历史记录。 困难： * 模型看到的是一长串历史记录。如果不做特殊处理，系统分不清哪些 token 是这次新说的，哪些是以前说过的。 * 解决方案（Delta-based strategy）： 1. 先把“第1句到第N句”打包变成 token，记下长度。 2. 再把“第1句到第N+1句（最新回复）”打包变成 token。 3. 两者相减（Delta），剩下的就是这一轮新生成的 token。 * 操作：系统默认会这么做。它还会做一个“健康检查”（Sanity Check），如果发现训练和推理时的 token 对不上，会给你报 Warning。你可以选择关掉这个检查，但最好别关。

✅ Task 4: 处理“不听话”的模型 (Special Cases - Qwen)

目标：处理像 Qwen (千问) / QwQ 这种带有“思考过程”（Reasoning/Think）的模型。 困难： * Qwen 模型有个特性，它在处理历史对话时，可能会把之前的 <think>...思考内容...</think> 删掉。 * 这就导致 Task 3 里的“减法”失效了（因为历史记录变短了，导致算出来的 token 错位）。 * 解决方案：文档说系统会针对 Qwen 系列使用一种“固定基座”（Fixed Base）的方法来绕过这个问题。 * 额外操作：如果你用的是 Qwen/QwQ-32B，它有个官方 bug，文档让你去下载一个特定的修复版本（Revision refs/pr/81）。

✅ Task 5: 决定要不要保留“思考过程” (Discrepancy)

目标：权衡训练效果和显存/长度限制。 抉择： * 选项 A（默认）：保留所有的思考过程。 * 好处：模型能看到自己之前的推理逻辑，可能更聪明。 * 坏处：多轮对话后，文本会变得超级长，容易爆显存（超出 Context Window）。 * 选项 B（生产环境模式）：像真实上线那样，把历史记录里的“思考过程”删掉。 * 好处：省长度，且符合上线后的真实情况。 * 坏处：模型可能因为丢失上下文变笨。 * 操作：如果你想选 B（为了省长度），就把 use_inference_chat_template 设为 True。

总结

这篇文档其实就在讲三件事： 1. 怎么开：改 YAML 配置。 2. 怎么算：用“差值法”算 Token，确保只训练新生成的回复。 3. 怎么修：针对 Qwen 这种会吞掉思考标签的模型，要做特殊处理，并由你决定是否在历史记录里保留思考内容。
