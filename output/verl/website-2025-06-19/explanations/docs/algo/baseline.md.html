docs/algo/baseline.md

这份文件其实是一个“成绩单”或者叫“实验参考手册”。

简单来说，它的作用是告诉你：如果你使用 verl 这个框架，搭配不同的 AI 模型（如 Qwen, Gemma）和不同的训练算法（如 PPO, GRPO），在标准的数学和代码考试中，你应该能跑出多少分。

为了让你更容易理解，我把它拆解成一个 “开发者任务清单 (To-Do List)”，带你一步步看懂文中的观点和流程：

✅ Task 1: 准备工作 (Data Preprocessing)

文中的内容：

python3 examples/data_preprocess/*.py

解读： * 第一步要做的事：在你开始训练模型之前，必须先处理数据。 * 观点：这份文档里的所有成绩，都是基于通过这个命令处理好的 GSM8k（小学数学数据集）或其他数据集跑出来的。如果你不跑这行代码，后续的实验可能无法复现。

✅ Task 2: 查阅“数学考试”成绩单 (Math Baselines - GSM8k)

文中的内容： 那个巨大的表格（包含 Model, Method, Test score 等列）。

解读： 这是核心部分。你可以把它看作是一个排行榜。你需要关注这几列的组合逻辑：

  1. 选模型 (Model)：比如 google/gemma-2-2b-it 或 Qwen/Qwen2.5-0.5B。
  2. 选方法 (Method)：
    • hf checkpoint：表示没经过强化学习训练，直接拿原版模型去考，分数通常较低（例如 Gemma 只有 23.9 分）。
    • SFT (Supervised Fine-Tuning)：经过“老师带着做题”的微调，分数变高了（52.06 分）。
    • PPO / GRPO / ReMax：这些是强化学习算法。这是 verl 框架的强项。你会发现使用了这些算法后，分数通常会进一步飙升（例如 Gemma 用了 PPO 涨到了 64.02 分）。
  3. 看分数 (Test score)：这是基准线（Baseline）。如果你自己跑实验，分数应该和这个差不多。
  4. 抄作业 (Details)：点击表格里的链接（log 或 script），你可以直接看到当初跑出这个分数的具体代码命令和参数配置。

核心观点： * 强化学习（RL）通常比单纯的微调（SFT）能获得更好的数学解题能力。 * 不同的模型大小（0.5B 到 72B）和不同的算法（PPO vs GRPO）效果不同。

✅ Task 3: 查阅“高阶数学”与“编程”成绩单

文中的内容： DAPO math-17k 和 Coding related datasets 章节。

解读： * 进阶任务：除了基础的小学数学（GSM8k），文档还列出了更难的数学竞赛题（AIME 2024）和编程题目（LeetCode）的基准。 * DAPO 的例子：展示了如何用 Qwen 模型在更难的数据集上训练，并提示你为了让模型回答更长的步骤，他们修改了模型的配置（max_position_embeddings 改为 32768）。

✅ Task 4: 阅读注意事项 (Notes)

文中的内容： 文章底部的 [1] 和 [2]。

解读： 这是“避坑指南”： 1. 关于评分标准：目前的评分比较死板，只抓取 "####" 后面的答案。如果模型答对了但格式不对，可能会被判错。这意味着实际能力可能比表格里的分数更高。 2. 关于参数变化：提醒你 verl 版本更新后（0.3.x 版本），有个参数 entropy_coeff 默认值变了。如果你用旧版本跑，可能结果不一样。

总结 (Summary)

如果你是一个刚拿到这个项目的工程师，你的行动路径应该是：

  1. 运行 Task 1 的数据处理脚本。
  2. 去 Task 2 的表格里找一个你显卡跑得动的模型（比如 Qwen2.5-0.5B）。
  3. 点击表格右侧的链接，复制它的训练脚本。
  4. 跑完后，看你的分数是不是接近表格里的 Test score。
    • 如果接近：恭喜，环境搭建成功，基准对齐了。
    • 如果不接近：检查 Task 4 里的注意事项或参数配置。
