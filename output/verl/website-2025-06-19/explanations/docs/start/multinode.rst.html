docs/start/multinode.rst

这份文档主要讲的是如何在多台机器（多节点）上联合训练大模型。因为大模型参数量大，单台机器的显卡（GPU）往往装不下或者训练太慢，所以需要把多台机器连起来一起跑。

文档主要介绍了三种场景/工具：手动 Ray 集群、dstack 工具、以及AMD 集群上的 Slurm 调度。

为了让你更容易理解，我把这份文档拆解成一个 Task Todo List（任务清单），你只需要根据你的硬件环境选择其中一条路径即可。

✅ 核心任务清单 (Task Todo List)

阶段一：环境确认（必做）

  • Task 0: 确认你的硬件环境。
    • 如果你是几台裸机（比如两台插了网线的服务器），看 路径 A。
    • 如果你想用 dstack 这个工具来简化云端或本地部署，看 路径 B。
    • 如果你是在学校或超算中心，使用 AMD 显卡且有 Slurm 调度系统，看 路径 D。
    • 路径 C 是通用的调试方法。

🏛️ 路径 A：手动搭建 Ray 集群 (Manual)

这是最基础的方法，适合你自己有几台机器，需要手动把它们连起来。

  • Task A-1: 启动“包工头” (Head Node)

    • 操作: 在第一台机器（主节点）上运行 ray start --head ...。
    • 目的: 让这台机器成为集群的管理者。
    • 记录: 记下屏幕上显示的 IP 地址和端口（例如 192.168.1.100:6379）。

  • Task A-2: 启动“打工仔” (Worker Node)

    • 操作: 在其他机器上运行 ray start --address=<主节点IP>。
    • 目的: 让这些机器加入刚才建立的集群，听从指挥。

  • Task A-3: 检查队伍 (Check Status)

    • 操作: 在主节点输入 ray status。
    • 预期: 你应该能看到所有机器都在列表中（比如 2 nodes）。
    • 进阶: 在浏览器打开 Dashboard 地址（通常是 http://localhost:8265）可视化查看。

  • Task A-4: 派发任务 (Submit Job)

    • 操作: 在主节点运行 ray job submit ... 命令。
    • 解释: 这条命令告诉 Ray 集群：“去运行 verl.trainer.main_ppo 这个训练代码，用 2 个节点，每个节点 8 张卡”。

☁️ 路径 B：使用 dstack 工具

dstack 是一个第三方工具，用来简化配置，不用你自己手动敲 Ray 命令。

  • Task B-1: 初始化 (Init)

    • 操作: 安装 dstack 并运行 dstack init。

  • Task B-2: 写配置文件 (Config)

    • 操作: 创建一个 .yaml 文件（如 ray-cluster.dstack.yml）。
    • 关键点: 在文件里写好你需要几个节点（nodes: 2），用什么镜像，以及安装环境的命令。

  • Task B-3: 启动集群 (Apply)

    • 操作: 运行 dstack apply -f ...。
    • 效果: dstack 会自动帮你搞定环境配置和端口映射，把 Ray 的后台映射到你本地的 localhost:8265。

  • Task B-4: 提交任务

    • 操作: 和路径 A 类似，运行 ray job submit，但地址指向本地。

🐛 路径 C：怎么修 Bug (Debugging)

代码跑不通怎么办？文档推荐了两种方法。

  • Task C-1: 使用 VSCode 插件 (推荐)

    • 操作: 安装 "Ray Distributed Debugger" 插件。
    • 设置: 在代码里想暂停的地方写 breakpoint()。
    • 效果: 代码运行到这里会自动暂停，你可以在 VSCode 里看到变量值，就像调试本地代码一样。

  • Task C-2: 使用旧版调试器 (Legacy)

    • 操作: 启动 Ray 时加上 RAY_DEBUG=legacy 参数。
    • 效果: 在终端里通过命令行进行调试（比较硬核，不推荐新手）。

🏎️ 路径 D：AMD 集群 + Slurm (高级脚本)

这一部分最长，是一个复杂的自动化脚本。如果你是在超算上用 AMD 显卡，直接抄这个作业。

  • Task D-1: 理解脚本逻辑 (slurm_script.sh)

    • 这个脚本帮你把一堆繁琐的事情自动化了，它的执行流程是：
      1. 向 Slurm 申请资源: 比如我要 2 台机器，每台 8 张卡，跑 30 小时 (#SBATCH 开头的部分)。
      2. 设置环境变量: 各种网络配置（NCCL）、缓存路径等。
      3. 启动容器 (Docker/Podman): 因为环境复杂，脚本会自动在每台机器上拉取并启动 Docker 容器。
      4. 在容器里启动 Ray:
        • 脚本会自动判断哪台是 Head，哪台是 Worker。
        • 自动在 Head 节点运行 ray start --head。
        • 自动在 Worker 节点运行 ray start --address=...。
      5. 数据与模型准备: 自动下载数据、测试模型能不能加载。
      6. 开始训练: 最后运行 python3 -m verl.trainer.main_ppo ... 开始真正的训练。

  • Task D-2: 提交作业

    • 操作: 只需要运行 sbatch slurm_script.sh。
    • 效果: 坐等超算排队调度，然后自动跑完上述所有流程。

总结建议

如果你是初学者，想先跑通流程： 1. 找两台带显卡的机器。 2. 按照 路径 A (Manual) 操作。 3. 先不要管 Slurm 和 dstack，那是进阶工具。 4. 重点看文档里 ray job submit 那一段代码，那是你真正运行训练的地方，里面的参数（比如 trainer.nnodes=2）决定了是不是多机训练。
