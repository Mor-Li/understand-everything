这份文档其实是在教你如何在 Ray 分布式系统中进行代码调试（Debug）。

因为 Ray 是多进程甚至多节点运行的，你不能像调试普通 Python 脚本那样直接按 F5 就能轻松搞定，所以文档提供了两种方法。

我把文档内容拆解成了一个 To-Do List（任务清单），你按照这个顺序一步步做，就能看懂并操作了。

核心任务：使用 VSCode 插件进行可视化调试（强烈推荐）

这是文档中最主要推荐的方法，因为它有图形界面，比较直观。

✅ Task 1：安装必要的工具

文档步骤 1 & 2 你需要先准备好“武器库”： 1. 安装 VSCode 插件：在 VSCode 扩展商店里搜索并安装 Ray Distributed Debugger（由 Anyscale 开发）。 2. 检查 Python 包：确保你的环境里安装了以下版本的包： * ray[default] 版本要大于等于 2.9.1 * debugpy 版本要大于等于 1.8.0 3. 连接集群：按照插件提示，输入你的 Ray Dashboard URL（通常是你启动 Ray 集群时显示的那个地址）把 VSCode 连上集群。

✅ Task 2：设置环境变量（关键配置）

文档步骤 3 在运行代码的终端里，你需要告诉 Ray：“我要开启调试模式”。 1. 执行命令：export RAY_DEBUG_POST_MORTEM=1 * 解释：这能让程序出错或暂停后保留现场供你检查。 2. 清理旧配置（重要）：如果你以前设过 RAY_DEBUG=legacy 或者用了 --ray-debugger-external，一定要删掉或取消，否则会冲突。

✅ Task 3：在代码里“埋点”

文档步骤 4 你需要告诉程序在哪里停下来。 1. 修改代码：在你想要调试的函数里写上一行 breakpoint()。 2. 注意限制：这个断点必须写在被 @ray.remote 装饰的函数（也就是 Ray 的远程任务）里面才有效。

✅ Task 4：启动你的程序

文档步骤 5 1. 运行方式：不要用 VSCode 的 F5 调试启动，直接在终端里用命令行跑： * python job.py

✅ Task 5：连接调试器

文档步骤 6 1. 等待触发：当程序运行到你写的 breakpoint() 那一行时，它会挂起（暂停）。 2. 点击图标：这时候看你的 VSCode 左侧边栏，点击那个 Ray Debugger 的图标。 3. Attach（附加）：点击连接，你就能像调试本地代码一样查看变量、单步执行了。

✅ Task 6：处理多个断点（如果需要）

文档步骤 7 如果你代码里有好几个断点，或者循环里多次触发断点： 1. 断开当前：每调试完一个任务，你需要先点“断开连接”（Disconnect）。 2. 重连下一个：再次点击插件图标，去连接下一个触发的断点。 * 解释：这是因为分布式任务是独立的，你得一个任务一个任务地连上去调。

备选任务：使用旧版命令行调试（Legacy 模式）

这是文档最后一部分提到的“老方法”，比较原始，只有在上面的插件方法用不了时才考虑。

❌ Task (备选)：命令行硬核调试

文档 Legacy Ray Debugger 部分 1. 启动集群时带参数：在启动 Ray (ray start) 时，必须加上 RAY_DEBUG=legacy 和 --ray-debugger-external。 2. 运行代码：提交你的任务。 3. 进入调试：在终端输入 ray debug 命令。这会让你进入一个类似 GDB 或 PDB 的纯文本交互界面来调试。

总结一下文中的观点

  1. 首选方案：用 VSCode 的 Ray Distributed Debugger 插件。它对用户最友好，配置简单（设个环境变量就行），体验接近本地调试。
  2. 避坑指南：用新方案时，千万别混用旧方案的环境变量（比如 legacy 标志），否则会跑不通。
  3. 操作逻辑：它的逻辑是 “埋点 -> 运行 -> 挂起 -> 手动连接”，而不是传统的“点击运行即调试”。
