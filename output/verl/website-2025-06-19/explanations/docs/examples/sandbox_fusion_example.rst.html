docs/examples/sandbox_fusion_example.rst

这篇文章其实是在介绍一个叫 Sandbox Fusion 的工具，以及如何把它用到大模型（LLM）的训练流程中。

为了让你更容易理解，我们可以打个比方： * 大模型（LLM） 像是一个正在学写代码的学生。 * 训练过程 就是让学生做题，然后老师批改。 * Sandbox Fusion 就像是一个专门的、高性能的“自动阅卷机”。

文章的核心观点是：以前老师（本地电脑）自己批改代码太慢了，现在我们把学生写的代码发给这台远程的“自动阅卷机”（Sandbox Fusion）去跑，这样既安全（不会搞坏老师电脑），速度又快（能快 10%-30%）。

下面我为你列一个 Task To-Do List，一步步拆解文中的操作流程：

📋 Task To-Do List (任务清单)

  1. [理解概念] 搞懂为什么要用这个工具（为了加速和安全）。
  2. [准备教材] 下载训练用的题目数据（Dataset）。
  3. [搭建阅卷机] 部署 Sandbox Fusion 服务，获得一个访问地址（URL）。
  4. [告诉老师] 修改训练脚本的配置，填入刚才获得的地址。
  5. [开始上课] 运行脚本，开始训练。

📝 详细步骤拆解

下面我按照上面的清单，结合文中的内容给你详细讲讲每一步在干什么。

Task 1: 理解目标 (Introduction)

  • 文中观点：Sandbox Fusion 是一个远程代码沙盒。
  • 为什么要做：大模型生成的代码需要运行一下才知道对不对。如果在本地跑，既危险（万一模型写了删库代码怎么办？）又慢。用这个工具，可以利用更强的 CPU 资源并发（同时）验证很多代码。
  • 预期效果：能把“奖励阶段”（就是验证代码对不对的阶段）的时间缩短 10% 到 30%。

Task 2: 准备数据 (Step 1: Prepare the Dataset)

  • 你要做什么：你需要给模型准备“习题集”。
  • 文中操作：去 HuggingFace 下载一个叫 Eurus-2-RL-Data 的数据集。
  • 解释：这个数据集里包含了数学题和代码题，非常适合用来训练大模型写代码。

Task 3: 搭建服务 (Step 2: Set Up the Sandbox Fusion Service)

  • 你要做什么：你需要把那个“自动阅卷机”搭建起来。
  • 文中操作：
    1. 看官方文档（链接在文中）。
    2. 选择一种部署方式：
      • Local Deployment：在你自己的另一台服务器上部署。
      • FaaS Instance (Volcengine)：在火山引擎（云服务）上创建一个实例。
    3. 最终目标：部署好后，你会得到一个 API 地址（URL），长得像这样：https://<你的IP或域名>/run_code。
  • 解释：这一步是把后端服务跑起来，等着接收代码来运行。

Task 4: 配置训练脚本 (Step 3: Configure the Training Script)

  • 你要做什么：你需要修改你的训练设置，把训练程序和刚才搭建的服务连起来。
  • 文中操作：找到你的训练脚本，修改以下参数：
    1. reward_model.sandbox_fusion.url='<你的API地址>'：把 Task 3 里拿到的那个 URL 填进去。
    2. reward_model.sandbox_fusion.max_concurrent=256：设置并发数（比如同时批改 256 份作业）。
    3. reward_model.reward_manager=prime：开启并行处理模式，进一步加速。

Task 5: 运行示例 (Example Script)

  • 你要做什么：一切准备就绪，按按钮开始。
  • 文中操作：
    • 官方提供了一个现成的脚本文件路径：examples/ppo_trainer/run_deepseek7b_llm_sandbox_fusion.sh
    • 你只要确保在这个脚本里填好了 Task 4 说的那个 URL，然后运行这个脚本（.sh 文件），训练就开始了。

总结

这篇文章其实就是一份操作指南： 下载数据 -> 启动沙盒服务 -> 把沙盒地址填入配置文件 -> 运行训练脚本。
