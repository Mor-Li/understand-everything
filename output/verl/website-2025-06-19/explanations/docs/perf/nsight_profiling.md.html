docs/perf/nsight_profiling.md

这篇文档主要讲的是：如何使用 NVIDIA Nsight Systems 这个工具来分析 verl 训练过程中的性能瓶颈。

简单来说，如果你觉得训练太慢，或者显卡利用率不高，就需要用这个功能来“体检”一下，看看时间都花哪儿了。

为了让你更容易理解，我把它拆解成一个 “性能分析任务清单 (To-Do List)”，你只需要按顺序执行这几步即可。

📋 任务清单：一步步开启性能分析

✅ 第一步：准备工作 (Prerequisites)

目标：确保你的环境里有能用的分析工具。 * 动作：检查你的 Docker 环境或系统里是否安装了 NVIDIA Nsight Systems。 * 注意：文档提到版本很重要，最好参考 docker/Dockerfile.vllm.sglang.megatron 里使用的版本，否则可能跑不起来。

✅ 第二步：决定“什么时候”分析 (Global Control)

目标：你不可能从头到尾一直录制（文件会巨大），你需要指定录制哪几步。 * 修改文件：ppo_trainer.yaml (或者其他 trainer 配置文件)。 * 设置参数：找到 trainer 部分。 * 设置 profile_steps： * 比如写 [1, 2, 5]：意思是只在第1步、第2步、第5步训练时开启录制。 * 写 null：意思是关闭分析功能（平时不用时就设这个）。 * Controller/Worker Options：通常保持默认即可。文档解释了 worker_nsight_options 里固定使用了 cudaProfilerApi，意思是“通过代码指令来控制开始和结束”，不要手动改它。

✅ 第三步：决定“谁”需要被分析 (Worker Profiling)

目标：verl 有很多角色（Actor生成数据, Critic打分, Ref参考模型等），你需要决定监控哪些角色的 GPU。 * 修改文件：同上，在配置文件的各个角色部分（如 actor_rollout_ref, critic）。 * 设置参数 profiler： * ranks: 指定具体哪几张卡（进程ID）。比如 [0, 1] 表示只分析第0号和第1号进程。 * all_ranks: * True: 所有卡都分析（文件会很多，慎用）。 * False: 只分析上面 ranks 指定的卡（推荐）。

✅ 第四步：决定“怎么”存数据 (Discrete Mode)

目标：决定生成的数据文件是“大而全”还是“小而散”。 * 设置参数 discrete： * False (推荐新手)：连续模式。在一个训练步骤（Step）内，所有操作都录制在同一个文件里。你会得到一个完整的 timeline，看这一步整体发生了什么。 * True：离散模式。在一个训练步骤内，不同的动作（比如 Actor 生成、Critic 计算）会被切分成独立的小文件。适合极度深度的调试。

✅ 第五步：运行训练并获取“体检报告”

目标：拿到 .nsys-rep 文件，并在电脑上打开分析。 * 动作：启动你的训练任务。 * 找文件： * 去训练节点的这个目录找：/tmp/ray/session_latest/logs/nsight/。 * 这是 Ray 框架的默认日志目录，改不了，只能去那儿找。 * 文件名格式：通常是 worker_process_<PID>.<step>.nsys-rep。 * 查看：把文件下载到本地，用 NVIDIA Nsight Systems 桌面版软件打开。你可以看到 CUDA 核函数执行时间、显存操作、CPU/GPU 同步情况等。

💡 举个栗子 (配置总结)

如果你想只分析第 1、2、5 步，且只看 Actor 和 Critic 的前两张卡，且希望每个 Step 生成一个完整文件，配置应该长这样：

trainer:
    profile_steps: [1, 2, 5]  # 👈 关键点1：指定分析哪几步

# 角色1配置
actor_rollout_ref:
    actor:
        profiler:
            discrete: False   # 👈 关键点3：False表示合并成一个文件
            all_ranks: False  # 👈 关键点2：不分析所有卡
            ranks: [0, 1]     # 👈 关键点2：只看前两张

# 角色2配置
critic:
    profiler:
        discrete: False
        all_ranks: False
        ranks: [0, 1]

总结

这篇文档就是教你怎么改 yaml 配置文件来开启“录像”功能，以便你找出代码哪里跑得慢。核心就改三个地方：哪几步(steps)、哪几张卡(ranks)、怎么存(discrete)。
