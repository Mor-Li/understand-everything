docs/perf/perf_tuning.rst

这篇文章主要是在讲 “如何榨干你的显卡性能”，专门针对 verl 这个强化学习（RLHF）训练框架的。

简单来说，训练大模型（尤其是 PPO 这种强化学习）主要分两步： 1. 生成（Rollout）： 模型做题，生成一大堆回答。 2. 训练（Update）： 根据回答的好坏，修改模型参数。

这篇文章就是在教你如何调整参数，让这两个过程跑得更快，且不爆显存（OOM）。

为了让你好理解，我把文中复杂的逻辑拆解成一个 “性能优化 To-Do List”，你可以按这个顺序一步步检查和调整：

🚀 阶段一：加速“做题”速度 (Rollout Generation)

这一步是让模型（Actor）快速生成数据。用的后端通常是 vLLM。

✅ 任务 1：把显存塞满 (vLLM Tuning) * 原理：vLLM 需要预占显存来存 KV Cache。占得越多，能同时处理的并发请求就越多。 * 怎么做： * 找到参数 gpu_memory_utilization。 * 建议值：0.5 到 0.7 之间。 * 注意：太高会导致 OOM（爆显存），太低会浪费显卡算力。注意 vLLM 版本不同（v0.6 vs v0.7），这个比例的计算方式略有不同，但核心逻辑是“给推理留够空间”。

✅ 任务 2：增加并发量 * 原理：显卡就像一辆大巴车，一次拉的人（Token）越多越划算。 * 怎么做： * 如果日志显示 GPU Cache 利用率低，说明没吃饱。 * 调大 max_num_batched_tokens（建议大于 2048）或者 max_num_seqs。

✅ 任务 3：少用张量并行 (TP)，多用数据并行 (DP) * 原理：如果显卡够多，与其让多张卡合作算一个模型（TP），不如让每张卡独立算一个模型（DP/Replicas），后者吞吐量通常更高。 * 怎么做： * 减小 tensor_parallel_size。

📦 阶段二：数据打包 (去除 Padding)

这一步是为了避免显卡计算一堆无意义的“0”或填充符。

✅ 任务 4：开启“去填充”功能 * 原理：通常一句话短、一句话长，为了对齐会补零（Padding）。这很浪费。开启这个功能后，会像俄罗斯方块一样把数据挤在一起。 * 怎么做： * 设置 use_remove_padding=True。 * 适用模型：Llama, Mistral, Gemma, Qwen 等主流模型目前都支持。

🏋️ 阶段三：加速“训练”速度 (Batch Size Tuning)

这一步是调整模型反向传播、更新参数时的效率。

这里有两种策略，二选一：

策略 A：手动调小批次 (Static Batch Size)

如果你不开启动态批次，就需要手动微调 micro_batch_size_per_gpu。

✅ 任务 5：根据不同模型，设置不同的 Batch Size * 核心原则：训练参数（Actor/Critic）比较占显存，推理参数（Ref/Reward）不占显存。 * 怎么做： 1. 开启省显存模式：把 Actor 和 Critic 的 enable_gradient_checkpointing 设为 True。 2. Actor/Critic (训练用)：ppo_micro_batch_size_per_gpu 设小一点。 3. Ref/Reward (只推理)：log_prob_micro_batch_size_per_gpu 可以设大一点（比如是上面的 2 倍）。 4. Critic/Reward 模型：通常比 Actor 模型更能吃数据（因为词表层通常较小），可以设得比 Actor 大。

策略 B：使用动态批次 (Dynamic Batch Size) —— 推荐 🔥

  • 原理：不按“几条数据”算，而是按“总共多少个字（Token）”算。这样更灵活，显存利用率最高。

✅ 任务 6：开启动态批次 * 怎么做： * 设置 use_dynamic_bsz=True。 * 不用管 micro_batch_size 了。 * 改为调整 max_token_len_per_gpu（每张卡最大吃多少个 Token）。

✅ 任务 7：调整动态批次的上限 * 怎么做： * actor.ppo_max_token_len_per_gpu：至少要是 (提问长度 + 回答长度) 的 2 倍以上。作者建议设为 3 倍甚至更多，直到显存快爆为止。 * critic 和 reward 的上限：可以设得非常大（比如 Actor 的 4 倍）。

🛠️ 阶段四：特殊场景优化

✅ 任务 8：超长文本训练 (Long Context) * 场景：如果你要训练超过 32k 长度的文本。 * 怎么做： * 开启 Ulysses 序列并行：ulysses_sequence_parallel_size > 1。 * 同时减小 Batch Size 防止爆显存。

✅ 任务 9：SFT 微调加速 (Liger Kernel) * 场景：做 SFT（有监督微调）时。 * 怎么做： * 安装 pip3 install liger-kernel。 * 配置里设置 use_liger: True。

📝 总结：新手调优路径

如果你完全不想看细节，请按这个傻瓜路径操作：

  1. 先开去填充：use_remove_padding=True。
  2. 再开动态批次：use_dynamic_bsz=True。
  3. 调大 vLLM 显存：gpu_memory_utilization 设个 0.6 左右。
  4. 试探上限：慢慢调大 max_token_len_per_gpu，直到程序报错说 OOM（显存不足），然后往回退一点点。
  5. 区别对待：记得 Critic（评论家模型）和 Reward（奖励模型）比 Actor（演员模型）能吃更多数据，参数给大点。
