docs/faq/faq.rst

这份文档其实是一个常见问题解答（FAQ），专门针对一个叫 verl 的大模型训练框架。

因为原文是根据问题分类的（比如Ray相关、安装相关），对于新手来说确实显得跳跃且晦涩。

为了让你听懂，我把这些内容重新整理成一个“从安装到跑任务，再到修Bug”的操作清单（To-Do List）。你可以按照这个流程来理解文档里的每一个知识点。

第一阶段：环境准备与安装 (Installation & Setup)

在你开始跑代码之前，可能会遇到环境安装的问题。

Task 1: 解决安装包报错（针对 ARM 架构服务器） * 遇到的问题：如果你用的是 Linux-ARM64 架构的机器，安装 tensordict 包时可能会报错 NotImplementedError，或者找不到版本。 * 文档建议： * 方法A：卸载当前的包，从 GitHub 下载源码手动编译安装（文档里给了具体代码）。 * 方法B：临时修改代码，把 key in tensordict 改成 key in tensordict.keys()。

Task 2: 在集群上配置 Ray 和 Slurm * 遇到的问题：很多公司或实验室用 Slurm 系统管理集群。你想在上面用 Ray 框架跑 verl。 * 文档建议： 1. 如果集群支持 Apptainer/Singularity 容器，先把 Docker 镜像转成 Apptainer 镜像。 2. 准备好数据和模型。 3. 修改官方提供的脚本 examples/slurm/ray_on_slurm.slurm，填入你自己的集群信息。 4. 用 sbatch 命令提交任务。

第二阶段：配置训练任务 (Configuration)

环境装好了，现在你要配置参数来准备训练。

Task 3: 理解显存/批量大小 (Batch Size) * 遇到的问题：配置里有 Train Batch Size, Mini Batch Size, Micro Batch Size，搞不清啥区别。 * 文档建议：看了一张图（链接在文档里），理解它们之间的包含关系。简单说就是：总批次 > 小批次 > 微批次。

Task 4: 设置网络代理 (Proxy) * 遇到的问题：训练时需要用 WandB 记录日志（需要联网），但内网机器连不上外网。如果设全局代理又怕影响其他内部通信。 * 文档建议：不要设全局环境变量，而是在训练脚本里加一行配置 +trainer.wandb_proxy=http://你的代理地址，这样只给 WandB 开代理。

Task 5: 解决 CPU 核心数识别错误 * 遇到的问题：启动时报错 "Unable to register worker"，通常是因为 Slurm 限制了 CPU 的可见性，导致 Ray 以为有很多核可以用，实际上没权限。 * 文档建议：手动设置配置项 ray_init.num_cpus，告诉程序到底能用几个核。

第三阶段：运行与调试 (Running & Debugging)

任务跑起来了，但是中途报错或者崩了，这时候看这里。

Task 6: 解决显存非法访问错误 (Illegal Memory Access) * 遇到的问题：训练中途突然崩了，报错 CUDA error: an illegal memory access...。 * 文档建议：这是 vLLM (一个底层库) 的已知 Bug。解决方法是在运行命令前加个环境变量：export VLLM_ATTENTION_BACKEND=XFORMERS。

Task 7: 解决 Triton 编译错误 * 遇到的问题：报错一大堆，里面包含 triton 和 compile_module_from_src。 * 文档建议：这是即时编译（JIT）出了问题。去配置文件里把 use_torch_compile 这个选项关掉（设为 False）。

Task 8: 如何调试代码 (Debugging) * 遇到的问题：代码跑得不对，想打断点（Breakpoint）调试。 * 文档建议：因为是分布式训练，不能直接打断点。请去查看 Ray 的官方文档，学习如何使用 ray-distributed-debugger。

第四阶段：后续分析与处理 (Post-Processing)

训练跑完了，你需要拿结果。

Task 9: 转换模型格式 * 遇到的问题：训练出来的模型 Checkpoint 格式可能不通用，你想转成 HuggingFace 的 safetensor 格式。 * 文档建议：运行脚本 scripts/model_merger.py 来转换。

Task 10: 分析性能瓶颈 (Timeline) * 遇到的问题：训练太慢了，想知道时间都花哪儿了。 * 文档建议： 1. 在配置里加上 ray_init.timeline_file=/tmp/ray_timeline.json。 2. 跑完任务后，拿到这个 JSON 文件。 3. 打开 Chrome 浏览器的 chrome://tracing，把文件拖进去，就能看到详细的时间轴图表。

Task 11: 多机后训练 (Multi-node Post-training) * 遇到的问题：怎么在多台机器上跑后续任务？ * 文档建议：启动 Ray 集群，然后在配置里把 trainer.nnode 设置为机器的数量。

总结

这篇文档就是一个“踩坑指南”。 如果你刚开始用，先看 Task 1, 2。 配置参数时看 Task 3, 4, 5。 跑崩了看 Task 6, 7。 跑完了看 Task 9, 10。
