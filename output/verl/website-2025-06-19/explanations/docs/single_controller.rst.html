docs/single_controller.rst

这份文档是一篇面向开发者的设计文档，主要解释了 verl 框架中 single_controller 这个模块是如何工作的。

简单总结： 它的核心目的是“让写分布式（多显卡）代码像写单机代码一样简单”。通常在多显卡训练时，你需要处理复杂的数据同步和进程管理，而这个模块把这些脏活累活都藏起来了，让你感觉好像只在控制一个进程，但实际上后台有一群工人在帮你干活。

下面我按照你的要求，列一个 Task List，并一步步拆解文中的观点。

核心任务清单 (Task List)

如果你要在这个框架下开发一个分布式功能（比如让多个 GPU 一起生成文本），你需要经历以下 4 个步骤：

  1. [贴标签]： 在你的函数上加一个装饰器 @register，告诉系统这个函数需要分布式运行。
  2. [组建团队]： 创建一个 WorkerGroup（工人组），把你的类放进去。
  3. [自动绑定]： 系统会自动扫描你的类，把贴了标签的函数“改装”成分布式版本。
  4. [一键调用]： 像调用普通函数一样调用它，系统自动完成数据的拆分、分发和结果回收。

逐步讲解 (Step-by-Step Guide)

0. 背景：为什么要搞这个？(Origin)

  • 痛点： 传统的 PyTorch DDP（分布式数据并行）虽然好用，但在做 RLHF（强化学习）时很麻烦，因为流程复杂（不仅仅是简单的训练），且很难调试中间过程。
  • 方案： 作者想用 Ray（一个分布式框架）来管理，但 Ray 默认是一对一调用的。
  • 目标： 作者想做一个“中间层”，把复杂的分布式调用封装起来，让用户无感。

1. 第一步：[贴标签] 使用装饰器注册 (Register)

你在写代码定义一个“工人类”（Worker）时，需要告诉系统哪个方法是核心任务。

  • 操作： 在函数 generate_sequences 上面写 @register(dispatch_mode=...)。
  • 原理： 这个装饰器通过 MAGIC_ATTR 给函数贴了个“便利贴”。
    • 便利贴上写着：这个任务的数据需要切分（Dispatch）、执行模式是全体执行（Execute）、是否阻塞等。
    • 关键点： 此时代码还没跑起来，只是打了个标记。

2. 第二步：[组建团队] 初始化 WorkerGroup (Binding)

这是最神奇的一步。当你创建 RayWorkerGroup 时，它不仅是启动了几个进程，还做了一次“魔改”。

  • 操作： python wg = RayWorkerGroup(resource_pool=..., ray_cls_with_init=...)
  • 原理：
    1. WorkerGroup 启动后，会检查你传入的类。
    2. 它会遍历类里所有的方法，找谁身上贴了 MAGIC_ATTR（刚才那个便利贴）。
    3. 动态生成新方法： 一旦找到，它会根据便利贴的内容，现场写一个新的函数来替换掉原来的逻辑。

3. 第三步：[自动绑定] 数据如何分发与回收 (Dispatch & Collect)

在“动态生成新方法”的过程中，系统配置了三个关键动作，这是分布式运行的核心逻辑：

  • Dispatch (分发)： 比如你有一大块数据（Batch Size = 100），你有 4 个 GPU。
    • 如果是 ONE_TO_ALL 模式：系统把这份数据复制 4 份，每人一份。
    • 如果是 DP_COMPUTE_PROTO 模式：系统把数据切成 4 份（每份 25），每人领一份。
  • Execute (执行)： 命令这 4 个 GPU 同时开始干活。
  • Collect (回收)： 4 个 GPU 干完活了，系统把它们的结果收集起来，拼回成一个完整的结果返给你。

4. 第四步：[一键调用] 实际运行 (Call Chain)

对于使用这个框架的人来说，这一步非常简单。

  • 单机代码写法（旧）： python rollout.generate_sequences(batch) # 只有一个进程在跑
  • Verl 分布式写法（新）： python rollout_group.generate_sequences(batch) # 这是一个 WorkerGroup
  • 发生了什么： 当你调用这行代码时，后台默默完成了：
    1. 切肉： 把 batch 切分成小块。
    2. 派活： 通过网络（RPC）发给远程的 GPU。
    3. 干活： 远程 GPU 运行原始的逻辑。
    4. 装盘： 把结果拼好给你。

总结

这篇文章讲的就是 verl 如何通过装饰器和动态绑定的黑魔法，把复杂的“数据切分-远程执行-结果合并”这套流程自动化了。

你只需要记住：你写的是单机逻辑，Verl 帮你把它变成了分布式执行。
