docs/amd_tutorial

这里是 docs/amd_tutorial 文件夹的通俗导读：

1. 这个文件夹主要负责什么功能？

你可以把这个文件夹看作是 Verl 框架的“AMD 显卡特供说明书”。

通常深度学习框架（如 PyTorch、vLLM）在 NVIDIA 显卡上就像在平原上开车，顺畅无阻。但在 AMD 显卡（ROCm 环境）上运行，可能会遇到“水土不服”的情况（比如驱动不兼容、显存管理机制不同）。

这个文件夹就是为了解决这些“水土不服”，教你如何搭建特定的环境，并对底层引擎进行改装，确保 Verl 能在 AMD MI300 等显卡上顺利、高效地跑起来。

2. 这个文件夹下的各个直接文件是干什么的？

这里有两个核心文档，分别解决了“能不能跑”和“跑得好不好”的问题：

  • 📄 amd_build_dockerfile_page.rst（怎么跑起来：搭建与启动）

    • 作用：这是入门安装向导。
    • 比喻：相当于教你在 AMD 的地基上盖一座能住人的房子（构建 Docker 镜像）。它特别叮嘱你，进门的时候要带一把特殊的钥匙（设置 RAY_... 环境变量），否则房子里的管家（Ray 框架）会因为看不懂 AMD 的门牌号而罢工。
    • 核心：搞定 Dockerfile，搞定启动命令，搞定 Ray 的兼容性。

  • 📄 amd_vllm_page.rst（怎么跑得顺：魔改与优化）

    • 作用：这是进阶改装指南。
    • 比喻：Verl 需要 vLLM 这个引擎来做推理，但原厂引擎在 AMD 上比较费油（显存）。这份文档教你手动改装引擎（编译特制版 vLLM），给它加个“自动启停”功能（Sleep Mode，推理完释放显存），并调整涡轮增压的参数（CUDA Graph 设置），防止油门踩太猛把引擎憋熄火（Crash）。
    • 核心：编译支持 Sleep 模式的 vLLM，限制 CUDA Graph 大小以防崩溃。

4. 给我一个高层的认知

如果说 Verl 是一个赛车手，那么：

  • 普通用户（NVIDIA）：直接上车，点火就能跑。
  • AMD 用户：必须先读完这个 docs/amd_tutorial。
    • 先按第一篇文档（Build Page）把赛道和车库修好（环境搭建）；
    • 再按第二篇文档（vLLM Page）把赛车的引擎参数调校好，防止爆缸（显存优化）。

一句话总结：这是 AMD 显卡用户运行 Verl 的必读生存指南，不看它，你的代码大概率跑不起来或者跑得很慢。
