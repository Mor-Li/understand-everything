这份文档的核心目的是指导用户如何在 AMD GPU（特别是 MI300 系列）上运行 verl 这个强化学习训练框架。

由于 AMD 的软件环境（ROCm）和 NVIDIA（CUDA）不同，不能直接用通用的安装方式，必须通过构建特定的 Docker 镜像并设置特定的环境变量来解决兼容性问题。

为了让你更容易理解，我将文档内容拆解为一个“任务清单 (To-Do List)”，你只需要按顺序执行这些步骤即可。

任务清单：在 AMD GPU 上运行 Verl

第一步：准备 Docker 环境 (Build Docker)

目标：构建一个包含 AMD ROCm 驱动、PyTorch 和 vLLM/SGLang 的运行环境。 原因：AMD 的深度学习环境依赖比较复杂，直接在物理机安装容易出错，官方推荐用 Docker。

  1. 复制 Dockerfile 内容：
    • 文档中 docker/Dockerfile.rocm 下面的代码块，保存为文件 Dockerfile.rocm。
    • 注意点：这个镜像基于 lmsysorg/sglang，因为它支持 vLLM 和 FSDP（完全分片数据并行）。
  2. 构建镜像：
    • 在终端运行命令：docker build -f docker/Dockerfile.rocm -t verl-rocm .
    • 这会生成一个名为 verl-rocm 的 Docker 镜像。

第二步：启动 Docker 容器 (Run Container)

目标：进入刚才构建好的环境，并确保容器能访问 AMD 的 GPU 硬件。

  1. 运行启动命令：
    • 使用文档 Run the container 部分的命令。
    • 关键参数解释：
      • --device /dev/dri 和 --device /dev/kfd：这是让 Docker 能看到 AMD GPU 的关键。
      • --shm-size 128G：防止内存溢出。
      • -v $HOME:$HOME：把你的家目录挂载进去，方便读取数据。

第三步：设置关键环境变量 (Configuration)

目标：解决 Ray 框架在 AMD 环境下的兼容性 Bug。这是文档中最强调的一点。

  1. 检查 Ray 版本：
    • 通常现在的版本都大于 2.45.0。
  2. 设置变量：
    • 在运行训练脚本前，必须执行： export RAY_EXPERIMENTAL_NOSET_HIP_VISIBLE_DEVICES=1
    • 解释：如果不加这个，Ray 可能无法正确识别或调度 AMD GPU，导致报错。

第四步：运行训练任务 (单机模式)

目标：在一台机器上跑通 PPO 或 GRPO 算法。

  1. 准备数据和模型：
    • 下载模型（如 Qwen2.5-0.5B）。
    • 预处理数据（运行 examples/data_preprocess/gsm8k.py）。
  2. 选择推理引擎：
    • 文档默认使用 vLLM (ENGINE=vllm)。
  3. 运行训练脚本：
    • PPO 示例：参考文档 PPO 章节的代码块。
    • GRPO 示例：参考文档 GRPO 章节的代码块。
    • 核心动作：直接复制对应的 python3 -m verl.trainer.main_ppo ... 命令运行即可。

进阶任务：多节点集群训练 (Slurm)

(如果你只有一台机器，可以忽略此部分)

目标：在高性能计算集群（使用 Slurm 调度系统）上，利用多台机器进行大规模训练。

文档提供了一个全自动脚本 (slurm_script.sh)，它的逻辑流程如下：

  1. 环境清理与准备：
    • 脚本会自动加载 Docker 镜像，清理旧容器。
    • 设置大量的网络环境变量（如 NCCL_...），这是为了让多台机器的 GPU 通信顺畅。
  2. 启动 Ray 集群：
    • Head Node (主节点)：脚本会自动在第一台机器上启动 Ray Head。
    • Worker Nodes (工作节点)：脚本会在其他机器上启动 Ray Worker，并连接到主节点。
  3. 数据与模型准备：
    • 在 Docker 容器内自动下载数据和模型。
  4. 开始训练：
    • 最后，脚本会在主节点上触发 verl.trainer.main_ppo 命令，开始分布式训练。

你的 Todo： 1. 将 slurm_script.sh 内容复制并保存。 2. 根据你的集群情况修改头部参数（如 #SBATCH --nodes=2）。 3. 运行 sbatch slurm_script.sh 提交任务。

总结 (TL;DR)

这篇文章其实就讲了三件事： 1. 装环境：用 Dockerfile.rocm 建个 Docker。 2. 打补丁：运行前记得 export RAY_EXPERIMENTAL_NOSET_HIP_VISIBLE_DEVICES=1。 3. 跑代码：提供了单机和多机（Slurm）的运行脚本模板，直接抄作业改改参数就能跑。
