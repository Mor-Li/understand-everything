这份文档主要是写给使用 AMD 显卡（ROCm环境）来运行 verl（一个强化学习训练框架）的开发者的。

它的核心目的是：解决 AMD 显卡上显存不够用和运行速度慢的问题。

简单来说，verl 训练时需要用到 vLLM 进行推理。为了省显存，verl 希望 vLLM 在不用的时候能“休眠”（把显存腾出来给训练用）。但这个功能在 AMD 显卡的原版软件上支持得不好，所以文档教你怎么打补丁和改配置。

为了让你更容易理解，我把它拆解成一个 4步走的 Task List（待办清单）：

📋 待办清单 (Task Todo List)

  1. [环境准备] 检查并升级你的 AMD ROCm 驱动版本。
  2. [软件安装] 并不使用官方 vLLM，而是下载并编译一个“特制版”的 vLLM。
  3. [功能验证] 运行一段测试代码，确认“休眠模式”真的生效了。
  4. [性能优化] 修改配置开启 CUDA Graph 加速，同时防止因为显卡驱动问题导致的崩溃。

💡 逐步详细讲解

第一步：检查并升级 AMD ROCm 版本

  • 文档原文观点：
    • 显卡驱动版本太低不行。
    • 必须 $\ge$ ROCm 6.3.4。
    • 强烈推荐使用 ROCm 6.4.0，性能更好。
  • 你需要做：
    • 确认你服务器或 Docker 容器里的 ROCm 版本。如果是旧版本，请升级。

第二步：安装“特制版” vLLM (开启休眠模式)

  • 文档原文观点：
    • verl 需要 vLLM 支持“休眠模式”（Sleep Mode），即推理完把显存吐出来，把数据挪到 CPU 内存里。
    • 官方的 vLLM 还没合并这个功能，所以要去下载一个网友修改过的分支（branch: sleep_amd）。
  • 你需要做：
    • 卸载原有的 vLLM。
    • 执行文档给出的命令（git clone ..., python3 setup.py develop 等）从源码编译安装这个特制版本。

第三步：验证“休眠模式”是否生效

  • 文档原文观点：
    • 装好后，别盲目开始跑大任务，先跑个小脚本测一下。
    • 如果显存在 llm.sleep() 后显著下降，说明成功了。
  • 你需要做：
    • 复制文档中间那段 Python 代码（import torch... 那段）。
    • 运行它。
    • 观察输出：CUDA Memory Usage (after sleep) 的数值应该比 after inference 小很多。如果没变小，说明安装有问题。

第四步：开启加速并防止崩溃 (CUDA Graph 设置)

  • 文档原文观点：
    • 有一个叫 CUDA Graph 的技术可以让推理变快。
    • 但是：在 AMD 显卡上，如果一次处理的数据（batch）太大，开启这个功能会导致程序直接崩溃（Crash）。
    • 解决办法：手动限制 CUDA Graph 捕获的大小，只允许小 batch（如 1, 2, ..., 64）使用这个加速功能，避开大 batch 导致的崩溃。
  • 你需要做：
    1. 改代码/配置：在你的 verl 配置或代码中（vllm_rollout_spmd.py），找到 LLM 初始化的部分，加上 compilation_config={"cudagraph_capture_sizes": [1, 2, 4, 8, 16, 32, 64]}。
    2. 开启加速开关：设置环境变量或参数 enforce_eager=False（意思是不强制使用慢速模式，即开启加速）。

总结

这篇文档就在说两件事： 1. 为了省显存：请手动编译安装支持 AMD 休眠模式的 vLLM 版本。 2. 为了提速且不崩：请限制 CUDA Graph 的捕获大小，只对小 Batch 开启加速。
