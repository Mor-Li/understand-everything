examples/data_preprocess/preprocess_search_r1_dataset.py

这份代码其实是一个数据“清洗”和“打包”的流水线脚本。

它的核心目的是：把从网上下载的原始问答数据，改造成专门用来训练“会思考、会搜索的AI（类似 DeepSeek-R1）”的格式。

为了让你听懂，我把这个脚本的工作拆解成一个 5步走的 Task List（任务清单），我们一步步来看：

📋 Task 1：制定“游戏规则” (定义提示词)

代码位置： 开头的 DEFAULT_SYSTEM_CONTENT 和 DEFAULT_USER_CONTENT_PREFIX 变量。 任务说明： 在处理数据前，先规定好训练 AI 时要对它说的话。 * 设定人设 (System)：告诉 AI “你是一个乐于助人且无害的助手”。 * 设定指令 (User Prefix)：这是最关键的！它强行规定了 AI 的回答格式： 1. 必须先在 <think> 标签里思考。 2. 如果不懂，可以用 <tool_call> 标签去调用搜索引擎。 3. 最后在 <answer> 标签里写出答案。

这一步的观点： 只有把这些指令加到数据里，训练出来的 AI 才会养成“先思考、遇事不决查搜索、最后给答案”的好习惯。

📋 Task 2：设计“加工车间” (处理单行数据)

代码位置： def process_single_row(...) 函数。 任务说明： 这是流水线的核心。 raw data（原始数据）进来，formatted data（格式化数据）出去。 假设原始数据只有一行：“北京的首都是哪里？” 这个函数要做这几件事： 1. 拼接 Prompt：把 Task 1 里的“游戏规则”和“具体问题”拼在一起，变成一段完整的对话录音。 2. 提取标准答案 (Ground Truth)：从数据里把正确答案找出来（比如“Beijing”），为了后面判断 AI 答得对不对。 3. 配置工具参数 (tools_kwargs)：这是给训练框架看的。它告诉环境：“如果 AI 发起搜索，你要用这个正确答案去验证它，或者辅助它”。 4. 打包：把上面所有东西塞进一个新的“包裹”（Pandas Series）里。

这一步的观点： 原始数据太乱，必须统一整理成包含 prompt（输入）、ground_truth（答案）和 extra_info（辅助信息）的标准格式，模型才能吃得下去。

📋 Task 3：进货 (下载数据)

代码位置： main() 函数里的 hf_hub_download 部分。 任务说明： 工厂开工前得有原料。 * 脚本会自动连接 HuggingFace（一个AI模型/数据社区）。 * 下载指定的仓库（PeterJinGo/nq_hotpotqa_train）里的 train.parquet 和 test.parquet 文件。 * 把它放到一个临时的文件夹里备用。

这一步的观点： 自动化下载，不需要人手动去网页上下文件。

📋 Task 4：开动流水线 (批量处理与保存)

代码位置： main() 函数里的 df_raw.apply(...) 和 to_parquet。 任务说明： * 读取：打开下载好的文件。 * 批量加工：调用 Task 2 里的“加工车间”函数，把成千上万条数据全部处理一遍。 * 存盘：把处理好的数据保存到你电脑的本地目录（~/data/searchR1_processed_direct）。

这一步的观点： 这一步把“生肉”变成了“熟肉”，可以直接喂给 AI 训练程序了。

📋 Task 5：入库归档 (上传 HDFS - 可选)

代码位置： main() 函数最后的 if args.hdfs_dir: 部分。 任务说明： 如果你在公司的大集群上工作，本地文件可能会丢。 * 这个任务会检查你有没有提供 HDFS（大数据分布式存储）的地址。 * 如果有，就把刚才处理好的文件复制一份到云端硬盘/集群硬盘里备份。

这一步的观点： 保证数据安全，方便多台机器读取训练。

总结

这个脚本其实就干了一件事：

把“普通问答数据” $\rightarrow$ 变成 $\rightarrow$ “教 AI 如何思考和使用搜索工具的训练数据”。

它并没有在训练模型，它只是在准备食材。
