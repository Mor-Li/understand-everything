verl/utils/megatron/tensor_parallel.py

这份代码确实涉及到了大模型训练中最硬核的部分——张量并行（Tensor Parallelism, TP）。如果你对分布式训练不熟悉，看这份代码就像看天书一样正常。

简单来说，这个文件是 VeRL (Volcengine Reinforcement Learning) 框架为了适配 Megatron-LM（英伟达开发的大模型训练框架）而写的一个“工具箱”。

它的核心目的是：当一个大模型大到一张显卡装不下，需要把它的参数矩阵（Tensor）切分到多张显卡上时，如何正确地配置模型、以及如何正确地计算数学公式（如熵、概率）。

1. 核心观点 List（这文件里到底有什么？）

这个文件主要干了三件事：

  1. 配置帮手 (Configuration Helpers)：
    • Megatron 的层（Layer）初始化需要很复杂的配置参数。这里提供了一堆函数（比如 get_default_...），帮你自动填好默认参数，让你能轻松创建并行的 Linear 层或 Embedding 层。
  2. 参数检查 (Inspection Utilities)：
    • 提供函数来检查某个参数是不是被切分过的（TP），以及它是怎么切分的。
  3. 并行数学计算 (Parallel Math Operations)：
    • 这是最难也最重要的部分。当词表（Vocabulary）被切分到不同显卡上时（比如 10万个词，卡1负责前5万，卡2负责后5万），计算熵 (Entropy) 和 对数概率 (Log Probs) 变得很复杂。你不能只在本地算，必须和别的显卡通信。这个文件实现了这些可以在多卡间同步计算的数学函数。

2. Task Todo List（如果我要实现这个，步骤是啥？）

想象你正在开发 VeRL 框架，要把 RL 算法（如 PPO）跑在 Megatron 切分的大模型上，你的 Todo List 是这样的：

  • Task 1: 初始化模型层
    • [ ] Megatron 的 ColumnParallelLinear 需要传一堆 config，太麻烦了。
    • [ ] 实现：写一堆 get_default_kwargs... 函数，把通用的配置（如初始化方法、dtype）封装起来，方便上层调用。
  • Task 2: 搞定强化学习需要的数学指标（熵）
    • [ ] RL 算法为了鼓励探索，需要计算策略的熵 (Entropy)。
    • [ ] 问题：模型的输出层（Logits）被切分了。显卡 A 只有一部分 Logits，显卡 B 有另一部分。计算 Softmax 需要全局的分母（所有 exp 的和）。
    • [ ] 实现：写一个 vocab_parallel_entropy。在计算过程中，让所有显卡通过 dist.all_reduce 交换数据，算出全局正确的熵，并支持反向传播（自动求导）。
  • Task 3: 搞定序列数据的概率计算
    • [ ] 训练时需要知道模型生成某个 Token 的概率（Log Prob）。
    • [ ] 实现：vocab_parallel_log_probs_from_logits，复用 Megatron 的交叉熵计算逻辑。
  • Task 4: 优化显存（处理变长序列）
    • [ ] 现在的训练都用 FlashAttention 的 "remove padding" (rmpad) 技巧，把所有句子拼成一条长蛇，去掉 padding 以省显存。
    • [ ] 实现：vocab_parallel_log_probs_from_logits_response_rmpad。先把数据还原（unpad），算出概率，再拼回去。

3. 逐步讲解（手把手读代码）

我们把代码分成三块来讲。

第一块：配置生成器 (Line 27 - 83)

这部分全是 get_default_... 开头的函数。 * 背景：Megatron 定义模型层（比如全连接层 Linear）时，不接受简单的参数，它要求传入一个 ModelParallelConfig 对象。 * 代码做了啥： * get_default_model_parallel_config(): 创建一个基础的配置对象，设定好 float32，不使用 CPU 初始化等默认值。 * get_default_kwargs_for_column_parallel_linear(): 专门为“列并行”线性层准备配置。 * 观点：这是为了解耦。VeRL 不想在主逻辑里写满 Megatron 的配置代码，所以在这里统一管理默认值。

第二块：参数检查 (Line 86 - 98)

  • 代码：is_tensor_parallel_param(param)
  • 解释：判断一个 PyTorch 的参数（Tensor）是不是被切分过的。Megatron 会给切分过的参数打上标记 tensor_model_parallel。这主要用于后续的检查和保存模型时的处理。

第三块：并行数学计算（核心难点） (Line 101 - End)

这是本文件的精华。我们重点看 熵 (Entropy) 的计算。

场景： 假设词表大小是 4，模型输出 logits 为 [2.0, 1.0, 0.5, 0.1]。 现在有 2 张显卡进行张量并行（TP=2）。 * GPU 0 拿着前两个数：[2.0, 1.0] * GPU 1 拿着后两个数：[0.5, 0.1]

问题：要计算 Softmax，公式是 $e^{x_i} / \sum e^{x_j}$。 GPU 0 知道分子，但它不知道分母！因为分母需要加上 GPU 1 里的那些数的指数和。

代码 _VocabParallelEntropy 的逻辑：

  1. forward (前向传播):

    • logits_max = ...: 先找自己手里的最大值。
    • dist.all_reduce(logits_max, op=dist.ReduceOp.MAX, ...): 关键步骤！ 所有显卡大喊一声自己手里的最大值，然后大家都拿到了全局最大值。（为了数值稳定性，防止 exp 溢出）。
    • normalized_vocab_parallel_logits = ...: 减去最大值。
    • normalized_sum_exp_logits = ...: 自己算自己手里的 exp 之和。
    • dist.all_reduce(..., group=...): 关键步骤！ 所有显卡再次通信，把大家的 exp 之和加在一起。现在每张卡都知道全局分母了。
    • 接下来就是标准的 Softmax 和 Entropy 公式计算：$Entropy = \sum -p \cdot \log(p)$。
    • 最后再次 all_reduce 把散落在各卡的计算结果加起来，得到最终的一个标量熵。

  2. backward (反向传播):

    • 因为这是手写的 PyTorch Function，必须手写梯度计算公式。代码里实现了熵对于 logits 的导数。

其他函数： * vocab_parallel_log_probs_from_logits: * 计算 Log Probability 其实就是负的 Cross Entropy。这里直接偷懒调用了 Megatron 库里的 tensor_parallel.vocab_parallel_cross_entropy。 * vocab_parallel_log_probs_from_logits_response_rmpad: * 这是为了处理 FlashAttention 格式的数据。 * 输入的数据是去掉了 Padding 的一维长条（为了省显存）。 * 函数逻辑： 1. unpad_input: 把长条数据还原成带 Padding 的 [batch, seq_len] 格式，并记录原来的位置。 2. vocab_parallel_log_probs...: 调用上面的函数算概率。 3. pad_input: 把算好的概率再压缩回 FlashAttention 需要的格式。 * 用途：在 PPO 训练中，我们需要针对模型生成的回答（Response）计算概率，这个函数就是干这个的，同时处理了并行和显存优化。

总结

这篇代码是 VeRL 框架和 Megatron-LM 框架之间的“胶水”。 它解决了一个核心矛盾：强化学习算法需要计算全局的概率分布（如熵），但底层模型为了存得下，把概率分布切碎放在了不同显卡上。 这个文件通过手动管理显卡间的通信（all_reduce），把切碎的数据逻辑上连起来，算出了正确的数学指标。
