fp16/loss_scaler.py

这个文件看起来很吓人，但其实它只做了一件事：为了让模型能用“半精度（FP16）”训练，想办法把原本太小的数字“放大”来看。

为了让你看懂，我把这个文件的逻辑拆解成三个部分： 1. 核心背景（为什么要用这个？） 2. Task To-Do List（代码在干什么活？） 3. 代码逐段解析（怎么实现的？）

第一部分：核心背景（秒懂版）

现在的深度学习模型通常用 FP32（32位浮点数）训练。为了加速和省显存，大家想用 FP16（16位浮点数）。 但是 FP16 有个大坑：它的刻度尺不够细。

  • 问题（Underflow/下溢）： 训练时梯度（Gradient）往往非常非常小（比如 0.0000001）。FP16 存不下这么小的数，会直接把它们当成 0。如果梯度是 0，模型就不学东西了。
  • 解决办法（Loss Scaling）： 在算梯度之前，先把 Loss（误差）放大 比如 1000 倍。这样梯度也就变大了 1000 倍，FP16 就能存下来了。
  • 副作用（Overflow/上溢）： 既然放大了，有时候运气不好，梯度本身就很大，再放大就爆了（变成 Infinity/无穷大）。
  • 最终方案（Dynamic Scaling）： 搞一个智能调节器。先尝试放大很多倍，如果发现爆了（Overflow），就缩小一点倍数；如果一直没爆，就尝试再放大一点。

这个文件 loss_scaler.py 就是这个“智能调节器”。

第二部分：Task To-Do List

想象你是一个负责调节显微镜倍数的实验员（LossScaler），你的工作流程如下：

✅ Task List (训练循环中的步骤)

  1. [设定倍数] 拿出一个初始的放大镜倍数（loss_scale），通常设得很大（比如 $2^{32}$）。
  2. [放大误差] 拿到模型算出的 Loss 后，用倍数乘以 Loss (scaled_loss = loss * scale)。
  3. [反向传播] 对放大的 Loss 进行反向传播，算出“放大版”的梯度。
  4. [安全检查] 检查所有的梯度：
    • 有没有变成 NaN (不是数)？
    • 有没有变成 Inf (无穷大)？
  5. [决策与更新]
    • 情况 A（出事了/Overflow）： 发现梯度爆了。
      • 动作： 这一轮训练作废（不更新模型参数）。
      • 调节： 把放大倍数减小（除以2），下次小心点。
    • 情况 B（一切正常）： 梯度都在有效范围内。
      • 动作： 把梯度除以放大倍数（还原回去），更新模型参数。
      • 调节： 如果连续很多次（比如2000次）都没出事，说明倍数太保守了，把放大倍数增大（乘以2）。

这个文件就是在写这个流程的控制代码。

第三部分：一步一步讲代码观点

文件中主要定义了两个类：LossScaler（固定倍数，傻瓜式）和 DynamicLossScaler（动态调节，智能式）。重点看 DynamicLossScaler。

1. 初始化 (准备放大镜)

__init__ 函数里定义了调节器的初始状态。 * cur_scale: 当前的放大倍数（默认 $2^{32}$，非常大）。 * scale_factor: 调节因子（默认 2.0）。意思是如果爆了就除以2，如果稳了就乘以2。 * scale_window: 观察窗口（默认 1000）。意思是连续 1000 步没出事，我才敢把倍数调大。

2. 放大 Loss (Task 2 & 3)

对应代码中的 backward 方法：

def backward(self, loss, retain_graph=False):
    # 观点：所有的梯度计算都基于这个放大后的 Loss
    scaled_loss = loss * self.loss_scale 
    scaled_loss.backward(retain_graph=retain_graph)

这里很简单，就是把 Loss 乘上当前的倍数，然后让 PyTorch 去算梯度。

3. 安全检查 (Task 4)

对应代码中的 has_overflow 和 _has_inf_or_nan 方法：

def has_overflow(self, params):
    for p in params:
        # 观点：遍历每一个参数的梯度，只要有一个是 Inf 或 NaN，就视为“溢出”
        if p.grad is not None and DynamicLossScaler._has_inf_or_nan(p.grad.data):
            return True
    return False

它像个安检员，挨个检查梯度。_has_inf_or_nan 里面用了一些技巧（比如转成 float 求和）来判断数值是不是炸了。

4. 决策与更新 (Task 5)

这是核心逻辑，对应 update_scale 方法：

def update_scale(self, overflow):
    # overflow 是个布尔值，True 表示刚才检查出问题了

    if overflow:
        # 观点：如果溢出（爆了），说明倍数太大。
        # 动作：把当前倍数除以 factor（变小），并记录这次出事的迭代次数。
        self.cur_scale = max(self.cur_scale/self.scale_factor, self.min_scale)
        self.last_overflow_iter = self.cur_iter
    else:
        # 观点：如果没溢出，说明很安全。
        # 检查：是不是已经连续 scale_window (比如1000) 步都没出事了？
        if (self.cur_iter - self.last_overflow_iter) % self.scale_window == 0:
            # 动作：尝试把倍数乘以 factor（变大），以此来试探边界。
            self.cur_scale *= self.scale_factor

    self.cur_iter += 1

总结

这个文件的观点是：FP16 训练就像走钢丝，由于精度不够，我们需要一个“动态放大镜”。

  • 激进策略：起手先用巨大的倍数放大 Loss，防止梯度消失（Underflow）。
  • 容错机制：如果倍数太大导致梯度爆炸（Overflow），立刻认怂，减小倍数，跳过这一步。
  • 贪婪机制：如果长期没事，就尝试增大倍数，始终保持在“不爆炸的前提下尽可能大”的状态，以保证精度最高。

你看懂这个逻辑后，再回看代码，它就是把这个“试探-反馈-调节”的过程写成了 Python 而已。
