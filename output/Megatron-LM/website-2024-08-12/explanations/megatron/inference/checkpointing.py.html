megatron/inference/checkpointing.py

这份代码主要是在处理 NVIDIA Megatron-LM 框架和 NVIDIA ModelOpt（模型优化工具，比如用于量化、剪枝）之间的对接。

简单来说，它的核心任务是：“如何正确地加载一个可能经过了优化的、格式各异（可能是分片的、可能是 .nemo 格式的）的模型检查点（Checkpoint）。”

为了让你听懂，我把这段代码的逻辑拆解成一个 “加载优化模型的 TODO List”。想象你是一个仓库管理员，你需要把货物（模型参数）从仓库（硬盘）搬到货架（显存）上。

任务清单 (TODO List)

第一步：前置准备 (环境检查)

代码位置： 开头的 try...except ImportError * 任务： 检查你的工具箱里有没有 nvidia-modelopt 这个工具。 * 逻辑： 如果你没安装这个库，这活儿没法干，直接报错停止。

第二步：只加载“优化配置说明书” (不搬运重物)

代码位置： 函数 load_modelopt_state 场景： 有时候我们只需要知道模型是“怎么被优化的”（比如量化的缩放系数是多少），而不需要把几百 GB 的模型权重全部读进内存。

  • Sub-task 2.1：确定仓库位置

    • 看参数 load_dir，如果没有指定，就去读全局参数 args.load。

  • Sub-task 2.2：判断仓库类型（是分布式存储还是单体存储？）

    • 情况 A：分布式存储 (args.use_dist_ckpt 为真)
      1. 找路标： 看看有没有 latest_checkpointed_iteration.txt 文件，确定要读第几次迭代的版本。
      2. 找特定房间： 或者是直接看有没有 .nemo 格式特有的 model_weights 目录。
      3. 取说明书： 进入对应的目录，找 modelopt_state 文件夹。
      4. 执行： 如果找到了，用分布式加载工具 (dist_checkpointing.load) 只把这个元数据读出来。
    • 情况 B：传统/单体存储 (else)
      1. 全量读取： 尝试加载基础的 Checkpoint 文件。
      2. 提取： 从读进来的大字典里，把 modelopt_state 这一页撕下来返回。

第三步：加载真正的“模型权重” (搬运重物)

代码位置： 函数 load_modelopt_checkpoint 场景： 现在要正式把模型参数加载到模型里去，准备开始推理了。这里有个大坑：不同格式的 Checkpoint，参数的名字（Key）可能不一样。

  • Sub-task 3.1：定义“改名规则” (Hook 函数)

    • 问题： 存档里的名字可能是 model.layers.0.weight，但你现在的模型代码里叫 layers.0.weight。多了个 model. 前缀。
    • 对策： 定义一个内部函数 _remove_prefix_state_dict_pre_hook。它的作用是：在加载数据前，如果发现名字里有 model. 这种前缀，把它切掉，以匹配当前模型的变量名。

  • Sub-task 3.2：识别是否为 .nemo 分片格式

    • 检查加载路径下是否存在 model_weights 文件夹。如果存在，说明这是特殊格式（通常是 .nemo 解压出来的）。

  • Sub-task 3.3：分支执行加载

    • 分支 A：是 .nemo / 分片格式 (走这里稍微麻烦点)

      1. 拆包模型： 用 unwrap_model(model) 拿到原始模型对象。
      2. 临时调整配置 (Hack)： 设置 non_homogeneous_layers = False。
        • 通俗解释： 这是一个临时的“补丁”。为了让加载时的形状计算对齐，先把这个开关关掉，等加载完了再开回来。
      3. 准备空壳： 获取模型的 sharded_state_dict（分片状态字典结构）。
      4. 挂载改名器： 把上面定义的“改名规则 (Hook)”挂上去。
      5. 搬运数据： 调用 dist_checkpointing.load 把硬盘上的数据填进模型里。
      6. 恢复配置： 把 non_homogeneous_layers 设回 True。

    • 分支 B：是普通 Megatron 格式

      1. 直接干： 直接调用 Megatron 自带的 load_checkpoint 函数，不需要做那些花里胡哨的前缀修改和配置调整。

总结：这代码到底在干啥？

这代码主要是为了兼容性。

  1. 兼容 ModelOpt： 它确保能单独把模型优化的元数据（比如量化信息）读出来。
  2. 兼容 .nemo 格式： 很多时候模型是用 NVIDIA NeMo 框架训练并导出的（文件夹结构不同，变量名多了前缀）。这段代码能自动识别这种格式，帮你在加载时自动改名（去掉前缀）并调整配置，让 Megatron 的推理引擎能顺利吃进 NeMo 的模型权重。
