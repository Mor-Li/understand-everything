megatron/core/tensor_parallel/mappings.py

这份代码确实非常抽象，因为它处理的是分布式训练中最底层的“通信逻辑”。如果不了解 Megatron-LM 的并行原理，看这份代码就像看天书。

简单来说，这个文件的作用是：告诉 PyTorch，当模型被切分到多张显卡上时，数据（Tensor）该怎么切（Split）、怎么合（Gather）、怎么同步（Reduce），以及在反向传播算梯度时，该怎么做相反的操作。

🚀 逐步讲解

Task 1: 理解背景 —— 为什么要切分 Tensor？

假设你有一个巨大的矩阵乘法 $Y = X \times A$。 * $X$ 是输入数据。 * $A$ 是模型参数（权重矩阵）。 * 问题：矩阵 $A$ 太大了，一张显卡（GPU）放不下。 * 解决：我们把 $A$ 切成几块，分给不同的 GPU。这就是 Tensor Parallel (TP)。

这个文件的作用：定义了一些“连接器”。当数据流经这些被切开的层时，需要用这些函数来处理数据的合并与分发。

Task 2: 掌握四个原子动作 —— 显卡之间怎么“传球”？

代码的前半部分（_reduce, _split..., _gather...）全是这种基础动作。想象有 2 张 GPU（Rank 0 和 Rank 1）：

  1. Split (切分):

    • 代码: _split_along_last_dim, _split_along_first_dim
    • 含义: 一个完整的 Tensor [1, 2, 3, 4]。
    • 结果: GPU 0 拿 [1, 2]，GPU 1 拿 [3, 4]。大家各拿一部分。

  2. Gather (收集/聚合):

    • 代码: _gather_along_last_dim, _gather_along_first_dim
    • 含义: Split 的逆操作。GPU 0 有 [1, 2]，GPU 1 有 [3, 4]。
    • 结果: 大家通信，最后每张卡都得到了完整的 [1, 2, 3, 4]。

  3. Reduce (All-Reduce 归约):

    • 代码: _reduce
    • 含义: 大家都有不一样的数据，想求和。GPU 0 有 [1]，GPU 1 有 [2]。
    • 结果: 通信后，GPU 0 得到 [3] (1+2)，GPU 1 也得到 [3]。关键点：保持形状不变，数值相加。

  4. Reduce-Scatter (归约并切分):

    • 代码: _reduce_scatter...
    • 含义: 先求和，再切分。比 "先Reduce再Split" 更高效。

Task 3: 理解核心机制 (Autograd) —— 为什么会有 Forward 和 Backward？

这是看懂这份代码最关键的一步。

PyTorch 的 torch.autograd.Function 允许你自定义算子。对于分布式训练，有一个黄金法则：

前向传播 (Forward) 做的通信操作，反向传播 (Backward) 通常要做“数学上共轭”的操作（通常是逆操作）。

举个例子（代码中的 _CopyToModelParallelRegion 类）：

  • 场景: 输入 $X$ 是完整的，准备进入一个被切分的层。
  • Forward: 什么都不用做，直接把 $X$ 复制给各个 GPU 即可（代码里直接 return input）。
  • Backward (算梯度):
    • 因为 Forward 时大家都有 $X$，相当于 $X$ 被用了 $N$ 次（每张卡一次）。
    • 算 $X$ 的梯度时，必须把所有卡上算出来的关于 $X$ 的梯度加起来。
    • 代码逻辑: python def backward(ctx, grad_output): return _reduce(grad_output) # 调用 All-Reduce 动作

再举个例子（代码中的 _ScatterToModelParallelRegion 类）：

  • Forward: 把完整的 Tensor 切开，分给不同 GPU（调用 _split）。
  • Backward: 既然前向是切开，反向传播时，就要把各张卡上的梯度拼回来（调用 _gather）。

Task 4: 场景一 (Tensor Parallel) —— 模型太宽，怎么切？

Megatron-LM 经典的 MLP 层切分策略是：先列切（Column Parallel），再行切（Row Parallel）。

  1. copy_to_tensor_model_parallel_region:

    • 用途: 在进入并行区域前使用。
    • 动作: Forward 复制（Identity），Backward 求和（All-Reduce）。
    • 什么时候用: 当你把权重矩阵按“列”切分时，输入数据 $X$ 需要完整地拷贝到每张卡上。

  2. gather_from_tensor_model_parallel_region:

    • 用途: 并行计算结束了，想把结果拼起来。
    • 动作: Forward 拼凑（All-Gather），Backward 切分（Split）。
    • 什么时候用: 当你需要得到一个完整的输出 Tensor 时。

  3. reduce_from_tensor_model_parallel_region:

    • 用途: 也就是代码里的 _ReduceFromModelParallelRegion。
    • 动作: Forward 求和（All-Reduce），Backward 复制（Identity）。
    • 什么时候用: 当你把权重矩阵按“行”切分时，每张卡算出的是部分和，最后需要把结果加起来。

Task 5: 场景二 (Sequence Parallel) —— 句子太长，怎么切？

后来人们发现，显存还是不够，于是发明了 Sequence Parallel (SP)。不再切权重矩阵，而是把输入数据的“句子长度”切开。

  • 比如句子长 1024，有 2 张卡。每张卡只处理 512 个 token。

  • scatter_to_sequence_parallel_region:

    • 动作: Forward 沿着第1维度（序列长）切分。
    • 含义: 把长句子切短，分给每张卡。

  • gather_from_sequence_parallel_region:

    • 动作: Forward 沿着第1维度拼接。
    • 含义: 把各张卡处理完的半截句子，拼成一个长句子。

  • MoE (Mixture of Experts) 相关:

    • 代码里带 _moe 后缀的，是因为 MoE 模型的通信量巨大，有时需要用特殊的 Global Memory Buffer 来优化性能，但逻辑和普通 SP 是一样的。

📝 总结：如何阅读这个文件

不要一行行读，要按类 (Class) 读。每个 Class 代表一个“连接器”。

  1. 看 类名：猜它是干嘛的（比如 Scatter 就是切分，Gather 就是拼接）。
  2. 看 Forward：看它在前向传播时调用了哪个原子函数（_split, _gather, _reduce）。
  3. 看 Backward：验证你的直觉。
    • 如果 Forward 是 Split，Backward 必须是 Gather。
    • 如果 Forward 是 Gather，Backward 必须是 Split (或者 ReduceScatter)。
    • 如果 Forward 是 Identity (直接通过)，Backward 必须是 All-Reduce。

这个文件就是 Megatron-LM 的交通指挥官，指挥数据流在多张显卡的高速公路上如何拆分、合并和掉头（反向传播）。
