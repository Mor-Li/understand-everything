megatron/core/dist_checkpointing/strategies/torch.py

这份代码确实比较晦涩，因为它处于两个复杂系统的交界处：Megatron-Core (MCore) 的分布式张量管理系统和 PyTorch 原生 的分布式检查点系统 (torch.distributed.checkpoint，简称 DCP)。

简单来说，这个文件的作用是一个“翻译官”或者“适配器”。它负责把 MCore 内部定义的切分张量（ShardedTensor），转换成 PyTorch 能听懂的格式，以便利用 PyTorch 的底层功能进行存取。

为了让你看懂，我把这个文件要做的事情拆解成一个 Project To-Do List（任务清单），模拟程序执行的逻辑流程。

核心任务清单：如何实现“翻译”与存取

这个文件主要定义了两个核心策略类：TorchDistSaveShardedStrategy (负责存) 和 TorchDistLoadShardedStrategy (负责取)。

Task 1: 存盘流程 (Saving Workflow)

目标：把显存里切碎的 MCore 张量，存成 PyTorch 格式的文件。

  1. [准备] 整理字典键值 (Flatten Keys)

    • 代码位置: _replace_state_dict_keys_with_sharded_keys
    • 动作: MCore 的状态字典可能是嵌套的（字典套字典）。第一步要把它们“拍平”成一层，并处理好键名（Key），方便后续索引。

  2. [转换] 核心翻译：MCore -> PyTorch (The Translation)

    • 代码位置: mcore_to_pyt_state_dict -> sharded_tensor_to_torch_sharded_tensor
    • 动作: 这是最难的一步。
      • MCore 说：“我有一个大张量，被切成了很多块，我现在手里拿着第 [x, y] 块。”
      • 这个函数要把它转换成 PyTorch 的 ShardedTensor 对象。它需要计算：全局形状是多少？我这一块在全局的哪个偏移量（Offset）？
      • 难点: 代码中处理了三种情况：普通切分、1D 扁平化切分、N-D 扁平化切分（这是 MCore 特有的优化，需要复杂的数学计算来重组形状）。

  3. [规划] 制定保存计划 (Planning)

    • 代码位置: MCoreSavePlanner
    • 动作: 并不是所有 GPU 都把所有数据写到磁盘。这个 Planner 决定谁负责写什么。
    • 特例: 它还专门处理了 io.BytesIO 对象（非张量数据），确保这些元数据也能被正确保存。

  4. [执行] 异步写入 (Async Write)

    • 代码位置: TorchDistSaveShardedStrategy.async_save
    • 动作: 调用 PyTorch 的 FileSystemWriterAsync。因为保存很慢，所以是“异步”的，程序可以继续跑，后台慢慢写磁盘。

Task 2: 读盘流程 (Loading Workflow)

目标：从磁盘读取文件，还原成 MCore 需要的切分张量格式。

  1. [准备] 读取元数据 (Read Metadata)

    • 代码位置: get_reformulation_metadata
    • 动作: 先读一下文件头，看看存了哪些张量，它们的原始形状是什么。特别是对于那些“N-D 扁平化”的特殊张量，需要获取它们变形前的形状。

  2. [重组] 计算切分逻辑 (Resharding Logic)

    • 代码位置: apply_nd_flattened_tensors_reformulation
    • 动作: 因为读取时的 GPU 数量可能和保存时不一样（比如 8卡存，4卡读）。这里需要根据元数据，重新计算当前每个 GPU 应该加载哪一部分数据。

  3. [转换] 建立空壳 (Setup Empty Shells)

    • 代码位置: mcore_to_pyt_state_dict (带 is_loading=True 参数)
    • 动作: 在显存里先创建好一堆“空的”PyTorch ShardedTensor，告诉 PyTorch：“一会儿请把数据填到这里面”。

  4. [执行] 加载数据 (Load)

    • 代码位置: checkpoint.load_state_dict
    • 动作: 调用 PyTorch 原生接口，从磁盘读取数据并填充到刚才建立的空壳里。
    • 细节: MCoreLoadPlanner 会在这里发挥作用，它会校验加载进来的形状是否匹配，并处理 FP8（8位浮点数）张量的特殊内存连续性问题。

  5. [还原] 逆向翻译：PyTorch -> MCore (Unwrap)

    • 代码位置: _unwrap_pyt_sharded_tensor
    • 动作: 数据加载完了，现在手里是 PyTorch 的对象。需要把里面的 Tensor 数据取出来，塞回 MCore 的对象里，并恢复之前“拍平”的字典结构。

关键类与函数速查表

如果你要读代码，重点关注这几个部分：

  • sharded_tensor_to_torch_sharded_tensor:

    • 作用: 核心转换器。
    • 看点: 里面有很多 if/else 判断 has_flattened_range，这是在处理 MCore 为了性能把多维张量拉直（Flatten）后的特殊情况。它要把这些拉直的张量在逻辑上映射回全局的多维视角，以便 PyTorch 理解。

  • MCoreSavePlanner / MCoreLoadPlanner:

    • 作用: 指挥官。
    • 看点: 继承自 PyTorch 的 DefaultPlanner。主要修改了如何处理非 Tensor 数据（BytesIO）以及在加载时对 FP8 数据做内存连续化处理（resolve_tensor 方法）。

  • TorchDistSaveShardedStrategy:

    • 作用: 保存策略入口。
    • 看点: async_save 方法。它整合了上述所有步骤：转换字典 -> 生成计划 -> 异步写入。它还支持缓存元数据（cached_metadata），这样在训练中频繁保存 checkpoint 时不用每次都重新计算结构，提升速度。

  • TorchDistLoadShardedStrategy:

    • 作用: 加载策略入口。
    • 看点: load 方法。它不仅要加载，还要处理“Resharding”（重切分）。比如你用 TP=4 (张量并行) 训练存的模型，想在 TP=2 的环境下加载，这个类里的逻辑就要负责处理这种形状变化。

总结

这篇代码其实就是在回答一个问题： “PyTorch 标准库不懂 Megatron 是怎么切分模型的，我该怎么把 Megatron 的切分方式‘骗’过 PyTorch，让它以为这就是它自己标准的切分方式，从而帮我存文件？”

代码里大量的逻辑（比如处理 flattened_range、prepend_axis_num）都是为了抹平这两个系统之间的数据结构差异。
