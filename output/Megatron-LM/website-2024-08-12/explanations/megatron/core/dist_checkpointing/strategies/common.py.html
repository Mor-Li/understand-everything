megatron/core/dist_checkpointing/strategies/common.py

这段代码确实比较抽象，因为它是 Megatron-LM（一个用于训练超大模型的框架）中关于 分布式检查点（Distributed Checkpointing） 的底层实现逻辑。

简单来说，它的作用是：定义了如何用最基础的 PyTorch 方式（torch.save 和 torch.load）来保存和读取那些分散在不同显卡上的模型数据。

为了帮你读懂，我制定了一个 “学习任务清单 (Todo List)”。我们按照这个清单，从宏观概念到具体代码，一步步拆解。

📋 学习任务清单 (Todo List)

✅ Task 1: 理解背景 —— 我们在解决什么问题？

核心概念： 在多卡训练（分布式训练）中，保存模型（Checkpointing）比单卡复杂得多。 * 问题： 模型太大，被切分（Sharded）到了不同的 GPU 上。 * 目标： 我们需要把这些切碎的数据保存下来，或者把保存好的数据加载回去。 * 这个文件的角色： 它是“通用策略（Common Strategy）”，也就是最朴素的保存方式——直接把数据存成 .pt 文件。

✅ Task 2: 区分两种数据 —— "Common" vs "Sharded"

代码里反复出现这两个词，必须先分清： 1. Common State (通用状态): * 是什么： 所有显卡上都一样的数据。比如：当前的训练步数（step）、学习率参数、配置参数。 * 怎么存： 只需要保存一份（通常由主进程保存），大家都能读。 * 文件名： 代码里定义了 COMMON_STATE_FNAME = 'common.pt'。 2. Sharded Objects (分片对象): * 是什么： 被切分的数据。比如：超大模型的参数矩阵、优化器的状态。GPU 1 只有第一半，GPU 2 只有第二半。 * 怎么存： 每块显卡（或每个分片）需要保存自己负责的那一部分。

✅ Task 3: 读懂“保存”逻辑 (TorchCommonSaveStrategy)

目标： 看懂 TorchCommonSaveStrategy 类。

  • Step 3.1: 保存通用状态 (save_common) python def save_common(self, common_state_dict: StateDict, checkpoint_dir: Path): if torch.distributed.get_rank() == 0: # 重点：只有 Rank 0 (主进程) 动手 torch.save(common_state_dict, checkpoint_dir / COMMON_STATE_FNAME)

    • 解读： 既然大家数据都一样，没必要每个人都存一遍。只有老大（Rank 0）把数据写进 common.pt。

  • Step 3.2: 保存分片数据 (save_sharded_objects) python def save_sharded_objects(self, sharded_objects_state_dict: ShardedStateDict, checkpoint_dir: Path): for sh_obj in nested_values(sharded_objects_state_dict): # 遍历所有分片对象 if is_main_replica(sh_obj.replica_id): # 重点：去重 # ... 生成保存路径，然后 torch.save ...

    • 解读：
      • 这里有一个 is_main_replica 的判断。因为在某些并行策略下，GPU 1 和 GPU 2 可能持有相同的数据副本（Replication）。
      • 为了节省空间，如果有多个人持有同一份数据，只让“主副本”去保存。
      • 保存的文件名通常是 unique_key.pt。

✅ Task 4: 读懂“加载”逻辑 (TorchCommonLoadStrategy)

目标： 看懂 TorchCommonLoadStrategy 类。

  • Step 4.1: 加载通用状态 (load_common)

    • 逻辑： 很简单，找到 common.pt，用 torch.load 读进内存。如果文件不存在就报错。

  • Step 4.2: 加载分片数据 (load_sharded_objects)

    • 逻辑： 这是一个替换的过程。输入是一个包含“占位符”的字典，函数要把真正的 Tensor 数据填进去。
    • 核心代码段： python def load_sharded_object(sh_obj: ShardedObject): # 1. 拼凑出文件名 unique_key.pt load_path = checkpoint_dir / f'{sh_obj.unique_key}.pt' try: # 2. 尝试加载 loaded_obj = torch.load(load_path) except FileNotFoundError as e: # ... 后面一大堆是处理旧版本兼容性的 (Backward compatible) ... return loaded_obj
    • 解读： 代码主要是根据 unique_key 找到对应的 .pt 文件，加载数据并返回。try...except 块里那一长串代码是为了兼容旧版本的保存路径格式（以前可能不叫这个名，或者路径层级不同），如果找不到新格式的文件，就去试旧格式。

✅ Task 5: 理解元数据扫描 (进阶)

目标： 看懂 load_sharded_metadata。

  • 场景： 有时候我们不想真的把几百 GB 的模型加载进内存，我们只想知道“磁盘上有哪些分片？它们的形状（Shape）是多少？”
  • 逻辑：
    1. 遍历文件夹 (checkpoint_dir.iterdir())。
    2. 寻找 shard_*.pt 这种文件。
    3. 根据文件名推断出这是一个什么样的分片对象（构建 ShardedObject）。
    4. 解读： 这通常用于预检查或者转换 checkpoint 格式时使用。

✅ Task 6: 注册策略 (收尾)

目标： 看懂最后两行。

default_strategies[StrategyAction.LOAD_COMMON.value][('torch', 1)] = TorchCommonLoadStrategy()
default_strategies[StrategyAction.SAVE_COMMON.value][('torch', 1)] = TorchCommonSaveStrategy('torch', 1)
  • 解读：
    • 这是把上面定义的两个类“挂载”到系统的全局配置里。
    • 它的意思是：如果用户配置说我要用 torch 格式、版本 1 来进行 LOAD 或 SAVE 操作，那就请调用这个文件里写的 TorchCommonLoadStrategy 或 TorchCommonSaveStrategy。

总结 (Takeaway)

这个文件其实就是一个翻译官： 1. 对于保存： 它告诉 Megatron 框架，“别管那些复杂的分布式逻辑了，把数据给我，我用最标准的 torch.save 帮你存成文件，通用数据存一个文件，分片数据各存各的文件。” 2. 对于加载： 它告诉框架，“把你要读取的 Key 给我，我去硬盘上找对应的 .pt 文件，用 torch.load 读出来给你。”
