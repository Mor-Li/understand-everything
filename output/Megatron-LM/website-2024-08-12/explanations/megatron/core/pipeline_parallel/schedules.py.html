megatron/core/pipeline_parallel/schedules.py

这份代码 megatron/core/pipeline_parallel/schedules.py 是 Megatron-Core 中最核心的调度逻辑。

简单来说，它的作用就是充当流水线并行（Pipeline Parallelism）的“指挥官”。在一个庞大的模型被切分到多个 GPU 上时（比如 GPU 1 算第 1-10 层，GPU 2 算第 11-20 层），这个文件负责告诉每个 GPU 在每一时刻该做什么：是计算前向传播（Forward）？是计算反向传播（Backward）？还是给隔壁 GPU 发送数据？

为了让你看懂，我把这个文件要做的事情拆解成一个 GPU 的待办事项清单 (To-Do List)，并按逻辑顺序列出来。

核心观点：流水线并行的“三部曲”

这个文件主要实现了一种叫做 1F1B (One-Forward-One-Backward) 的调度策略。为了节省显存并保持 GPU 忙碌，它把一大批数据切分成很多个小份（Micro-batches），然后按以下三个阶段处理：

  1. 热身阶段 (Warmup): 先连续做几次前向计算，填满流水线。
  2. 稳定阶段 (Steady State / 1F1B): 做一次前向，紧接着做一次反向。进一个，出一个，保持平衡。
  3. 冷却阶段 (Cooldown): 流水线不再进新数据了，把剩下的反向传播做完。

这里的代码逻辑 To-Do List

假设你就是其中一块 GPU（比如 GPU Rank 1），以下是代码 forward_backward_pipelining_without_interleaving 函数指挥你执行的详细步骤：

✅ 任务一：准备工作 (Setup)

  1. 确定身份：
    • 我是流水线的第几站？（parallel_state.get_pipeline_model_parallel_rank()）
    • 我是第一站（只发不收）、中间站（既收又发）还是最后一站（只收不发，且要算 Loss）？
  2. 确定形状：
    • 我要接收的 Tensor 长什么样？我要发送的 Tensor 长什么样？（get_tensor_shapes）
  3. 关闭梯度同步：
    • 因为我们把一大批数据切碎了算，所以在所有 Micro-batch 算完之前，先别急着在这个 GPU 内部做 DDP（数据并行）的梯度同步。（disable_grad_sync()）

✅ 任务二：热身阶段 (Warmup Phase)

代码位置：forward_backward_pipelining_without_interleaving 中的第一个 for 循环

  • 目标：先把流水线填满，让后面的 GPU 有活干。
  • To-Do:
    1. 接收数据：从上一个 GPU（Rank 0）接收 input_tensor。（如果是第一站则直接读数据）。
    2. 前向计算 (forward_step)：
      • 调用 model(input_tensor)。
      • 如果是最后一站，计算 Loss。
    3. 发送数据：把计算结果 output_tensor 发给下一个 GPU（Rank 2）。
    4. 保存现场：把 input_tensor 和 output_tensor 存进一个列表里，因为等会儿反向传播要用（这很占显存）。
    5. 重复：重复上述步骤 num_warmup_microbatches 次。

✅ 任务三：稳定阶段 (1F1B Steady State)

代码位置：forward_backward_pipelining_without_interleaving 中的第二个 for 循环

  • 目标：这是最高效的阶段。为了不让显存爆炸，算完一个前向（占用显存），立马算一个反向（释放显存）。
  • To-Do:
    1. 前向部分 (1F):
      • 接收下一个 Micro-batch 的输入。
      • 执行 forward_step。
      • 关键点：如果不需要留着做反向（比如推理模式），或者为了节省显存，这里会调用 deallocate_output_tensor 把发出去的 Tensor 数据清空，只留个壳。
    2. 通信交换:
      • 把刚才的前向结果发给后一个 GPU。
      • 同时，从后一个 GPU 接收之前 Micro-batch 的梯度（output_tensor_grad）。
      • 代码函数：send_forward_recv_backward
    3. 反向部分 (1B):
      • 从缓存列表里取出很久以前存的 input_tensor 和 output_tensor。
      • 执行 backward_step：根据收到的梯度，算出当前层的梯度，以及要传给上一个 GPU 的梯度。
    4. 发送梯度:
      • 把算出来的输入梯度发给上一个 GPU。
      • 代码函数：send_backward_recv_forward（发走梯度的同时，顺便接收下一次的前向输入，形成循环）。

✅ 任务四：冷却阶段 (Cooldown Phase)

代码位置：forward_backward_pipelining_without_interleaving 中的最后部分

  • 目标：前向计算都做完了，现在要把流水线里剩下的反向传播全部收尾。
  • To-Do:
    1. 接收梯度：从后一个 GPU 拿梯度。
    2. 反向计算 (backward_step)：算出梯度。
    3. 发送梯度：把梯度扔给上一个 GPU。
    4. 重复：直到所有 Micro-batch 都处理完。

✅ 任务五：收尾工作 (Finalize)

  1. 梯度同步：
    • 所有小批次都算完了，现在开启 enable_grad_sync()。
    • 把这一大批数据累积的梯度，在数据并行组（Data Parallel Group）之间做 All-Reduce 同步。
  2. 处理 Embedding：
    • 如果是特定的模型结构，可能需要专门处理一下 Embedding 层的梯度（finish_embedding_wgrad_compute）。
  3. 返回结果：
    • 返回 Loss 信息，供打印日志。

进阶：什么是 "Interleaving" (交错式)？

对应函数：forward_backward_pipelining_with_interleaving

你可能会看到代码里还有个巨复杂的 with_interleaving 函数。

  • 普通模式 (Without Interleaving): GPU 1 负责第 1-10 层，GPU 2 负责 11-20 层。
  • 交错模式 (With Interleaving): 为了减少“气泡”（GPU 等待的时间），我们把模型切得更碎。
    • GPU 1 负责：第 1-2 层 和 第 9-10 层 (Virtual Rank 0 & 2)。
    • GPU 2 负责：第 3-4 层 和 第 11-12 层 (Virtual Rank 1 & 3)。
    • 代码差异：逻辑变得更复杂，因为同一个 GPU 要在不同的“虚拟层级”之间反复横跳。代码里会有 get_model_chunk_id 来计算当前是算哪一块模型。

总结代码中的关键函数

  1. get_forward_backward_func: 调度中心。根据配置决定是用“普通流水线”、“交错流水线”还是“单卡跑”。
  2. forward_step: 真正干活的。调用 model()，如果是最后一站就算 Loss。
  3. backward_step: 真正干活的。调用 torch.autograd.backward() 算梯度。
  4. deallocate_output_tensor / custom_backward: 这是个黑魔法优化。
    • PyTorch 默认会保留前向的 Output 用于反向。
    • 但在这里，Output 发给下一个 GPU 后，当前 GPU 就不需要它的数值了（只需要它的图结构）。
    • 这个函数把 Output 的数据内存清空（设为 1），防止显存浪费。反向传播时再用 C++ 引擎的 trick 绕过检查。

一句话总结

这个文件就是一张极其精密的列车时刻表，它指挥着数据在多个 GPU 之间像接力棒一样传递，确保在训练超大模型时，每个 GPU 都在干活，且显存不会被撑爆。
