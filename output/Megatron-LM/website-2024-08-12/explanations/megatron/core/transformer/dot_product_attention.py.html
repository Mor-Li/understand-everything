megatron/core/transformer/dot_product_attention.py

这份代码实现了 Megatron-LM 中的核心组件：点积注意力机制 (Dot Product Attention)。简单来说，这就是 Transformer 模型中 "Self-Attention"（自注意力）具体的数学计算过程。

之所以你觉得难懂，是因为它不仅包含数学公式，还夹杂了 Megatron 的并行化逻辑（Model Parallelism） 以及为了 GPU 计算效率做的 维度变换（Reshape/View）。

我为你整理了一个 "阅读与执行任务清单 (Todo List)"，我们将把代码拆解成 6 个具体步骤，像流水线一样一步步看完。

📋 任务清单 (Todo List)

  1. 初始化检查 (Init): 确认配置，计算“我这块 GPU”负责多少个头（Head）。
  2. 输入预处理 (Pre-process): 处理 Grouped Query Attention (GQA)，如果 Key/Value 的头数少于 Query，需要复制数据。
  3. 计算注意力分数 (Q × K): 将 Query 和 Key 进行矩阵乘法，算出原始分数。
  4. 归一化与掩码 (Scale, Mask & Softmax): 除以系数，遮住未来的词（Mask），然后算概率（Softmax）。
  5. 计算上下文向量 (Score × V): 将概率与 Value 进行矩阵乘法，得到注意力结果。
  6. 输出重塑 (Output Reshape): 把数据的形状变回 Transformer 下一层需要的格式。

💡 逐步讲解

1. 初始化检查 (__init__ 方法)

任务：我是分布式训练中的一张卡，我该负责计算模型切分后的哪一部分？

# 代码片段
world_size = parallel_state.get_tensor_model_parallel_world_size()
self.hidden_size_per_partition = divide(projection_size, world_size)
self.hidden_size_per_attention_head = divide(projection_size, config.num_attention_heads)
self.num_attention_heads_per_partition = divide(self.config.num_attention_heads, world_size)
  • 解读：
    • Megatron 使用 张量并行 (Tensor Parallel, TP)。假设模型有 16 个头，你有 2 张 GPU。
    • 代码计算出：num_attention_heads_per_partition = 8。这意味着当前的这个 DotProductAttention 实例只负责计算 8 个头，而不是全部。
    • 它还顺便初始化了 FusedScaleMaskSoftmax（一个融合了缩放、Mask、Softmax 的算子，为了跑得更快）。

2. 输入预处理 (forward 开头)

任务：处理 Query (Q), Key (K), Value (V)。特别是当使用 GQA (Grouped Query Attention) 时，K 和 V 的头数比 Q 少，形状对不上怎么办？

# 代码片段
if self.num_attention_heads_per_partition // self.num_query_groups_per_partition > 1:
    key = key.repeat_interleave(...)
    value = value.repeat_interleave(...)
  • 解读：
    • 标准 Attention：Q, K, V 头数一样，这段代码不执行。
    • GQA (Group Query Attention)：比如 Q 有 8 个头，K 和 V 只有 1 个头。为了能做矩阵乘法，必须把 K 和 V 复制 7 次，变成 8 个头，强行让它们形状对齐。
    • repeat_interleave 就是在做这个复制的工作。

3. 计算注意力分数 (Q × K)

任务：计算 $Score = Q \times K^T$。这是注意力机制的第一步，看 Query 和 Key 的相似度。

# 代码片段
# 1. 调整形状，把 Batch 和 Head 维度合并，方便做大矩阵乘法
query = query.reshape(output_size[2], output_size[0] * output_size[1], -1)
key = key.view(output_size[3], output_size[0] * output_size[1], -1)

# 2. 矩阵乘法
matmul_result = torch.baddbmm(
    matmul_input_buffer,
    query.transpose(0, 1),  # [b * np, sq, hn]
    key.transpose(0, 1).transpose(1, 2),  # [b * np, hn, sk]
    beta=0.0,
    alpha=(1.0 / self.norm_factor), # 这里顺便除以了根号d (Scale)
)
  • 解读：
    • Reshape: 输入是 [序列长, Batch, 头数, 维度]。为了计算快，代码把它变成了 [Batch*头数, 序列长, 维度]。这叫 "Batching the heads"。
    • torch.baddbmm: 这是 PyTorch 的批量矩阵乘法。
    • 它在做：Query 乘以 Key的转置。
    • alpha=(1.0 / self.norm_factor)：根据公式 $Attention(Q, K, V) = \text{softmax}(\frac{QK^T}{\sqrt{d_k}})V$，这里直接在乘法里把除以 $\sqrt{d_k}$ 做掉了。

4. 归一化与掩码 (Softmax)

任务：把分数变成概率。如果是 GPT 这种生成模型，还得把“未来的词”遮住（Mask）。

# 代码片段
attention_probs: Tensor = self.scale_mask_softmax(attention_scores, attention_mask)
attention_probs = self.attention_dropout(attention_probs)
  • 解读：
    • scale_mask_softmax: 这是一个融合算子（Fused Kernel）。它一步到位完成了：
      1. 加上 Mask（把不该看的词的分数设为负无穷大）。
      2. 做 Softmax（把分数变成 0~1 之间的概率）。
    • attention_dropout: 随机扔掉一些概率（置为0），防止过拟合。

5. 计算上下文向量 (Score × V)

任务：根据刚才算出的概率，从 Value (V) 中提取信息。$Output = Prob \times V$。

# 代码片段
# 1. 调整 V 的形状
value = value.view(value.size(0), output_size[0] * output_size[1], -1)
# 2. 调整 Prob 的形状
attention_probs = attention_probs.view(output_size[0] * output_size[1], output_size[2], -1)

# 3. 矩阵乘法
context = torch.bmm(attention_probs, value.transpose(0, 1))
  • 解读：
    • 这里再次进行了形状调整（View/Reshape），目的是为了匹配矩阵乘法的维度。
    • torch.bmm: 又是批量矩阵乘法。这次是 概率矩阵 乘以 Value矩阵。
    • 此时得到的 context 就是这一层 Attention 提取出的特征。

6. 输出重塑 (Output Reshape)

任务：计算完了，把数据的形状还原成 Transformer 下一层能看懂的样子。

# 代码片段
# [b, np, sq, hn] --> [sq, b, np, hn]
context = context.permute(2, 0, 1, 3).contiguous()

# [sq, b, np, hn] --> [sq, b, hp]
new_context_shape = context.size()[:-2] + (self.hidden_size_per_partition,)
context = context.view(*new_context_shape)
  • 解读：
    • permute: 把维度换位置。把 序列长度(Sequence Length) 换回到第一个维度（这是 Megatron 的习惯 [s, b, h]）。
    • view: 把 [头数, 每个头的维度] 合并成一个大的 [隐藏层维度]。
    • 注意：这里的 hidden_size_per_partition 依然是切分后的维度（比如总维度 4096，两张卡，这里输出就是 2048）。后续会有其他模块负责把不同 GPU 的结果拼起来（All-Reduce）。

总结

这个文件其实就在干一件事：$Attention(Q, K, V) = \text{softmax}(\frac{QK^T}{\sqrt{d_k}})V$。

难点在于： 1. 并行 (Parallelism): 它只算总头数的一部分。 2. GQA: 需要手动复制 K 和 V。 3. 形状变换 (Reshape): 为了 GPU 计算快，反复地把维度拉平（flatten）又折叠（view）。
