megatron/core/distributed/finalize_model_grads.py

这份代码确实涉及了很多分布式训练（Distributed Training）的底层细节，特别是 Megatron-LM 这种支持 3D 并行（数据并行 DP + 流水线并行 PP + 张量并行 TP）的复杂框架。

如果直接看代码，很容易被各种 group 和 rank 绕晕。为了让你听懂，我们把这个文件看作是一个 “大扫除清单” (Cleanup Checklist)。

场景设定

想象一下，模型刚刚完成了一次 反向传播（Backpropagation），每个 GPU 上都算出了一堆梯度（Gradients）。但是，因为我们用了分布式训练，现在的梯度是“散乱”的、不完整的。

在把这些梯度交给优化器（Optimizer）去更新参数之前，我们需要照着这个清单，一步步把梯度整理好。

这个文件的核心函数是 finalize_model_grads，我们就以它为中心，列出 4 个待办任务 (Todo List)：

✅ Task 1: 数据并行（DP）的梯度同步

代码位置： finalize_model_grads 函数开头部分 对应代码： model_chunk.finish_grad_sync()

  • 背景： 假设你有 8 个 GPU，分成了 2 组，每组 4 个 GPU 负责跑同一个模型副本（这就是数据并行）。
  • 问题： 每一组 GPU 看到的数据不一样，所以算出来的梯度也不一样。
  • 任务： 必须把所有副本的梯度加起来取平均，保证大家的模型更新方向一致。
  • 动作： finish_grad_sync() 会触发 DDP（分布式数据并行）的 All-Reduce 操作，把大家的梯度同步一下。

✅ Task 2: 序列并行（SP）的 LayerNorm 梯度同步

代码位置： _allreduce_layernorm_grads 函数 对应代码： _allreduce_layernorm_grads(model, config)

  • 背景： 为了省显存，Megatron 开了 序列并行（Sequence Parallelism）。这意味着一个长句子（比如 4096 长度）被切分到了不同的 GPU 上。
  • 问题： LayerNorm（层归一化）层需要统计全局的均值和方差。但是因为数据被切分了，每个 GPU 只算了一部分，它们手里的 LayerNorm 梯度是不完整的。
  • 任务： 那些切分了序列的 GPU 之间，需要专门把 LayerNorm 的梯度凑在一起加一加。
  • 动作： 代码会遍历所有参数，找到标记为 sequence_parallel 或者名字里带 layernorm 的参数，把它们的梯度在 张量并行组（TP Group） 里做一次 All-Reduce。

✅ Task 3: 流水线并行（PP）的 Embedding 梯度同步

代码位置： _allreduce_embedding_grads -> _allreduce_word_embedding_grads 对应代码： _allreduce_embedding_grads(model, config)

  • 背景： 在 流水线并行（Pipeline Parallelism） 中，模型被切成好几段。
    • GPU A 负责第 1 层（有输入词表 Embedding）。
    • GPU Z 负责最后 1 层（有输出层 Unembedding）。
    • 关键点： 在 GPT/BERT 这类模型中，输入层的权重和输出层的权重通常是共享的（Weight Tying）。也就是说，GPU A 和 GPU Z 其实共用同一本“字典”。
  • 问题： GPU A 算出了“输入端”对字典的梯度，GPU Z 算出了“输出端”对字典的梯度。但它们相隔十万八千里（在不同的 Pipeline 阶段）。
  • 任务： 必须把 GPU A 和 GPU Z 手里的 Embedding 梯度加起来。
  • 动作：
    • 判断自己是不是第一个 Stage 或者最后一个 Stage。
    • 如果是，就把 Embedding 的梯度在 Embedding Group（专门连接首尾 GPU 的通信组）里做 All-Reduce。
    • 注：代码里还顺便处理了 T5 模型的 Position Embedding，逻辑一样。

✅ Task 4: 根据 Token 数量缩放梯度（可选）

代码位置： finalize_model_grads 函数末尾 对应代码： if num_tokens is not None: ...

  • 背景： 很多时候，我们计算 Loss 是按 Token 的总数来平均的（Loss / Total_Tokens）。
  • 问题： 在流水线并行中，只有最后一个 GPU 知道这一轮到底跑了多少个有效 Token（因为前面的 GPU 跑完就扔给后面了，或者有 Padding 只有最后才知道）。而且，梯度本身可能还没除以这个总数。
  • 任务：
    1. 让最后一个 GPU 告诉所有人：“喂，这轮一共有 1000 个 Token！”（Broadcast）。
    2. 把这个数字在数据并行组里加起来（如果有多组数据并行）。
    3. 所有人把手里的梯度除以这个总 Token 数。
  • 动作：
    • torch.distributed.broadcast(num_tokens, ...)：广播 Token 数量。
    • model_chunk.scale_gradients(scaling)：把梯度乘以 1.0 / num_tokens。

总结 (Executive Summary)

这个文件的作用就是 “大一统”。

当 GPU 们各自算完反向传播后，它们手里的梯度是碎片化的： 1. DP 没同步 -> Task 1 解决。 2. SP 切分了 LayerNorm -> Task 2 解决。 3. PP 切分了首尾 Embedding -> Task 3 解决。 4. 还没做全局平均 -> Task 4 解决。

跑完这个 finalize_model_grads 函数，所有的梯度就都归位了，准备好让 Optimizer 更新参数了。
