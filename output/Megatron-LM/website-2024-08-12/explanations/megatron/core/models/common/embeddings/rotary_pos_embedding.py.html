megatron/core/models/common/embeddings/rotary_pos_embedding.py

这份代码看起来确实比较晦涩，因为它不仅包含数学公式（RoPE 旋转位置编码），还混合了Megatron 的分布式训练逻辑（Context Parallelism）以及底层性能优化（Apex Fused Kernel）。

为了让你看懂，我们可以把这个文件想象成一个“给大模型装配旋转位置编码（RoPE）的施工队”。

我为你列了一个 Task To-Do List，我们按顺序一步步把这个任务完成，你就懂了。

🛠️ Task List: RoPE 施工流水线

  1. 【备料】初始化频率 (Initialization)
    • 目标： 准备好旋转的基础参数。
  2. 【造尺子】生成位置编码矩阵 (Forward)
    • 目标： 根据当前序列长度，造出对应的 cos 和 sin 矩阵。
  3. 【切蛋糕】上下文并行处理 (Context Parallelism)
    • 目标： 如果序列太长，多个 GPU 分着干，每个人只拿自己那一小段的尺子。
  4. 【核心工艺】执行旋转 (Rotate Half & Apply)
    • 目标： 把输入的数据（Query/Key）按公式进行数学变换。
  5. 【总调度】自动选择工具 (Dispatcher)
    • 目标： 决定是用慢一点的 Python 算，还是调用底层超快的 CUDA 加速算。

详细步骤讲解

1. 【备料】初始化频率 (__init__)

RoPE 的核心思想是把向量两两分组进行旋转。旋转的角度取决于位置（Position）和频率（Frequency）。

  • 代码位置： class RotaryEmbedding -> __init__
  • 他在干啥：
    • dim: 拿到每个注意力头（Head）的维度。
    • inv_freq: 计算一个“频率表”。公式是 $1 / 10000^{2i/d}$。你可以理解为：向量中不同维度的元素，旋转的速度是不一样的。有的转得快，有的转得慢。
    • 这一步只是算好这些固定的数字，存起来备用。

2. 【造尺子】生成位置编码矩阵 (forward)

现在数据来了，假设长度是 max_seq_len（比如 4096），我们需要给这 4096 个位置每个都生成对应的旋转角度。

  • 代码位置： class RotaryEmbedding -> forward
  • 他在干啥：
    1. seq: 生成一个序列 [0, 1, 2, ..., max_seq_len-1]。
    2. freqs = torch.outer(seq, self.inv_freq): 核心一步。把位置和频率相乘，得到每个位置、每个维度对应的角度。
    3. emb: 这里生成了 cos 和 sin 需要用到的角度表。
      • 代码里有一个 rotary_interleaved 判断：
      • False (默认): 也就是 [x, x] 模式，前半部分和后半部分对应。
      • True: 也就是 [x1, x2, x1, x2] 交叉模式。
    4. 结果： 返回一个 emb 张量，形状大概是 [seq_len, 1, 1, dim]，这就是一把做好的“尺子”。

3. 【切蛋糕】上下文并行处理 (get_pos_emb_on_this_cp_rank)

这是 Megatron 特有的逻辑。假设你的输入序列特别长（比如 100k tokens），一张显卡存不下，需要用 Context Parallel (CP) 技术，把序列切开给多个显卡。

  • 代码位置： get_pos_emb_on_this_cp_rank 和 forward 结尾处。
  • 他在干啥：
    • 如果 parallel_state.get_context_parallel_world_size() > 1，说明开启了 CP 并行。
    • 比如序列长 8000，开了 2 个 GPU。
      • GPU 0 负责处理第 0-4000 个 token。
      • GPU 1 负责处理第 4001-8000 个 token。
    • 关键点： RotaryEmbedding 一开始生成了完整的 0-8000 的“尺子”。这个函数的作用是：GPU 1 说“把我的那一段（4001-8000）切给我，前面的我不要”。
    • 这样每个 GPU 拿到的位置编码，就能跟它手上拿到的那部分数据对齐了。

4. 【核心工艺】执行旋转 (_rotate_half & apply_...)

这是 RoPE 的数学本体。公式是： $$f(x) = x \cdot \cos(\theta) + \text{rotate}(x) \cdot \sin(\theta)$$ 其中 $\text{rotate}(x)$ 就是把向量 [a, b] 变成 [-b, a]。

  • 代码位置： _rotate_half 和 apply_rotary_pos_emb_bshd
  • Task 4.1: _rotate_half
    • 它把输入向量切成两半 x1, x2，然后拼接成 [-x2, x1]。这就是在做 90 度旋转的准备工作。

  • Task 4.2: apply_rotary_pos_emb_bshd

    • 输入 t (你的 Query 或 Key)。
    • 计算 cos 和 sin。
    • 核心计算： (t * cos_) + (_rotate_half(t) * sin_)。
    • 这就是把位置信息“注入”到你的向量里去了。

    注：代码里还有一个 apply_rotary_pos_emb_thd，这是针对 "Packed Sequence"（去掉了 padding 的紧凑格式）的处理，逻辑一样，只是数据形状不同。

5. 【总调度】自动选择工具 (apply_rotary_pos_emb)

最后，这个是外部调用的入口函数。

  • 代码位置： 文件最底部的 apply_rotary_pos_emb
  • 他在干啥：
    • 它像一个工头。
    • 检查工具： 看看有没有安装 NVIDIA 的 apex 库（HAVE_APPLY_ROPE_FUSION）。
    • 分支选择：
      • 方案 A (Fused): 如果有 apex 且配置开启，直接调用 fused_apply_rotary_pos_emb。这是 C++ 写好的 CUDA kernel，速度极快，一步到位。
      • 方案 B (Unfused): 如果没有，就调用上面定义的 Python 函数 (apply_rotary_pos_emb_bshd)，虽然慢一点，但逻辑清晰，哪里都能跑。

总结：这段代码在讲什么？

这段代码定义了一个 RoPE 模块，它的独特之处在于： 1. 能算： 实现了标准的 RoPE 旋转数学逻辑。 2. 能分： 能够处理 Context Parallel，支持超长序列在多卡间切分时的位置对齐（get_pos_emb_on_this_cp_rank）。 3. 能快： 只要环境允许，它会自动切换到 Apex Fused Kernel 进行加速。

你看懂这个 List，再回头看代码，就会发现它只是把这些步骤翻译成了 Python 而已。
