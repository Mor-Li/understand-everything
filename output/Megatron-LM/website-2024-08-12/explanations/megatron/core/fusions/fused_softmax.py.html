megatron/core/fusions/fused_softmax.py

这份代码确实比较底层，它属于 深度学习性能优化 的范畴，具体来说是 Megatron-LM（一个训练超大模型的框架）中用于加速 Transformer 注意力机制核心计算的代码。

简单来说，它的作用是：把“缩放(Scale) + 遮盖(Mask) + Softmax”这三步操作，合并成一步（Fused），扔给显卡（CUDA）去一次性算完。

为了让你看懂，我为你列了一个 “理解任务清单 (Todo List)”，我们一步一步来拆解这个文件。

📋 你的学习任务清单 (Todo List)

  1. 搞懂背景：为什么要“融合 (Fused)”？这到底是在算什么？
  2. 认识工具：看懂代码前三个类（Scaled...）是干嘛的。
  3. 认识管家：看懂 FusedScaleMaskSoftmax 这个主类是干嘛的。
  4. 理清逻辑：看懂代码是如何判断“能不能加速”的。
  5. 看懂流程：看懂数据是怎么流转的（走快车道还是慢车道）。

✅ 任务 1：搞懂背景

场景：Transformer 模型里最核心的公式是 $Attention(Q, K, V) = Softmax(\frac{QK^T}{\sqrt{d}} + Mask)V$。 痛点： 在 PyTorch 的标准写法里，括号里的操作是分三步走的： 1. Scale: 乘以 $\frac{1}{\sqrt{d}}$。 2. Mask: 把不需要关注的位置（比如 Padding 或者未来的词）填成负无穷大。 3. Softmax: 归一化转成概率。

这三步如果分开做，GPU 需要反复读写显存，速度慢且占内存。 解决方案：写一个 C++ CUDA 核心（kernel），把这三步合并在一起做，不用中间存取数据，这就是 Fused Softmax。

✅ 任务 2：认识工具 (前三个类)

文件开头定义了三个类，它们都继承自 torch.autograd.Function。这说明它们是自定义的算子，底层调用了 C++ 写的 CUDA 代码。

  1. ScaledUpperTriangMaskedSoftmax

    • 用途：专门给 GPT 类模型 用的。
    • 特点：它包含了一个“上三角遮罩 (Upper Triangular Mask)”。在 GPT 里，当前的词不能看后面的词，这叫 Causal Mask（因果遮罩），形状像个三角形。
    • 动作：缩放 -> 加上三角遮罩 -> Softmax。

  2. ScaledMaskedSoftmax

    • 用途：给 BERT 类模型 或者处理 Padding 用的。
    • 特点：它接受一个用户传进来的任意形状的 Mask。
    • 动作：缩放 -> 加上给定的 Mask -> Softmax。

  3. ScaledSoftmax

    • 用途：没有遮罩的情况。
    • 动作：缩放 -> Softmax。

注意：这三个类里都有 forward（前向传播）和 backward（反向传播）。因为这是自定义算子，PyTorch 不知道怎么自动求导，所以必须手动写清楚反向传播怎么算（代码里通过 import ..._cuda 调用了底层的反向实现）。

✅ 任务 3：认识管家 (FusedScaleMaskSoftmax)

这是你真正调用的类，它是一个 nn.Module。它的作用是根据情况调度上面的工具。

初始化参数 (__init__) 里的关键点： * input_in_fp16/bf16：输入数据是半精度的吗？（通常大模型训练都用半精度）。 * attn_mask_type：是 GPT 模式 (causal) 还是普通模式？ * scaled_masked_softmax_fusion：开关。用户是否想要开启融合加速？ * mask_func：如果不能加速，兜底用的普通 mask 函数。

✅ 任务 4：理清逻辑 (能不能加速？)

这是代码里最复杂的一块逻辑：is_kernel_available 函数。 显卡加速代码（CUDA Kernel）通常很娇贵，对数据的形状有严格要求。如果不满足要求，强行调用会报错。

代码逻辑翻译：

def is_kernel_available(self, mask, b, np, sq, sk):
    # b: batch size, np: number of heads, sq: sequence length (query), sk: sequence length (key)

    if (
        self.scaled_masked_softmax_fusion  # 1. 用户开启了加速开关
        and self.input_in_float16          # 2. 输入必须是半精度 (fp16/bf16)
        and 16 < sk <= 4096                # 3. 序列长度必须在 16 到 4096 之间 (太长或太短都不行)
        and sq % 4 == 0                    # 4. 长度必须能被 4 整除 (为了内存对齐)
        and sk % 4 == 0                    # 5. 同上
        and attn_batches % 4 == 0          # 6. batch * heads 必须能被 4 整除
    ):
        # ... 还有一些更细致的关于 block 大小的检查 ...
        return True

    return False # 如果任一条件不满足，就不能用加速

✅ 任务 5：看懂流程 (forward 函数)

这是数据流动的核心路口。

def forward(self, input: torch.Tensor, mask: Optional[torch.Tensor]):
    # 1. 检查能不能用 CUDA 加速内核
    if self.is_kernel_available(mask, *input.size()):
        # 走快车道
        return self.forward_fused_softmax(input, mask)
    else:
        # 走慢车道（兜底方案）
        return self.forward_torch_softmax(input, mask)

分支 A：快车道 (forward_fused_softmax)

如果条件满足，直接调用任务 2 中介绍的工具： * 如果是 GPT 模式 (AttnMaskType.causal) -> 调用 ScaledUpperTriangMaskedSoftmax。 * 如果是普通模式 -> 调用 ScaledMaskedSoftmax。 * 如果没有 mask -> 调用 ScaledSoftmax。

分支 B：慢车道 (forward_torch_softmax)

如果条件不满足（比如序列长度是 4097，或者用了 float32），就得用 PyTorch 原生代码一步步算： 1. 类型转换：如果需要，转成 float32（Softmax 在 float32 下更稳定）。 2. Scale：input = input * self.scale。 3. Mask：如果没有给 mask 且是 GPT 模式，现场生成一个上三角 mask，然后应用 mask。 4. Softmax：调用 torch.nn.Softmax。 5. 转回半精度：如果输入是 fp16/bf16，把结果转回去。

总结

这个文件其实就在说一件事：

“我要算 Softmax，如果数据格式完美符合要求，我就调用底层超快的 C++ 代码（Fused）；如果格式不符合，我就老老实实调用 PyTorch 的普通函数算。”
