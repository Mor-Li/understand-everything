megatron/training/global_vars.py

这个文件 megatron/training/global_vars.py 可以被看作是整个 Megatron-LM 训练系统的 “总管家” 或 “中央仓库”。

它的核心作用是：在程序的任何地方，都能方便地拿到配置参数、分词器、日志记录器和计时器，而不需要把这些变量在函数之间传以此。

为了让你看懂，我们把这个文件想象成一个 “大型工程项目的开工清单 (To-Do List)”。当 Megatron 开始训练模型时，它必须按顺序完成以下任务，才能保证后续工作顺利进行。

以下是按照逻辑顺序列出的任务清单：

第一阶段：准备空仓库 (定义全局变量)

任务目标：在内存里留出位置，准备存放接下来要用到的核心工具。

  • 代码位置：文件最开头的一排 _GLOBAL_ARGS = None 等。
  • 解读：
    • 这里声明了一堆以 _GLOBAL_ 开头的变量，初始都是 None（空的）。
    • 就好比在仓库里贴了标签：这里放“配置手册(Args)”，那里放“翻译机(Tokenizer)”，那边放“记事本(Tensorboard/WandB)”。此时架子上还是空的。

第二阶段：进货与初始化 (设置全局变量)

任务目标：这是最关键的一步。当训练脚本启动时，会调用 set_global_variables 函数，把真正的工具填进仓库里。

To-Do List 步骤：

  1. [必做] 存入“施工图纸” (set_args)

    • 动作：把外部传进来的 args（包含所有超参数，如层数、学习率、batch size）存入 _GLOBAL_ARGS。
    • 原因：以后任何代码想知道“现在的学习率是多少”，直接来这里查图纸，不用满世界问。

  2. [必做] 设定“计算器” (init_num_microbatches_calculator)

    • 动作：根据 batch size 初始化微批次（micro-batch）计算器。
    • 原因：Megatron 训练大模型需要把大 batch 切碎，这里负责设定切碎的逻辑。

  3. [选做] 组装“翻译机” (_build_tokenizer)

    • 动作：如果 build_tokenizer=True，就初始化分词器并存入 _GLOBAL_TOKENIZER。
    • 原因：模型看不懂中文英文，只看懂数字。这个工具负责把文本变成数字 ID。

  4. [选做] 准备“监控大屏” (_set_tensorboard_writer / _set_wandb_writer)

    • 动作：检查 args 里有没有要求开启 TensorBoard 或 WandB。如果有，并且当前是主进程（Rank 0 或最后一个 Rank），就初始化记录器。
    • 原因：为了画出 Loss 曲线，让你在网页上看到训练是不是崩了。

  5. [选做] 启用“断点续传助手” (_set_adlr_autoresume)

    • 动作：如果这是在集群环境且需要自动恢复训练，加载这个模块。
    • 原因：大模型训练几周很常见，机器挂了需要自动接着跑。

  6. [必做] 启动“秒表” (_set_timers)

    • 动作：初始化 Timers 对象。
    • 原因：用来统计每一层计算花了多少时间，用来分析性能瓶颈。

  7. [选做] 设置“紧急制动阀” (_set_signal_handler)

    • 动作：处理系统信号（比如你按了 Ctrl+C 或者集群杀任务）。
    • 原因：确保程序死的时候能优雅地保存数据，而不是直接崩溃。

第三阶段：分发工具 (Getters 获取函数)

任务目标：当其他代码（比如训练循环、模型层）需要工具时，通过这些窗口领取。

To-Do List 步骤：

  1. 有人来拿图纸 (get_args)

    • 逻辑：先检查仓库里有没有 args。如果有，给出去；如果还是 None，报错（Assert）。
    • 场景：模型构建代码需要知道 hidden_size 是多少。

  2. 有人来拿翻译机 (get_tokenizer)

    • 逻辑：检查并返回 tokenizer。
    • 场景：数据加载器需要把文本转成 Tensor。

  3. 有人来写日志 (get_tensorboard_writer 等)

    • 逻辑：直接返回。注意这里允许返回 None（因为可能没开启日志功能），调用者自己要判断是不是 None。

第四阶段：安全检查 (Helper Functions)

任务目标：防止仓库管理员犯迷糊。

  1. 防止重复进货 (_ensure_var_is_not_initialized)

    • 逻辑：在设置变量前调用。如果变量已经有值了，报错。
    • 原因：防止程序跑着跑着，突然有人把全局配置给覆盖了，导致前后逻辑不一致。

  2. 防止发空货 (_ensure_var_is_initialized)

    • 逻辑：在获取变量前调用。如果变量是 None，报错。
    • 原因：防止还没初始化（还没开工），就有工人来拿工具，导致程序崩溃。

总结

这篇文章其实就讲了一件事：单例模式（Singleton Pattern）的实现。

  • 它不负责计算（不跑模型，不求导）。
  • 它负责管理状态。它保证了在 Megatron 这个巨大的代码库里，所有人用的 args、tokenizer、timers 都是同一个实例，且全局可访问。
