megatron/legacy/model/fused_softmax.py

🚀 逐步讲解

Task 1: 搞懂背景 (Attention 的三步曲)

在 Transformer 模型中，计算 Attention 分数时，有一个经典的公式： $$ \text{Softmax}(\frac{Q \cdot K^T}{\sqrt{d}} + \text{Mask}) $$

这个公式在代码里通常体现为三个连续的操作： 1. Scale (缩放)：把输入乘以一个系数（比如 $\frac{1}{\sqrt{d}}$）。 2. Mask (掩码)：加上一个 Mask 矩阵（比如把某些位置设为负无穷大，让模型看不见）。 3. Softmax (归一化)：把数值转化为概率分布。

这个文件的目的： 就是为了极其高效地完成这三个步骤。

Task 2: 理解 "Fused" (融合算子)

  • 普通做法 (PyTorch 原生)：

    1. 从显存读取数据 -> 做乘法(Scale) -> 写回显存。
    2. 从显存读取数据 -> 加 Mask -> 写回显存。
    3. 从显存读取数据 -> 做 Softmax -> 写回显存。 缺点：读写显存（IO）次数太多，速度慢。

  • Fused (融合) 做法：

    1. 从显存读取数据 -> 一次性在芯片里做完 Scale + Mask + Softmax -> 写回显存。 优点：极大地减少了内存读写，速度飞快。

结论：这个文件就是为了调用 NVIDIA 专门写的 C++/CUDA 代码（Apex 库）来实现这个 "一次性做完" 的骚操作。

Task 3: 认识三个工兵 (底层的加速器)

文件中定义了三个继承自 torch.autograd.Function 的类。它们是 Python 和底层 CUDA 代码的桥梁。

  1. ScaledUpperTriangMaskedSoftmax

    • 用途：专门用于 GPT 类模型（Causal Mask）。
    • 特点：它不仅做缩放和 Softmax，还顺便施加了 "上三角掩码"（Upper Triangular Mask），也就是让当前词只能看前面的词，不能看后面的词。
    • 代码行为：尝试导入 scaled_upper_triang_masked_softmax_cuda。

  2. ScaledMaskedSoftmax

    • 用途：用于 BERT 类模型 或通用的掩码场景。
    • 特点：接受一个用户传入的任意 mask 矩阵，做 Scale + Mask + Softmax。

  3. ScaledSoftmax

    • 用途：没有 Mask 的情况。
    • 特点：只做 Scale + Softmax。

注意：这些类里都有 try...except ImportError，意思是：如果你没安装 NVIDIA 的 Apex 加速库，我就报错或者打印警告。

Task 4: 认识总指挥 (FusedScaleMaskSoftmax)

这是你真正会在模型里调用的 nn.Module 类。它是一个管理器。

它的主要参数： * input_in_fp16 / bf16: 输入数据是半精度吗？（加速通常需要半精度）。 * attn_mask_type: 是 GPT 这种因果掩码，还是普通的掩码？ * scaled_masked_softmax_fusion: 开关，用户是否想开启这个加速功能。

Task 5: 核心逻辑 (高速公路 vs 普通公路)

这是这个文件最精彩的部分，在 forward 函数里。

逻辑流： 当数据进来时，总指挥会问自己一个问题：“我现在的情况，能用底层那个超快的 CUDA 加速代码吗？”

这个判断逻辑在 is_kernel_available 函数里：

    def is_kernel_available(self, mask, b, np, sq, sk):
        # ... 省略部分代码
        if (
            self.scaled_masked_softmax_fusion  # 1. 用户开了加速开关吗？
            and self.input_in_float16          # 2. 数据是 FP16/BF16 吗？(CUDA核通常只支持半精度)
            and 16 < sk <= 16384               # 3. 序列长度在合适范围内吗？(太长或太短 CUDA 都不支持)
            and sq % 4 == 0                    # 4. 长度能被 4 整除吗？(显存对齐要求)
            and sk % 4 == 0                    # 5. 长度能被 4 整除吗？
            # ...
        ):
            return True # 可以走高速公路！
        return False    # 只能走普通公路。

最终执行 (forward)：

  • 情况 A：能加速 (forward_fused_softmax)

    • 如果是 GPT 任务 -> 叫 ScaledUpperTriangMaskedSoftmax 过来干活。
    • 如果是普通任务 -> 叫 ScaledMaskedSoftmax 过来干活。
    • 结果：飞快地完成计算。

  • 情况 B：不能加速 (forward_torch_softmax)

    • 因为硬件限制或数据格式不对，只能用 PyTorch 原生代码。
    • 代码逻辑：input * scale -> input + mask -> torch.nn.Softmax。
    • 结果：慢一点，但保证能算出结果（保底方案）。

💡 总结

这个文件讲了这么一件事：

我是一个 Softmax 管理员。

当你把数据给我时，我会检查你的数据格式是否完美符合 NVIDIA 高速引擎 (Apex CUDA Kernels) 的要求（比如必须是半精度、长度必须是 4 的倍数）。

  • 如果符合，我就调用底层的 C++ 代码，把缩放、掩码、Softmax 三合一 瞬间做完。
  • 如果不符合，我就老老实实调用 PyTorch 的普通函数一步步算，保证程序不崩。

这就是 Megatron-LM 训练大模型快的原因之一：它在每一个微小的环节都尝试用定制的 CUDA 代码来榨干 GPU 的性能。
