CONTRIBUTING.md

没问题。这份文件其实就是 Megatron-LM 项目的“投稿指南”或“入群守则”。

它的核心意思是：虽然我们（NVIDIA）欢迎大家参与，但这个项目主要还是我们在内部开发。如果你想通过 GitHub 提交代码或报错，请遵守以下规则。

为了让你更容易理解，我把它拆解成一个“新手任务清单 (Todo List)”，你只需要按照你想做的事情（是想报错？还是想改代码？）对号入座即可。

🟢 阶段一：心态准备（在做任何事之前）

  • Task 1：认清形势
    • 要知道这个项目主要是 NVIDIA 内部团队在维护。
    • 重点： 如果你想提交的代码会被先拉到 NVIDIA 的内部仓库，审核通过后再推送到 GitHub 上（虽然你会得到署名，但流程会慢一点）。
  • Task 2：判断你的改动大小
    • 如果是修个小 Bug：直接来，非常欢迎。
    • 如果是大改动（比如改架构、为了好看重写代码）：先别动手！ 先开一个 Issue（讨论帖）跟官方商量一下，否则容易白干。

🟡 阶段二：如果你想报错或提建议（关于 Issue）

如果你发现程序跑不通，或者想加新功能，请按以下步骤操作：

  • Task 1：选择正确的“模板”
    • 程序报错了？选 BUG 模板。
    • 速度变慢了或精度下降了？选 REGRESSION（退化/回退）模板。
    • 想加新功能？选 ENHANCEMENT（增强）模板。
    • 纯提问？不用模板，但要写清楚。
  • Task 2：遵守“一事一议”原则
    • 不要在一个帖子里把修 Bug、提建议、问问题全写在一起。一个问题发一个帖。
  • Task 3：确保“可复现” (关键！)
    • 官方团队很忙，如果你能提供一段代码，让他们复制粘贴就能看到报错，你的问题会被最优先处理。
  • Task 4：注意语气和格式
    • 拼写语法要正确，语气要专业、技术化。

🔵 阶段三：如果你想贡献代码（关于 Pull Request/PR）

如果你写好了代码想合并进去，请检查以下清单（Do's and Don'ts）：

  • Task 1：模仿现有风格
    • 虽然没有明文规定的代码规范，但请看一眼现有的代码长啥样，你的代码要跟它保持一致。
  • Task 2：整理提交记录 (Commits)
    • 拆分： 一个功能或一个修复对应一次提交，不要把所有改动揉成一团。
    • 基准： 确保你的代码是基于最新的 master 分支修改的 (rebase)。
  • Task 3：写好提交信息 (Commit Message)
    • 语法要求： 必须用祈使句。
      • ✅ 正确：Change the default argument (更改默认参数)
      • ❌ 错误：Changed ... (已更改...) 或 Changes ... (更改了...)
    • 检查拼写和标点。
  • Task 4：避坑指南 (千万别做的事)
    • 不要提交有许可证冲突的代码。
    • 不要“夹带私货”：只改跟你这次 PR 有关的代码，不要顺手去改别的文件的格式。
    • 不要提交被注释掉的代码（垃圾代码）。

🟣 阶段四：提交之后的等待（关于反馈）

提交完之后，什么时候有人理你？

  • Task 1：管理预期
    • 维护团队人很少，通常需要 1周 左右才会看你的消息。
    • 优先级排序：
      1. 能复现的 Bug 修复（最快处理）。
      2. 新功能建议（可能会被标记为“不予修复”如果跟官方方向不符）。
      3. “求助怎么运行代码”（优先级最低，有空才回）。
  • Task 2：催单技巧
    • 如果 1周 没人理你，可以艾特维护者（@jaredcasper 和 @jon-barker）。
  • Task 3：注意“僵尸”清理
    • 如果你提交的 PR 60天 没人动，会被机器人标记为“过期 (stale)”。如果你的老问题被关了但你觉得还有效，记得去评论里喊一声让它重开。

总结一下： 这篇文档就是告诉你：NVIDIA 内部开发优先，想参与要按规矩来。报 Bug 要能复现，提代码要写好说明书，遇到回复慢请耐心等待。
