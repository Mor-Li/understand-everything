jet-tests.yml

这份文件 jet-tests.yml 是一个 GitLab CI/CD 配置文件。

简单来说，它的作用是：“遥控”一个名为 JET 的外部测试系统，来对你的代码进行大规模的自动化测试，并取回测试结果。

你可以把它想象成你在指挥一个“测试工厂”进行工作。为了让你更容易理解，我把这份文件要做的事情拆解成一个 Task To-Do List（任务清单），我们一步一步来勾选并讲解。

📋 任务清单 (Task To-Do List)

  1. [门禁检查]：决定什么时候才需要启动这个测试流程？
  2. [环境准备]：设置好这次测试的“过滤条件” (Filter)。
  3. [配方调整]：把测试用的“菜单” (YAML配置) 里的食材换成最新的（替换镜像版本）。
  4. [按下发射按钮]：通知外部系统 (JET) 开始跑测试 (Trigger)。
  5. [查收成绩单]：等测试跑完，下载报告并判断是否通过。

📝 逐步详细讲解

1. [门禁检查]：决定什么时候启动

对应代码段： .jet_common

  • 讲人话：并不是每次你提交代码都要跑这个昂贵的测试。
  • 规则 (rules)：
    • 只有当你在 GitLab 上提了合并请求 (Merge Request)，并且 给这个请求打上了 Run tests 或 Build only 的标签 (Label) 时，才会运行。
    • 或者，如果是定时任务 (schedule) 也会运行。
    • 其他情况一律不跑 (when: never)。

2. [环境准备]：设置过滤条件

对应代码段： jet-setup

  • 讲人话：先设定好一些基础变量，告诉系统我们要测什么范围。
  • 动作：
    • 它设置了一个变量 JET_FILTER。
    • 如果没有手动指定，默认就是 False。
    • 它把这个变量保存到了一个文件 config.env 里，传递给后面的步骤使用（这叫 artifacts:reports:dotenv）。

3. [配方调整]：替换最新镜像

对应代码段： jet-configure

  • 讲人话：这是关键的一步。测试系统需要知道用哪个版本的软件来跑测试。这里用了一个叫 yq 的工具（专门改 YAML 文件的工具）来修改“测试配方”。
  • 动作：
    • 它找到了一个配置文件：tests/functional_tests/jet_recipes/build-pyt.yaml。
    • 魔法操作：它把配方里名为 mcore-pyt 和 mcore-nemo 的任务所使用的 Docker 镜像 (Image)，替换成了当前流水线刚刚构建好的新镜像 (${CI_MCORE_IMAGE}:${CI_PIPELINE_ID})。
    • 目的：确保测试的是你刚刚写的代码生成的最新镜像，而不是旧的。

4. [按下发射按钮]：触发外部测试

对应代码段： jet-trigger

  • 讲人话：这一步不做具体的测试，而是“打电话”给另一个项目组（dl/jet/ci），让它们去跑繁重的测试任务。这在 CI 里叫“下游流水线” (Downstream Pipeline)。
  • 动作：
    • trigger：触发项目 dl/jet/ci。
    • strategy: depend：表示“我会等你跑完”。如果下游失败了，这里也会显示失败。
    • variables：把我们前面准备好的变量（比如重试策略 retrier、过滤条件 JET_WORKLOADS_FILTER）传给下游，告诉它们怎么测。

5. [查收成绩单]：生成报告

对应代码段： jet-results-summary

  • 讲人话：下游测试跑完了，这一步负责把结果拿回来，整理成我们可以看懂的格式。
  • 动作：
    • needs: [jet-trigger]：必须等上面那个“发射按钮”的任务彻底结束才能开始。
    • jet secrets jwt-login ...：这是在登录 NVIDIA 的内部安全系统 (Vault)，获取权限。
    • python ... jet_test_pipeline.py ...：运行一个 Python 脚本。这个脚本会去分析测试结果，如果测试挂了，它会报错 (exit $rc)，导致整个流水线变红。
    • artifacts：把生成的脚本或日志保存下来，供你下载查看。

总结

这份 jet-tests.yml 就像是一个中介：

  1. 检查老板（你）有没有下令要测试（看 Label）。
  2. 打包好最新的产品（修改镜像配置）。
  3. 外包给专业的测试工厂（Trigger dl/jet/ci）。
  4. 汇报最终结果（运行 Python 脚本检查结果）。

你看不懂是因为它充满了大量的 CI 语法糖（比如 yq 命令、extends、artifacts），但核心逻辑就是：配置 -> 触发 -> 检查结果。
