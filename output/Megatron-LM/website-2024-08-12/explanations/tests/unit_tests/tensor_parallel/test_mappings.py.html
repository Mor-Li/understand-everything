tests/unit_tests/tensor_parallel/test_mappings.py

这份代码确实非常抽象，因为它测试的是分布式深度学习中的底层通信逻辑。要看懂它，你需要想象有多个显卡（GPU）同时在跑这段代码，且它们之间在互相传球（数据）。

这份文件的核心观点是：验证 Megatron-Core 框架中，张量并行（Tensor Parallelism, TP）和序列并行（Sequence Parallelism, SP）的通信算子，在“前向传播”和“反向传播”时的数学正确性。

💡 逐步讲解

Task 1: 搞懂“排兵布阵”

代码第一行测试都会调用 Utils.initialize_model_parallel(4, 2)。 这是全篇的数学基础： * World Size (总显卡数) = 4 * 2 = 8 张卡。 * TP (张量并行度) = 4。这意味着每 4 张卡组成一个小组，在这个小组内切分模型。 * PP (流水线并行度) = 2。 * Rank (当前显卡编号) = 0 到 7。

关键分组： * TP Group 1: Rank [0, 1, 2, 3] 是一组。 * TP Group 2: Rank [4, 5, 6, 7] 是一组。 * 所有的通信（Copy, Reduce, Scatter）都只发生在组内。

Task 2: 理解“复制”与“归约” (Copy & Reduce)

这里涉及两个最基础的算子。

1. test_CopyToModelParallelRegion (复制到并行区域) * 场景： 比如虽然用了 4 张卡并行，但有个输入（比如 Dropout 的 mask）是单卡生成的，需要让 4 张卡都拿到一模一样的这份数据。 * 前向传播 (Forward): 简单的复制（Identity）。输入是什么，输出就是什么。 * 代码：mappings.copy_to_tensor_model_parallel_region(input_data) * 反向传播 (Backward): 重点来了！如果 4 张卡在前向时拿到了同一份数据，那么在反向传播算梯度时，需要把 4 张卡的梯度加起来 (All-Reduce) 才能得到总梯度。 * 代码解读： * input_data = ... * Utils.rank: 假设 Rank 0 的数据是 0，Rank 1 是 1... Rank 3 是 3。 * output_data = ...backward(...): 模拟反向传播。 * 结果验证： * 对于 Group 1 (0,1,2,3)：梯度之和 = 0+1+2+3 = 6。 * 对于 Group 2 (4,5,6,7)：梯度之和 = 4+5+6+7 = 22。 * 这就是代码里 result * 6 和 result * 22 的由来。

2. test_ReduceFromModelParallelRegion (从并行区域归约) * 场景： 4 张卡各自算了一部分结果，现在要加起来得到最终结果（比如最后算 Loss 的时候）。 * 前向传播: 所有卡的数据相加 (All-Reduce)。 * 代码验证了 reduce_from... 的结果等于 rank 之和 (6 或 22)。 * 反向传播: 如果前向是“加法”，反向传播时，梯度会原封不动地复制给每一张卡。 * 代码验证了 backward 的结果等于 input_data（即没变）。

Task 3: 理解“切分”与“收集” (Scatter & Gather)

这是张量并行（TP）的核心。假设有一个大矩阵 (8行, 4列)。

1. test_ScatterToModelParallelRegion (切分) * 动作： 把大矩阵切开，分给 TP 组里的 4 张卡。 * 怎么切？ 默认切最后一个维度（列）。 * 代码解读： * 输入 (8, 4)。TP=4。 * Rank 0 拿第 0 列，Rank 1 拿第 1 列... * 验证：output_data 等于 input_data 的第 req_dim 列。 * 反向传播： 前向是“切分”，反向就是“拼凑（Gather）”。代码验证了反向操作能把分散的数据拼回成 0, 1, 2, 3 的序列。

2. test_GatherFromModelParallelRegion (收集) * 动作： 4 张卡手里各有一小条数据，把它们拼成一个大矩阵。 * 代码解读： * 前向传播：拼凑。Rank 0 的数据放在第 0 列，Rank 1 在第 1 列... * 反向传播：前向是“拼凑”，反向就是“切分”。 * 代码验证了 backward 出来的结果，正是当前 Rank 对应的那一列数据。

Task 4: 理解“序列并行” (Sequence Parallel)

这是 Megatron-Core 的进阶特性。TP 通常切的是 Hidden Size（列），而 SP 切的是 Sequence Length（行，即句子长度）。

1. test_ScatterToSequenceParallelRegion * 区别： 注意代码里的 req_dim 计算方式变了。 * 动作： 沿着第 0 维（行）切分。 * 代码解读： * 输入 (8, 4)。 * Rank 0 拿第 [0, 1] 行。 * Rank 1 拿第 [2, 3] 行。 * ... * 验证：output_data 等于 input_data 的切片 [req_dim : req_dim+2]。

2. test_ReduceScatterToSequenceParallelRegion * 这是一个组合动作：先做 Reduce（求和），再做 Scatter（切分）。 * 场景： 在 Transformer 的 MLP 层或 Attention 层输出后，通常需要先对 TP 的结果求和，然后为了省显存，不保留完整的全量结果，而是直接切分给各张卡保存。 * 代码解读： * 输入：大家都有一个 (4) 大小的向量。 * 前向：先加起来 (All-Reduce)，然后切成 4 份，每人拿一份。 * 验证：expected_output 既包含了求和的逻辑，也包含了切分的逻辑。

Task 5: 总结——前向与反向的“对偶性”

看懂这个文件，你只需要记住一个核心逻辑表，所有测试都在验证这个表：

算子名称 (Function) 前向传播 (Forward) 反向传播 (Backward)
Copy 复制 (Identity) 求和 (All-Reduce)
Reduce 求和 (All-Reduce) 复制 (Identity)
Scatter (TP/SP) 切分 (Split) 拼凑 (All-Gather)
Gather (TP/SP) 拼凑 (All-Gather) 切分 (Split)

文中的观点总结： 这篇代码不是在讲“观点”，而是在通过单元测试保证数学逻辑的严密性。它在说： 1. “当我把一个张量切分给 4 张卡时，我必须保证每张卡拿到的那部分是对的。” 2. “当我在反向传播算梯度时，如果前向是切分，反向必须自动把梯度拼回来，数值不能错。” 3. “如果是 Sequence Parallel，我要切的是行；如果是 Tensor Parallel，我要切的是列。”
