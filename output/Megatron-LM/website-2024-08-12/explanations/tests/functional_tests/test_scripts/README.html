你好！这里是 tests/functional_tests/test_scripts 目录的 README 文档。

根据你提供的目录结构，这个文件夹是一个纯粹的分类容器。它本身没有放置任何文件，而是把不同类型的模型测试脚本分门别类地整理好了。

以下是通俗易懂的解读：

1. 🏢 当前文件夹的主要功能

这里是 Megatron-LM 的“分科考场大厅”。

它的功能非常单一且明确：分类。 Megatron-LM 支持很多种模型（GPT、BERT、T5 等），每种模型的训练方式和测试重点都不一样。这个文件夹就像是一个大厅，墙上挂着不同的指示牌，指引你去往不同的“考场”（子文件夹）去运行具体的测试脚本。

2. 📄 直接文件的作用

根据你提供的目录结构，这一层级没有任何直接文件。

它就像是一个干净的走廊，地上没有散落的文件，只有通往各个房间（子文件夹）的门。

3. 📁 子文件夹的作用（概括）

这里就是通往各个具体“考场”的门：

  • 📁 bert/：BERT 考场。存放专门测试 BERT 模型（主要用于理解语言）的脚本。
  • 📁 gpt3/：GPT-3 考场。存放测试 GPT-3 系列模型（主要用于生成文本）的脚本，包括底层手动测试和 NeMo 框架测试。
  • 📁 multimodal/：多模态考场。存放测试那些既能看图又能识字的模型（如 LLaVA）的脚本。
  • 📁 retro/：Retro 考场。存放测试带有“检索外挂”功能（查资料生成）的模型的脚本。
  • 📁 t5/：T5 考场。存放测试 T5 模型（翻译、摘要等任务）的脚本。

4. 🧠 高层认知：如何快速理解这里

你可以把这个文件夹想象成 汽车检修中心的“派单前台”。

  • 当你要修 GPT-3 跑车时，前台会指引你去 gpt3/ 车间。
  • 当你要修 BERT 卡车时，前台会指引你去 bert/ 车间。

一句话总结： 这里是测试脚本的“分类目录”，它不干活，只负责把不同模型的测试脚本归纳到各自的文件夹里，方便开发人员和自动化系统快速找到对应的“体检套餐”。
