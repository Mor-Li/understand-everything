tests/functional_tests/test_scripts/gpt3/pretrain_gpt3_distributed_test.sh

这份脚本确实看起来很复杂，因为它不仅仅是用来“训练模型”的，它是一个自动化测试脚本（CI/CD pipeline的一部分）。它的目的是在不同的配置下（比如是否用FP8，是否用Transformer Engine，是否用Megatron-Core等）运行GPT-3的预训练，并验证结果是否正确。

你可以把它想象成一个“全自动试飞员”。它上飞机前要检查仪表，根据天气（环境变量）调整飞行模式，飞一圈，然后把黑匣子数据拿出来对比标准数据，看看飞得对不对。

我为你整理了一个 “试飞员的任务清单 (To-Do List)”，按照脚本执行的顺序一步步拆解：

📋 脚本执行任务清单 (To-Do List)

  1. [准备阶段] 收取并解析任务指令
    • 读取外部传入的参数（比如 KEY=VALUE），把它们变成脚本里的环境变量。
  2. [准备阶段] 设定默认参数与硬件环境
    • 如果没指定Batch Size或文件路径，就用默认值。
    • 确定有多少个GPU，网络地址是多少。
  3. [配置阶段] 制定“飞行模式” (关键逻辑)
    • 根据开关决定：是用旧版代码还是新版Megatron-Core？是用FP16还是FP8？是否允许随机性？
    • 根据这些决定，拼接出不同的环境变量和启动参数。
  4. [构建阶段] 组装启动命令 (torchrun)
    • 写出一个超级长的 torchrun 命令，里面包含了模型大小（层数、隐藏层维度）、并行策略（TP/PP）、数据路径等。
  5. [特殊分支] 断点续训测试 (Checkpoint Resume Test)
    • 如果开启了此模式：不仅仅是跑一次，而是要模拟“跑一半挂了 -> 读取存档 -> 继续跑”的过程，验证存档功能是否正常。
  6. [执行阶段] 点火发射
    • 打印最终命令，保存到文件，并真正执行它 (eval)。
  7. [验收阶段] 数据分析与合规检查
    • 从 TensorBoard 日志中提取 Loss（损失值）等数据。
    • 运行 pytest：把这次跑出来的数据和“标准答案（Golden Values）”做对比。如果误差太大，测试失败。

🧐 逐步详细解读

下面我按照上面的清单，带你一段一段看代码：

1. 收取并解析任务指令

for ARGUMENT in "$@"
do
   KEY=$(echo $ARGUMENT | cut -f1 -d=)
   ...
   export "$KEY"="$VALUE"
done
  • 白话解释：这就像试飞员接过任务书。你在运行脚本时输入的 MBS=4 GBS=32 等参数，在这里被拆解并设置为环境变量，供后面使用。

2. 设定默认参数与硬件环境

if [[ -z $MBS ]]; then MBS=4; fi
...
GPUS_PER_NODE=8
MASTER_ADDR=localhost
...
  • 白话解释：如果任务书没写Micro Batch Size ($MBS)，默认设为4。这里假定是在单机8卡（GPUS_PER_NODE=8）的环境下运行测试。

3. 制定“飞行模式” (配置开关)

这是最让人眼花缭乱的部分，全是 if。 * 确定性 (Deterministic): if [[ $ALLOW_NONDETERMINISTIC -eq 1 ]];。测试通常需要结果可复现，所以默认会强制关闭随机性算法。 * 新旧核心 (Core vs Legacy): if [[ $USE_CORE -eq 1 ]];。Megatron正在从旧架构迁移到Megatron-Core，这里决定用哪套代码。 * 精度 (FP8/BF16/FP16): if [[ $USE_FP8 -eq 1 ]];。如果开启FP8，就要加一堆FP8专用的参数。如果是Transformer Engine (USE_TE)，通常强制用 bf16。 * 存档测试准备: if [[ $CHECKPOINT_RESUME_TEST -eq 1 ]];。如果是为了测存档功能，训练步数 (MAX_STEPS) 会被强制缩短（比如只跑100步），因为我们不需要训练完，只要测能不能存取就行。

4. 组装启动命令 (Build Command)

代码中定义了一个函数 build_torch_run_cmd()。

torch_run_cmd="$run_cmd \
       pretrain_gpt.py \
       --num-layers 12 \
       --hidden-size 512 \
       ..."
  • 白话解释：这是在造“核弹”。
    • pretrain_gpt.py: 这是真正干活的训练代码。
    • --num-layers 12 --hidden-size 512: 这里硬编码了一个很小的模型（GPT-3 345M参数量），因为这只是功能测试，没必要跑几千亿参数的大模型，太费钱费时。
    • --tensor-model-parallel-size $TP_SIZE: 设置模型并行度。
    • ${ADDITIONAL_PARAMS}: 把第3步里根据各种开关攒出来的额外参数塞进去。

5. 特殊分支：断点续训 (Resume Test)

if [[ $CHECKPOINT_RESUME_TEST -eq 1 ]]; then
  ...
  command="$command; rm -rf ...; echo 50 > ...; $torch_run_cmd"
fi
  • 白话解释：如果这是个“断点续训测试”，逻辑会变得很变态：
    1. 先生成运行命令。
    2. 修改命令：先跑一段 -> 删掉第100步的存档（模拟丢失） -> 手动把记录改回第50步 -> 再次运行命令（触发Resume）。
    3. 它的目的是验证：模型能不能成功从第50步的存档加载，并继续训练。

6. 正式执行

echo "$command" > $SCRIPTS_DIR/pretrain_gpt3_distributed_command.sh
eval $command
  • 白话解释：把刚才拼凑了几百个字符的超长命令打印出来（方便你Debug），然后用 eval 执行它。这时候GPU开始转动，风扇开始呼啸。

7. 验收阶段 (Validation)

PYTHONPATH=$PWD python3 .../get_test_results_from_tensorboard_logs.py ...
if [[ $SKIP_PYTEST != 1 ]]; then
    pytest ...
fi
  • 白话解释：
    • 训练完了，生成了一堆日志。
    • 用一个Python脚本去读日志，把Loss曲线拿出来。
    • 关键一步：运行 pytest。
      • 如果是普通测试：对比 test_ci_pipeline.py 里的“黄金数据”（比如：第10步Loss应该是8.5）。如果跑出来是10.0，测试Fail。
      • 如果是FP8测试：对比FP8的基准数据。
      • 如果是续训测试：对比第一次跑和第二次续跑的曲线是否吻合。

总结

这个脚本就是一个大管家。你告诉它：“嘿，帮我测一下Megatron在8卡上跑FP16行不行”。 它就会： 1. 配置好环境变量。 2. 拼好命令。 3. 跑一个小模型。 4. 拿着放大镜看结果对不对。 5. 最后告诉你：Pass 还是 Fail。
