tests/functional_tests/jet_recipes

这是一个非常形象的比喻，帮助你快速理解 tests/functional_tests/jet_recipes 这个文件夹。

你可以把这个文件夹想象成一家自动化测试餐厅的“中央点单系统”。

这里存放的不是具体的“厨具”（测试代码）或“食材”（数据），而是“菜单”和“订单生成器”。

1. 这个文件夹主要负责什么功能？

核心功能：定义测试策略和生成测试任务。

如果 Megatron-LM 是一个正在接受体检的“超级运动员”，那么这个文件夹里的文件就是“体检套餐单”。

它负责告诉测试系统（Jet）： * 测什么？（GPT-3, BERT, T5...） * 什么时候测？（有人提交代码时？每天晚上？每周一次？） * 用什么姿势测？（单机8卡？多机多卡？开启 FP8？开启流水线并行？） * 去哪里测？（申请 A100 还是 H100 显卡？）

2. 这个文件夹下的各个直接文件分别是干什么的？

这里的 YAML 文件其实就是不同规格的“体检套餐”，我们可以按前缀把它们分类：

🍔 “快餐类”：MR-*.yaml (Merge Request)

  • 文件：MR-bert.yaml, MR-gpt.yaml, MR-t5.yaml 等。
  • 作用：提交代码时的快速检查。
  • 比喻：就像“入职体检”。每当有程序员提交新代码（Merge Request），系统就会跑这些测试。因为要跑得勤，所以通常用较小的模型、较短的时间，确保新代码没把最基本的功能搞坏。

🌙 “晚餐类”：nightly-*.yaml

  • 文件：nightly-bert.yaml, nightly-gpt.yaml。
  • 作用：每晚的全面检查。
  • 比喻：就像“每日复盘”。每天半夜，系统会用更复杂的配置、更长的时间去跑测试。它会覆盖更多白天没时间测的边缘情况（比如各种花式并行策略组合）。

📅 “大餐类”：weekly-.yaml / monthly-.yaml

  • 文件：weekly-gpt.yaml, monthly-t5.yaml。
  • 作用：定期深度压力测试。
  • 比喻：就像“年度全身体检”。这些测试非常昂贵（可能要用 H100 这种顶级显卡），跑的时间很长，专门用来验证大规模、高负载下的稳定性，或者测试最新的实验性功能（如 FP8）。

🏗️ “后勤类”：build-pyt.yaml

  • 作用：定义运行环境。
  • 比喻：这是“厨房准备清单”。在做菜（跑测试）之前，它告诉系统需要准备什么样的锅碗瓢盆（Docker 镜像、PyTorch 版本、NeMo 环境）。

🖨️ “工具类”：local-generator.py

  • 作用：本地生成脚本的工具。
  • 比喻：这是一个“订单打印机”。如果你不在公司的自动化系统（Jet）上，而是想在自己的服务器上跑这些测试，你可以运行这个 Python 脚本。它会读取上面那些 YAML 菜单，自动帮你生成出一堆可以直接运行的 .sh 脚本文件。

3. 子文件夹的作用是什么？

（注意：根据你提供的内容，jet_recipes 目录下并没有列出子文件夹，只有文件。但通常在 tests/functional_tests 的层级下，会有与之配合的兄弟文件夹。）

如果这个文件夹是“菜单”，那么它所引用的兄弟文件夹（如 test_scripts）就是“烹饪指南”。 * jet_recipes 里的 YAML 文件只是定义了参数（放多少盐、用多大火）。 * 真正执行操作的 Shell 脚本通常存放在 ../test_scripts/ 目录下（你在 YAML 的 script 字段里能看到对它们的引用）。

4. 高层认知：一句话总结

tests/functional_tests/jet_recipes 是自动化测试的“大脑配置中心”。

它利用矩阵生成技术（Matrix Generation），通过写一份 YAML 配置文件，就能自动生成几十种不同参数组合的测试任务，确保 Megatron-LM 这个庞然大物在任何硬件、任何并行策略下都能正常工作。
