tests/functional_tests/jet_recipes/MR-t5.yaml

这份文件确实乍一看很复杂，充满了各种参数和脚本。但其实它的逻辑非常清晰，它就是一个自动化测试的“菜谱”（Recipe）。

简单来说，这个文件告诉测试系统（名为 JET）：“请用指定的配置、在指定的硬件上，跑一遍 T5 模型的预训练，看看能不能跑通。”

为了帮你读懂，我制定了一个 5步走的 To-Do List。我们一步一步来拆解它：

✅ Task 1：搞清楚“我是谁，我在哪？”（文件定位）

首先，不要看细节，先看宏观属性。

  • 文件名：MR-t5.yaml。MR 通常指 Merge Request（代码合并请求），t5 是模型名字。这意味着：每当有人提交代码修改时，系统就要运行这个文件里的测试，确保 T5 模型没被改坏。
  • Context：这是 Megatron-LM（NVIDIA 开发的大模型训练框架）的测试配置。
  • 核心作用：定义一个“基准测试任务”。

✅ Task 2：准备“原材料”（解读 spec 部分）

spec (Specification) 定义了这次测试的默认配置。你可以把它看作做菜的原材料清单。

  • 模型设定：
    • model: t5, variant: 220m -> 测试的是 T5 模型，大小是 2.2 亿参数。
    • precision: bf16 -> 训练精度使用 BF16。
  • 硬件设定：
    • nodes: 1, gpus: 8 -> 使用 1 台机器，8 张显卡。
    • platforms: dgx_a100 -> 显卡型号是 A100。
  • 关键开关：
    • use_mcore: True -> 使用 Megatron Core（新版核心库）。
    • use_te: False -> 默认不使用 Transformer Engine（但在后面的 Task 4 中会被覆盖）。
  • 数据准备：
    • artifacts -> 把测试用的数据文件映射到 /workspace/data 目录下，确保程序能读到数据。

✅ Task 3：理解“烹饪步骤”（解读 script 部分）

这是文件最核心的“动作”部分。它告诉机器具体要执行什么命令。

  • 代码逻辑： bash cd /workspace/megatron-lm # 1. 进入代码目录 ./tests/.../pretrain_t5_distributed_test.sh ... # 2. 运行这个测试脚本
  • 参数传递（重点）： 你会看到很多 {} 包裹的内容，比如 TP_SIZE={tp_size}。
    • 这是一种填空题。
    • 它会把 spec（Task 2）或 products（Task 4）里定义的变量值，填入这个 Shell 命令中。
    • 例子：如果配置里 use_te 是 True，那么脚本里的 USE_TE 就会变成 "1"，否则是 "0"。

✅ Task 4：生成“最终套餐”（解读 products 部分）

这是最容易让人晕的地方，但也是最重要的。

  • spec 只是默认值。
  • products 定义了具体要生成的测试列表。它会覆盖 spec 里的默认值。

文中这一段的意思是：

products:
  - {use_te: [True], tp_size: [1], ... extra_args: ["--calculate-per-token-loss"] ...}

翻译成人话： 系统会生成一个具体的测试任务，这个任务的配置是： 1. 开启 Transformer Engine (use_te: True)。 2. 张量并行 (TP) 为 1。 3. 流水线并行 (PP) 为 1。 4. 额外参数：加上 --calculate-per-token-loss（计算每个 token 的损失）。

结论：这个文件最终只生成1个具体的测试任务（单机8卡，跑T5，开启TE加速）。

✅ Task 5：看懂“标签”（解读 name 字段）

回到文件最上面的 name 字段，那一长串像乱码一样的东西：

name: "{model}_{variant}_{scope}_{'mcore_' if use_mcore else ''}..."
  • 这是什么？ 这是给测试任务起名字的规则（动态命名）。
  • 为什么这么长？ 因为测试结果会发到看板上，开发人员需要通过名字一眼看出这个任务跑的是什么配置。
  • 生成的名字大概长这样： t5_220m_mr_mcore_te_tp1_pp1_vp1_calculate_per_token_loss_dgx_a100_1N8G (包含了模型、是否用mcore、是否用te、并行度、硬件信息等)

总结

这个文件讲了啥？

它在对自动化测试系统说：

“嘿，帮我跑一个测试。 名字叫 t5_220m_...。 硬件用 1 台 8 卡 A100。 软件环境用 Megatron Core 和 Transformer Engine。 并行策略是 TP=1, PP=1。 执行的脚本是 pretrain_t5_distributed_test.sh。 记得加上 --calculate-per-token-loss 参数。”

现在再回头看文件，是不是清晰多了？
