tools/openwebtext/remove_group_duplicates.py

这个脚本的逻辑其实非常直白，它的核心功能只有一件事：根据网址（URL）给数据去重。

想象一下，你有一堆从网上抓取的文章，但很多文章是重复的。这个脚本就是用来把那些重复文章挑出来扔掉，只保留一份。

为了让你更容易理解，我把你当作这个脚本的执行者（打工人），给你列一个 “任务清单 (To-Do List)”。你只需要按顺序完成这 4 个任务，就读懂了整个代码。

📋 任务清单 (To-Do List)

✅ Task 0: 准备工作 (接收指令)

代码位置： sys.argv[1], [2], [3] 你的任务： 老板（运行程序的人）给了你三个文件的路径，你要先拿在手里： 1. 黑名单线索书 (url_filename)：这里面记录了哪些网址是重复的。 2. 原始档案 (data_filename)：这里面装着所有的文章数据（好坏混杂）。 3. 最终成品箱 (output_filename)：你要把筛选后留下的好文章写到这里面。

✅ Task 1: 建立“黑名单” (找出要删谁)

代码位置： with open(url_filename, 'r') as f: 到 print('will be removing...') 你的任务： 你需要先读那本“黑名单线索书”，拿一个小本本（urls = set()）把所有需要删除的网址记下来。

  • 核心逻辑（重点）： 线索书里每一行可能长这样：{"group_id": ["url_A", "url_A_copy1", "url_A_copy2"]}。 这表示 url_A 和它的两个副本是一组重复的内容。 代码 for i in range(1, len(this_urls)) 的意思是：
    • 保留列表里的第 1 个（索引0，即 url_A）当作正版。
    • 从第 2 个开始（索引1，即 url_A_copy1...）统统拉入黑名单。

结论： 做完这一步，你手里有了一个巨大的“黑名单”，里面全是重复文章的网址。

✅ Task 2: 开始筛选 (核心工作)

代码位置： with open(output_filename, 'wb') as fout: ... for line in fin: 你的任务： 现在开始处理“原始档案”。你一行一行地读文章：

  1. 拿出一篇文章：解析它的 JSON 数据。
  2. 查黑名单 (if url in urls)：
    • 看看这篇文章的 url 在不在刚才的小本本上？
  3. 做决定：
    • 如果在黑名单里：说明它是重复的副本。直接扔掉（continue），并要在心里记一笔“我又删了一个”（removed_docs += 1）。
    • 如果不在黑名单里：说明它是正版。把它写入“最终成品箱” (fout.write)，并在心里记一笔“我又保留了一个”（written_docs += 1）。

代码位置： if written_docs % 10000 == 0: 你的任务： 因为文章可能高达几百万篇，如果你一直闷头干活不说话，老板会以为程序卡死了。 所以，代码规定：每成功写入 10,000 篇文章，你就得大喊一声（打印一行字）： * “我已经处理了多少秒！” * “保留了多少篇！” * “删除了多少篇！”

✅ Task 4: 收工 (总结)

代码位置： 最后几行 print(...) 你的任务： 所有文件都处理完了，最后做个大总结： * 总共耗时多少？ * 总共保留了多少好文章？ * 总共删掉了多少重复垃圾？ * 说一句：done :-)（搞定！）

总结文中的核心观点

这个脚本体现的数据处理观点非常简单粗暴：

  1. 基于 URL 判定重复：它认为只要网址（URL）一样（或者被之前的步骤判定为一组），内容就是一样的。
  2. “留一去多”策略：在一组重复的网址中，只保留第一个出现的，剩下的全部视为垃圾删除。
  3. 流式处理：它不是把几个 G 的文件一次性读进内存，而是一行一行读、一行一行写（Stream processing），这样处理超大文件时电脑才不会死机。
