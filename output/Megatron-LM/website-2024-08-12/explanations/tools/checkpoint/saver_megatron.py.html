tools/checkpoint/saver_megatron.py

这份代码确实比较晦涩，因为它涉及到了 Megatron-LM（一个用于训练超大模型的框架）的底层机制。

简单来说，这个脚本是一个 “存档员”（Saver）。它的工作是从另一个程序（Loader，加载器）那里接收模型的数据（权重），然后把这些数据整理、切割，最后保存成 Megatron-LM 能够识别和加载的检查点（Checkpoint）文件格式。

你可以把它想象成一个 “打包搬家” 的过程：Loader 负责把家具（模型权重）搬过来，这个 Saver 负责把家具拆解（并行切分）并装进特定的箱子（保存文件）里。

为了让你看懂，我列了一个 Task List (任务清单)，然后我们一步步对照代码来讲。

📋 Task List (代码执行流程清单)

  1. 环境准备：加载 Megatron 库，确保能调用它的功能。
  2. 伪造配置：根据传入的模型元数据（Metadata），伪造命令行参数，初始化 Megatron 的全局配置。
  3. 搭建骨架：根据配置，初始化一个“空”的 Megatron 模型结构（还没有填入权重）。
  4. 处理词表（Embeddings）：接收词向量，根据并行度（TP）切分词向量，填入模型。
  5. 处理中间层（Transformer Layers）：
    • 循环接收每一层的权重。
    • 按需切分权重（为了适应多卡并行）。
    • 将切分后的权重填入模型的对应层。
  6. 处理收尾层（Output/Head）：接收并填入最后的归一化层（LayerNorm）和输出层权重。
  7. 保存文件：调用 Megatron 的接口，将填好权重的模型写入硬盘。

💡 逐步详细解读

1. 环境准备 (Imports & Megatron Path)

代码一开始尝试导入 megatron 库。

    try:
        from megatron.training.arguments import (parse_args, validate_args)
        # ... 导入其他模块
    except ModuleNotFoundError:
        print("Unable to import Megatron...")
  • 观点：因为我们要保存成 Megatron 的格式，必须依赖它的原生代码。如果找不到库，脚本就报错退出。

2. 伪造配置 (Fake Arguments & Initialization)

这是代码中最“黑客”也是最难懂的部分。 Megatron 是一个通过命令行参数（如 --num-layers 12）来初始化的框架。但是这里我们是脚本调用，不是命令行启动。 * 代码逻辑： * md = queue_get(): 从队列里拿到模型的元数据（比如层数、隐藏层大小）。 * sys.argv = ['script.py', ...]：这里是关键！ 代码手动修改了 sys.argv，假装用户是在命令行里输入了这些参数。 * margs = parse_args(): 让 Megatron 解析这些伪造的参数。 * set_global_variables(margs, ...): 初始化 Megatron 的全局变量。

  • 为什么要这样做？：为了骗过 Megatron 的初始化流程，让它以为自己是在正常启动训练，从而建立起正确的配置环境。

3. 搭建骨架 (Get Models & Fake Distributed)

配置好后，需要创建一个空的模型对象，用来存放即将到来的权重。

    # 伪造分布式环境，假装我们现在处于第0号显卡
    mpu.set_tensor_model_parallel_rank(0)

    # 创建模型实例
    models = get_models(args.target_tensor_parallel_size, ...)
  • 观点：
    • TP (Tensor Parallel)：张量并行。大模型通常把一个大矩阵切开放在不同显卡上。
    • PP (Pipeline Parallel)：流水线并行。把模型的不同层放在不同显卡上。
    • 这段代码会根据你设定的目标并行度（target_tensor_parallel_size），创建出对应数量的空模型对象。

4. 处理词表 (Embeddings)

模型的第一部分是 Embedding 层。

    embeddings_msg = queue_get("embeddings") # 从队列接收数据
    # ... 处理 padding (词表对齐) ...

    # 核心操作：切分
    out_word_embed = torch.chunk(full_word_embed, args.target_tensor_parallel_size, dim=0)
  • 观点：
    • torch.chunk：这是核心。如果我要把模型分成 2 份（TP=2），我就要把词向量矩阵切成 2 半。
    • 代码随后把切好的一块块权重，塞进 models 里的对应位置。

5. 处理中间层 (Transformer Layers Loop)

这是代码最长的一段循环，处理 Transformer 的核心层（Attention 和 MLP）。

    for layer in range(len(models[0].language_model.encoder.layers)):
        msg = queue_get(f"transformer layer {total_layer_num}")

        # 接收 QKV 权重，并切分
        qkv_weight = torch.chunk(msg.pop("qkv weight"), args.target_tensor_parallel_size, dim=0)
        # 接收 Dense 权重，并切分 (注意 dim=1，因为矩阵乘法维度不同)
        dense_weight = torch.chunk(msg.pop("dense weight"), args.target_tensor_parallel_size, dim=1)

        # ... 将切分后的权重 copy_ 到模型里 ...
  • 观点：
    • 权重切分规则：
      • QKV (Query, Key, Value) 矩阵通常按行切 (dim=0)。
      • Dense (输出投影) 矩阵通常按列切 (dim=1)。
    • SwiGLU：代码里有专门处理 md.swiglu 的逻辑，因为 SwiGLU 结构的权重组合方式和普通 MLP 不一样。
    • 这一步就是把通用的权重，按照 Megatron 的并行规则，“分发”到各个分片的模型中。

6. 处理收尾层 (Post Process)

Transformer 层结束后，还有最后的 LayerNorm 和输出层。

    if post_process:
        msg = queue_get("final norm")
        # ... 复制 final norm 权重 ...

        if md.output_layer:
            # 如果有独立的输出层，也要切分
            output_layer_weight = torch.chunk(...)
  • 观点：如果是 BERT 或 GPT，最后还有 Pooler 或 LM Head，逻辑是一样的：接收 -> 切分 -> 填入。

7. 保存文件 (Save Checkpoint)

最后，所有权重都填好了，调用 Megatron 的保存函数。

    for tp_rank in range(args.target_tensor_parallel_size):
        mpu.set_tensor_model_parallel_rank(tp_rank) # 假装自己是当前这个 rank
        save_checkpoint(md.iteration, [models[tp_rank]], ...)
  • 观点：
    • 代码模拟了每一张显卡（Rank）。
    • 例如 TP=2，它先假装自己是 Rank 0，保存前半部分模型；然后假装自己是 Rank 1，保存后半部分模型。
    • 最终在磁盘上生成 mp_rank_00/model_optim_rng.pt 等文件。

总结

这个脚本的核心逻辑就是： 接收完整参数 -> 按照 Megatron 的并行规则（TP/PP）进行切分（Chunk） -> 塞入 Megatron 模型结构 -> 落盘保存。
