tools/checkpoint/loader_mcore.py

这份代码文件 loader_mcore.py 的核心作用是：作为一个“搬运工”，读取 NVIDIA Megatron-Core (MCore) 格式的分布式模型 Checkpoint，将分散在不同 GPU 上的权重（Tensor Parallel）合并成完整的参数，并通过队列（Queue）发送给主进程（通常用于模型格式转换，比如转成 HuggingFace 格式）。

它通常不会单独运行，而是被其他转换脚本（如 convert_checkpoint.py）调用。

为了让你更容易理解，我将这个脚本的执行流程拆解为一个 Task List (任务清单)，然后一步步给你讲解。

📋 Task List: 脚本执行流程清单

  1. 环境准备 (Environment Setup): 设置路径，导入 Megatron 库。
  2. 伪造启动参数 (Mock Arguments): 假装自己是一个正在启动的训练任务，以便骗过 Megatron 的初始化检查。
  3. 加载元数据 (Load Metadata): 从 Checkpoint 中读取模型配置（层数、隐藏层大小等）。
  4. 构建空模型 (Build Model Structure): 在内存中初始化模型架构（此时是空的或随机权重的）。
  5. 加载分布式权重 (Load Checkpoint Weights): 将硬盘上的 Checkpoint 权重加载到刚才构建的模型架构中。
  6. 发送配置信息 (Send Config): 告诉主进程这个模型长什么样。
  7. 合并并发送 Embedding (Process Embeddings): 合并词向量层并发送。
  8. 循环处理每一层 (Process Transformer Layers):
    • 提取 Norm 层参数。
    • 核心步骤： 遍历所有 Tensor Parallel (TP) 分片，提取 QKV、Dense、MLP 权重。
    • 核心步骤： 将切分的权重拼合（Concat）成完整矩阵。
    • 发送该层数据。
  9. 发送收尾层 (Process Final Layers): 发送 Final Norm 和 Output Layer。
  10. 完成 (Done): 发送结束信号。

🔍 逐步详解 (Step-by-Step Explanation)

1. 环境准备 (Environment Setup)

  • 代码位置: _load_checkpoint 函数开头。
  • 在做什么: 因为 Megatron 是一个第三方库，脚本需要把它的路径加入 sys.path 才能 import 里面的模块（如 mpu, model_provider 等）。如果找不到 Megatron，程序会报错并退出。

2. 伪造启动参数 (Mock Arguments)

  • 代码位置: sys.argv = ['script.py', ...] 那一大段。
  • 为什么: Megatron 的代码设计是给训练用的，初始化时会强制检查很多命令行参数（比如 --micro-batch-size）。
  • 怎么做: 这里手动修改了 sys.argv，填入了一堆 --no-xxxx 和默认值。特别是 --use-cpu-initialization，这是为了让模型在 CPU 上加载，而不是占用 GPU 显存（因为转换脚本通常在单机 CPU 上跑）。

3. 加载元数据 (Load Metadata)

  • 代码位置: load_args_from_checkpoint(margs, ...)。
  • 在做什么: 读取 Checkpoint 文件夹里的 config.json 或参数文件。
  • 目的: 知道模型有多少层 (num_layers)，隐藏层多大 (hidden_size)，用了什么精度 (fp16/bf16)，以及原来的并行度 (tensor_model_parallel_size)。

4. & 5. 构建模型并加载权重 (Build & Load)

  • 代码位置: get_models 函数内部。
  • 核心逻辑:
    • Megatron 的模型是切分存储的。比如 TP=2，意味着一个矩阵被切成了两半存在两个文件里。
    • 这个函数会模拟分布式环境。它通过循环 for rank in range(count)，依次假装自己是第 0 号卡、第 1 号卡...
    • model_provider(...): 创建模型骨架。
    • load_checkpoint(model_, ...): 把硬盘上的权重填入骨架。
    • 最后，models 列表里存放了所有分片的模型实例。

6. 发送配置信息 (Send Config)

  • 代码位置: md = types.SimpleNamespace() 到 queue.put(md)。
  • 在做什么: 把整理好的模型参数（元数据）打包成一个对象 md，通过 queue 发送出去。接收方（主进程）拿到这个包，就知道接下来要转换什么模型、怎么初始化 HuggingFace 的 Config 了。

7. 合并并发送 Embedding (Process Embeddings)

  • 代码位置: message = { "word embeddings": torch.cat(...) }。
  • 关键点: torch.cat(..., dim=0)。
  • 解释: 在 Megatron 中，词表（Vocab）通常是被切分的。比如 50000 个词，卡 0 存前 25000 个，卡 1 存后 25000 个。这里使用 torch.cat 把它们沿着第 0 维拼起来，还原成完整的 Embeddings 矩阵。

8. 循环处理每一层 (Process Transformer Layers)

这是最复杂也是最重要的部分。 * 代码位置: for layer_num in range(...) 循环内。 * 逻辑: 1. Layer Norm: 不需要合并，因为每张卡上存的 Norm 参数是一样的（或者只有一份）。直接取 models[0] 的数据。 2. QKV / Dense / MLP: 这些是线性层（Linear Layers），在 Megatron 中被切分了。 * 代码遍历 models (所有分片)。 * qkv_weight.append(...): 把每张卡的 QKV 权重拿出来放到列表里。 * torch.cat(qkv_weight, dim=0) (或其他 dim): 拼合操作。 * 如果是按列切分（Column Parallel），就按 dim=0 拼。 * 如果是按行切分（Row Parallel），就按 dim=1 拼。 3. SwiGLU 特殊处理: 如果模型用了 SwiGLU 激活函数，权重切分方式比较特殊，代码里专门有一段 if md.swiglu: 来处理这种复杂的拼接。 4. Queue Put: 拼好这一层的所有参数后，打包成字典 message，扔进队列。

9. 发送收尾层 (Process Final Layers)

  • 代码位置: final_layernorm 和 output_layer 部分。
  • 在做什么: 处理 Transformer 最后的 LayerNorm 和输出层（LM Head）。输出层通常也需要像 Embedding 一样进行 cat 拼接。

10. 完成 (Done)

  • 代码位置: queue.put("done")。
  • 在做什么: 告诉主进程：“我干完活了，所有权重都发过去了，你可以收工了。”

总结

这个脚本就像一个拼图大师。 原来的模型像是一个被切碎的拼图，散落在不同的文件夹里（模拟不同的 GPU）。这个脚本负责把这些碎片一块块捡起来，按正确的顺序和边缘拼好，然后把拼好的完整图片递给外面的人。
