docs/source

没问题，我们继续用“造车”和“说明书”的比喻，带你轻松看懂 docs/source 这个文件夹。

你可以把 docs/source 想象成 Megatron Core 这辆豪车的“文案编辑部”或者“说明书印刷底稿”。

以下是具体的解读：

1. 这个文件夹（docs/source）主要负责什么？

它是说明书的“底片”仓库。

  • 这里的代码不会跑去训练模型，也不会参与计算。
  • 它们存在的唯一目的，就是被一个叫 Sphinx 的工具读取，然后“打印”成一个漂亮的 HTML 网页，给程序员看。
  • 如果没有这个文件夹，程序员拿到 Megatron Core 的代码就像拿到一堆散乱的乐高积木，完全不知道从哪插起。

2. 这个文件夹下的直接文件（index.rst）是干什么的？

这里只有一个主角：index.rst。

  • 身份： 它是整本说明书的“封面” + “总目录” + “大堂经理”。
  • 作用：
    • 打招呼： 告诉你这是“Megatron Core 用户指南”。
    • 指路（核心功能）： 它手里拿着两张地图（toctree），一张指向“新手教程（User Guide）”，一张指向“零件参数表（API Guide）”。
    • 定调： 告诉你这东西是干嘛的（造大模型的 Python 库），以及去哪找参考案例（NeMo）。

3. 子文件夹的作用是什么？

这里主要分成了两个大章节，分工非常明确：

  • 📁 user-guide/（用户指南）：
    • 这是“驾校教练”。
    • 它负责教你“怎么用”。比如：怎么启动引擎？怎么挂挡？怎么跑起来？它讲究的是流程和方法。
  • 📁 api-guide/（API 指南）：
    • 这是“维修手册”或“零件字典”。
    • 它负责告诉你“这是啥”。比如：这个函数叫什么？它需要传几个参数？它返回什么结果？这里面全是硬核的技术细节（比如并行策略、模型组件的具体定义）。

4. 高层认知（一句话理解）

这里是 Megatron Core 的“图书馆”。

当你以后想知道“这个功能怎么用”或者“那个函数是什么意思”时，最终看到网页上的文字，全都是源自这里。它是给人看的，不是给机器跑的。
