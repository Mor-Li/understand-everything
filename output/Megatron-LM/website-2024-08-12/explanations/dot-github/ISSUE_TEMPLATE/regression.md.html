.github/ISSUE_TEMPLATE/regression.md

这份文件不是代码，也不是给你运行的脚本。

它是一个“填空题模板”。

背景解释： 这个文件位于 .github/ISSUE_TEMPLATE/ 目录下。当你在 GitHub 上给 Megatron-LM（一个训练大模型的软件）提 Issue（问题报告） 时，如果你选择“报告性能下降或准确率下降（Regression）”，GitHub 会自动把这段文字加载出来，让你照着填。

所谓的 Regression (回退/退化)，意思就是：“以前好好的，更新了版本之后，变慢了或者变笨了”。

为了帮你理解，我把你（作为一个用户）如果遇到了这个问题，需要做的 Todo List (任务清单) 列出来。按照这个清单一步步走，你就读懂这个文件的意思了。

📋 任务清单：如何向开发者报告“版本变差了”

假设场景：你上周用 Megatron-LM 训练模型很快，昨天更新了代码，今天发现训练速度变慢了一半。你需要填这个表告诉开发者。

✅ Task 1: 一句话概括发生了什么 (Describe the regression)

  • 原文对应： Describe the regression
  • 你需要做的事： 简单清楚地写下问题。
  • 例子： “更新到最新版代码后，GPT-3 模型的训练速度从 150 TFLOPS 降到了 100 TFLOPS。”

✅ Task 2: 告诉开发者怎么复现 (To Reproduce)

  • 原文对应： To Reproduce
  • 你需要做的事： 列出步骤，让开发者在他们电脑上也能看到这个问题。如果他们复现不了，通常就不会修。
  • 例子：
    1. 下载最新代码。
    2. 运行 pretrain_gpt.sh 脚本。
    3. 观察第 100 步的日志输出。

✅ Task 3: 拿出证据——以前的数据 (Previous performance)

  • 原文对应： Previous performance
  • 你需要做的事： 填入更新代码之前的速度或准确率。
  • 例子： “更新前：每次迭代耗时 2.5秒。”

✅ Task 4: 拿出证据——现在的数据 (New performance)

  • 原文对应： New performance
  • 你需要做的事： 填入更新代码之后（变差了的）速度或准确率。这也就是所谓的“Regression”。
  • 例子： “更新后：每次迭代耗时 5.0秒（慢了一倍）。”

✅ Task 5: 贴出报错日志 (Stack trace/logs)

  • 原文对应： Stack trace/logs
  • 你需要做的事： 如果程序崩了，把屏幕上那一长串看不懂的红色报错代码复制粘贴在这里。如果没有报错只是变慢了，可以贴运行日志。

✅ Task 6: 交代“案发现场”环境 (Environment)

  • 原文对应： Environment
  • 你需要做的事： 这是开发者最看重的部分。你需要对比新旧环境，填空：
    • Previous Megatron-LM commit ID: 以前好用的那个版本的代码编号是多少？
    • New Megatron-LM commit ID: 现在出问题的这个版本代码编号是多少？
    • PyTorch / CUDA / NCCL: 你的显卡驱动、PyTorch 框架版本有没有变？（有时候不是代码的问题，是你升级了 PyTorch 导致的）。

✅ Task 7: 提供建议 (Proposed fix) & 补充信息 (Additional context)

  • 原文对应： Proposed fix / Additional context
  • 你需要做的事： (可选) 如果你也是个高手，知道怎么修，可以在这里写方案。如果不知道，或者有其他想说的（比如“我很急，在线等”），写在 Additional context 里。

总结

这个文件的核心观点就是： “如果你觉得我们的新版本把事情搞砸了（速度变慢或精度下降），请不要只说‘不好用’，请按照这个格式，把新旧数据的对比、环境版本的变化详细列出来，这样我们才能修。”
