.github/ISSUE_TEMPLATE/question.md

这段代码对于不熟悉 GitHub 运作机制的人来说确实像天书。别担心，这其实不是一段用来“运行”的程序代码，而是一张“电子表格的设置单”。

为了让你彻底看懂，我们把这个过程想象成：你要去一家大公司（Megatron-LM 项目组）的前台办事。

这里有一份为你准备的学习 To-Do List，我们一步步来拆解：

✅ Task 1：理解场景（这是在哪儿？）

  • 背景： 你现在在 GitHub 网站上，Megatron-LM 是一个很有名的 AI 项目。
  • 问题： 每天都有成百上千的人想问开发者问题。如果大家随便乱写，开发者会疯掉。
  • 解决方案： 开发者决定设立一个“前台取号机”。你想提问？必须按格式填表。
  • 结论： 这个文件（question.md）就是定义那张提问表格长什么样的说明书。

✅ Task 2：看懂文件位置（它是干嘛的？）

  • 文件路径： .github/ISSUE_TEMPLATE/question.md
  • 解读：
    • .github/：这是给 GitHub 网站看的专用文件夹。
    • ISSUE_TEMPLATE/：意思是“问题模版”。
    • question.md：这是专门给“提问（Question）”这类事情准备的模版。
  • 结论： 这个文件告诉 GitHub：“当有人想提问时，请弹窗显示这个文件的内容。”

✅ Task 3：拆解头部设置（给“取号机”贴标签）

文件最上面被三根短横线 --- 包裹起来的部分，是给 GitHub 系统看的配置信息。

---
name: QUESTION
about: Ask a question about Megatron-LM that is not a bug, regression or enhancement request
title: "[QUESTION]"
labels: ''
assignees: ''
---

我们逐行翻译： 1. name: QUESTION * 意思： 在菜单里，这个选项叫“QUESTION”。 * 类比： 银行取号机上的按钮名称，比如“个人业务”。 2. about: Ask a question... * 意思： 这是按钮下面的小字说明。告诉用户：“如果你不是报 Bug，也不是求新功能，只是想问问题，就点这个。” 3. title: "[QUESTION]" * 意思： 当你点进去，标题栏里会自动帮你填好 [QUESTION] 这几个字，省得你动手敲。 4. labels: '' 和 assignees: '' * 意思： 标签和指派人是空的。意思是这个问题暂时不自动贴标签，也不自动指定给某个具体的管理员处理。

✅ Task 4：拆解正文内容（表格里的默认文字）

三根短横线下面的部分，是给用户看的，也是你点开后输入框里默认显示的文字：

**Your question**
Ask a clear and concise question about Megatron-LM.
  • **Your question**：这是加粗的标题，提示你“在这里写你的问题”。
  • Ask a clear...：这是提示语，意思是“请关于 Megatron-LM 问一个清晰、简洁的问题”。

✅ Task 5：脑补最终效果（用户看到了什么？）

当你完成了上面 4 步的学习，现在闭上眼想象一下，当一个用户想在 Megatron-LM 项目里提问时，会发生什么：

  1. 用户点击“New Issue”（新建问题）。
  2. 系统弹出一个菜单（由 Task 3 决定）：
    • 用户看到了一个叫 QUESTION 的按钮。
    • 下面有一行小字解释：Ask a question about Megatron-LM...
  3. 用户点击了这个按钮。
  4. 系统打开一个编辑器（由 Task 3 和 Task 4 决定）：
    • 标题栏自动填好了：[QUESTION]。
    • 正文框里已经写好了：**Your question** Ask a clear and concise question...
  5. 用户只需要在这些字后面接着打字就行了。

总结

你看到的这个文件，本质就是一张“在线表单”的配置文件。它存在的唯一目的，就是为了让来提问的人能按规矩办事，不要乱发帖子。
