.github/ISSUE_TEMPLATE/enhancement.md

这段代码看起来像天书，其实它根本不是代码，而是一张“电子问卷调查表”（或者叫填空题模板）。

在 GitHub（程序员存放代码的地方）上，当有人想要给这个项目提建议（比如增加新功能）时，项目管理者不希望大家乱写。所以，他们写了这个文件，强制要求提建议的人按照这个格式来回答问题。

为了让你完全看懂，我为你列了一个“理解任务清单 (To-Do List)”。请按照顺序，一步步完成下面的任务：

✅ 任务一：搞清楚“这是在哪儿发生的？”

  • 场景想象：假设你在用一个软件，觉得它少了一个功能，你想给开发者提建议。
  • 这个文件的作用：当你点击“提建议”按钮时，屏幕上会自动弹出这段文字。你必须在这些文字下面填空，开发者才会理你。
  • 文件名含义：.github/ISSUE_TEMPLATE/enhancement.md
    • ISSUE = 问题/事务
    • TEMPLATE = 模板
    • enhancement = 增强/改进（也就是“提新功能”的意思）

✅ 任务二：看懂“表头设置”（最上面几行）

文件最上面夹在两个 --- 之间的内容，是给系统看的“设置项”，不是给人填的。

  • name: ENHANCEMENT
    • 含义：告诉系统，这个模板的名字叫“功能增强”。
  • about: Suggest an idea to improve this project
    • 含义：简介。告诉用户，选这个模板是为了“给项目提改进点子”。
  • title: "[ENHANCEMENT]"
    • 含义：当你打开这个模板，标题栏会自动帮你填好 [ENHANCEMENT] 这个前缀，方便分类。

✅ 任务三：理解“核心五问”（中间的英文部分）

这是文件的主体。开发者通过这五个问题，表达了他们的“观点”：别只说‘我要这个’，请告诉我‘为什么’和‘怎么做’。

请逐行对照：

1. 第一问：你为什么痛？

原文：Is your feature request related to a problem? Please describe. A clear and concise description of what the problem is. Ex. I'm always frustrated when [...]

  • 翻译：你的这个请求是因为遇到了什么问题吗？请描述一下。比如：“每当我……的时候，我都感到很挫败。”
  • 潜台词：不要为了加功能而加功能。请先告诉我你的痛点在哪里。

2. 第二问：你要什么药？

原文：Describe the solution you'd like A clear and concise description of what you want to happen.

  • 翻译：描述一下你想要的解决方案。清晰简洁地说明你希望发生什么。
  • 潜台词：直接告诉我，你希望软件变成什么样？

3. 第三问：有没有别的药能治？

原文：Describe alternatives you've considered A clear and concise description of any alternative solutions or features you've considered.

  • 翻译：描述一下你考虑过的替代方案。
  • 潜台词：除了你刚才说的办法，还有没有别的办法能解决你的问题？（这能看出你是否经过了深思熟虑）。

4. 第四问：你会做药吗？

原文：Proposed implementation If you have a proposed implementation for the feature state it here or link to a PR.

  • 翻译：提议的实现方式。如果你知道怎么写代码实现它，请在这里说明，或者贴上你的代码链接。
  • 潜台词：如果你自己能动手写代码解决，那就更好了，直接把方案甩给我。

5. 第五问：还有啥要补充的？

原文：Additional context Add any other context or screenshots about the feature request here.

  • 翻译：额外的背景信息。在这里添加任何其他背景，或者截图。
  • 潜台词：有图有真相，或者有其他补充的赶紧说。

✅ 任务四：总结（完成理解）

现在你回头看这个文件，它其实就是一张“新功能申请单”。

  • 它的核心观点是：沟通效率。
  • 它想避免的情况是：用户只说一句“能不能把这个改好点？”，然后开发者一脸懵逼。
  • 它强制用户做的事：按逻辑（痛点 -> 方案 -> 替代方案 -> 技术细节）把事情说清楚。

恭喜你，你现在已经完全看懂这个 GitHub 模板文件在讲什么了！
